# BUG-366 — `SubprocessTransport` leaks `pidfd` when exit watcher is cancelled during `loop.close()` or `SubprocessTransport` deallocation

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — leaks the kernel `pidfd` file descriptor whenever a `SubprocessTransport` is still waiting for process exit when the loop closes
- **Category**: FD Leak
- **Files**:
  - `src/transports/subprocess/transport.zig:23-44, 81-96, 326-336`
- **Related**: [BUG-314](314.md), [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/transports/subprocess/transport.zig:285-324`, `start_exit_watcher` opens a `pidfd` via `std.os.linux.pidfd_open(transport.pid, 0)`, stores it in `transport.pidfd = pidfd`, and queues a `PollFd` task on `loop_data.io` with `.func = &pidfd_exit_callback` and `.cleanup = &pidfd_exit_cleanup`.

Look at `pidfd_exit_callback` (lines 326–336), `pidfd_exit_cleanup` (lines 364–367), `subprocess_clear` (lines 23–36), and `subprocess_dealloc` (lines 38–44):

```zig
fn pidfd_exit_callback(data: *const CallbackManager.CallbackData) !void {
    const transport: *SubprocessTransportObject = @ptrCast(@alignCast(data.user_data.?));
    if (data.cancelled()) {
        python_c.py_decref(@ptrCast(transport));
        return;
    }

    // Close the pidfd
    if (transport.pidfd >= 0) {
        _ = std.os.linux.close(transport.pidfd);
        transport.pidfd = -1;
    }
```

```zig
fn pidfd_exit_cleanup(ptr: ?*anyopaque) void {
    const transport: *SubprocessTransportObject = @ptrCast(@alignCast(ptr.?));
    python_c.py_decref(@ptrCast(transport));
}
```

When the event loop is closed while a subprocess is still running (or if `pidfd_exit_cleanup` runs instead of `pidfd_exit_callback`):
1. `pidfd_exit_callback` takes the `if (data.cancelled())` branch at line 327, decrefs `transport`, and returns at line 329 **before** closing `transport.pidfd` (lines 333–336)!
2. `pidfd_exit_cleanup` (lines 364–367) only decrefs `transport` without closing `transport.pidfd`.
3. Neither `subprocess_clear` (lines 23–36) nor `subprocess_dealloc` (lines 38–44) closes `instance.pidfd` when `instance.pidfd >= 0`!
Thus `transport.pidfd` is permanently leaked in the process file descriptor table.

Additionally, at line 290 of `start_exit_watcher`:
```zig
const pidfd: std.posix.fd_t = @intCast(rc);
```
is executed **before** `if (@as(isize, @bitCast(rc)) < 0)` at line 291, so if `pidfd_open` fails (e.g. `ESRCH` or `EMFILE`), `@intCast(rc)` panics in `Debug`/`ReleaseSafe` builds (violating Mandate #1).

## Trigger Scenario

1. Spawn a subprocess via `await loop.subprocess_exec(...)`.
2. Close the loop (`loop.close()`) before the subprocess exits (or after `transport.kill()` before the exit poll fires).
3. `pidfd_exit_callback` receives `data.cancelled() == true` and returns at line 329 without closing `transport.pidfd`.

## Proposed Remediation

1. Close `transport.pidfd` (if `transport.pidfd >= 0`) inside the `if (data.cancelled())` branch of `pidfd_exit_callback`, in `pidfd_exit_cleanup`, and as a final safety net in `subprocess_dealloc`.
2. In `start_exit_watcher` (`src/transports/subprocess/transport.zig:289-292`), check `if (@as(isize, @bitCast(rc)) < 0)` **before** `const pidfd: std.posix.fd_t = @intCast(rc);`.


## Resolution (2026-10-18)

Report claim 2 (pidfd_open truncation) was already obsolete: BUG-326's
raw-syscall errno decoding landed before the `@intCast`. Claim 1 is real
and fixed:

- new `close_pidfd(transport)` helper (`pidfd >= 0` guard + `-1`
  reset — double-close impossible across all exit paths, and the
  watcher's owning transport reference rules out a concurrent dealloc);
- `pidfd_exit_callback`'s cancelled/closed branch now closes the pidfd
  before dropping the reference — this is the leak the report's
  `loop.close()` reproduction hits (subprocess_close() already clossed
  it for the `closed` half, so the helper is a no-op there);
- `cleanup_pidfd` (watcher destroyed without executing — teardown
  drain) closes the pidfd too;
- `subprocess_dealloc` gained the final safety net close.

## Test

`tests/test_subprocess.py::test_bug366_pidfd_closed_on_loop_close`:
six spawns of `sleep 5` abandoned at loop close; the test counts
`anon_inode:[pidfd]` descriptors in `/proc/self/fd` (a plain fd count
would also pick up the abandoned transport's child pipes, which are
outside this bug's scope) and asserts zero stray pidfds.

**Bite verification**: reverting transport.zig to the pre-fix shape
(no close on the cancelled branch, plain decref cleanup, no dealloc
net) makes the test fail with `6 stray descriptors` — one leaked pidfd
per spawn. Green on 3.13/3.13t/3.14/3.14t in ReleaseFast.
