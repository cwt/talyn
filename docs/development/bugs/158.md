# BUG-158 — `BTree.get_min_value_ptr` returns `?Value` instead of `?*Value`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — type signature mismatch / double-dereference bug
- **Files**: `src/utils/btree.zig:150-158`
- **Lessons**: [Data Structures §Lesson 02](../lessons/07-data-structures-and-algorithms.md), [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/utils/btree.zig`, `get_min_value_ptr` declares its return type as `?Value` instead of `?*Value` (in contrast with `get_max_value_ptr` which correctly returns `?*Value`). For non-pointer `Value` types, returning `find_min_from_node` (which returns `?*Value`) produces a compile error. For pointer types (such as `*FDWatcher`), `get_min_value` executes `value_ptr.*`, double-dereferencing the pointer and returning the underlying struct rather than the pointer value.
- **Trigger**: Instantiating or calling `get_min_value_ptr` / `get_min_value` on a `BTree`.
- **Consequences**: Compilation failure on non-pointer values or incorrect double-dereference on pointer values.
- **Fix**: Corrected the return type of `get_min_value_ptr` to `?*Value`, matching `get_max_value_ptr` and `find_min_from_node`.
