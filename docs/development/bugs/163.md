# BUG-163 — Use-After-Free and refcount leak on OOM in `ChildWatcher.add_child_handler`

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — use-after-free & refcount leak
- **Files**: `src/loop/child_watcher.zig:55-75`
- **Lessons**: [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md), [Unix Signals §Lesson 77](../lessons/07-signals-and-processes.md)
- **Description**: In `src/loop/child_watcher.zig`, `add_child_handler` allocates `handler`, increments `handler.callback` with `py_newref`, and submits the handler to `io_uring` with `user_data = handler`. If the subsequent `self.handlers.put(...)` fails with OOM, `errdefer self.loop.allocator.destroy(handler)` destroys `handler` immediately while `io_uring` is still actively monitoring the `pidfd`. When the child exits or the loop shuts down, the completion callback accesses freed memory. Additionally, `handler.callback` is never decreffed on error.
- **Trigger**: Memory allocation failure when registering a child process watcher handler.
- **Consequences**: Memory corruption, invalid pointer dereference (UAF), and Python reference leak.
- **Fix**: In the `errdefer` path, cancel the queued `io_uring` task, call `python_c.py_decref(handler.callback)`, and safely coordinate destruction with cancellation completion.
