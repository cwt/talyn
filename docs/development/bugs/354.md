# BUG-354 — Memory and `PyObject` reference leak of `SocketCreationData`, `SocketConnectionData`, `ServerCreationData`, and `ServerSocketData` on DNS failure or cancellation

- **Status**: 🔴 Open
- **Severity**: 🔴 High — 100% memory and `PyObject` reference leak of `FutureObject`, `LoopObject`, `protocol_factory`, and all host/port/option objects whenever DNS resolution fails or is cancelled in `loop.create_connection` or `loop.create_server`
- **Category**: Memory & Reference Leak
- **Files**:
  - `src/loop/python/io/client/create_connection.zig:369-418`
  - `src/loop/python/io/server/create_server.zig:267-281, 311-369`
- **Related**: [Lesson 28](../lessons/02-zig-and-memory.md), [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

In both `src/loop/python/io/client/create_connection.zig` and `src/loop/python/io/server/create_server.zig`, `set_future_exception` has return type `void` (not an error union). However, four DNS resolution functions rely on `errdefer ...deinit()` while returning `set_future_exception(...)` on failure:

1. **`try_resolv_host` (`src/loop/python/io/client/create_connection.zig:369-374`)**:
   ```zig
   errdefer socket_connection_data.deinit();
   ...
   } else |err| {
       return set_future_exception(err, creation_data.future.?);
   }
   ```
   Because `return set_future_exception(...)` returns `void` (normal return), `errdefer socket_connection_data.deinit()` does **not** run when synchronous `dns.lookup` returns an error!

2. **`host_resolved_callback` (`src/loop/python/io/client/create_connection.zig:383-418`)**:
   ```zig
   const socket_connection_data: *SocketConnectionData = @ptrCast(@alignCast(data.user_data.?));
   errdefer socket_connection_data.deinit();

   const creation_data = socket_connection_data.creation_data;
   if (data.cancelled()) {
       python_c.raise_python_runtime_error("Host resolution cancelled\x00");
       return set_future_exception(error.PythonError, creation_data.future.?);
   }
   ...
   } else {
       python_c.raise_python_runtime_error("DNS resolution failed\x00");
       return set_future_exception(error.PythonError, creation_data.future.?);
   }
   ```
   In both the `if (data.cancelled())` branch and the `else` ("DNS resolution failed") branch, `host_resolved_callback` returns `void` via `set_future_exception(...)`! Neither `errdefer socket_connection_data.deinit()` nor `CallbackManager`'s `cleanup_host_resolved_callback` runs (because the callback returned `void`, not an error), leaking `SocketConnectionData`, `SocketCreationData`, and all owned `PyObject` references (`future`, `loop`, `protocol_factory`, `py_host`, `py_port`, etc.).

3. **`try_resolve_server_host` (`src/loop/python/io/server/create_server.zig:267-281`)**:
   Same bug: `errdefer server_socket_data.deinit();` is bypassed when `dns.lookup` fails and `else |err| return set_future_exception(...)` returns `void`.

4. **`server_host_resolved_callback` (`src/loop/python/io/server/create_server.zig:311-369`)**:
   Same bug: `errdefer server_socket_data.deinit();` is bypassed when `if (data.cancelled())` or `else` ("DNS resolution failed") returns `set_future_exception(...)` (`void`), leaking `ServerSocketData`, `ServerCreationData`, and all owned `PyObject` references.

## Trigger Scenario

Call `await loop.create_connection(factory, "nonexistent.invalid", 80)` or `await loop.create_server(factory, "nonexistent.invalid", 80)`. When the DNS query returns `NXDOMAIN` or times out, `host_resolved_callback` / `server_host_resolved_callback` takes the `else` branch, calls `set_future_exception`, and returns `void`, leaking the entire connection/server creation state and all Python references.

## Proposed Remediation

Explicitly call `socket_connection_data.deinit()` (or `server_socket_data.deinit()`) **before** `return set_future_exception(...)` in all non-error-returning failure branches (fetching `const future = creation_data.future.?;` with a local `py_newref`/`defer py_decref` before `deinit()` so `future` stays valid during `set_future_exception`).
