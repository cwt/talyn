# BUG-222 — Missing error-path release in `initialize_python_imports` leaking acquired references on partial import failure

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Python Reference Count Leak
- **Files**: `src/utils/python_imports.zig:111-137`
- **Lessons**: [Memory & Reference Counting §Lesson 1](../lessons/01-memory-and-reference-counting.md), [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/utils/python_imports.zig`, `initialize_python_imports` sequentially imports and stores 28 Python modules, functions, and exceptions during extension module initialization. If any import or attribute lookup fails midway through the sequence, the function returns `error.PythonError` immediately without calling `release_python_imports()`.
- **Trigger**: Failure to import a required module or attribute during extension initialization (e.g. running on an incompatible Python version or under severe memory pressure).
- **Consequences**: Python module and attribute references imported before the failure point are leaked.
- **Fix**: Add `errdefer release_python_imports();` at the beginning of `initialize_python_imports`.
