# BUG-166 — Heap memory leak on synchronous DNS lookups in `DNS.lookup`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — memory leak on every synchronous lookup
- **Files**: `src/loop/dns/main.zig:106-115`, `src/loop/python/io/socket/getaddrinfo.zig:189-201`, `src/loop/python/io/client/create_connection.zig:327`
- **Lessons**: [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md), [Network Protocols §Lesson 06](../lessons/06-network-protocols-and-io.md)
- **Description**: In `src/loop/dns/main.zig`, `DNS.lookup` resolves numeric IP strings and `localhost` synchronously using `resolve_sync`. Line 109 executes `return try self.loop.allocator.dupe(utils.Address, resolved_buf[0..n]);` and returns the slice. Unlike asynchronous DNS resolutions which store records in `self.cache`, this allocated slice was not cached. Callers assume the returned slice is managed by the DNS cache and do not free it.
- **Trigger**: Resolving IP addresses, `localhost`, or static hosts synchronously via `getaddrinfo`, `create_connection`, `create_server`, or `create_datagram_endpoint`.
- **Consequences**: Heap memory leak proportional to the number of synchronous connection or resolution attempts.
- **Fix**: Registered synchronous resolutions in `cache_slot.create_new_record_from_resolved(parsed_hostname, slice, 60)` so that lifecycle and deallocation are managed uniformly by the DNS cache.
