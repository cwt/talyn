# BUG-198 — execute_task_send leaks PythonTaskObject reference if future_fast_set_exception errors

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Python Reference Count Leak
- **Files**: `src/task/callbacks.zig:538-547`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md)
- **Description**: In `src/task/callbacks.zig`, `execute_task_send` handles errors from `_execute_task_send` in a `catch` block that calls `try Future.Python.Result.future_fast_set_exception(&task.fut, fut, exc);`. If `future_fast_set_exception` fails (such as an allocation failure during callback queue dispatch), the `try` returns early, skipping `python_c.py_decref(@ptrCast(task));`.
- **Trigger**: Memory allocation failure or error during exception propagation to task done callbacks.
- **Consequences**: Permanent leak of the `PythonTaskObject` reference count.
- **Proposed Fix**: Add `errdefer python_c.py_decref(@ptrCast(task));` before `future_fast_set_exception` or ensure `py_decref` executes unconditionally upon exit from the catch handler.
