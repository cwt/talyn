# BUG-208 — Leaked Heap Structs, Buffers, and PyObjects on Error Path in src/loop/python/io/socket/ops.zig

- **Status**: 🔴 Open
- **Severity**: 🔴 High — Memory & Reference Leak
- **Files**: `src/loop/python/io/socket/ops.zig:45-66, 193-219, 298-328, 537-573, 663-694, 897-929`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Lifecycle & Error Handling §Lesson 4](../lessons/004-lifecycle-error-handling.md)
- **Description**: In `src/loop/python/io/socket/ops.zig`, callback functions (`sock_accept_callback`, `sock_connect_callback`, `sock_recv_callback`, `sock_sendto_callback`, `sock_recvfrom_callback`, `sock_recv_into_callback_with_buf`) gate their resource cleanup behind `var success = false; defer if (success) cleanup_*(ad);`. If `set_future_exception`, `PyTuple_Pack`, `toPyAddr`, or future result setting returns an error, `success` remains `false`, bypassing `cleanup_*`. Since the task has already completed and was popped from io_uring, CallbackManager will not invoke cleanup again, permanently leaking the operation struct, heap buffers, and PyObject references (`future`, `loop`).
- **Trigger**: Error during terminal socket operation completion or exception setting.
- **Consequences**: Permanent heap and PyObject memory leaks during socket errors.
- **Fix**: Perform `cleanup_*` unconditionally on terminal completions.
