# BUG-316 — DNS resolution double-dispatch and cache invalidation race

- **Status**: 🔴 Open (2026-09-07)
- **Severity**: 🟡 Medium — DNS double-dispatch race condition causing future InvalidStateError and cache eviction
- **Files**:
  - `src/loop/dns/resolv.zig` (`mark_resolved_and_execute_user_callbacks`: lines 236–261; `process_dns_response`: line 562)
- **Lessons**: [Concurrency & Thread Safety](../lessons/02-concurrency-and-thread-safety.md), [Network Protocols & IO](../lessons/06-network-protocols-and-io.md)
- **Description**:
In `src/loop/dns/resolv.zig`:
```zig
pub fn mark_resolved_and_execute_user_callbacks(self: *Resolv, server_data: *ResolvServerData) void {
    var control_data = server_data.control_data;
    control_data.resolved = true;
    ...
```
There is no `if (control_data.resolved) return;` guard.
When multiple nameservers are configured:
1. Nameserver 1 receives answers, calls `mark_resolved_and_execute_user_callbacks`, dispatches callbacks to `Soon`, and caches the record.
2. Nameserver 2 finishes shortly after with no answers. Line 562 in `process_dns_response` calls `mark_resolved_and_execute_user_callbacks(server_data)`.
3. `mark_resolved_and_execute_user_callbacks` runs again, evicts the newly cached record (`self.cache.discard(record)`), and re-dispatches the user callbacks into the `Soon` ring buffer.
4. When Python futures receive the second result completion, Python raises `asyncio.InvalidStateError`.
- **Root Cause**: Missing idempotency check on `control_data.resolved` in callback execution entry point.
- **Trigger Scenario**: Multi-nameserver DNS resolution where queries resolve at slightly different times.
- **Proposed Remediation**: Add an early return at the start of `mark_resolved_and_execute_user_callbacks`: `if (control_data.resolved) return; control_data.resolved = true;`.
