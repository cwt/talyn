# BUG-347 — Use-after-free and double-free in `HookHandle.cancel` and `PathWatcherHandle.cancel` after `loop.close()`, plus GC list corruption in `z_loop_add_hook`

- **Status**: 🟢 Fixed
- **Severity**: 🔴 Critical — deterministic use-after-free and double-free when calling `hook_handle.cancel()` after `loop.close()` (or after `loop` is GC'd), plus CPython GC doubly-linked list corruption on `add_hook` error
- **Category**: Use-After-Free (UAF), Double-Free, & GC Corruption
- **Files**:
  - `src/loop/python/control.zig:126-176, 227-253, 255-289`
  - `src/loop/main.zig:189-209`
- **Related**: [Lesson 44](../lessons/05-python-c-api-correctness.md), [BUG-116](116.md)

## Overview & Root Cause

In `src/loop/python/control.zig`, `HookHandle` (lines 126–176) and `PathWatcherHandle` (lines 255–289) have three critical memory-safety bugs:

1. **Double-free of `HooksList.Node` and double-decref of `HookHandle` when `hook_handle.cancel()` is called after `loop.close()`**:
   In `Loop.release()` (`src/loop/main.zig:191-209`), all hook lists are drained and freed, and `cleanup_hook_handle` (`src/loop/python/control.zig:201-204`) calls `python_c.py_decref(ptr)` on each `HookHandle`, **without** setting `handle.cancelled = true` or `handle.node = undefined`:

   ```zig
   inline for (hook_lists) |list| {
       var it = list.first;
       while (it) |node| {
           const next = node.next;
           if (node.data.cleanup) |cleanup| {
               cleanup(node.data.data.user_data);
           }
           self.allocator.destroy(node);
           it = next;
       }
       list.* = .{};
   }
   ```

   If Python code still holds a reference to `hook_handle` and calls `hook_handle.cancel()` after `loop.close()`, `HookHandle.cancel` (`src/loop/python/control.zig:135-145`) sees `instance.cancelled == false`, does **not** check `instance.loop_data.initialized`, calls `instance.loop_data.remove_hook(instance.kind, instance.node)` (which reads `node.prev`/`node.next` from the already-freed `HooksList.Node` and calls `self.allocator.destroy(node)` a **second time**), and then calls `python_c.py_decref(@ptrCast(instance))` a **second time**!

2. **Dangling `loop_data: *Loop` pointer on both `HookHandle` and `PathWatcherHandle`**:
   Neither `HookHandle` nor `PathWatcherHandle` holds a strong `PyObject` reference to `LoopObject` (`self`). If `PathWatcherHandle` (or `HookHandle` after `loop.close()`) outlives the `LoopObject` and `.cancel()` is called, `instance.loop_data` points into a deallocated `LoopObject`.

3. **GC doubly-linked list corruption in `z_loop_add_hook` `errdefer` (`src/loop/python/control.zig:236-241`)**:
   ```zig
   const handle: *HookHandle = @ptrCast(@alignCast(
       HookHandleType.tp_alloc.?(HookHandleType, 0) orelse return error.PythonError,
   ));
   python_c.PyObject_GC_Track(@ptrCast(handle));
   errdefer HookHandleType.tp_free.?(@ptrCast(handle));
   ```
   `HookHandleType` has `Py_TPFLAGS_HAVE_GC`, so `tp_alloc` (`PyType_GenericAlloc`) **already** tracks the object in CPython's GC generation list (making the explicit `PyObject_GC_Track` at line 239 redundant), and if `loop_data.add_hook` fails at line 243, `errdefer HookHandleType.tp_free.?(@ptrCast(handle))` frees the memory **without** calling `PyObject_GC_UnTrack`, leaving a freed node linked inside CPython's global GC list!

## Trigger Scenario

1. Register a hook via `h = loop.add_hook(0, cb)`.
2. Close the loop via `loop.close()`.
3. Call `h.cancel()` -> `HookHandle.cancel` unlinks and frees the already-freed `HooksList.Node` and decrefs `h` a second time.

## Proposed Remediation

1. In `cleanup_hook_handle` (`src/loop/python/control.zig:201-204`), mark `handle.cancelled = true` before calling `python_c.py_decref(@ptrCast(handle))`:
   ```zig
   fn cleanup_hook_handle(ptr: ?*anyopaque) void {
       const handle: *HookHandle = @ptrCast(@alignCast(ptr.?));
       handle.cancelled = true;
       python_c.py_decref(@ptrCast(handle));
   }
   ```
2. Store an owned `loop: ?*LoopObject` reference on both `HookHandle` and `PathWatcherHandle` (visited in `tp_traverse` and released in `tp_clear`/`tp_dealloc`), and check `if (instance.loop == null or !instance.loop_data.initialized) return python_c.get_py_none();` in `cancel()` (guarding both post-`loop.close()` and post-`tp_clear` calls).
3. In `z_loop_add_hook`, remove the redundant `PyObject_GC_Track` call and replace `errdefer HookHandleType.tp_free.?(@ptrCast(handle))` with `errdefer python_c.py_decref(@ptrCast(handle))` (after initializing `handle.cancelled = true` and `handle.py_callback = null`).
