# BUG-196 — SubprocessTransport protocol callback failure leaks pidfd descriptor and PyObject reference

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — File Descriptor & PyObject Reference Leak
- **Files**: `src/transports/subprocess/transport.zig:358-377`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Defensive Programming §Lesson 53](../lessons/053-defensive-programming.md)
- **Description**: In `src/transports/subprocess/transport.zig`, `pidfd_exit_callback` invokes the protocol's `process_exited` and `connection_lost` callbacks upon process termination. If `PyObject_GetAttrString` returned null or `PyObject_Call` returned an error, the function returned early via `return error.PythonError;` before reaching `success = true;` and the subsequent cleanup.
- **Trigger**: A subprocess protocol without `process_exited`/`connection_lost` or an unhandled Python exception raised in either callback.
- **Consequences**: `transport.pidfd` was never closed (kernel file descriptor leak), `popen` was not decreffed, and the `SubprocessTransportObject` itself leaked 1 reference count.
- **Fix**: Extracted `dispatch_subprocess_exit_callbacks` helper which catches Python exceptions locally, forwards them to `loop.call_exception_handler`, and guarantees `pidfd` closure and `transport` decref across all exit paths.
