# BUG-138 — DNS `validate_hostname` erroneously rejects consecutive hyphens (IDN/Punycode rejection)

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — DNS lookup failure for IDN, Punycode, and cloud hostnames
- **Files**: `src/loop/dns/parsers.zig:35-48`
- **Lessons**: [Security §Lesson 58](../lessons/09-security-and-input-validation.md), [Security §Lesson 91](../lessons/09-security-and-input-validation.md)
- **Description**: `validate_hostname` contained `if (hyphen and has_hyphen) return false;`, which explicitly forbade consecutive hyphens within a hostname label. Under RFC 1035, RFC 1123, and RFC 5890, consecutive hyphens are legal anywhere within a label (except leading and trailing positions).
- **Trigger**: Attempting to resolve any Punycode domain (`xn--...`), cloud-generated hostname (e.g. `app--123.region.run.app`), or hostname containing `--`.
- **Consequences**: `getaddrinfo` / `create_connection` immediately failed with `error.InvalidHostname`.
- **Fix**: Removed the `if (hyphen and has_hyphen) return false;` check in `src/loop/dns/parsers.zig` and updated DNS unit tests to verify Punycode and double-hyphen domains.
