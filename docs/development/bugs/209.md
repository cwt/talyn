# BUG-209 — Leaked PythonHandleObject on Callback Exception in callback_for_python_generic_callbacks

- **Status**: 🟡 Open
- **Severity**: 🟡 Medium — Reference Leak on Exception
- **Files**: `src/handle.zig:72-77`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Lifecycle & Error Handling §Lesson 4](../lessons/004-lifecycle-error-handling.md)
- **Description**: In `src/handle.zig`, `callback_for_python_generic_callbacks` increments `handle` reference count upon dispatch and releases it with `var success = false; defer { if (success) { python_c.py_decref(@ptrCast(handle)); } }`. When the scheduled Python callback raises an exception or returns `null`, the function returns `error.PythonError` without setting `success = true`. Because the runner dispatches the error to the exception handler without decreffing the handle, the handle object is leaked.
- **Trigger**: Any scheduled Python callback that raises an exception.
- **Consequences**: Memory leak of `PythonHandleObject` instances on callback errors.
- **Fix**: Make handle decref unconditional via `defer python_c.py_decref(@ptrCast(handle));` once the callback execution scope is entered.
