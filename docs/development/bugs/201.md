# BUG-201 — @panic in RingBuffer push methods violates Architectural Mandate 1

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Process Crash Hazard & Mandate 1 Violation
- **Files**: `src/callback_manager.zig:191`, `src/callback_manager.zig:358`, `src/callback_manager.zig:366`
- **Rules**: `TALYN-002/NO_PANIC_IN_IO`, [Architectural Mandates §Mandate 1](../architectural-mandates.md), [BUG-105](105.md), [BUG-188](188.md)
- **Description**: In `src/callback_manager.zig`, `StaticRingBuffer.push`, `DynamicRingBuffer.push`, and `DynamicRingBuffer.push_or_grow` contained `@panic("RingBuffer overflow")` or `@panic("RingBuffer overflow after grow")`. Under high concurrent callback load or ring exhaustion, these functions crash the Python process with SIGABRT instead of returning error unions.
- **Trigger**: Ring buffer capacity exhaustion or memory allocation failure when appending callbacks under high load.
- **Consequences**: Unrecoverable hard crash of the runtime process in production environments.
- **Fix**: Update ring buffer push methods to return `error{RingBufferOverflow}!void` (or `!void`) and propagate the error to callers to convert into Python exceptions.
