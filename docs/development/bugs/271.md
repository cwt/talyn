# BUG-271 — `failed_execution` double-decref → UAF of the raised SystemExit/KeyboardInterrupt

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🔴 Critical — Use-after-free on Ctrl+C / SystemExit in a task
- **Files**:
  - `src/task/callbacks.zig:371` (`exception` owned ref from `PyErr_GetRaisedException`)
  - `src/task/callbacks.zig:412` (`errdefer python_c.py_decref(exception)` — BUG-255 fix)
  - `src/task/callbacks.zig:426-428` (`PyErr_SetRaisedException(py_newref(exception))`; `py_decref(exception)`; `return error.PythonError`)
- **Lessons**: [Memory & Reference Counting §Lesson 107](../lessons/01-memory-and-reference-counting.md), [Event Loop Lifecycle](../lessons/03-event-loop-lifecycle.md)
- **Description**: The function owns one reference (:371). The fatal-signal branch creates a second via `py_newref` and transfers it to the thread state (:426), releases its own (:427) — balanced so far — but then returns an error, firing the :412 errdefer and releasing a third. Net −2 vs refs created = the exception object can be freed **while installed as the thread state's current exception**; the caller's next `PyErr_GetRaisedException()` / `PyErr_Occurred()` (e.g. `callback_manager.zig` KI/SystemExit match) reads freed memory.
- **Trigger**: Any `SystemExit` or `KeyboardInterrupt` propagating out of a coroutine — i.e., Ctrl+C delivered while a task is running.
- **Consequences**: UAF crash precisely on interpreter shutdown/interrupt paths; intermittent, load-dependent.
- **Fix (Proposed)**: Drop either the manual decref at :427 or make the re-raise a non-error return path (so the errdefer never fires for this branch).
