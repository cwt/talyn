# BUG-146 — `OSError` reference leak on single connection failure in `create_connection`

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium-High — Python object leak on connection failure
- **Files**: `src/loop/python/io/client/create_connection.zig:874-889`
- **Lessons**: [Memory §Lesson 30](../lessons/01-memory-and-reference-counting.md), [Memory §Lesson 36](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `socket_connected_callback`, when a single connection attempt fails (non-`all_errors` branch), `exc = python_c.PyObject_CallFunction(python_c.PyExc_OSError, ...)` returns a new reference. `future_fast_set_exception` adds another reference. Unlike the `all_errors` branch (line 843) and other error handlers in the codebase, `exc` is never decreffed with `defer python_c.py_decref(exc);`.
- **Trigger**: Any failed TCP connection attempt via `loop.create_connection()` (e.g. `ConnectionRefusedError`).
- **Consequences**: Leaks 1 `OSError` instance per failed connection.
- **Proposed Fix**: Add `defer python_c.py_decref(exc);` immediately after `PyObject_CallFunction` returns a non-null `exc`.
