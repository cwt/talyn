# BUG-429 — `queue_eof` deferred `SocketShutdown` races the fd close

- **Status**: 🟡 Open
- **Severity**: 🟡 Medium — FIN sent on a closed/reused fd
- **Category**: io_uring deferred submission / write lifecycle
- **Files**: `src/transports/write_transport.zig:399-411,451-470`
- **Related**: [BUG-379](379.md) (eof_pending buffering), [BUG-275](275.md), [BUG-60](../lessons/04-io-uring-and-kernel.md)

## Description

```zig
_ = try self.loop.io.queue(.{ .SocketShutdown = .{ .socket_fd = self.fd, .how = std.os.linux.SHUT.WR } });
try self.close();
```

`loop.io.queue` may defer submission (no immediate `flush_pending_sqes`). `close()` → `maybe_close_fd`
can then `cancel_and_close_fd` and `close(self.fd)` before the SQE is submitted. The same shape exists
in `write_operation_completed` (queues `SocketShutdown` at line 404, then the `is_closing` settle at
407-411). The kernel then processes the shutdown against a closed — possibly reused — fd.

## Trigger

`transport.write_eof()` when the read side is already closed (or a full-drain completion with `is_closing`).

## Consequences

FIN not delivered, or delivered to an unrelated reused fd.

## Fix

`flush_pending_sqes()` (or synchronous `shutdown(2)`) before the settle/close, so the FIN SQE is
consumed while the fd is still valid.
