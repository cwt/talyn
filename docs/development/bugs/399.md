# BUG-399 — Ctrl-C / SIGINT hangs the event loop indefinitely because `io_uring_enter` blocks forever without signal interruption

- **Status**: 🟢 Fixed
- **Severity**: 🟡 High — Ctrl-C (SIGINT) does not stop the event loop; process must be killed with `kill -9`
- **Category**: Signal Handling / Event Loop Lifecycle
- **Files**:
  - `src/loop/runner.zig:349-382` — `poll_blocking_events()` blocking wait path
- **Related**: [BUG-348](348.md) (loop teardown), [BUG-267](267.md) (ring thread-handoff)

## Overview

`Runner.start()` calls `poll_blocking_events()` which calls `io_uring.submit_and_wait(1)` to block until a completion event arrives. On some Linux kernels, `io_uring_enter(fd, 0, 1, 0, NULL, NULL)` is **not interrupted by SIGINT** (Ctrl-C), even though the signal is pending. The event loop thread is stuck in the syscall forever, never checking `self.stopping` or `PyErr_Occurred()`.

Confirmed via GDB backtrace: the main thread is blocked at `os.linux.IoUring.enter` with `io_uring_enter` returning `-ENOMEM` instead of `-EINTR` on signal interruption. Standard `asyncio`/`uvloop` handles Ctrl-C correctly — this is a Talyn-specific issue.

## Trigger Scenario

1. Start a Talyn-based application (e.g., Wormhole proxy) with `talyn.run()` or `asyncio.run(loop_factory=TalynLoop)`
2. Press Ctrl-C (SIGINT)
3. The application does not terminate — it hangs in `io_uring_enter`
4. Must use `kill -9` from another terminal to terminate

## Proposed Remediation

Two changes in `poll_blocking_events()` (`src/loop/runner.zig`):

1. **Queue a watchdog timeout SQE (100ms) before each `submit_and_wait(1)`** so the blocking call can't block indefinitely. When the timeout expires, `submit_and_wait` returns and the loop checks `self.stopping` and pending Python signals. `user_data=0` ensures `fetch_completed_tasks` skips this watchdog completion.

2. **Call `PyErr_CheckSignals()` after every `submit_and_wait` return** (not just on `error.SignalInterrupt`) so pending Python signals (Ctrl-C → KeyboardInterrupt) are processed even when `io_uring_enter` returns normally after the watchdog timeout.

## Resolution

Added a watchdog timeout SQE (100ms) queued via `ring.timeout(0, &timeout_ts, 0, 0)` before each blocking `submit_and_wait(1)` call in `poll_blocking_events()`. Added `PyErr_CheckSignals()` / `PyErr_Occurred()` checks after every blocking wait return. The watchdog completion has `user_data=0` so it's skipped by `fetch_completed_tasks`.

Builds and tests verified passing under:
- `ReleaseFast` (Starburst) / Zig 0.16.0
- `ReleaseSafe` / Zig 0.16.0
- `Debug` / Zig 0.16.0
- `ReleaseFast` / Zig 0.17.0
- `zig build lint` — 0 violations
