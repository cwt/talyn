# BUG-322 — Architectural Mandate 1 violation (unreachable in IO error path of z_loop_add_watcher)

- **Status**: 🟢 Fixed (2026-09-07)
- **Severity**: 🟢 Low / Architectural — unreachable invocation in IO watcher error recovery violating Mandate 1
- **Files**:
  - `src/loop/python/io/watchers.zig` (`z_loop_add_watcher`: lines 240–242)
- **Lessons**: [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md), [Zig Specific Patterns](../lessons/08-zig-specific-patterns.md)
- **Description**:
In `src/loop/python/io/watchers.zig`:
```zig
errdefer {
    if (watchers.delete(fd) == null) unreachable;
}
```
Architectural Mandate 1 explicitly mandates:
> *"Zero-Panic Guarantee in the IO Path: Functions in the hot I/O, submission, completion, or callback-dispatch paths MUST NEVER panic or invoke unreachable."*

If an error triggers this `errdefer` and the B-tree node removal returns `null`, `unreachable` triggers an immediate panic in Debug/ReleaseSafe modes.
- **Root Cause**: `unreachable` assertion placed inside error cleanup path of a public event loop method.
- **Trigger Scenario**: Watcher registration failure during hash/tree rollback.
- **Proposed Remediation**: Replace `if (watchers.delete(fd) == null) unreachable;` with `_ = watchers.delete(fd);`.

- **Fix (Applied — 2026-09-07)**:
  - `z_loop_add_watcher` (`src/loop/python/io/watchers.zig`): the rollback errdefer is now a best-effort `_ = watchers.delete(fd);` — a null return only means the entry was already gone. No panic path remains in the watcher error recovery.
  - Triggerability note: with the current single-threaded flow the `unreachable` was invariant-unreachable (the insert immediately above succeeded and nothing re-enters between it and the rollback), so the fix is Mandate-1 hygiene rather than a crash fix; the guard now also survives any future re-entrant mutation between insert and rollback.
  - No dedicated regression test: the trigger condition is not Python-reachable; the watcher add/remove/cancel/re-arm suite (tests/loop/test_loop_watchers.py, tests/test_watchers_safety.py) covers the errdefer's normal operation.
- **Validation (2026-09-07)**: Confirmed still present.
  - `src/loop/python/io/watchers.zig:239-243` matches the quoted code verbatim: `errdefer { if (watchers.delete(fd) == null) unreachable; }` — an `unreachable` panic in the public `z_loop_add_watcher` error path, violating Architectural Mandate 1 (Zero-Panic Guarantee in the IO Path).
