# BUG-409 — custom task factory invoked twice on `TypeError`

- **Status**: 🔴 Open (confirmed, unfixed)
- **Severity**: 🟡 Medium — duplicate user-visible factory side effects and swallowed exceptions
- **Category**: Task Factory / Error Handling
- **Files**:
  - `src/loop/python/utils/task.zig:56-101` — custom-factory path
  - `src/loop/python/utils/task.zig:64-79` — `PyDict_SetItemString` results ignored
- **Related**: [BUG-389](389.md) (task factory kwargs), [BUG-303](303.md)

## Overview

```zig
const res = python_c.PyObject_Call(factory, py_args, py_kwargs);
if (res) |t| {
    task = t;
} else {
    if (python_c.PyErr_ExceptionMatches(python_c.PyExc_TypeError.?) != 0) {
        python_c.PyErr_Clear();
        task = python_c.PyObject_Call(factory, py_args, null) orelse return error.PythonError;
        ...
    } else return error.PythonError;
}
```

The fallback is intended for legacy `factory(loop, coro)` implementations that reject the `context=`/`name=` kwargs, but it fires for **every** `TypeError`, including a genuine bug inside the factory. The first exception is cleared, so the diagnostic is lost; the factory is called a second time.

## Trigger Scenario and Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, ReleaseFast, Python 3.13.16 and 3.13.16t.

Repro: `h18_task_factory.py` — a factory that always raises `TypeError("factory exploded for a real reason")`.

```text
raised TypeError: factory exploded for a real reason
factory calls: 2 [{'name': 'probe'}, {}]
RESULT: FAIL (factory invoked repeatedly)
```

The failure also breaks `talyn.run()` cleanup: `shutdown_asyncgens()` calls the factory again and leaves an unawaited coroutine warning.

## Proposed Remediation

- Only retry when the failure is specifically "unexpected keyword argument" (inspect the exception message, or probe the factory signature with `inspect.signature` once).
- Otherwise propagate the original `TypeError` without clearing it.
- Check `PyDict_SetItemString` failures and abort before calling the factory if the kwargs dict cannot be built.
- Add a test asserting the factory is called exactly once and the original message is preserved.
