# BUG-282 — `fetch_completed_tasks` Overflow drops completions and skews accounting

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟡 Medium-High — Dropped I/O completions / accounting drift / hang risk
- **Files**:
  - `src/loop/runner.zig:245` (`if (!ready_queue.try_push(v.*)) return error.Overflow;`)
  - `src/loop/runner.zig:250-251` (`reserved_slots -= 1; blocking_task.deinit();` — skipped on Overflow)
  - `src/loop/runner.zig:292,301-309` (`copy_cqes` already consumed all nevents from the ring)
- **Lessons**: [Event Loop Lifecycle §Lesson 47](../lessons/03-event-loop-lifecycle.md), [Defensive Programming §Lesson 57](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: On try_push failure at element k: (1) the BlockingTask pool slot is never released (its callback data intact; if batch-dispatched, the transport ref is stranded); (2) `reserved_slots` stays inflated forever, skewing wait decisions in `poll_blocking_events`; (3) elements k+1..n were already removed from the CQ ring but are never processed — their transports never re-arm.
- **Trigger**: Ready-ring exhaustion on allocation failure of `push_or_grow` during a large completion batch.
- **Consequences**: Permanently stalled connections after one bad batch; cumulative slot leakage.
- **Fix (Applied — 2026-08-23)**: A full ready ring now falls back to `push_or_grow` (ring growth) instead of aborting the batch — no completions are dropped and accounting stays exact. Only a genuine allocation failure propagates, and even then the task slot is released and `reserved_slots` decremented before unwinding.
- **Regression test**: covered structurally; forcing a deterministic full-ring + OOM injection would require allocator mocking.
