# BUG-234 — Dead code: trivially true unit test in `streamserver/main.zig`

- **Status**: ✅ Fixed (2026-08-17)
- **Severity**: 🟢 Low — Dead code / Test quality
- **File**: `src/transports/streamserver/main.zig:~340-370` (tests)
- **Lessons**: [Defensive §Lesson 79 — Silent Failure](../lessons/10-defensive-programming-and-code-quality.md), [BUG-224](0224.md) (unused legacy dead code)
- **Description**: Two test functions in `streamserver/main.zig` create a `StreamServerObject` struct literal with `accept_paused = false` and assert it is `false`:

  ```zig
  test "BUG-33: start_serving clears the accept_paused flag" {
      const server: StreamServerObject = .{
          ...
          .accept_paused = false,
          ...
      };
      try testing.expect(!server.accept_paused);
  }

  test "BUG-33: accept_paused default is false on fresh init" {
      const server: StreamServerObject = .{
          ...
          .accept_paused = false,
          ...
      };
      try testing.expect(!server.accept_paused);
      try testing.expect(!server.closed);
  }
  ```

  These tests are tautologies — they construct a value with a known field and assert it equals that value. They provide zero coverage of the actual `start_serving()` function or the `accept_paused` flag lifecycle. The real regression test for BUG-33 (EMFILE/ENFILE pause-and-retry) is entirely absent.

- **Trigger**: N/A (test quality issue only).
- **Consequences**: False sense of test coverage; the actual BUG-33 fix path (pause on EMFILE, retry timer, resume on `start_serving`) is untested.
- **Resolution (2026-08-17)**: Replaced both tautological tests with a single integration test that actually calls `start_serving()` on a server with `accept_paused = true` (simulating EMFILE/ENFILE pause state), then verifies the flag is cleared. The second test (which just asserted a struct literal field equals its constructor value) was removed entirely as it tested nothing.
