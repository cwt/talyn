# BUG-225 — Abandoned skeleton transport modules and empty utility files

- **Status**: ✅ Fixed
- **Severity**: 🟢 Low — Dead code / Scaffolding redundancy
- **Files**: `src/transports/ssl/`, `src/transports/pipe/`, `src/transports/subprocess/main.zig`, `src/transports/subprocess/constructors.zig`, `src/utils/allocator.zig`
- **Lessons**: [Defensive Programming §Lesson 10](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: Early scaffolding files for SSL, Pipe, and a previous Subprocess transport skeleton remain in `src/transports/` despite never being initialized, registered, or used (the real subprocess transport is in `src/transports/subprocess/transport.zig`). In addition, `src/transports/ssl/main.zig:30` references a non-existent `Constructors.ssl_new` identifier, which would fail to compile if imported, and `src/utils/allocator.zig` is a 0-byte empty file.
- **Trigger**: None (unreferenced dead scaffolding).
- **Consequences**: Dead file accumulation and latent compile hazards if accidentally imported.
- **Fix**: Deleted `src/transports/ssl/`, `src/transports/pipe/`, `src/transports/subprocess/main.zig`, `src/transports/subprocess/constructors.zig`, and `src/utils/allocator.zig`, and removed commented imports in `src/transports/main.zig`.
