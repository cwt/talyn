# BUG-139 — Argument order mismatch in `create_unix_server` constructor call (`backlog` passed as `family`)

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium-High — corrupted socket address family on Unix domain server sockets
- **Files**: `src/loop/python/io/pipe/unix.zig:234-238`, `src/transports/streamserver/main.zig:159-160`
- **Lessons**: [Network Protocols §Lesson 31](../lessons/06-network-protocols-and-io.md), [Defensive §Lesson 101](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: `z_loop_create_unix_server` invokes `StreamServer` instantiation via:
  ```zig
  const server = python_c.PyObject_CallFunction(
      @as(*python_c.PyObject, @ptrCast(StreamServer.StreamServerType.?)),
      "OOOi\x00",
      @as(*python_c.PyObject, @ptrCast(self)), protocol_factory, py_fd, backlog
  ) orelse return error.PythonError;
  ```
  `StreamServerObject.__init__` expects arguments in the order `(loop, protocol_factory, server_fd, family, backlog)`. Passing `backlog` as the 4th argument sets `self.family = backlog` (100) instead of `AF_UNIX` (`1`), while `self.backlog` receives its default value of 100.
- **Trigger**: Creating a Unix domain socket server via `loop.create_unix_server()`.
- **Consequences**: Calling `server.sockets` or `server._get_socket()` fails or returns a socket object with invalid address family `100`.
- **Proposed Fix**: Pass `py_family` (`AF_UNIX`) as the 4th argument and `py_backlog_obj` as the 5th argument with format `"OOOOO\x00"`.
