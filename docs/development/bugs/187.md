# BUG-187 — Hanging futures on error in create_datagram_endpoint and subprocess_exec

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Coroutine hang / deadlock on async IO errors
- **Files**: `src/loop/python/io/datagram/create_endpoint.zig:262, 308, 311, 314, 316, 321, 329`, `src/loop/python/io/subprocess/exec.zig:38-66`
- **Lessons**: [Python C API §Lesson 21](../lessons/021-python-c-api.md), [Concurrency & Event Loop §Lesson 24](../lessons/024-concurrency-and-event-loop.md)
- **Description**: In `create_datagram_endpoint` and `subprocess_exec`, when an error occurs during socket binding, protocol initialization, or watcher setup, functions return Zig error tags (such as `error.SystemResources` or `error.PythonError`) up the stack without setting an exception on the already-allocated `FutureObject`.
- **Trigger**: Any binding failure, protocol exception, or resource limit error during `loop.create_datagram_endpoint()` or `loop.subprocess_exec()`.
- **Consequences**: Python coroutines awaiting these methods hang forever without timing out or raising an error.
- **Fix**: Catch errors and explicitly call `set_future_exception(err, fut)` before returning.
