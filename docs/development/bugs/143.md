# BUG-143 — Parent transport reference leak on I/O read error in `ReadTransport`

- **Status**: 🔴 Open
- **Severity**: 🟠 High — strong reference leak of StreamTransport on connection errors
- **Files**: `src/transports/read_transport.zig:184-195`
- **Lessons**: [Memory §Lesson 107](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `ReadTransport.read_operation_completed`, when an I/O error occurs (`io_uring_err != .SUCCESS`), `parent_transport` is passed to `connection_lost_callback` and the function returns `void`. The success path at line 180 explicitly decrefs `parent_transport` (`python_c.py_decref(parent_transport)`), but the error path returns `void` without doing so.
- **Trigger**: Any socket read error (e.g. `ECONNRESET`, `ETIMEDOUT`, `EPIPE`).
- **Consequences**: Leaks 1 strong reference to the parent `StreamTransportObject` on every read error, preventing the transport and its associated protocol/buffers from ever being garbage-collected.
- **Proposed Fix**: Decref `parent_transport` in the error branch (or use a `defer` to balance the reference on all completion paths).
