# BUG-150 — Leaked `PyUnicode` strings in child watcher and FS watcher exception dictionaries

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — string reference leak on callback exception handling
- **Files**: `src/loop/child_watcher.zig:170`, `src/loop/fs_watcher.zig:127`
- **Lessons**: [Memory §Lesson 52](../lessons/01-memory-and-reference-counting.md), [Python C API §Table](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/loop/child_watcher.zig` line 170 and `src/loop/fs_watcher.zig` line 127:
  ```zig
  _ = python_c.PyDict_SetItemString(ctx, "message\x00", python_c.PyUnicode_FromString("...") orelse return);
  ```
  `PyUnicode_FromString` creates a new Python string reference. `PyDict_SetItemString` borrows the value and increments its reference count inside the dictionary. Because the caller's reference is never captured and decreffed, it leaks.
- **Trigger**: An unhandled exception occurring inside a child process watcher callback or inotify filesystem watcher callback.
- **Consequences**: Leaks 1 `PyUnicode` object per callback exception.
- **Proposed Fix**: Assign the result of `PyUnicode_FromString` to a local `const py_msg`, insert it into the dict, and add `defer python_c.py_decref(py_msg);`.
