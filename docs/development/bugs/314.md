# BUG-314 — Child watcher unhandled non-transient waitid error descriptor leak

- **Status**: 🔴 Open (2026-09-07)
- **Severity**: 🔴 High — Permanent ChildHandler and pidfd leak when waitid returns non-zero error
- **Files**:
  - `src/loop/child_watcher.zig` (`on_child_exit`: lines 170–173)
- **Lessons**: [io_uring & Kernel](../lessons/04-io-uring-and-kernel.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**:
In `on_child_exit`:
```zig
const wait_res = std.os.linux.waitid(.PID, handler.pid, &info, std.os.linux.W.EXITED | std.os.linux.W.NOHANG);
if (wait_res != 0) {
    log.err("waitid failed for pid {d}: {d}", .{ handler.pid, wait_res });
    return;
}
```
If `waitid` returns a non-zero error (e.g. `-ECHILD` because another thread, library, or signal handler reaped the zombie):
The function logs and returns immediately. The handler remains permanently registered in `self.handlers`, `handler.pidfd` is never closed, and the allocated `ChildHandler` memory is leaked.
- **Root Cause**: Early return on `waitid` failure without cleaning up registered handler state.
- **Trigger Scenario**: Subprocess monitored by child watcher that is reaped by a parent process hook or external signal disposition.
- **Proposed Remediation**: On non-zero `waitid` return, log the error, remove `handler` from `self.handlers`, and invoke `self.teardown_child_handler(handler)`.
