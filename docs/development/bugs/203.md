# BUG-203 — Leaked Python FutureObject and pre-init resource leaks in z_loop_create_unix_connection and z_loop_create_unix_server

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Resource Cleanup & Reference Leak
- **Files**: `src/loop/python/io/pipe/unix.zig:120-136`, `src/loop/python/io/pipe/unix.zig:191-233`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Defensive Programming §Lesson 53](../lessons/053-defensive-programming.md)
- **Description**: In `src/loop/python/io/pipe/unix.zig`:
  1. `z_loop_create_unix_connection` and `z_loop_create_unix_server` allocate a new Python `FutureObject` via `fast_new_future` without registering `errdefer python_c.py_decref(@ptrCast(fut));`. If any subsequent initialization step fails (OOM in `allocator.create`, socket creation failure, or bind/listen failure), `fut` is leaked.
  2. In `z_loop_create_unix_connection`, `ucd.* = .{ ... .addr = (try utils.Address.fromPyAddr(py_path, std.posix.AF.UNIX)).un }` evaluates `fromPyAddr` within the struct initialization expression before the `errdefer` block is registered. If `fromPyAddr` fails, `ucd.future`, `ucd.loop`, and `ucd.protocol_factory` acquired via `py_newref` may not be cleaned up.
- **Trigger**: System resource exhaustion (file descriptor or memory limit) or invalid unix socket path during unix connection/server creation.
- **Consequences**: Permanent leak of Python Future objects and unix connection context data structures.
- **Fix**: Add `errdefer python_c.py_decref(@ptrCast(fut));` immediately after creating `fut` in both functions, and parse `utils.Address.fromPyAddr` prior to constructing `ucd.*`.
