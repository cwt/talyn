# BUG-404 — `ceilPowerOfTwo` overflow crashes `Loop()` on large capacities

- **Status**: 🔴 Open (confirmed, unfixed)
- **Severity**: 🔴 Critical — untrusted Python input causes a native crash in both optimized and safety builds
- **Category**: Input Validation / Integer Overflow (Mandate #1)
- **Files**:
  - `src/callback_manager.zig:134-146` — `ceilPowerOfTwo`
  - `src/loop/main.zig:81-86` — `queues[0].init(allocator, rtq_capacity)`
  - `src/loop/python/constructors.zig:208-247` — capacity parsed from Python
- **Related**: [BUG-226](226.md) (32-bit capacity narrowing), [BUG-361](361.md) (unchecked narrowing)

## Overview

```zig
fn ceilPowerOfTwo(val: usize) usize {
    if (val <= 1) return 1;
    var x = val - 1;
    ...
    return x + 1;     // overflows when val-1 fills all bits
}
```

For `val = 2**63 + 1`, `x` becomes `maxInt(usize)` and `x + 1` wraps to 0. `DynamicRingBuffer.init` then allocates zero-length `callbacks`/`executed` slices and treats the ring as having capacity 0; under ReleaseFast this led to a SIGSEGV inside `init` (line 164, the `executed` initialization loop). Under ReleaseSafe/Debug the `x + 1` is a clean `integer overflow` panic. Either way, a Python-controlled constructor argument aborts the interpreter.

`z_loop_init` only checks `ready_tasks_queue_capacity > maxInt(usize)` (never true on 64-bit) and then `@intCast`s.

## Trigger Scenario

```python
import talyn
loop = talyn.Loop(2**63 + 1)
```

`2**63` alone fails cleanly with `MemoryError`; `2**63 + 1` crashes the process.

A standalone Zig program confirms `ceilPowerOfTwo((1<<63)+1) == 0`.

## Proposed Remediation

1. Validate `ready_tasks_queue_capacity` in `z_loop_init` with an explicit range (for example `1..1<<24`) and raise `ValueError`/`MemoryError` outside it.
2. Replace the hand-rolled helper with `std.math.ceilPowerOfTwo(usize, val) catch return error.OutOfMemory` (or equivalent checked arithmetic).
3. Make `DynamicRingBuffer.init` reject `capacity == 0` before allocating, and add a unit test for `2**63 + 1` under ReleaseSafe and ReleaseFast.
