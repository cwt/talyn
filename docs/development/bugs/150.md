# BUG-150 — Leaked `PyUnicode` strings in child watcher and FS watcher exception dictionaries

- **Status**: ✅ Fixed
- **Severity**: 🟢 Low — string reference leak on callback exception handling
- **Files**: `src/loop/child_watcher.zig:170`, `src/loop/fs_watcher.zig:127`
- **Lessons**: [Memory §Lesson 52](../lessons/01-memory-and-reference-counting.md), [Python C API §Table](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/loop/child_watcher.zig` and `src/loop/fs_watcher.zig`, `PyUnicode_FromString` was passed directly into `PyDict_SetItemString`, leaking the caller's reference.
- **Trigger**: An unhandled exception occurring inside a child process watcher callback or inotify filesystem watcher callback.
- **Consequences**: Leaked 1 `PyUnicode` object per callback exception.
- **Fix**: Assigned `PyUnicode_FromString` to a local `const msg` with `defer python_c.py_decref(msg);`.
