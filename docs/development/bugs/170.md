# BUG-170 — Memory and Python handle leak on unhandled exception in `loop_watcher_python_wrapper_callback`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — memory & Python handle leak
- **Files**: `src/loop/python/io/watchers.zig:60-70`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/03-event-loop-lifecycle.md), [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/loop/python/io/watchers.zig`, `loop_watcher_python_wrapper_callback` invokes `try Handle.callback_for_python_generic_callbacks(&temp_data);`. If the user-defined reader/writer callback raises an exception or fails, `try` immediately returned an error. This skipped the mutex lock and subsequent watcher cleanup block. Since `CallbackManager`'s `.cleanup` only runs on discarded/cancelled callbacks, the heap-allocated `Loop.FDWatcher` and `watcher.handle` Python reference were never freed.
- **Trigger**: Any reader or writer Python callback raising an exception when invoked.
- **Consequences**: Permanent leak of `FDWatcher` heap structures and strong references to Python `Handle` objects.
- **Fix**: Caught exceptions via `catch |err| utils.handle_zig_function_error(err, {})`, allowing execution to proceed safely to mutex lock, rearm, and cleanup.
