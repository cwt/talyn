# BUG-382 — `UnixSignals` bugs: `unlink`/`deinit` install no-op `default_signal_handler` instead of `SIG_DFL` (breaking `SIGINT`/Ctrl+C after `loop.close()`), `@as(u6, @intCast(sig))` panics on `sig == 64` or short read, `Soon.dispatch` failure leaks `handle` ref, and `deinit` skips `CancelIO`

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — after `loop.add_signal_handler(signal.SIGINT, cb)` and `loop.remove_signal_handler(signal.SIGINT)` (or `loop.close()`), `SIGINT` (Ctrl+C) is permanently swallowed by a no-op C signal handler instead of raising `KeyboardInterrupt` or terminating the process
- **Category**: Logic Bug, Panic (Mandate #1), & Reference Leak
- **Files**:
  - `src/loop/unix_signals.zig:12-19, 44-110, 179-236`
- **Related**: [BUG-345](345.md), [Architectural Mandate #1](../architectural-mandates.md)

## Overview & Root Cause

In `src/loop/unix_signals.zig`, there are four bugs in `UnixSignals`:

1. **`unlink()` and `deinit()` install a no-op function `default_signal_handler` instead of restoring `SIG.DFL` (or the previous `Sigaction`) (`src/loop/unix_signals.zig:12-19, 198-203, 217-222`)**:
   ```zig
   fn default_signal_handler(_: c_int) callconv(.c) void {}

   var DefaultSignalHandler: std.os.linux.Sigaction = .{
       .handler = .{ .handler = &default_signal_handler },
       .mask = std.os.linux.sigemptyset(),
       .flags = std.os.linux.SA.RESTART,
   };
   ```
   When `remove_signal_handler` (`unlink`) or `loop.close()` (`deinit`) runs, it calls `std.os.linux.sigaction(sig, &DefaultSignalHandler, null)` and unblocks `sig` via `sigprocmask(SIG_UNBLOCK)`.
   Because `DefaultSignalHandler` points to an empty function `fn default_signal_handler(_: c_int) void {}` (rather than `std.os.linux.SIG.DFL` or the previous `Sigaction` saved when `link` was called, such as Python's `SIGINT` handler), delivering `SIGINT` (Ctrl+C) or `SIGTERM` after `remove_signal_handler` or `loop.close()` invokes the empty `default_signal_handler` and **does nothing**!

2. **`@as(u6, @intCast(sig))` panics on `sig == 64` (`SIGRTMAX` is 64 on Linux) and `signalfd_read_callback` does not check `io_uring_res()` before reading `self.info.signo` (`src/loop/unix_signals.zig:58-64, 152, 187, 194, 215`)**:
   - On Linux, valid signals are `1..64` (`NSIG = 64`), where signal `64` is `SIGRTMAX`. In `link`, `unlink`, `deinit`, and `signalfd_read_callback`, `@as(u6, @intCast(sig))` is used instead of `@as(u6, @intCast(sig - 1))`! Passing `sig == 64` panics because `64` overflows `u6` (`0..63`), and slot `0` of `callbacks: [64]?*PythonHandleObject` is wasted.
   - In `signalfd_read_callback` (`lines 55-64`), `io_uring_res()` is never checked (`if (data.io_uring_res() < @sizeOf(std.os.linux.signalfd_siginfo))`), and `const sig = self.info.signo;` is cast via `@as(u6, @intCast(sig))` without bounds checking.

3. **`python_c.py_incref(@ptrCast(handle))` leaked if `Soon.dispatch` fails (`src/loop/unix_signals.zig:89-95`)**:
   ```zig
   if (self.callbacks[@as(u6, @intCast(sig))]) |handle| {
       python_c.py_incref(@ptrCast(handle));
       try Soon.dispatch(self.loop, &.{ ... });
   }
   ```
   If `Soon.dispatch` returns an error (e.g. OOM), there is no `errdefer python_c.py_decref(@ptrCast(handle));`, leaking the incremented reference.

4. **`deinit()` closes `self.sfd` without cancelling `self.blocking_task_id` (`src/loop/unix_signals.zig:212-236`)**:
   `deinit()` closes `self.sfd` while the `PerformRead` SQE (`self.blocking_task_id`) is still armed in `io_uring`.

## Trigger Scenario

1. Register `loop.add_signal_handler(signal.SIGINT, cb)` and then call `loop.remove_signal_handler(signal.SIGINT)` (or `loop.close()`).
2. Send `SIGINT` (press Ctrl+C) -> `default_signal_handler` swallows the signal; neither `KeyboardInterrupt` nor process termination occurs.
3. Call `loop.add_signal_handler(signal.SIGRTMAX, cb)` (`sig == 64`) -> immediate Zig `@intCast` panic (`64` does not fit in `u6`).

## Proposed Remediation

1. Save the previous `std.os.linux.Sigaction` per signal in `link()` (`prev_sigactions: [64]std.os.linux.Sigaction`) and restore it in `unlink()` and `deinit()` (falling back to `.handler = .{ .handler = std.os.linux.SIG.DFL }`).
2. Index `callbacks` and bitmasks using `@as(u6, @intCast(sig - 1))` for `1 <= sig <= 64` (matching `std.os.linux.sigaddset`), and validate `1 <= sig and sig <= 64` before casting.
3. Add `errdefer python_c.py_decref(@ptrCast(handle));` before `try Soon.dispatch(...)` in `signalfd_read_callback`.
4. Cancel `self.blocking_task_id` in `UnixSignals.deinit()` before closing `self.sfd`.
