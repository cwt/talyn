# BUG-380 — `Record.append_callback` unconditionally accesses `self.state.pending`, panicking when a second DNS lookup hits an existing `.ptr`, `.resolved`, or `.none` cache record

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — violates Architectural Mandate #1 (NO PANICS in the IO Path); accessing an inactive union payload field `self.state.pending` panics the process on tag mismatch
- **Category**: Logic Bug (Tagged Union Panic / Mandate #1 Violation)
- **Files**:
  - `src/loop/dns/main.zig:128-135, 148-161`
  - `src/loop/dns/cache.zig:33-45`
- **Related**: [BUG-316](316.md), [Architectural Mandate #1](../architectural-mandates.md)

## Overview & Root Cause

In `src/loop/dns/main.zig:128-135`, `Record.append_callback` unconditionally accesses `self.state.pending`:

```zig
pub inline fn append_callback(self: *Record, allocator: std.mem.Allocator, callback: *const CallbackManager.Callback) !void {
    const control_data = self.state.pending;
    if (control_data.resolved) {
        return error.RecordAlreadyResolved;
    }
    try control_data.user_callbacks.append(allocator, callback.*);
}
```

And in `src/loop/dns/cache.zig:33-45`, `Cache.new_record` calls `record.append_callback` whenever `self.records.get(hostname)` finds an existing non-expired record and `state` has a `.callback`:

```zig
pub fn new_record(self: *Cache, hostname: []const u8, state: RecordStateInit) !void {
    if (self.records.get(hostname)) |record| {
        switch (state) {
            .pending, .ptr => |callback| {
                const allocator = self.dns.arena.allocator();
                return record.append_callback(allocator, callback);
            },
            else => unreachable,
        }
    }
```

Look at what happens when:
1. A reverse DNS lookup `loop.getnameinfo(('127.0.0.1', 80), 0)` resolves `"127.0.0.1"` via `DNS.lookup_hostname` (`src/loop/dns/main.zig:137-162`), storing `.ptr = "localhost"` in `self.cache.records` under the key `"127.0.0.1"`.
2. Next, `loop.getaddrinfo("127.0.0.1", 80)` calls `DNS.lookup("127.0.0.1", ...)` (`src/loop/dns/main.zig:97-125`), which first calls `self.cache.get("127.0.0.1")`:
   - In `Cache.get` (`src/loop/dns/cache.zig:101-125`), `.ptr` hits `else => return null` (leaving the `.ptr` record in `self.records`!).
   - `DNS.lookup` then parses `"127.0.0.1"` as an IPv4 literal and calls `try self.cache.new_record("127.0.0.1", .{ .resolved = slice })`!
   - Inside `Cache.new_record` (`src/loop/dns/cache.zig:34-40`), `if (self.records.get("127.0.0.1"))` finds the existing `.ptr` record, switches on `state` (`.resolved`), and hits **`else => unreachable`** — an immediate Zig panic!
3. Conversely, if `loop.getaddrinfo("127.0.0.1", 80)` runs **first** (storing `.resolved = slice` under `"127.0.0.1"`) and `loop.getnameinfo(('127.0.0.1', 80), 0)` runs **second**:
   - `DNS.lookup_hostname` (`src/loop/dns/main.zig:137-159`) calls `self.cache.get_ptr("127.0.0.1")`, which sees `.resolved` (not `.ptr`) and returns `null` (leaving the `.resolved` record in `self.records`!).
   - `DNS.lookup_hostname` then calls `self.cache.new_record("127.0.0.1", .{ .ptr = callback })`!
   - `Cache.new_record` finds the existing `.resolved` record and calls `record.append_callback(allocator, callback)`, which accesses `self.state.pending` on a `.resolved` union — an immediate Zig panic (`access of union field 'pending' while field 'resolved' is active`)!

## Trigger Scenario

Run `await loop.getaddrinfo("127.0.0.1", 80)` followed by `await loop.getnameinfo(("127.0.0.1", 80), 0)` (or vice versa) on the same event loop -> immediate Zig panic in `Record.append_callback` or `Cache.new_record` because forward (`.resolved`) and reverse (`.ptr`) lookups share the same `Cache` key space without distinguishing record types or handling non-`.pending` existing records.

## Proposed Remediation

1. In `Record.append_callback` (`src/loop/dns/main.zig:128-135`), switch on `self.state` instead of assuming `.pending`: if `self.state != .pending`, return `error.RecordAlreadyResolved` so `Cache.new_record` / caller can replace or handle the record safely without panicking.
2. In `Cache.new_record` (`src/loop/dns/cache.zig:34-45`), handle `.resolved` when an existing record is present (via `update_record` instead of `else => unreachable`), and separate forward (`A`/`AAAA`) and reverse (`PTR`) cache namespaces (or key `PTR` records by their `.in-addr.arpa` / `.ip6.arpa` reverse query name).
