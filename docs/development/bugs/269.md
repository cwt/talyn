# BUG-269 — DNS `prepare_data` dual errdefer double-frees `ControlData`

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🔴 Critical — Deterministic double-free / heap corruption
- **Files**:
  - `src/loop/dns/resolv.zig:724` (`errdefer allocator.destroy(control_data)` — armed first)
  - `src/loop/dns/resolv.zig:749-751` (`errdefer control_data.release()`)
  - `src/loop/dns/resolv.zig:200` (`release()` ends with `self.allocator.destroy(self)`)
  - `src/loop/dns/resolv.zig:764` (`return error.InvalidHostname` — deterministic trigger)
- **Lessons**: [Zig-Specific Patterns §errdefer Discipline](../lessons/08-zig-specific-patterns.md), [Memory & Reference Counting](../lessons/01-memory-and-reference-counting.md)
- **Description**: `prepare_data` creates `control_data` (:723) and arms `errdefer allocator.destroy(control_data)` (:724). After :747 succeeds it arms a second errdefer calling `control_data.release()` (:749-751), whose final statement destroys the struct (:200). Zig executes same-scope errdefers in reverse declaration order, so on ANY error after :751 both fire: `release()` deinits the arena and destroys `control_data`, then :724 destroys it again.
- **Trigger**: A fully-qualified hostname whose candidates all exceed the 255-byte DNS name limit passes `lookup`'s `hostname.len > 255` check (`dns/main.zig`) but makes `get_hostname_array` return an empty array → `return error.InvalidHostname` at :764. Also reachable via OOM at :753/:756/:757/:769 or `build_queries` failure (:782).
- **Consequences**: Double free / heap corruption on a user-triggerable deterministic path; secondary hazard because the :754 errdefer deinits `user_callbacks` against an already-released arena before `release()` iterates it.
- **Fix (Applied — 2026-08-23)**: Single-owner cleanup. The early `errdefer allocator.destroy(control_data)` was removed; record creation now uses an explicit `catch` that tears down arena + struct locally, after which `control_data.release()` is the only destructor. The redundant `errdefer user_callbacks.deinit(arena_allocator)` was also removed — `release()`'s `arena.deinit()` owns arena-backed fields (the old ordering even ran the list deinit before `release()` iterated it).
- **Regression test**: `resolv.zig` "prepare_data error path does not double-free ControlData (BUG-269)" drives the deterministic trigger (dotless hostname + empty search → empty candidates → `error.InvalidHostname`) through a live test Loop; under `std.testing.allocator` the previous code reported the double free.
