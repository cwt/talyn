# BUG-437 — `getsockopt` int-vs-bytes keyed off the wrong condition

- **Status**: 🟡 Open
- **Severity**: 🟢 Low — API shape mismatch
- **Category**: API compatibility
- **Files**: `src/utils/pseudosocket.zig:193-212`
- **Related**: [BUG-264](264.md), [BUG-262](262.md)

## Description

```zig
var buflen: std.c.socklen_t = 256;
if (argc >= 3) { ... buflen = @intCast(bl); }
const rc = getsockopt(...);
if (buflen == 4) {
    return python_c.PyLong_FromLong(@intCast(int_val));   // int form
}
return python_c.PyBytes_FromStringAndSize(...);
```

CPython's contract: `getsockopt(level, optname)` → int; `getsockopt(level, optname, buflen)` → `bytes`
of that length. The code keys off the post-call `buflen`, ignoring whether the length argument was
supplied, so `sock.getsockopt(SOL_SOCKET, SO_RCVBUF, 4)` returns an int instead of a 4-byte `bytes`.

## Fix

Remember whether the length argument was provided (`argc >= 3`) and only return the int form when it was
omitted.
