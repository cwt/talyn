# BUG-442 — `add_done_callback` no-op leaks caller-transferred references

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — reference leak
- **Category**: Reference counting / API contract
- **Files**: `src/future/callback.zig:276-291`, `src/future/python/callbacks.zig:54-55`, `src/task/callbacks.zig:404-406`
- **Related**: [BUG-369](369.md) (released flag), [BUG-297](297.md)

## Description

```zig
pub inline fn add_done_callback(self: *Future, callback_data: Data) !void {
    if (self.status != .pending or self.released) return;   // silent no-op
    try self.callbacks_queue.append(self.loop.allocator, .{ .data = callback_data });
    ...
}
```

Callers transfer ownership *after* the call assuming the entry was stored
(`future/python/callbacks.zig` `py_callback`/`context`; `task/callbacks.zig` `py_incref(task)`). A
`released` future can still have `status == .pending` (e.g. a Future resurrected after `tp_clear`), so
the transferred references leak.

## Fix

Make `add_done_callback` return `bool` (or have callers check `future_data.released`) and release the
transferred references on the no-op path.

## Resolution (2026-11-12)

`add_done_callback` now returns `!bool` — `true` when the entry was stored, `false` for the silent
released/no-op path. Both callers condition their ownership transfer on the result:

- `future/python/callbacks.zig`: the transferred `py_callback`/`context` references are released on
  the no-op path (the call still returns `None`, mirroring BUG-369's inert-mutation contract).
- `task/callbacks.zig`: the wakeup-task `py_incref` is only taken when the entry was stored (the
  reference is otherwise balanced only by the queue-release path, so a no-op incref leaked it).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (502 pytest passed on
py3.15, 501 + 1 skipped on py3.15t; stdlib asyncio green on both).
