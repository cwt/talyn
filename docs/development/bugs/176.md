# BUG-176 — Infinite DNS TTL when `ttl == maxInt(u32)` in cache violating TTL capping mandate

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — stale DNS record retention
- **Files**: `src/loop/dns/cache.zig:126-134`
- **Lessons**: [Network Protocols §Lesson 112](../lessons/112-dns-ttl-capping.md)
- **Description**: In `src/loop/dns/cache.zig`, `create_new_record_from_resolved` creates cache records for resolved addresses. When `ttl == std.math.maxInt(u32)`, the function sets `expire_at = std.math.maxInt(i64)` instead of capping it to a reasonable maximum (such as 60 seconds). This violates Lesson 112 and allows synthetic or non-expiring records to persist in the DNS cache indefinitely.
- **Trigger**: DNS resolution producing synthetic records with maximum TTL.
- **Consequences**: Stale DNS cache records never expiring, preventing failover or IP migration.
- **Fix**: Cap `ttl` to 60 seconds when `ttl == std.math.maxInt(u32)`.
