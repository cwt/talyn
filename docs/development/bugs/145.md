# BUG-145 — Double decref and use-after-free of `loop` in `create_server` with custom socket

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — use-after-free and reference count underflow on Loop object
- **Files**: `src/loop/python/io/server/create_server.zig:225, 481, 37`
- **Lessons**: [Memory §Lesson 14](../lessons/01-memory-and-reference-counting.md), [Memory §Lesson 106](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `z_loop_create_server` when `py_sock` is provided:
  1. Line 225 executes `python_c.deinitialize_object_fields(creation_data_ptr, &.{"future", "protocol_factory"});`. Because `"loop"` is not in the excluded list, `creation_data_ptr.loop` is decreffed immediately.
  2. Later, when the `create_server_socket` callback executes, line 481 reads `creation_data.loop.?` and passes it to `StreamServer` instantiation.
  3. When `server_data.deinit()` runs, it calls `creation_data.deinit()`, which executes `deinitialize_object_fields(self, &.{});` — decreffing `self.loop` a second time.
- **Trigger**: Calling `loop.create_server(..., sock=existing_socket)`.
- **Consequences**: Premature deallocation and memory corruption of the `Loop` Python object.
- **Proposed Fix**: Add `"loop"` to the exclude list in line 225: `&.{"future", "protocol_factory", "loop"}`.
