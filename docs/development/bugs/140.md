# BUG-140 — Inverted condition in `Server._detach` causes `Server.wait_closed()` to hang indefinitely

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — event loop shutdown hang on `await server.wait_closed()`
- **Files**: `talyn/server.py:17-45`
- **Lessons**: [Network Protocols §Lesson 40](../lessons/06-network-protocols-and-io.md), [Event Loop §Lesson 57](../lessons/03-event-loop-lifecycle.md)
- **Description**: `Server._detach` previously required `self._servers is not None` to wake up waiters, but `close()` sets `self._servers = None`, causing `await server.wait_closed()` to hang when active connections completed.
- **Trigger**: Calling `server.close()` while active client connections exist, followed by `await server.wait_closed()`.
- **Consequences**: Process hung indefinitely waiting for server closure.
- **Fix**: Updated `Server._detach` to wake up waiters when `self._active_count <= 0 and (self._servers is None or not self.is_serving())`, and made `Server.close()` only wake up immediately if `self._active_count <= 0`.
