# BUG-320 — Transport get_extra_info signature and family incompatibilities

- **Status**: 🟢 Fixed (2026-09-07)
- **Severity**: 🟡 Medium — get_extra_info violates asyncio specification across Datagram and Subprocess transports
- **Files**:
  - `src/transports/datagram/main.zig` (line 221); `src/transports/datagram/extra_info.zig` (line 23); `src/transports/subprocess/transport.zig` (lines 144–157)
- **Lessons**: [Network Protocols & IO](../lessons/06-network-protocols-and-io.md), [Python C-API Correctness](../lessons/05-python-c-api-correctness.md)
- **Description**:
1. In `src/transports/datagram/main.zig`:
`z_datagram_get_extra_info` is registered with `METH_O` (1 positional argument only). The standard asyncio API is `get_extra_info(name, default=None)`. Calling `transport.get_extra_info('socket', None)` raises `TypeError: function takes exactly one argument (2 given)`.
In `extra_info.zig`, `family = 2` (`AF_INET`) is hardcoded, returning wrong socket family for IPv6 or UNIX datagram sockets.

2. In `src/transports/subprocess/transport.zig`:
`SubprocessTransport.get_extra_info` accepts `*args, **kwargs` but unconditionally returns `Py_None` for unknown keys, ignoring any user-specified `default` keyword argument.
- **Root Cause**: `METH_O` registration in DatagramTransport and missing `default` kwarg return in SubprocessTransport.
- **Trigger Scenario**: Standard asyncio code passing `default` parameter to `transport.get_extra_info()` or querying socket on IPv6 datagram transport.
- **Proposed Remediation**: Switch DatagramTransport to `METH_VARARGS | METH_KEYWORDS`, query actual socket family via `getsockname`, and return `default` on SubprocessTransport.

- **Fix (Applied — 2026-09-07)**:
  - Datagram: `get_extra_info` re-registered as `METH_FASTCALL | METH_KEYWORDS` and now parses the standard asyncio signature `(name, default=None)` — positionally and via the `default=` keyword (extra positional arguments raise `TypeError`). Unknown keys return the caller's default (`py_newref`'d) instead of an unconditional `None`; the known keys (`socket`, `sockname`) are unchanged.
  - Datagram family: the hardcoded `AF_INET (2)` passed to `socket.fromfd` is replaced by the family queried from a live `getsockname` (fallback `AF_INET` if the probe fails); the type constant is now the symbolic `std.posix.SOCK.DGRAM`. IPv6/UNIX datagram transports report their real family.
  - Subprocess: unknown keys return the caller-provided `default` (keyword via `PyDict_GetItemString`, or a second positional argument) instead of an unconditional `None`; the known keys (`subprocess`, `pid`) are unchanged. `PyDict_GetItemString` was added to the `python_c` re-exports for the default lookup.
- **Regression tests**: `tests/test_datagram.py::test_datagram_get_extra_info_default_and_signature` (2-arg positional + `default=` keyword, unknown-key defaults, known keys with the extended signature) and `test_datagram_get_extra_info_socket_family_ipv6` (`socket.family == AF_INET6`, `type == SOCK_DGRAM`); `tests/test_subprocess.py::test_subprocess_get_extra_info_default` (positional and keyword defaults, known keys unaffected).
- **Validation (2026-09-07)**: Confirmed still present — all three claims verified.
  - `METH_O` registration at `src/transports/datagram/main.zig:221` (the 2-arg standard call `get_extra_info(name, default)` raises `TypeError`).
  - Hardcoded `family = 2` at `src/transports/datagram/extra_info.zig:23` (and socket `type = 2` hardcoded at `:25`); IPv6/UNIX datagram sockets report AF_INET.
  - `subprocess_get_extra_info` (`src/transports/subprocess/transport.zig:144-157`) discards `kwargs` (`_ = kwargs` at `:146`) and returns `Py_None` for unknown keys, ignoring any user-supplied `default`.
