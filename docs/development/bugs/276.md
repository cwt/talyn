# BUG-276 — `WriteTransport.init` `add_hook` failure double-destroys buffer lists

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟠 High (impact) / Low (OOM-only trigger) — Double destroy + UAF
- **Files**:
  - `src/transports/write_transport.zig:52-56` (`create` both lists + local errdefers)
  - `src/transports/write_transport.zig:61-77` (struct literal commits `.initialized = true` and stores the pointers)
  - `src/transports/write_transport.zig:79-83` (`try loop.add_hook(.prepare, ...)` — fallible, allocates node)
  - `src/transports/write_transport.zig:142-146` (`deinit()` reads `.items`, deinits and destroys both lists)
  - `src/transports/stream/constructors.zig:145` (`errdefer write_transport_data.deinit()`)
- **Lessons**: [Zig-Specific Patterns §Lesson 77](../lessons/08-zig-specific-patterns.md), [Memory & Reference Counting §Lesson 49](../lessons/01-memory-and-reference-counting.md)
- **Description**: On `add_hook` failure the two heap ArrayLists are destroyed by the local errdefers; the caller's errdefer then runs `deinit()`, which — because `initialized == true` was already committed — iterates the freed `pending_py_buffers.items` (`PyBuffer_Release`) and calls `.deinit(allocator)` + `destroy()` on both dangling pointers.
- **Trigger**: OOM during prepare-hook node allocation in transport construction.
- **Consequences**: Double destroy / UAF of ArrayList internals during error unwinding.
- **Fix (Applied — 2026-08-23)**: The struct literal now commits `.initialized = false`; the flag flips to `true` only after `add_hook` succeeds, so a failed hook arm leaves `deinit()` as a no-op while the local errdefers destroy the lists exactly once.
- **Regression test**: none added (OOM-only trigger on hook-node allocation); construction is heavily exercised by the transport suites.
