# BUG-191 — Use-after-free / double-release hazard in LRUCache.pop_tail with eviction callback

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Dangling pointer return on cache pop
- **Files**: `src/utils/lru.zig:105-117`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/01-memory-and-reference-counting.md), [Data Structures §Lesson 40](../lessons/07-data-structures-and-algorithms.md)
- **Description**: In `src/utils/lru.zig`, `pop_tail` removed the oldest entry. If `self.evict_callback` was configured (which typically frees or decrements the reference count of the value), `pop_tail` invoked `evict_callback` and then returned `value` to the caller. The caller received a pointer to already-freed or decreffed data.
- **Trigger**: Calling `pop_tail` on an LRUCache configured with an eviction callback.
- **Consequences**: Use-after-free if the caller attempts to use or free the returned value.
- **Fix**: Removed `evict_callback` invocation in `pop_tail`, transferring value ownership directly to the caller. Added unit test in `src/utils/lru.zig`.
