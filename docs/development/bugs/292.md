# BUG-292 — `failed_execution` arm-level exception leaks

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Refcount leak on error paths only
- **Files**:
  - `src/task/callbacks.zig:371` (owned ref acquired)
  - `src/task/callbacks.zig:375` (`stop_iteration.value orelse return error.PythonError` — no release)
  - `src/task/callbacks.zig:378-381` (`set_result` catch returns error without release; cause incref does not transfer ownership)
  - `src/task/callbacks.zig:395-398` (cancelled arm mirror)
  - `src/task/callbacks.zig:412` (errdefer armed only AFTER these arms)
- **Lessons**: [Memory & Reference Counting §Lesson 107](../lessons/01-memory-and-reference-counting.md), [Zig-Specific Patterns §Lesson 77](../lessons/08-zig-specific-patterns.md)
- **Description**: Every internal failure inside the StopIteration and CancelledError arms leaks one exception object (+ its cause graph). The errdefer covering the generic arm was added too late in the function to cover them. Related to but distinct from fixed BUG-255 (generic path) and open BUG-271 (over-release).
- **Trigger**: `set_result`/`future_fast_cancel` failures or StopIteration without a value.
- **Consequences**: Bounded per-event leak of exception objects during task failure handling.
- **Fix (Proposed)**: Arm the errdefer immediately after :371 and remove the manual decrefs on the balanced success paths.
