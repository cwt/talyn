# BUG-251 — Zig float cast panics on NaN, Inf, and large floats in scheduling.zig, timer_handle.zig, and timeout_from_secs

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Runtime panic / process crash
- **Files**: `src/loop/python/scheduling.zig`, `src/timer_handle.zig`, `src/loop/dns/resolv.zig`, `src/loop/python/io/client/create_connection.zig`
- **Lessons**: [Defensive §Lesson 90 — Float Safety & Math Checks](../lessons/10-defensive-programming-and-code-quality.md), [Zig 0.16.0 Compatibility §Float Conversions](../../../AGENTS.md)
- **Description**: In Zig 0.16.0 runtime safety checks, calling `@intFromFloat(v)` on non-finite (`NaN`, `Inf`) or values exceeding target integer capacities (e.g. `1e20 > maxInt(u64)` or `> maxInt(time_t)`) panics immediately (SIGABRT):
  1. In `src/loop/python/scheduling.zig:166-186` (`call_later` and `call_at`), `ts = PyFloat_AsDouble(args[0])`. If `ts` is `NaN`, `ts < 0.0` evaluates to `false`, proceeding to `@intFromFloat(@trunc(ts))` which crashes the process. Furthermore, if `PyFloat_AsDouble` fails on non-numeric arguments (returning `-1.0` with `TypeError`), the code does not check `PyErr_Occurred()`, instead treating `ts < 0.0` as true and raising `ValueError`, masking Python's standard `TypeError`.
  2. In `src/timer_handle.zig:69-70`, `ts` from `PyArg_ParseTupleAndKeywords` is passed directly to `@intFromFloat` without finite bounds validation.
  3. In `timeout_from_secs` (`src/loop/dns/resolv.zig:24`) and `create_connection.zig:696`, large finite floats (e.g. `1e20`) pass `isFinite()` but cause `@intFromFloat` integer overflow panics.
- **Trigger**: Calling `loop.call_later(float('nan'), cb)`, `loop.call_later("invalid", cb)`, or passing large timeout floats `1e20+`.
- **Consequences**: Process crash / panic instead of raising `TypeError`/`ValueError` or clamping timeouts.
- **Resolution**: Check `PyErr_Occurred()` first, ensure `!std.math.isFinite(val) or val < 0.0 or val > 1e15` returns a Python error or clamps to valid bounds, and guard all float-to-integer conversions against integer overflow.
- **Verification**: Add test cases for `call_later` and `call_at` with `NaN`, `Inf`, `-1.0`, `"string"`, and `1e20`.
