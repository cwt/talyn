# BUG-427 — Pseudo-socket aliases the transport fd without `dup`

- **Status**: 🟡 Open
- **Severity**: 🟠 High — double-close / fd-reuse
- **Category**: fd ownership / socket lifetime
- **Files**: `src/transports/stream/extra_info.zig:13-23`, `src/transports/stream/lifecycle.zig:278-301`
- **Related**: [BUG-291](291.md) (PseudoSocket.close idempotency), [BUG-110](110.md), [BUG-48](048.md), [BUG-447](447.md) (mirrored hazard: app `sock.close()` leaves `transport.fd` stale)

## Description

```zig
const py_sock = try utils.PseudoSocket.fast_new_pseudosocket(self.fd, self.family, std.posix.SOCK.STREAM, 0);
```

The pseudo-socket wraps the transport's raw fd **without** `dup`. When the transport tears down,
`cancel_and_close_fd` closes `self.fd` but never marks the pseudo-socket closed (the transport does not
hold a back-pointer to invalidate it). A subsequent `sock.close()` from the application closes a
descriptor number that may already have been reused by an unrelated socket.

## Trigger

`transport.get_extra_info('socket')`, then close the transport, then close the returned socket.

## Consequences

Closing an unrelated, reused fd → protocol corruption / hangs.

## Fix

`dup` the fd for the pseudo-socket (so it owns its own descriptor), or invalidate/mark the pseudo-socket
closed during transport teardown.
