# BUG-310 — Systemic PyObject reference leaks in all socket operations on io.queue failure

- **Status**: 🔴 Open (2026-09-07)
- **Severity**: 🔴 High — Systemic Python object reference leak across all 7 socket operations under submission backpressure or allocation failure
- **Files**:
  - `src/loop/python/io/socket/ops.zig` (`loop_sock_accept`: lines 144–155; `loop_sock_connect`: lines 250–260; `loop_sock_recv`: lines 357–366; `loop_sock_sendall`: lines 486–496; `loop_sock_recvfrom`: lines 602–623; `loop_sock_sendto`: lines 737–759; `loop_sock_recv_into`: lines 810–820)
- **Lessons**: [Memory & Reference Counting](../lessons/01-memory-and-reference-counting.md), [Python C-API Correctness](../lessons/05-python-c-api-correctness.md)
- **Description**:
In all 7 socket operation initiators in `src/loop/python/io/socket/ops.zig`:
```zig
sd.* = .{
    .future = python_c.py_newref(fut),
    .loop = python_c.py_newref(self),
    ...
};
errdefer allocator.destroy(sd);
loop_data.io.queue(sd) catch |err| {
    return PyErr(err);
};
```
If `loop_data.io.queue(sd)` fails (e.g. ring full or OOM), `errdefer allocator.destroy(sd)` frees the memory of `sd` but does NOT call `python_c.py_decref` on `sd.future` or `sd.loop`. Both Python references are permanently leaked in the CPython runtime.
- **Root Cause**: The `errdefer` only frees the container struct and fails to release the owned Python object references stored in its fields.
- **Trigger Scenario**: Ring saturation, submission queue exhaustion, or memory allocation error during `sock_accept`, `sock_connect`, `sock_recv`, `sock_sendall`, `sock_recvfrom`, `sock_sendto`, or `sock_recv_into`.
- **Proposed Remediation**: Update `errdefer` across all 7 functions to release `sd.future` and `sd.loop`: `errdefer { python_c.py_decref(sd.future); python_c.py_decref(sd.loop); allocator.destroy(sd); }`.
