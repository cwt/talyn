# BUG-393 — `talyn/loop.py` & `talyn/runner.py` API compliance bugs: ignored `start_serving=False`, ignored `subprocess_exec` `**kwargs`, premature `_subprocess_popens.pop`, and incomplete `Runner.close()`

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — breaks `loop.create_server(..., start_serving=False)`, silently ignores `cwd`/`env`/`start_new_session` in `loop.subprocess_exec(...)`, and skips async generator / default executor shutdown in `talyn.Runner.close()`
- **Category**: Logic Bug (`asyncio` API Compliance)
- **Files**:
  - `talyn/loop.py:1056, 1485, 1659-1668, 2116-2163`
  - `talyn/server.py:8-12, 38-49`
  - `talyn/runner.py:38-43`
- **Related**: [Lesson 55](../lessons/06-network-protocols-and-io.md)

## Overview & Root Cause

1. **`start_serving=False` is ignored in `create_server`, `_create_ssl_server`, and `create_unix_server` (`talyn/loop.py:1056, 1228, 1485`, `talyn/server.py:8-12, 38-49`, `src/loop/python/io/server/create_server.zig:511`)**:
   - `Loop.create_server` (`talyn/loop.py:1056`) and `Loop.create_unix_server` (`talyn/loop.py:1485`) accept `start_serving=True` in their signatures, **never read `start_serving`**, and `z_create_server_socket` / `z_loop_create_unix_server` unconditionally call `StreamServer.serve(...)` immediately.
   - `Server.__init__` (`talyn/server.py:12`) hardcodes `self._serving = True`, and `Server.start_serving()` (`talyn/server.py:38-40`) only sets `self._serving = True` without calling `srv.serve()` on the underlying Zig `StreamServer` objects!

2. **`Loop.subprocess_exec` silently drops `**kwargs` (`cwd`, `env`, `start_new_session`, `pass_fds`, etc.) (`talyn/loop.py:1659-1668, 2116-2126`)**:
   ```python
   async def subprocess_exec(
       self, protocol_factory, program, *args,
       stdin=subprocess.PIPE, stdout=subprocess.PIPE,
       stderr=subprocess.PIPE, **kwargs,
   ):
   ```
   `kwargs` is accepted in the signature of `subprocess_exec` (line 1662), **and is never passed to `_make_subprocess_transport` (line 1664) or `subprocess.Popen` (line 2116)**! Passing `env=...`, `cwd=...`, or `start_new_session=True` to `await loop.subprocess_exec(...)` (or `asyncio.create_subprocess_exec(...)`) silently ignores those arguments!

3. **Premature `self._loop._subprocess_popens.pop(self._pid, None)` on pipe close (`talyn/loop.py:2161-2162`)**:
   In `_SubprocessProtocolWrapper`:
   ```python
   def connection_lost(self, exc):
       self._loop._subprocess_popens.pop(self._pid, None)
       self._proto.connection_lost(exc)
   ```
   In `_make_subprocess_transport` (lines 2135–2148), `_PipeProto(self, fd_num, user_proto)` forwards pipe `connection_lost` events, and if `user_proto.connection_lost` is called when a pipe closes before the child process exits, `_subprocess_popens.pop(self._pid, None)` removes the `Popen` reference before `process_exited` fires.

4. **`talyn.Runner.close()` skips task cancellation, `shutdown_asyncgens()`, and `shutdown_default_executor()` (`talyn/runner.py:38-43`)**:
   ```python
   def close(self):
       if self._loop is not None:
           try:
               self._loop.close()
           finally:
               asyncio.set_event_loop(None)
               self._loop = None
   ```
   Unlike `Loop.run()` (`talyn/loop.py:2249-2270`, which cancels remaining tasks, awaits `loop.shutdown_asyncgens()`, and awaits `loop.shutdown_default_executor()`), `talyn.Runner.close()` calls `self._loop.close()` directly, abandoning live async generators and executor threads when `with talyn.Runner() as runner:` exits.

## Trigger Scenario

1. Call `await asyncio.create_subprocess_exec("env", env={"FOO": "BAR"}, stdout=asyncio.subprocess.PIPE)` -> `env={"FOO": "BAR"}` is silently ignored and the child inherits `os.environ`!
2. Call `server = await loop.create_server(factory, "127.0.0.1", 0, start_serving=False)` -> `server.is_serving()` is `True` and the server is already accepting connections.

## Proposed Remediation

1. Forward `**kwargs` from `Loop.subprocess_exec` to `_make_subprocess_transport` and `subprocess.Popen` in `talyn/loop.py:1659-1668, 2116-2126`.
2. Pass `start_serving` through to `_create_server_zig`, `create_unix_server`, and `Server.__init__`, and have `Server.start_serving()` call `srv.serve()` on each underlying `StreamServer` when `not self._serving`.
3. Only pop `self._pid` from `_subprocess_popens` in `process_exited` (and transport `close()`).
4. In `talyn/runner.py:38-43`, run the same task-cancellation, `shutdown_asyncgens()`, and `shutdown_default_executor()` cleanup sequence in `Runner.close()` as `talyn/loop.py:2249-2270`.

## Resolution

1. **`start_serving` Support**: In `talyn/server.py` and `talyn/loop.py`, added `start_serving` parameter, tracked `_serving` status, implemented `start_serving()` method to start serving deferred servers, and updated `close()` to mark `_serving = False`.
2. **`subprocess_exec` Kwargs Forwarding**: Forwarded `**kwargs` directly to `subprocess.Popen`.
3. **`_subprocess_popens` Lifecycle**: Popped `_subprocess_popens` on process exit and failure, avoiding premature removal on pipe closure.
4. **`Runner.close` Teardown**: Updated `Runner.close()` in `talyn/runner.py` to cancel pending tasks, await `shutdown_asyncgens()`, and await `shutdown_default_executor()` prior to closing the loop.
5. **Regression Tests**: Added regression tests in `tests/test_api_compliance_and_cleanup.py`.
