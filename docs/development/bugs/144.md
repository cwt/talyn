# BUG-144 — Reference leak of coroutine, context, and name in `create_task` with custom `task_factory`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — 3 Python object reference leaks on every task creation with a custom task factory
- **Files**: `src/loop/python/utils/task.zig:56-85`
- **Lessons**: [Memory §Lesson 37](../lessons/01-memory-and-reference-counting.md), [Memory §Lesson 107](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `z_loop_create_task`, `coro`, `context`, and `name` are created as new references. In the standard path (`self.task_factory == null`), ownership was transferred to `PythonTaskObject`. When `self.task_factory != null`, the local variables were packed into arguments without decreffing or transferring `coro`, `context`, and `name`.
- **Trigger**: Calling `loop.create_task()` when a custom `task_factory` is set on the loop.
- **Consequences**: Leaked 1 reference each to `coro`, `context`, and `name` per task created.
- **Fix**: Added explicit decrefs of `coro`, `context`, and `name` on the `self.task_factory != null` success path while relying on top-level `errdefer`s on error.
