# BUG-364 — `BlockingTasksSet.free()` ignores `self.free_count`, permanently leaking ~80 KB `BlockingTasksSet` nodes into `busy_sets` every 1024 operations (plus `reserved_slots` leak on `Overflow`)

- **Status**: 🔴 Open
- **Severity**: 🔴 High — defeats `BlockingTasksSet.free_slots` reuse after the first 1024 `io_uring` operations in a set and causes unbounded memory growth (~80 KB per 1024 ops) whenever a set contains any long-lived task (`eventfd`, `signalfd`, server socket, or idle connection)
- **Category**: Memory Leak & Unoptimized Algorithm
- **Files**:
  - `src/loop/scheduling/io/main.zig:232-245, 282-289, 860-894`
- **Related**: [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/loop/scheduling/io/main.zig`, `BlockingTasksSet` maintains both a bump index (`self.index: usize = 0` up to `TotalTasksItems = 1024`) and a LIFO free-list of recycled slots (`self.free_slots: [TotalTasksItems]u16`, `self.free_count: usize = 0`).

Look at `BlockingTasksSet.push` (lines 232–245):

```zig
pub inline fn push(self: *BlockingTasksSet, data: CallbackManager.Callback) *BlockingTask {
    const slot_idx: usize = if (self.free_count > 0) blk: {
        self.free_count -= 1;
        break :blk self.free_slots[self.free_count];
    } else blk: {
        const idx = self.index;
        @atomicStore(usize, &self.index, idx + 1, .release);
        break :blk idx;
    };
```

And now look at `BlockingTasksSet.free` (lines 282–289):

```zig
pub inline fn free(self: *BlockingTasksSet) bool {
    if ((self.index + self.reserved_slots) < TotalTasksItems) {
        return true;
    }

    self.disattached = true;
    return false;
}
```

1. **`BlockingTasksSet.free()` completely ignores `self.free_count`**:
   - Once `self.index` reaches `TotalTasksItems` (`1024`), `(self.index + self.reserved_slots) < TotalTasksItems` is `false` **forever** (because `self.index` is only reset when `self.active_tasks == 0` in `release()` at line 269)!
   - Even if `1022` of the `1024` slots have completed and are sitting in `self.free_slots` (`self.free_count == 1022`), `get_free_set` (lines 860–871) calls `set.free()`, which returns `false`, sets `self.disattached = true`, moves the `BlockingTasksSet` to `busy_sets`, and allocates a brand new ~80 KB `BlockingTasksSet`!
   - The first `BlockingTasksSet` always holds the loop's permanent `eventfd` read task (`active_tasks >= 1`), and subsequent sets often hold long-lived `signalfd`, `inotify`, `StreamServer`, or keep-alive `StreamTransport` reads. Any `BlockingTasksSet` with even **one** long-lived task will **never** reach `active_tasks == 0`, so once its bump counter `self.index` hits `1024`, it is permanently stranded in `busy_sets` with up to `1023` unused slots!

2. **Permanent `reserved_slots` leak when `queue_unlocked` returns `error.Overflow` (`src/loop/scheduling/io/main.zig:873-894`)**:
   ```zig
   pub fn reserve_slot(self: *IO) !*BlockingTasksSetNode {
       self.blocking_tasks.lock.lock();
       defer self.blocking_tasks.lock.unlock();

       const set = try self.get_free_set();
       set.data.reserved_slots += 1;
       return set;
   }
   ```
   Every caller of `reserve_slot` (`Read.perform`, `Write.perform`, `Socket.perform`, `Timer.perform`, `DNS.Resolv`, etc.) calls `const set = try self.reserve_slot();` without an `errdefer set.data.reserved_slots -= 1;` before `ring.get_sqe()` / `flush_pending_sqes()`. If `ring.get_sqe()` or `flush_pending_sqes()` fails, `set.data.reserved_slots` stays incremented forever.

## Trigger Scenario

1. Start an event loop with one idle TCP connection (or `StreamServer`) created every ~1000 short-lived operations.
2. Each `BlockingTasksSet` (~80 KB) hits `self.index == 1024`, is moved to `busy_sets` by `free()`, and is never reclaimed because `active_tasks >= 1`, even though `free_count == 1023`.

## Proposed Remediation

1. In `BlockingTasksSet.free()` (`src/loop/scheduling/io/main.zig:282-289`), account for `self.free_count` (i.e. available slots are `(TotalTasksItems - self.index) + self.free_count`, which must exceed `self.reserved_slots`):

```zig
pub inline fn free(self: *BlockingTasksSet) bool {
    const used_slots = self.index - self.free_count;
    if ((used_slots + self.reserved_slots) < TotalTasksItems) {
        return true;
    }

    self.disattached = true;
    return false;
}
```

And in `BlockingTasksSet.release()` (`src/loop/scheduling/io/main.zig:262-280`), when `self.disattached` is true and a slot is returned to `self.free_slots` (so `used_slots < TotalTasksItems`), re-attach the node from `busy_sets` back to `availables_sets`.
2. Add `errdefer` in all `reserve_slot()` callers (or a helper method on `BlockingTasksSet`) to decrement `reserved_slots` if SQE preparation fails before `set.data.push(...)`.
