# BUG-326 — libc-style errno decoder mis-reads raw syscall returns across 5 call sites

- **Status**: 🟢 Fixed (2026-09-07)
- **Severity**: 🔴 High — Failed syscalls decoded as SUCCESS: bogus descriptors / garbage sockaddr output on error paths
- **Files**:
  - `src/loop/child_watcher.zig:55` (`add_child_handler`: `pidfd_open` errno check)
  - `src/transports/subprocess/transport.zig:385` (`start_exit_watcher`: `pidfd_open` errno check)
  - `src/transports/datagram/write.zig:153` (`datagram sendto`: `getsockname` family probe)
  - `src/transports/datagram/extra_info.zig:37` (`datagram get_extra_info("sockname")`: `getsockname`)
  - `src/utils/pseudosocket.zig:59` (`PseudoSocket.getsockname`)
- **Lessons**: [io_uring & Kernel](../lessons/04-io-uring-and-kernel.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**:
  All five sites decode the raw `usize` return of a `std.os.linux.*` syscall with `std.posix.errno(rc)`. In Zig 0.16 with a libc-linked target, `std.posix.errno` is `system.errno` (i.e. `std.c.errno`):
  ```zig
  pub fn errno(rc: anytype) E {
      return if (rc == -1) @enumFromInt(_errno().*) else .SUCCESS;
  }
  ```
  Raw Linux syscalls return `-errno` (e.g. `-ESRCH` = -3), never `-1`-typed integers comparable that way, and the C `errno` TLS is unrelated to raw syscall returns. Consequences:
  1. `pidfd_open` on a reaped/nonexistent pid (child watcher `add_child_handler`, subprocess `start_exit_watcher`): the failure decoded as `.SUCCESS`, and `@intCast(rc)` truncated `-3` into `pidfd = -3`. The armed `WaitReadable` on fd -3 later failed `waitid` with `EINVAL` and the handler was stranded (leak), with `add_child_handler` silently "succeeding" for dead pids.
  2. `getsockname` failures (pseudosocket, datagram sendto family probe, datagram `get_extra_info("sockname")`): decoded as `.SUCCESS`, proceeding to read the **uninitialized** `sockaddr.storage` and return/apply a garbage address or family.
- **Root Cause**: `std.posix.errno` is the libc-ABI decoder, not the raw-syscall decoder. Raw syscall returns must be decoded with the bit-cast range check (`std.os.linux.errno` / the repo's `utils.getSyscallErrno`, as already used throughout the codebase).
- **Trigger Scenario**: Registering a child watcher for an already-reaped pid; requesting `sockname` extra info (or sendto) when `getsockname` fails; `PseudoSocket.getsockname` on a torn-down fd.
- **Proposed Remediation**: Replace every `std.posix.errno(rc)` on a raw `std.os.linux.*` syscall return with `utils.getSyscallErrno(rc)`.

## Fix (Applied — 2026-09-07)

- All five call sites now use `utils.getSyscallErrno(rc)`; `src/utils/pseudosocket.zig` gained the `utils` import. A repo-wide grep confirms zero remaining live `std.posix.errno` uses on raw syscall returns (the linter rule text in `tools/linter/rules/syscall_safety.zig` already flags the pattern class).
- Regression test: `tests/test_child.py::test_add_child_handler_on_reaped_pid_raises` — `add_child_handler` for a fully reaped pid must raise `RuntimeError("No such process")`; previously it "succeeded" with a bogus `pidfd = -3` and the handler stranded on EINVAL `waitid`s.

## Validation (2026-09-07)

Discovered during the BUG-307..325 fix pass: the BUG-313 re-register probe (`os.pidfd_open` → ESRCH) while talyn's `add_child_handler` "succeeded" on the same reaped pid exposed the decoder split. Verified against Zig 0.16.0 std: `std.posix.errno = system.errno` (`std/c.zig:76`), while `std.os.linux.errno` (`os/linux.zig:592`) implements the correct bit-cast range decode.
