# BUG-189 — Systemic keyword argument reference leaks across multiple loop APIs

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Cumulative reference and memory leaks on keyword calls
- **Files**: `src/loop/python/io/datagram/create_endpoint.zig:83-94`, `src/loop/python/io/socket/getaddrinfo.zig:120-124`, `src/loop/python/io/pipe/unix.zig:110-112, 178-180`, `src/loop/python/io/subprocess/exec.zig:22-27`, `src/transports/stream/extra_info.zig:39-46`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/004-memory-management-and-refcounting.md), [Python C API §Lesson 21](../lessons/021-python-c-api.md)
- **Description**: `parse_vector_call_kwargs` performs `py_newref` on all extracted keyword values. In `create_endpoint.zig`, lines 88-93 called `py_xincref` a second time, leaking one reference per kwarg. In `getaddrinfo.zig`, `pipe/unix.zig`, `exec.zig`, and `extra_info.zig`, the extracted keyword variables were never decreffed on the success path.
- **Trigger**: Calling `create_datagram_endpoint`, `getaddrinfo`, `create_unix_connection`, `create_unix_server`, `subprocess_exec`, or `get_extra_info` with keyword arguments.
- **Consequences**: Gradual Python heap growth and leaked PyObjects across loop lifetime.
- **Fix**: Removed redundant `py_xincref` calls and added `defer python_c.py_xdecref(...)` for all extracted kwargs across all affected APIs.
