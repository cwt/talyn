# BUG-256 — datagram `close()` frees an in-flight recv buffer (UAF)

- **Status**: 🔍 Open
- **Severity**: 🔴 Critical — Memory safety / io_uring lifetime (use-after-free, buffer-pool corruption)
- **Files**: `src/transports/datagram/main.zig`, `src/transports/datagram/read.zig`
- **Lessons**: [io_uring §Deferred Submission](../lessons/04-io-uring-and-kernel.md)
- **Description**: `datagram_close` sets `closed = true`, queues a recv cancel (`Cancel(read_task_id)` / `CancelByFd`) which is only **queued asynchronously** (lines 165-170), then synchronously calls `cleanup_resources(instance)` (line 182). `cleanup_resources` (lines 45-80) nulls `buffer_ptr` and releases/frees the registered buffer (`release_buffer`) or frees the heap buffer (`allocator.free`) (lines 65-78). But `queue_read` (read.zig:11) had already armed a `PerformRecvMsg` whose `rd.iov.base = self.buffer_ptr.?` (read.zig:28) is still pending; the io_uring cancel only takes effect once its CQE is processed by the loop. Between `close()` freeing the buffer and the cancel being processed, the kernel can complete the still-pending recv and **write into the now-freed / re-leased buffer**, or the re-leased registered buffer can be handed to another transport's recv. This is exactly the io_uring deferred-submission hazard: a buffer handed to io_uring must remain valid until the CQE is reaped, not until the cancel is queued. The stream transport avoids this by freeing its read buffer only in `deinit`/`tp_clear`, never in `close()`.
- **Trigger**: Closing a datagram transport while a recv is in flight — common when `transport.close()` is invoked from a callback while reads are armed.
- **Consequences**: Use-after-free / buffer-pool corruption; the kernel writes into freed memory (or one transport receives another's datagram bytes). Corrupts unrelated transports and can leak/alias datagram payloads.
- **Resolution**: Do not reclaim `buffer_ptr` in `datagram_close`. Only release/free it in `datagram_dealloc` / `datagram_clear` (which run after the transport is fully unreferenced — i.e. after the in-flight recv's completion has dropped its transport ref via `cleanup_read`). If eager reclaim is required, defer the free until `read_completed` reports `cancelled()`/`closed()`.
- **Verification**: Stress `close()` concurrently with incoming datagrams; run under AddressSanitizer and a kernel with io_uring; assert `buffer_ptr` validity at recv completion and that no other transport observes the closed transport's buffer.
