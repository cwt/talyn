# BUG-370 — `Future.remove_done_callback` compares pointer identity (`@intFromPtr`) instead of Python equality (`Py_EQ`) and leaks removed callback/context references until `Future` deallocation

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — breaks `fut.remove_done_callback(self.method)` for bound methods (including Talyn's own `Loop.run_until_complete` in `talyn/loop.py:432, 440`) and retains strong references to removed callbacks and contexts until the `Future` is destroyed
- **Category**: Logic Bug & Reference Leak
- **Files**:
  - `src/future/python/callbacks.zig:104-112`
  - `src/future/callback.zig:202-225`
  - `talyn/loop.py:432, 440`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

1. **Pointer identity (`@intFromPtr`) instead of Python equality (`Py_EQ`) (`src/future/python/callbacks.zig:104-112`)**:
   ```zig
   const py_callback_ptr = @intFromPtr(py_callback);
   for (callbacks_queue.items) |*item| {
       const callback = &item.data.PythonFutureCallback;
       if (!callback.cancelled and @intFromPtr(callback.callback.?) == py_callback_ptr) {
           callback.cancelled = true;
           removed_count += 1;
       }
   }
   ```
   In Python, accessing a bound method attribute (`obj.method`) allocates a **new** `PyMethodObject` wrapper each time. Two bound method wrappers for the same receiver and function have **different** `PyObject*` addresses (`obj.method is not obj.method`), but compare equal (`obj.method == obj.method`).
   Standard `asyncio.Future.remove_done_callback` removes all callbacks where `cb == fn` (`PyObject_RichCompareBool(..., Py_EQ)`).
   Because Talyn compares `@intFromPtr`, calling `fut.remove_done_callback(obj.method)` **always returns `0`** and fails to remove the callback!
   In fact, Talyn's own `Loop.run_until_complete` in `talyn/loop.py:432, 440` hits this exact bug:
   ```python
   future.add_done_callback(self.__run_until_complete_cb)
   try:
       self.run_forever()
   except:
       ...
       future.remove_done_callback(self.__run_until_complete_cb)
       raise
   ```
   When `run_forever()` is interrupted (e.g. by `loop.stop()` or `KeyboardInterrupt`), `future.remove_done_callback(self.__run_until_complete_cb)` creates a second bound method object whose pointer differs from the one passed to `add_done_callback`, so `__run_until_complete_cb` is **not** removed! When `future` later completes during a subsequent `run_forever()`, the stale `__run_until_complete_cb` fires and stops the loop unexpectedly!

2. **Removed callbacks and contexts are not decref'd when removed (`src/future/python/callbacks.zig:108` & `src/future/callback.zig:218`)**:
   Both `z_future_remove_done_callback` and `Future.Callback.remove_done_callback` only set `callback.cancelled = true` without calling `python_c.py_xdecref(callback.callback)` / `python_c.py_xdecref(callback.context)` (or removing the entry from `callbacks_queue`). If a long-lived `Future` has callbacks repeatedly added and removed via `add_done_callback` / `remove_done_callback`, `callbacks_queue` and all captured `callback`/`context` objects grow without bound until the `Future` finishes or is garbage-collected.

## Trigger Scenario

1. On any `Future`:
   ```python
   class Handler:
       def on_done(self, fut): pass
   h = Handler()
   fut.add_done_callback(h.on_done)
   assert fut.remove_done_callback(h.on_done) == 1  # FAILS under Talyn: returns 0!
   ```
2. Interrupt `loop.run_until_complete(fut)` before `fut` finishes, then call `loop.run_forever()` and resolve `fut` -> the unremoved `__run_until_complete_cb` stops the loop prematurely.

## Proposed Remediation

In `z_future_remove_done_callback` (`src/future/python/callbacks.zig:104-112`):
1. Compare `callback.callback.?` with `py_callback` using `python_c.PyObject_RichCompareBool(callback.callback.?, py_callback, python_c._c.Py_EQ)` (checking `< 0` for errors).
2. When a callback matches, set `callback.cancelled = true`, detach `callback.callback` and `callback.context` (setting the fields to `null`), and `py_xdecref` both immediately.


## Resolution (2026-10-18)

Both defects confirmed live and fixed:

1. **Equality comparison (fixed)**: `Future.Callback.remove_done_callback`
   now takes the `PyObject` and compares `PythonGeneric` entries via
   `PyObject_RichCompareBool(..., Py_EQ)` in
   src/future/callback.zig (the caller in
   src/future/python/callbacks.zig passes the raw callback). The loop
   iterates by index (holding a temporary incref on `candidate` and
   re-validating bounds and `!self.released` after `PyObject_RichCompareBool`)
   so a custom `__eq__` or `__del__` finalizer that calls
   `add_done_callback` and reallocates `callbacks_queue.items` cannot
   invalidate pointers into the slice, and skips null callbacks via
   `value.callback orelse continue` instead of `get_py_none()`. Custom
   `__eq__` errors propagate to the slot (`error.PythonError`).
   `ZigGeneric` entries were never matchable through the Python path
   (function-pointer ids vs PyObject pointers) and stay untouched.

2. **Immediate reference release (fixed)**: a matched entry is marked
   `cancelled`, its `callback`/`context` fields are detached (nulled)
   and `py_xdecref`'d at removal time. To make the detach sound, the
   `PythonGenericData` fields became optional and every consumer
   handles detached entries explicitly: `release_callbacks_queue` now
   `py_xdecref`s (removed entries carry no references), the runner
   iteration guards null fields (already skipped via the cancelled
   check), and `traverse_callbacks_queue` skips `cancelled` entries —
   pre-fix that walk visited still-held references, post-fix visiting
   a detached (nulled) entry would crash, so the skip is required.

## Test

`tests/test_future_callbacks.py`: removal of a bound method returns 1
(the second attribute lookup wraps a NEW `PyMethodObject` — identity
could never match); the removed callback doesn't fire on resolution;
and a `weakref` on the handler dies immediately after removal (the
removed entry no longer holds the callback/context until teardown).

**Bite verification**: reverting callback.zig + callbacks.zig to tip
makes all three fail — `assert 0 == 1` (identity returned 0), the
removed callback fired, and the weakref stayed alive (the message
'cyan weakref alive: removal did not release its references').
