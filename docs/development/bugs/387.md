# BUG-387 — `FSWatcher` leaks `callback` reference and `wd` on `add_watch` error, disarms permanently on `on_inotify_event` error, and performs per-event `dupe` + $O(W^2)$ scan

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — leaks Python callback references and kernel `inotify` watch descriptors on `add_watch` errors, permanently disarms all filesystem watches if any error occurs in `on_inotify_event`, and does $O(W^2)$ work per event batch
- **Category**: Reference/Resource Leak, Logic Bug, & Unoptimized Algorithm
- **Files**:
  - `src/loop/fs_watcher.zig:78-115, 117-149, 151-208`
- **Related**: [BUG-319](319.md), [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/loop/fs_watcher.zig`, there are three bugs in `FSWatcher`:

1. **`add_watch` leaks `wd` and `callback` reference on error (`src/loop/fs_watcher.zig:84-112`)**:
   ```zig
   const rc = std.os.linux.inotify_add_watch(self.inotify_fd, path_z.ptr, mask);
   if (@as(isize, @bitCast(rc)) < 0) {
       return error.WatchFailed;
   }
   const wd: i32 = @intCast(rc);

   const path_copy = try self.allocator.dupe(u8, path);
   errdefer self.allocator.free(path_copy);

   const handler = try self.allocator.create(WatchHandler);
   errdefer self.allocator.destroy(handler);

   handler.* = .{
       .wd = wd,
       .path = path_copy,
       .callback = python_c.py_newref(callback),
   };

   try self.watches.put(self.allocator, wd, handler);
   ```
   - There is no `errdefer _ = std.os.linux.inotify_rm_watch(self.inotify_fd, wd);` after line 88.
   - There is no `errdefer python_c.py_decref(handler.callback);` before `try self.watches.put(...)` at line 105 (or before `try self.arm_read()` at line 109).
   - Furthermore, if `inotify_add_watch` is called on a path that is **already** watched on `self.inotify_fd`, Linux `inotify_add_watch` returns the **same** `wd`, and `self.watches.put(self.allocator, wd, handler)` silently overwrites the previous `WatchHandler` entry in the hash map, leaking the old `WatchHandler`, its `path_copy`, and its `callback` reference!

2. **Permanent watcher disarm on error in `on_inotify_event` (`src/loop/fs_watcher.zig:151-208`)**:
   In `on_inotify_event`, `self.read_armed = false` is set at line 156, and `try self.arm_read()` is at the very end of the function (line 207). If any call inside the event-processing `while` loop (`self.allocator.dupe`, `PyUnicode_FromStringAndSize`, `PyLong_FromUnsignedLong`, `PyTuple_New`, `Handle.fast_new_handle`, or `Soon.dispatch`) returns an error, `on_inotify_event` exits before line 207, leaving `self.read_armed == false` and permanently disarming all inotify watches on the loop.

3. **Unnecessary heap `dupe` and $O(W^2)$ scan in `on_inotify_event` (`src/loop/fs_watcher.zig:125-145, 183-190`)**:
   - In `on_inotify_event` (lines 183–190), `const name = try self.allocator.dupe(u8, name_slice); defer self.allocator.free(name);` heap-allocates and copies `name_slice` only to pass `name.ptr` and `name.len` to `PyUnicode_FromStringAndSize` on the very next line (which makes its own copy and does not require NUL-termination!).
   - In `remove_watch_by_path` (lines 125–145), removing by path scans all entries in `self.watches` linearly ($O(W)$).

## Trigger Scenario

1. Watch the same directory path twice with `loop.watch_path("/tmp", mask, cb1)` and `loop.watch_path("/tmp", mask, cb2)` -> `inotify_add_watch` returns the same `wd` and `self.watches.put` overwrites and leaks the first `WatchHandler` and `cb1`.
2. Trigger an inotify event when `Soon.dispatch` or tuple creation fails -> `on_inotify_event` returns before `self.arm_read()`, permanently disarming `FSWatcher`.

## Proposed Remediation

1. In `add_watch`, check `if (self.watches.get(wd))` before `put` to free/decref any replaced `WatchHandler`, and add `errdefer _ = std.os.linux.inotify_rm_watch(self.inotify_fd, wd);` and `errdefer python_c.py_decref(handler.callback);`.
2. In `on_inotify_event`, pass `name_slice.ptr` and `@intCast(name_slice.len)` directly to `PyUnicode_FromStringAndSize` without `self.allocator.dupe(u8, name_slice)`, and ensure `self.arm_read()` is re-armed via `defer` whenever `self.watches.count() > 0` and `self.loop.initialized`.
