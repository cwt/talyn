# BUG-419 — `execute_task_throw` cancelled arm double-decrefs the `Task`

- **Status**: 🟡 Open
- **Severity**: 🔴 Critical — double-free / UAF of `PythonTaskObject` during loop shutdown
- **Category**: Reference counting / callback-contract violation
- **Files**: `src/task/callbacks.zig:625-640`, `src/callback_manager.zig:412-426`
- **Related**: [BUG-273](273.md) (same contract, non-cancelled arms), [BUG-254](254.md), [BUG-177](177.md)

## Description

The cancelled arm of `execute_task_throw` releases the dispatch-owned task reference twice on
error:

```zig
if (data.cancelled()) {
    const exception = task.exception orelse { python_c.py_decref(@ptrCast(task)); return; };
    const fut = utils.get_data_ptr(Future, &task.fut);
    errdefer python_c.py_decref(@ptrCast(task));            // (1) local release
    try Future.Python.Result.future_fast_set_exception(&task.fut, fut, exception);
    python_c.py_decref(@ptrCast(task));                      // success release
    return;
}
```

`execute_task_throw` is dispatched with `.cleanup = &cleanup_task` (`callbacks.zig:299`), and
`cleanup_task` is a plain `py_decref` (`callbacks.zig:526-529`). The executor contract is
"self-release on success only; on error the manager runs cleanup" — exactly what BUG-273 fixed
for the non-cancelled arms. This arm still violates it: when `future_fast_set_exception` fails
(loop shutting down → `call_done_callbacks` returns `error.PythonError` once
`!loop.initialized`, or the future is already resolved), `errdefer` decrefs the task **and**
`release_dynamic_ring_buffer`/`execute_dynamic_ring_buffer` then run `cleanup_task` → **double
decref / premature free**.

## Trigger

`loop.close()` with a still-queued `execute_task_throw` whose task has a done-callback (e.g.
`run_until_complete`), so the future resolution fails during the teardown drain.

## Consequences

Task object freed while the future/registry may still reference it → UAF, corrupted
`asyncio.current_task()` state, possible interpreter crash.

## Fix

Drop the `errdefer` and let the manager cleanup own the single decref on the error path
(mirror the non-cancelled arm at `callbacks.zig:662-668`): on error return the error without a
local decref; on success keep the single self-release.
