# BUG-383 — Missing `ring.fd >= 0` guards in `IO.deinit()`, `flush_pending_sqes()`, and `ensure_ring_for_current_thread()` (Mandate #6), lost fixed files on thread handoff, and early `self.index` release-store in `BlockingTasksSet.push()` (Mandate #5)

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — violates Architectural Mandates #5 and #6, causes `EBADF` on all existing transports after thread handoff (`ensure_ring_for_current_thread`), and exposes uninitialized `BlockingTask` slots to concurrent GC traversal in free-threaded Python
- **Category**: Logic Bug, Race Condition, & Architectural Mandate #5/#6 Violations
- **Files**:
  - `src/loop/scheduling/io/main.zig:232-260, 673-690, 847-853, 896-935`
- **Related**: [Architectural Mandate #5](../architectural-mandates.md), [Architectural Mandate #6](../architectural-mandates.md), [Lesson 64](../lessons/04-io-uring-and-kernel.md)

## Overview & Root Cause

1. **Architectural Mandate #5 violation in `BlockingTasksSet.push()` (`src/loop/scheduling/io/main.zig:232-256`)**:
   Architectural Mandate #5 states:
   > *"When adding items to a collection traversed by Python's GC, ALWAYS fully initialize the data before advancing the index or linking the node. Use `@atomicStore` with release semantics to ensure initialization is visible to GC threads."*
   Look at `BlockingTasksSet.push` (lines 236–246):
   ```zig
   } else blk: {
       const idx = self.index;
       @atomicStore(usize, &self.index, idx + 1, .release);
       break :blk idx;
   };

   const slot = &self.tasks[slot_idx];
   slot.* = .{
       .data = data,
       .set = self,
       .active = true,
   };
   ```
   `BlockingTasksSet.push` advances `self.index` via `@atomicStore(..., .release)` at line 238 **before** writing `slot.*` at lines 243–247!
   In free-threaded Python, `BlockingTasksSet.traverse` (`lines 321-331`) loads `self.index` with `.acquire` and iterates over `self.tasks[0..idx]`. If a GC thread runs between line 238 and line 247, it reads an uninitialized `slot` whose `active` / `data` fields are still `undefined`!

2. **Architectural Mandate #6 violations in `IO.deinit()`, `flush_pending_sqes()`, and `ensure_ring_for_current_thread()` (`src/loop/scheduling/io/main.zig:673-690, 847-853, 896-902`)**:
   - In `IO.deinit()` (lines 847–853):
     ```zig
     try self.blocking_tasks.release();
     self.ring.deinit();
     ```
     `self.ring.deinit()` is called **after** `self.blocking_tasks.release()` (without checking `if (self.ring.fd >= 0)`), and during `self.blocking_tasks.release()` callbacks run while `self.ring` is still live or if `deinit()` is called when `ring.fd < 0`, `std.os.linux.IoUring.deinit` asserts `self.fd >= 0` (`SIGABRT`).
   - In `flush_pending_sqes()` (lines 896–902):
     Calls `submit_guaranteed(&self.ring)` without checking `if (self.ring.fd < 0) return 0;`. During `loop.close()`, if any teardown callback calls `flush_pending_sqes()` after `ring.deinit()` has set `ring.fd = -1`, `submit_guaranteed` passes `fd = -1` to `io_uring_enter`.
   - In `ensure_ring_for_current_thread()` (line 676):
     Calls `self.ring.deinit()` without checking `if (self.ring.fd >= 0)`.

3. **Fixed-file table is lost on `ensure_ring_for_current_thread()` (`src/loop/scheduling/io/main.zig:673-690`)**:
   When a loop created on Thread A is run on Thread B (`SINGLE_ISSUER` handoff), `ensure_ring_for_current_thread()` destroys the old ring (`self.ring.deinit()`), creates a new ring, and re-registers `self.buffer_pool`, **but only initializes an empty fixed-file table (`init_fixed_files`) without re-registering the file descriptors already stored in `self.fixed_files` (`1..fixed_files_next_slot`)**!
   Any `StreamTransport`, `StreamServer`, or `DatagramTransport` created before `loop.run_forever()` (e.g. on the setup thread) holds a non-zero `fixed_file_index` that maps to `-1` in the new ring's kernel table, causing every subsequent read/write/accept on that transport to fail with `-EBADF`!

## Trigger Scenario

1. Create a loop and a server/connection on Thread A, then hand the loop to Thread B to call `loop.run_forever()`. `ensure_ring_for_current_thread` replaces the ring with a blank fixed-file table, breaking all pre-existing fixed-file transports with `-EBADF`.
2. In free-threaded mode, GC runs `loop_traverse` while `BlockingTasksSet.push` is between line 238 and line 247, reading uninitialized `BlockingTask` memory.

## Proposed Remediation

1. In `BlockingTasksSet.push()` (`src/loop/scheduling/io/main.zig:232-248`), initialize `slot.*` **first**, and only then execute `@atomicStore(usize, &self.index, idx + 1, .release)` (when allocating from the bump pointer) or `@atomicStore(bool, &slot.active, true, .release)`.
2. Guard `self.ring.deinit()` and `flush_pending_sqes()` with `if (self.ring.fd >= 0)`.
3. In `ensure_ring_for_current_thread()`, track registered fds in `FixedFileTable` so they can be re-registered into the new ring on thread handoff.
