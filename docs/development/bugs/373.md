# BUG-373 — `Py_None` reference leaked on every coroutine step (`talyn_task_step_trampoline` / `talyn_task_throw_trampoline`) and every task registration (`register_asyncio_task`)

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — 100% deterministic reference count leak on the hottest coroutine execution paths (every single coroutine `send` and `throw` step and every `Task` creation)
- **Category**: Reference Leak
- **Files**:
  - `src/task/callbacks.zig:98, 159, 533-547, 622-626`
  - `src/utils/python_imports.zig:55-66`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

1. **`_execute_task_send` and `_execute_task_throw` discard `trampoline_ret` without `py_decref` (`src/task/callbacks.zig:98, 159, 533-547, 622-626`)**:
   In `src/task/callbacks.zig`, `talyn_task_step_trampoline` (line 98) and `talyn_task_throw_trampoline` (line 159) are registered `PyCFunction`s that return `python_c.get_py_none()` (which increments `Py_None`'s refcount) on success.
   In `_execute_task_send` (lines 533–547):
   ```zig
   const trampoline_ret = python_c.PyObject_CallOneArg(step_trampoline_cfunc.?, @ptrCast(task));
   ...
   if (trampoline_ret == null) {
       return error.PythonError;
   }
   ```
   And in `_execute_task_throw` (lines 622–626):
   ```zig
   const trampoline_ret = python_c.PyObject_CallOneArg(throw_trampoline_cfunc.?, @ptrCast(task));
   if (trampoline_ret == null) {
       return error.PythonError;
   }
   ```
   Neither function ever calls `python_c.py_decref(trampoline_ret.?)`, leaking 1 reference on **every single coroutine step** across the entire application!

2. **`register_asyncio_task` discards `_register_task` return value without `py_decref` (`src/utils/python_imports.zig:55-66`)**:
   ```zig
   pub inline fn register_asyncio_task(task: PyObject) !void {
       const register_task_fn = get("asyncio_register_task");
       if (python_c.PyObject_CallOneArg(register_task_fn, task) == null) {
           return error.PythonError;
       }
   }
   ```
   Compare this with `unregister_asyncio_task` (lines 68–74) right below it:
   ```zig
   pub inline fn unregister_asyncio_task(task: PyObject) !void {
       const unregister_task_fn = get("asyncio_unregister_task");
       const res = python_c.PyObject_CallOneArg(unregister_task_fn, task) orelse return error.PythonError;
       python_c.py_decref(res);
   }
   ```
   `unregister_asyncio_task` properly decrefs `res`, whereas `register_asyncio_task` discards the returned `PyObject` (usually `Py_None`, or a custom return value if `_register_task` is monkeypatched by profiling/tracing tools) without calling `python_c.py_decref(res)`!

## Trigger Scenario

Every `Task` creation (`register_asyncio_task`) and every coroutine resume (`_execute_task_send` / `_execute_task_throw`) leaks 1 reference to the returned object.

## Proposed Remediation

1. In `_execute_task_send` (`src/task/callbacks.zig:544-547`) and `_execute_task_throw` (`src/task/callbacks.zig:622-626`), decref `trampoline_ret`:
   ```zig
   const ret = trampoline_ret orelse return error.PythonError;
   python_c.py_decref(ret);
   ```
2. In `register_asyncio_task` (`src/utils/python_imports.zig:55-66`), capture the return value of `PyObject_CallOneArg` and call `python_c.py_decref(res)`.


## Resolution (2026-10-18)

Both leak classes confirmed live and fixed:

1. **Trampoline returns (fixed)**: `talyn_task_step_trampoline` and
   `talyn_task_throw_trampoline` return `get_py_none()` — an OWNED
   reference (the current code calls the trampolines directly, so the
   report's `PyObject_CallOneArg` description was stale, but the
   discarded owner is the same defect). The call sites in
   `_execute_task_send` / `_execute_task_throw` now
   `py_decref(trampoline_ret.?)` right after the null-check — one leak
   per coroutine send step and one per throw step previously.

2. **`register_asyncio_task` (fixed)**: both registrar call sites now
   capture the returned object and `py_decref` it (preserving the
   `PyErr_Clear()` swallow on failure). The second
   (`asyncio.py_register_task`) call is responsible for the leak
   talyn's own __unittest crashed on whenever both registrars were
   distinct.

## Test

No Python-facing regression test is possible for this fix: both
leaked references are to `Py_None`, which is immortal on every Python
Talyn supports (3.13 / 3.14), so neither `sys.getrefcount(None)` nor
RSS changes pre-fix — the leaks were purely counter debt with no
memory impact, and `register_asyncio_task` cannot reach a
non-immortal return because the registrar pointers are read once at
import time (a monkeypatch returning a tracked object would never be
observed through the cached pointer). Validated at the code level
(BUG-362 precedent): the decref sites are asserted present in both
files (source-tree check), and the full gate is green — any
double-release regression would surface immediately across the 431
tests × 4 pythons.

**Bite verification**: not buildable honestly (see the impossibility
note above); the pre-fix and post-fix behavior of the entire test
suite is byte-identical, which is itself the verification that the fix
is release-diff-only.
