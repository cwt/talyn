# BUG-197 — Coroutine throw error paths bypass _leave_task leaving corrupted asyncio.current_task state

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — State Invariant Violation & Task Tracking Corruption
- **Files**: `src/task/callbacks.zig:396-446`
- **Lessons**: [Concurrency & Free-Threading §Lesson 11](../lessons/011-concurrency.md), [Architectural Mandates §Mandate 4](../architectural-mandates.md)
- **Description**: In `src/task/callbacks.zig`, `_execute_task_throw` called `enter_task_func` to register the task as running on the loop. If `PyContext_Enter` failed or `PyObject_GetAttrString(task.coro.?, "throw")` failed, the function returned `error.PythonError` immediately before calling `leave_task_func`.
- **Trigger**: Failure to enter the task context or failure to resolve the `throw` method on a task's coroutine object.
- **Consequences**: `asyncio.current_task(loop)` permanently reported this task as running on the loop, corrupting asyncio context and task tracking invariants.
- **Fix**: Implemented `talyn_task_throw_trampoline` and updated `talyn_task_step_trampoline` to guarantee `leave_task_func` is always executed whenever `enter_task_func` succeeds.
