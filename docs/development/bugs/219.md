# BUG-219 — Nested GC traversal bug skipping `callback_ptr` when `module_ptr` is null in `BlockingTasksSet.traverse`

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Incomplete GC Traversal & Cyclic Memory Leak
- **Files**: `src/loop/scheduling/io/main.zig:299-306`
- **Lessons**: [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md), [Defensive Programming §Lesson 10](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/loop/scheduling/io/main.zig`, `BlockingTasksSet.traverse` iterates over in-flight blocking IO tasks to visit references for CPython's cyclic GC. The visit call for `cb.data.callback_ptr()` is nested inside `if (cb.data.module_ptr()) |mod|`. When blocking tasks have `module_ptr == null` (such as Future/Task wait tasks), `callback_ptr` is skipped.
- **Trigger**: In-flight IO operations awaiting callbacks without a `module_ptr` participating in cyclical references.
- **Consequences**: CPython cyclic GC cannot detect and collect cyclic references during pending blocking IO operations.
- **Fix**: Move `if (cb.data.callback_ptr())` outside the `module_ptr` block.
