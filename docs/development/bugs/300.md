# BUG-300 — Shutdown leak of `write_iovs_copy` via `cancel_all`

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Forgotten free (shutdown-path only)
- **Files**:
  - `src/loop/scheduling/io/main.zig:212-222` (`cancel_all`: set_cancelled + dispatch; no discard/deinit)
  - `src/loop/scheduling/io/main.zig:80-99` (`discard`/`deinit` are the ONLY free sites for `write_iovs_copy`)
  - `src/loop/scheduling/io/write.zig:134-142` (allocation site)
- **Lessons**: [Memory & Reference Counting §Lesson 18](../lessons/01-memory-and-reference-counting.md), [Event Loop Lifecycle §Lesson 56](../lessons/03-event-loop-lifecycle.md)
- **Description**: `cancel_all` hands the callback to the Soon queue (which consumes the reserved slot) but never releases the pool slot's heap payload; the subsequent `set.deinit()` destroys the pool node containing the slot without freeing the iovec array.
- **Trigger**: Any loop close with vectored writes still queued.
- **Consequences**: Orphaned heap allocations at shutdown (one per pending WriteV).
- **Fix (Proposed)**: Free `write_iovs_copy` in the cancellation branch (or route through `discard()` semantics).
