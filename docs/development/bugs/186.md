# BUG-186 — Double-close of socket file descriptors on connection_made exception in StreamServer, create_connection, and create_endpoint

- **Status**: 🔴 Open
- **Severity**: 🟠 High — File descriptor recycling hazards and race conditions
- **Files**: `src/transports/streamserver/main.zig:231-252`, `src/loop/python/io/client/create_connection.zig:848-862, 874-881`, `src/loop/python/io/datagram/create_endpoint.zig:263-264, 311-317`
- **Lessons**: [Lifecycle & Shutdown §Lesson 29](../lessons/029-lifecycle-and-shutdown.md), [Defensive Programming §Lesson 53](../lessons/053-defensive-programming.md)
- **Description**: In `StreamServer.accept_callback`, `create_connection`, and `create_datagram_endpoint`, an `errdefer _ = std.os.linux.close(fd)` is defined. When the transport struct is instantiated with `owns_fd = true`, it assumes ownership of `fd`. If a subsequent operation (such as `protocol.connection_made` or `server_ref._attach`) raises a Python exception, `defer py_decref(transport)` destroys the transport and closes `fd`. Then the function-level `errdefer` executes and closes `fd` a second time.
- **Trigger**: Any user protocol raising an unhandled exception in `connection_made()` or an error attaching to server ref.
- **Consequences**: Double close of file descriptors; in high-concurrency environments, this inadvertently closes a completely unrelated socket created concurrently on another thread.
- **Fix**: Clear the outer `errdefer` / set `owns_fd = false` on the stack guard immediately once transport ownership is transferred.
