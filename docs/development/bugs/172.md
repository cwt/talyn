# BUG-172 — Memory and reference leaks on failure paths in `z_loop_add_hook` and `z_loop_add_path_watcher`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — resource & memory leak
- **Files**: `src/loop/python/control.zig:201-286`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/03-event-loop-lifecycle.md), [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/loop/python/control.zig`, `z_loop_add_hook` allocates a `HookHandle` object and increments `callback` with `py_newref`. If the subsequent `loop_data.add_hook` fails (e.g. OOM), the handle and callback were not cleaned up. Similarly, in `z_loop_add_path_watcher`, if `tp_alloc` fails after `loop_data.fs_watcher.add_watch`, the newly created inotify watch in the kernel was not removed.
- **Trigger**: Memory allocation failure when registering loop lifecycle hooks or filesystem path watchers.
- **Consequences**: Leaked heap memory, leaked Python callback references, and dangling kernel inotify watches.
- **Fix**: Added `errdefer` blocks in `z_loop_add_hook` (decreffing callback and freeing `handle`) and `z_loop_add_path_watcher` (removing watch via `remove_watch`).
