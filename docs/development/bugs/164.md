# BUG-164 — Tautological `ret >= 0` comparison on unsigned `usize` in `IO.wakeup_eventfd`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — silent deadlock & failure
- **Files**: `src/loop/scheduling/io/main.zig:699-707`
- **Lessons**: [Syscall Errno Decoding §Lesson 109](../lessons/04-io-uring-and-kernel.md), [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/loop/scheduling/io/main.zig`, `wakeup_eventfd` invokes `std.os.linux.write` to signal the eventfd and checks `if (ret >= 0) return;`. Because `ret` is of type `usize` (unsigned), `ret >= 0` is a tautology (always `true`). On syscall errors, Linux returns `~errno + 1` (a large unsigned value). The condition evaluates to true, so error recovery, `EINTR` retries, and error logging are completely dead code.
- **Trigger**: Any eventfd write returning `EINTR`, `EAGAIN`, or `EBADF`.
- **Consequences**: Cross-thread loop wakeups fail silently without retry, risking worker thread deadlocks.
- **Fix**: Replace `if (ret >= 0)` with proper errno decoding via `const err = utils.getSyscallErrno(ret); if (err == .SUCCESS) return; if (err == .INTR) continue;`.
