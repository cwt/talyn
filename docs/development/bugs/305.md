# BUG-305 — Free-threaded builds skip `release_python_imports()` at module cleanup

- **Status**: 🟢 Fixed (2026-08-27)
- **Severity**: 🟢 Medium-Low — Refcount leak scoped to extension unload / subinterpreter restart cycles under free-threading
- **Files**:
  - `src/lib.zig` (`module_cleanup`: release now unconditional; type poisoning stays single-threaded-only)
  - `src/utils/python_imports.zig` (`release_python_imports` — swap-extract for race-safe exactly-once decref)
- **Lessons**: [Memory & Reference Counting](../lessons/01-memory-and-reference-counting.md), [Concurrency & Thread Safety](../lessons/02-concurrency-and-thread-safety.md)
- **Description**: `module_cleanup` guarded ALL teardown with `if (builtin.single_threaded)`. In free-threaded mode neither `deinitialize_talyn_types()` nor `release_python_imports()` ran, so every entry of the ~25-slot `Atomic(?PyObject)` cache retained its owned reference until process exit.
- **Not covered by**: BUG-106 fixed read-side thread-safety via atomics; BUG-154 fixed uninitialized storage on partial init failure. Neither addressed skipping teardown itself.
- **Root cause re-analysis**: the historical skip comment ("teardown segfaults from GC/refcounting race conditions") traced back to the BUG-41-era double-decref of static type objects, which BUG-41 already removed. Plain `Py_DecRef` of imported modules carries no such hazard: CPython's free-threaded runtime supports concurrent reference counting natively, and interpreter finalization reaches module dealloc after world threads are joined.
- **Fix (Applied — 2026-08-27)**:
  - `src/lib.zig`: call `utils.PythonImports.release_python_imports()` unconditionally in `module_cleanup`, keeping only `deinitialize_talyn_types()` gated on single-threaded mode — that function poisons live type-object pointers (`ptr.* = undefined`), which under free-threading could race a straggler reader; it is defensive-only and reclaims no memory, so skipping it costs nothing.
  - `src/utils/python_imports.zig`: rewritten with `field.swap(null, .acq_rel)` instead of load→store so exactly one thread receives each cached reference (double-decref-proof if cleanup ever races or reenters). Optional pointers have plain word ABI, making the swap a single-word atomic exchange.
- **Residual (documented, out of scope)**: repeated `PyInit_talyn_zig` while cache slots are still non-null overwrites them without releasing (stale refs orphaned). Consumers do not reload C extensions today; revisit alongside subinterpreter support.
- **Regression test**: `tests/test_module_cleanup.py::test_bug305_repeated_load_unload_does_not_leak_cached_imports` — subprocess performs 8 import→full-unload→re-import cycles and asserts `sys.getrefcount(asyncio)` shows no positive drift; the same subprocess also exercises the fixed `m_free` path (any reintroduced teardown crash fails the exit-code check). Verified drift-free on python3.13, 3.14, 3.13t, 3.14t; full suite green via `test_all.sh --starburst --verbose` (339 passed / variant + stdlib asyncio suites + zig unit tests).
- **Validation**: `zig fmt` clean; `zig build lint` 0 violations (104 Zig files).
