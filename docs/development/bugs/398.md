# BUG-398 — `register_asyncio_task()` never invokes pure-Python task registry when C accelerator is absent

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — `asyncio.all_tasks()` and `asyncio.current_task()` do not see talyn tasks under free-threaded builds that use pure-Python task registries
- **Category**: Missing Feature Path / Logic Bug
- **Files**:
  - `src/utils/python_imports.zig:55-77`
- **Related**: [BUG-268](268.md), [BUG-373](373.md)

## Overview

`register_asyncio_task()` (`src/utils/python_imports.zig:55`) registers a talyn task in both asyncio's C accelerator registry (`_register_task`) and the pure-Python registry (`_py_register_task` / `_py_enter_task` / `_py_leave_task`). The C registry path is correct:

```zig
if (register_task_func.load(.acquire)) |func| {
    ...
}
```

But the pure-Python path is nested inside a condition that re-checks `register_task_func`:

```zig
if (py_register_task_func.load(.acquire)) |func| {
    if (register_task_func.load(.acquire)) |cfunc| {   // BUG: requires C accelerator present
        if (cfunc != func) {
            python_c.PyObject_CallOneArg(func, task);   // only called if both exist AND differ
        }
    }
    // MISSING: else branch — when only py_register_task_func exists, it is NEVER called
}
```

When `register_task_func` is null (C accelerator unavailable) but `py_register_task_func` is present, the inner `if` never executes and `py_register_task_func` is never invoked. This is exactly the scenario under Python free-threading builds that switch asyncio to its pure-Python `_current_tasks` / `_scheduled_tasks` registries — talyn tasks become invisible to `asyncio.all_tasks()` and `asyncio.current_task()`.

## Trigger Scenario

1. Run Talyn under a free-threaded Python build (`python3.13t` / `python3.14t`) where asyncio switches to the pure-Python `_current_tasks` registry (`_py_register_task` exists, `_register_task` does not).
2. Create tasks via `loop.create_task()` / `asyncio.create_task()`.
3. Call `asyncio.all_tasks(loop)` — talyn tasks are absent; `asyncio.current_task()` returns the wrong task or null.

## Proposed Remediation

Add an `else` branch to the `if (register_task_func.load(.acquire)) |cfunc|` check that calls `py_register_task_func` when `register_task_func` is null, mirroring the same owned-reference cleanup (`py_decref(ret)` / `PyErr_Clear()`) as the both-exist case.

## Resolution

Added the missing `else` branch to `register_asyncio_task()` in `src/utils/python_imports.zig`:

```zig
if (py_register_task_func.load(.acquire)) |func| {
    if (register_task_func.load(.acquire)) |cfunc| {
        if (cfunc != func) {
            if (python_c.PyObject_CallOneArg(func, task)) |ret| {
                python_c.py_decref(ret);
            } else {
                python_c.PyErr_Clear();
            }
        }
    } else {
        // Only the pure-Python registry exists (no C accelerator) —
        // register the task there so asyncio.all_tasks() sees it.
        if (python_c.PyObject_CallOneArg(func, task)) |ret| {
            python_c.py_decref(ret);
        } else {
            python_c.PyErr_Clear();
        }
    }
}
```

Builds and tests verified passing under:
- `ReleaseFast` (Starburst) / Zig 0.16.0
- `ReleaseSafe` / Zig 0.16.0
- `Debug` / Zig 0.16.0
- `ReleaseFast` / Zig 0.17.0
- `zig build lint` — 0 violations
