# BUG-212 — Out-of-Bounds Uninitialized Read and Dropped Addresses in interleave_address_list

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — Out-of-Bounds Memory Read & Logic Bug
- **Files**: `src/loop/python/io/client/create_connection.zig:425-439`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Defensive Programming §Lesson 49](../lessons/049-uninitialized-struct-fields.md), [BUG-072](072.md)
- **Description**: In `src/loop/python/io/client/create_connection.zig`, `interleave_address_list` interleaves IPv4 and IPv6 addresses for Happy Eyeballs connections. The loop checks `if (interleave_count == 0 or ipv6_index >= ipv6_addresses)` and assigns `v.* = tmp_list[ipv4_index]`. If `ipv4_addresses` runs out before `address_list` is fully processed (e.g. 1 IPv4 and 3 IPv6 addresses), once `interleave_count == 0` is reached, it accesses `tmp_list[ipv4_index]` where `ipv4_index >= ipv4_addresses`. This reads uninitialized garbage memory from `tmp_list` and drops the remaining valid IPv6 addresses from the connection candidate list.
- **Trigger**: Resolving dual-stack hosts where the count of IPv4 and IPv6 addresses differ.
- **Consequences**: Connecting to corrupt/garbage IP addresses and omitting valid resolved endpoints.
- **Fix**: Guard IPv4 selection with `and ipv4_index < ipv4_addresses` and fallback to remaining IPv6 addresses when IPv4 addresses are exhausted.
