# BUG-335 — `Read.perform` zero-copy `.iovecs` branch staged a kernel-dereferenced pointer at caller-owned memory (latent BUG-30/BUG-334 class)

- **Status**: ✅ Fixed (2026-09-26) — latent hazard eliminated *before* its first caller existed
- **Severity**: 🟡 Medium — zero current production impact (the branch was unreachable), but a live BUG-30/BUG-334-class trap for the first future caller
- **Files**:
  - `src/loop/scheduling/io/read.zig:88-101` (zero-copy branch collapses to `error.NotImplemented` for `.buffer_selection`/`.iovecs`)
  - `src/loop/scheduling/io/read.zig:110-125` (structural tripwire test)
  - `tools/linter/rules/sqe_pointer_lifetime.zig` (new rule **TALYN-015**)
  - `src/loop/main.zig` (BUG-334 test: baseline `active_tasks` + per-case SQE-tail rollback so it runs green on Linux)
- **Related**: [BUG-334](334.md) (same class, same sites, fixed 2026-09-25), [BUG-30](030.md) (iovec lifetime rule), [Lesson 61](../lessons/04-io-uring-and-kernel.md)
- **Discovered by**: Deep audit of every `ring.*` SQE-prep call site for the Lesson 60/61 class after accepting BUG-334.

## Nature of the finding

A full inventory of every SQE-producing `ring.*` call (timeout, link_timeout, connect, accept, recvmsg, sendmsg, read, write, read_fixed, poll_add, shutdown, cancel, timeout_remove) traced each kernel-dereferenced pointer (`sqe.addr`/`sqe.__pad2`) to its owner, checked against the deferral window (`queue_unlocked` defers submission until a cancel or a near-full SQ — pointer targets must be valid until *submit*, not merely until return). All reachable sites resolve to BlockingTask-owned, transport-owned, or loop-resident storage. The only hazard left was `Read.perform`'s zero-copy `.iovecs` branch:

```zig
// WRONG — msg_storage.iov aliases the caller's array; the kernel reads
// it at submit time, which is deferred past this frame.
.iovecs => |iovecs| {
    data_ptr.msg_storage.iov = @constCast(iovecs.ptr);
    data_ptr.msg_storage.iovlen = @intCast(iovecs.len);
    ...
}
const sqe = try ring.recvmsg(..., &data_ptr.msg_storage, std.posix.MSG.ZEROCOPY);
```

Three independent reasons the branch was wrong:
1. **Lifetime**: `msg_storage` is correctly heap-resident, but `.iov` pointed at the *caller's* array — the exact pre-fix BUG-30 pattern that `Write.perform_with_iovecs` already fixes by copying. If a future caller passed a stack iovec array, the kernel would arm the SQE from reclaimed stack bytes (BUG-334 symptoms: timeout/no-completion or instant completion).
2. **Semantics**: `MSG.ZEROCOPY` is a transmit-only flag; io_uring has no zero-copy receive. A zero-copy *read* through `recvmsg` was meaningless.
3. **Reachability**: every `PerformRead` caller passes `.buffer` (DNS `recv_buf`, transports, eventfd, signalfd); `.buffer_selection` was already `error.NotImplemented`. The `.iovecs` arm was unreachable dead code.

## Fix

Both non-`.buffer` selectors now reject instead of staging unsound kernel pointers:

```zig
if (data.zero_copy) {
    // BUG-335: io_uring has no zero-copy receive (MSG.ZEROCOPY is
    // transmit-only), and this branch used to point msg_storage.iov
    // at the caller's — possibly stack-allocated — iovec array...
    switch (data.data) {
        .buffer_selection, .iovecs => return error.NotImplemented,
        .buffer => {},
    }
}
const sqe = try ring.read(@intCast(@intFromPtr(data_ptr)), fd_arg, data.data, data.offset);
```

`zero_copy = true` with `.buffer` behaves exactly as before (`ring.read`); `BlockingTask.msg_storage` remains in use by the sound write paths (`Write.perform` zero-copy, `Write.perform_with_iovecs`).

## Regression tripwire

`src/loop/scheduling/io/read.zig` carries a BUG-306-style structural test: the read path must never contain `data_ptr.msg_storage` (needle split at compile time so the test's own source cannot satisfy it). Any reintroduction of task-staged kernel pointers from caller arrays on the read side fails `zig build test`.

## Static detection — new rule TALYN-015 (`SQE_POINTER_LIFETIME`)

The AST linter now detects the *class*, not just this instance. `tools/linter/rules/sqe_pointer_lifetime.zig` scans `src/loop/scheduling/io/*.zig` (the only place direct `ring.*` prep calls live) and flags pointer-position arguments (per-op positions: `link_timeout`/`timeout` ts=1, `connect` addr=2, `accept` addr/addrlen=2/3, `recvmsg`/`sendmsg` msghdr=2, `read`/`write` buffer=2, `read_fixed`/`write_fixed` iov=2, plus `send_zc`/`openat`/`statx` for future sites) that are:

1. `&<by-value-param>...` — address of the callee's stack copy;
2. `&<capture>...` — address of a stack capture copy;
3. bare `<capture>...` whose controlling expression roots in a by-value parameter — the exact BUG-334 shape (`if (data.timeout) |*timeout| ... ring.link_timeout(0, timeout, 0)`);
4. `&<local>...` where the local's initializer is not provably heap/pool-resident (no `set`/`self`/`loop`/`io`-rooted target and no `push`/`create`/`alloc`/`dupe`/`.empty` construction).

Validated against the historical BUG-334 pattern (flags all five original sites' shape) and against every safe pattern in the current tree (flags nothing; `zig build lint` stays at 0 violations, 131ms). Documented limitations: bare pointer-valued parameter fields (`data.msg`, `data.addr`) are pre-existing pointers to caller-owned heap structs, enforced by the BlockingTask/cleanup conventions and review rather than statically; by-value `ReadBuffer` arguments hide their inner pointer from the AST and are covered by the transport lifetime rules.
