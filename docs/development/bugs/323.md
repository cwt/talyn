# BUG-323 — Dead & broken completion dispatch methods in Python event loop

- **Status**: 🟢 Fixed (2026-09-07)
- **Severity**: 🟢 Low — Dead code and type-confusion segfault hazard in unused Python completion dispatch methods
- **Files**:
  - `talyn/loop.py` (lines 349–385)
- **Lessons**: [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md), [Event Loop Lifecycle](../lessons/03-event-loop-lifecycle.md)
- **Description**:
In `talyn/loop.py`:
Methods `_dispatch_completions`, `_dispatch_completions_with_list`, and `_test_batch_dispatch` are never called anywhere in the codebase.
In `_dispatch_completions`:
```python
completions = self._loop.get_completions()
for completion in completions:
    completion.handle()
```
`get_completions()` returns raw integer memory addresses. Calling `.handle()` on an integer causes an immediate `AttributeError` or segfault if cast as PyObject.
- **Root Cause**: Abandoned prototype methods left in the Python wrapper.
- **Trigger Scenario**: Calling private methods `_dispatch_completions` or `_test_batch_dispatch`.
- **Proposed Remediation**: Remove the obsolete methods.

- **Fix (Applied — 2026-09-07)**:
  - Removed the three obsolete prototype methods `_dispatch_completions`, `_test_batch_dispatch`, and `_dispatch_completions_with_list` from `talyn/loop.py` (never called anywhere). The `_ctypes`/`ctypes`/`struct` imports existed solely for that dead code and were removed with it.
  - The four `_dispatch_*` handlers they would have fed are KEPT — they are the actual dispatch surface a future P15 batch engine calls, and they are exercised directly by the BUG-321 regression test. The header comment was updated accordingly.
  - Validation-drift note: the segfault hazard described in the original report (`get_completions()` returning raw integer addresses + `completion.handle()`) no longer existed at validation time — `_dispatch_completions` had been rewritten to ctypes `CompletionRecord` parsing during P15. The dead-code claim was the surviving defect.
- **Regression test**: covered by the existing suite (removal-only change; `grep` confirms zero references to the removed methods).
- **Validation (2026-09-07)**: Partially valid — the dead-code claim stands; the segfault-hazard claim was stale. Status kept Open (dead code remains).
  - Confirmed: `_dispatch_completions`, `_test_batch_dispatch`, and `_dispatch_completions_with_list` (`talyn/loop.py:349-404`) exist and are never called anywhere in the codebase.
  - Stale: the quoted `get_completions()` / `completion.handle()` type-confusion code no longer exists. `_dispatch_completions` was rewritten (P15 Phase 1) to parse raw `CompletionRecord` structs via `ctypes.string_at` / `struct.unpack_from` (`talyn/loop.py:349-381`), and retention is documented in the header comment at `talyn/loop.py:342-347` ("Currently unused (batch always empty) — infrastructure in place for future optimization").
