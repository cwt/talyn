# BUG-134 — NULL pointer passed to `PyObject_CallOneArg` in `cancel_future_waiter`

- **Status**: ✅ Fixed
- **Severity**: 🔴 Critical — interpreter crash / null pointer dereference on task cancellation
- **Files**: `src/task/cancel.zig:28-30`
- **Lessons**: [Python C API §Lesson 54](../lessons/05-python-c-api-correctness.md), [Python C API §Lesson 55](../lessons/05-python-c-api-correctness.md)
- **Description**: In `cancel_future_waiter`, when a Task is awaiting a foreign/legacy Future and `task.cancel()` is called without a message (`cancel_msg_py_object == null`), the code invokes:
  ```zig
  const ret: PyObject = python_c.PyObject_CallOneArg(cancel_function, cancel_msg_py_object) orelse return error.PythonError;
  ```
  Passing `NULL` as the second argument causes CPython vectorcall internals to dereference a null pointer during argument processing.
- **Trigger**: Calling `task.cancel()` (no `msg` argument) on a Task awaiting a standard `asyncio.Future` or foreign future.
- **Consequences**: Immediate segmentation fault / interpreter crash.
- **Fix**: Updated `cancel_future_waiter` in `src/task/cancel.zig` to use `PyObject_CallNoArgs(cancel_function)` when `cancel_msg_py_object` is null, avoiding passing a NULL pointer.
