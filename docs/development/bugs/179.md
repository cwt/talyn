# BUG-179 — Truncated IPv6 reverse DNS return slice in build_reverse_name

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Protocol logic defect breaking all IPv6 reverse DNS lookups
- **Files**: `src/loop/dns/parsers.zig:55-67`
- **Lessons**: [Network Protocols §Lesson 47](../lessons/047-network-protocols.md)
- **Description**: In `src/loop/dns/parsers.zig`, `build_reverse_name` handles `AF.INET6` by formatting 32 hex nibbles separated by dots into `buf[0..64]`. The final line executes `return try std.fmt.bufPrint(buf[offset..], "ip6.arpa", .{})`. Because `bufPrint` returns only the subslice written during that specific call (`buf[offset .. offset + 8]`), the function returns `"ip6.arpa"` instead of `"<nibbles>.ip6.arpa"`.
- **Trigger**: Any reverse DNS lookup (`getnameinfo` or `reverse_lookup`) on an IPv6 address.
- **Consequences**: All IPv6 reverse DNS queries look up `"ip6.arpa"` at the DNS root/TLD level rather than the client's actual PTR record.
- **Fix**: Suffix `offset += (try std.fmt.bufPrint(buf[offset..], "ip6.arpa", .{})).len;` and return `buf[0..offset]`.
