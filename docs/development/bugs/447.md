# BUG-447 — App `sock.close()` leaves `transport.fd` stale (double-close mirror)

- **Status**: 🟡 Open
- **Severity**: 🟠 High — double-close of a possibly-reused descriptor number
- **Category**: fd ownership / socket lifetime
- **Files**: `src/utils/pseudosocket.zig:90-99`, `src/transports/stream/extra_info.zig:19-21`, `src/transports/stream/lifecycle.zig:297-299`
- **Related**: [BUG-427](427.md) (the mirror direction), [BUG-291](291.md), [BUG-110](110.md)

## Description

`get_extra_info('socket')` wraps the transport's raw fd in a `PseudoSocket` **without** `dup`
(`extra_info.zig:19-21`) and caches it (`self.socket`). When the application closes that socket,
`pseudosocket_close` (`pseudosocket.zig:90-99`) closes `instance.fd` and sets it to `-1` — but the
transport's own `fd` field is untouched. The transport later tears down
(`cancel_and_close_fd`, `lifecycle.zig:297-299`: `if (self.owns_fd) _ = std.os.linux.close(fd);`,
`owns_fd` defaults true) and closes the **same descriptor number again** — by then it may have been
reassigned by `open()`/`accept()` to an unrelated socket or file.

## Trigger

`transport.get_extra_info('socket')` → app calls `sock.close()` → transport later closes (connection
end, `abort()`, server close).

## Consequences

Same failure class as BUG-427, mirrored direction: closing an unrelated, reused fd → protocol
corruption / hangs. (BUG-291 made the pseudo-socket's *own* close idempotent, but neither side knows
about the other's close.)

## Fix

`dup` the fd for the pseudo-socket so each side owns its own descriptor (this also fixes BUG-427), or
share one closed-state flag: invalidate the transport's fd (set `owns_fd = false` / `fd = -1`) when the
pseudo-socket closes, and mark the pseudo-socket closed when the transport tears down.
