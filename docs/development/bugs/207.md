# BUG-207 — PyObject Reference and Struct Leak on Error Path in z_loop_create_server

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — Refcount & Resource Leak
- **Files**: `src/loop/python/io/server/create_server.zig:126-190`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [BUG-203](203.md)
- **Description**: In `src/loop/python/io/server/create_server.zig`, `creation_data_ptr` is allocated on the heap and protected with `errdefer allocator.destroy(creation_data_ptr)`. If any subsequent step fails (such as address parsing, `getsockname`, `fileno` extraction, or `server_data` allocation), `allocator.destroy(creation_data_ptr)` frees the heap allocation directly without calling `creation_data_ptr.deinit()`.
- **Trigger**: An error occurring during `z_loop_create_server` after `creation_data_ptr` is populated (e.g. invalid host/port, address lookup failure, socket error).
- **Consequences**: Leaked PyObject references for `py_sock`, `py_family`, `py_flags`, `loop`, `future`, `protocol_factory`, `py_backlog`, etc.
- **Fix**: Change `errdefer allocator.destroy(creation_data_ptr);` to `errdefer creation_data_ptr.deinit();`.
