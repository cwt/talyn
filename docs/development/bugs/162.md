# BUG-162 — PyObject reference leak on every batch protocol read in `dispatch_completion_batch`

- **Status**: ✅ Fixed
- **Severity**: 🔴 Critical — memory/refcount leak per packet
- **Files**: `src/loop/runner.zig:158-170`
- **Lessons**: [Python C API Integration §Lesson 10](../lessons/05-python-c-api-correctness.md), [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/loop/runner.zig`, `dispatch_completion_batch` dispatches batched I/O completions directly to Python protocol callbacks (`protocol_data_received` or `protocol_buffer_updated`). Both call sites use `if (python_c.PyObject_CallOneArg(...) == null)` and completely discard non-null return values (`Py_None`) without calling `python_c.py_decref()`.
- **Trigger**: Any I/O read data dispatched through the batch completion loop.
- **Consequences**: Continuous monotonic reference count leak on every received packet or buffer update, causing memory bloat and eventual process exhaustion under high-throughput network streaming.
- **Fix**: Capture the `PyObject*` result of `PyObject_CallOneArg` and call `python_c.py_decref(ret)` on the non-null success branch.
