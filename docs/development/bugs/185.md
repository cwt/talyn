# BUG-185 — Kernel -EINVAL from unnormalized nanoseconds in loop.call_later

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Sporadic timer failures and broken event scheduling
- **Files**: `src/loop/python/scheduling.zig:196-204`
- **Lessons**: [io_uring Safety & Directives §Lesson 17](../lessons/017-io-uring-safety-and-directives.md)
- **Description**: In `src/loop/python/scheduling.zig`, `z_loop_delayed_call` converts a floating-point delay into an absolute monotonic `timespec`:
  ```zig
  time.sec += @intFromFloat(delay_sec);
  time.nsec += @as(@FieldType(std.posix.timespec, "nsec"), @intFromFloat((ts - delay_sec) * 1_000_000_000));
  ```
  `time.nsec` is added to `raw_ts.nsec` without a normalization step. When the sum equals or exceeds 1,000,000,000 nanoseconds, `time.nsec >= 1_000_000_000`. The Linux kernel strictly enforces `tv_nsec < 1_000_000_000` in `io_uring_prep_timeout` and rejects the timer submission with `-EINVAL`.
- **Trigger**: Any `loop.call_later(delay, cb)` call where `current_nsec + delay_nsec >= 1_000_000_000`.
- **Consequences**: Uncaught `-EINVAL` from io_uring; timers fail to schedule and callbacks are never called or raise an unexpected error.
- **Fix**: Normalize `time.nsec` by carrying overflow into `time.sec`:
  ```zig
  if (time.nsec >= 1_000_000_000) {
      time.sec += @intCast(time.nsec / 1_000_000_000);
      time.nsec = @intCast(time.nsec % 1_000_000_000);
  }
  ```
