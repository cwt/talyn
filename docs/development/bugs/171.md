# BUG-171 — Missing port bounds check causing integer overflow panic in `Address.fromPyAddr`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — integer overflow panic
- **Files**: `src/utils/address.zig:325-332`
- **Lessons**: [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/utils/address.zig`, `Address.fromPyAddr` parses port integers using `const port_val = python_c.PyLong_AsInt(py_port);`. The code only checked `if (port_val == -1 and python_c.PyErr_Occurred() != null) return error.PythonError;` and immediately called `const port: u16 = @intCast(port_val);`. If `port_val` was negative (e.g. `-2`) or greater than 65535, `@intCast` panicked in Debug/ReleaseSafe or truncated in ReleaseFast.
- **Trigger**: Passing an out-of-range port number (e.g. `-5` or `70000`) to address resolution or socket creation methods.
- **Consequences**: Process crash or silent port truncation to invalid endpoints.
- **Fix**: Added explicit validation checking `0 <= port_val and port_val <= 65535` raising `OverflowError` on violation prior to casting.
