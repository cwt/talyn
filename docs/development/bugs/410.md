# BUG-410 — 10 ms idle poll quantum

- **Status**: 🔴 Open (confirmed, unfixed)
- **Severity**: 🟠 High — latency regression on every idle-to-active transition; 100 wakeups/s while idle
- **Category**: Event Loop Performance / Scheduling
- **Files**:
  - `src/loop/runner.zig:338-396` — `poll_blocking_events`
  - `src/loop/scheduling/io/main.zig:865-875` — `wakeup_eventfd`
  - `src/loop/scheduling/soon.zig:9-11` — wakeup on blocking dispatch
- **Related**: [BUG-399](399.md) (blocking wait/watchdog)

## Overview

```zig
if (should_wait and ready_queue.is_empty()) {
    @atomicStore(... ring_blocked = 1 ...);
    mutex.unlock();
    defer { mutex.lock(); ring_blocked = 0; }

    const py_thread_state = PyEval_SaveThread();
    _ = self.io.ring.submit() catch ...;
    const sleep_ts = std.os.linux.timespec{ .sec = 0, .nsec = 10_000_000 };
    _ = std.os.linux.nanosleep(&sleep_ts, null);
    PyEval_RestoreThread(py_thread_state);
    ...
    nevents = try copy_cqes_eintr_safe(...);
}
```

`ring.submit()` does not wait for completions. The loop then sleeps 10 ms, restores the GIL, and only then copies CQEs. Any completion that lands during the sleep (socket read, timer, signalfd, eventfd wakeup) is delayed by up to 10 ms. The loop also wakes 100 times per second with no work. `wakeup_eventfd()` sets `ring_blocked` and writes to the eventfd, but that cannot interrupt the `nanosleep`; the eventfd read completion is only copied after the sleep returns.

## Trigger Scenario and Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, ReleaseFast, Python 3.13.16 and 3.13.16t.

Repro: `o1_timer_latency.py` — `await asyncio.sleep(0.001)` repeatedly on an idle loop.

ReleaseFast / 3.13 (GIL):

```text
sleep(1ms) samples: [10.94, 10.98, 11.61, 11.19, 12.31, 15.32, 33.56, 18.54]
median=11.96 ms
RESULT: FAIL (10ms poll quantum visible)
```

ReleaseFast / 3.13t: median `12.46 ms`.

## Proposed Remediation

Replace the sleep with a real wait:

- Use `io_uring_enter` with a timeout (`submit_and_wait`/`submit_and_wait_timeout`) or a blocking `copy_cqes` variant, and handle `EINTR`/signals as BUG-399 does.
- Keep `ring_blocked`/eventfd for cross-thread wakeups, and treat the eventfd read completion as the wake source instead of polling.
- Only fall back to a short sleep when no SQEs are pending and no wake source exists (or remove it entirely).

Add a latency regression test asserting a 1 ms timer completes well below the 10 ms quantum (for example `< 3 ms`).
