# BUG-379 — `WriteTransport` flow-control and `write_eof` bugs: `writing_low_water_mark` ignored until buffer hits 0, `write_eof()` silently dropped when `buffer_size > 0`, and `set_write_buffer_limits` rejects `None` and leaks positional refs

- **Status**: 🔴 Open
- **Severity**: 🔴 High — breaks `asyncio.WriteTransport.write_eof()` whenever called after `transport.write()` (since writes are buffered until `.prepare`), disables `writing_low_water_mark` during multi-buffer draining, and breaks `set_write_buffer_limits(high=None, low=None)`
- **Category**: Logic Bug & Reference Leak
- **Files**:
  - `src/transports/write_transport.zig:332-375, 409-415`
  - `src/transports/stream/write.zig:15-37, 78-124, 142, 177`
- **Related**: [Lesson 55](../lessons/06-network-protocols-and-io.md)

## Overview & Root Cause

1. **`WriteTransport.queue_eof` silently drops `write_eof()` whenever `self.buffer_size > 0` (`src/transports/write_transport.zig:409-415`)**:
   ```zig
   pub fn queue_eof(self: *WriteTransport) !void {
       if (self.buffer_size > 0) return;

       try self.close();

       _ = try self.loop.io.queue(.{ .SocketShutdown = .{ .socket_fd = self.fd, .how = std.os.linux.SHUT.WR } });
   }
   ```
   Because `WriteTransport` batches all `transport.write(data)` calls into `pending_buffers` and only submits them in the `.prepare` hook (`flush_buffered_writes`), calling:
   ```python
   transport.write(b"request")
   transport.write_eof()
   ```
   **always** finds `self.buffer_size > 0`! `queue_eof` executes `if (self.buffer_size > 0) return;` without setting any `eof_pending` flag, so `SHUT_WR` (`FIN`) is **never sent** after the buffer flushes!
   And when `self.buffer_size == 0` and `read_transport.closed` is already `true` (e.g. peer already sent EOF and `eof_received()` returned `True`), `try self.close()` at line 412 calls `maybe_close_fd` which **closes `self.fd`** before line 414 queues `.SocketShutdown = .{ .socket_fd = self.fd }` on the just-closed `fd`!

2. **`writing_low_water_mark` is ignored during multi-chunk draining (`src/transports/write_transport.zig:332-375`)**:
   ```zig
   if (!self.closed and self.buffer_size > 0) {
       try self.submit_next_chunk();
       success = true;
   } else if (self.closed) {
       success = true;
   } else if (self.buffer_size == 0) {
       ...
       _ = self.write_completed_callback(self, bw, 0, .SUCCESS) catch |err| { ... };
       success = true;
   }
   ```
   When multiple buffers are queued (or a partial write occurs), `self.write_completed_callback` (`Stream.Write.write_operation_completed`) is **not called** in the `self.buffer_size > 0` branch — it is only called when `self.buffer_size == 0` (passing `remaining_data = 0`)!
   Thus `Stream.Write.write_operation_completed` (`src/transports/stream/write.zig:27-36`), which checks `if (remaining_data <= instance.writing_low_water_mark)` to call `protocol.resume_writing()`, never sees intermediate `self.buffer_size` values and delays `resume_writing()` until the write buffer is completely empty (`0` bytes).

3. **`z_transport_set_write_buffer_limits` bugs (`src/transports/stream/write.zig:78-124, 142, 177`)**:
   ```zig
   if (args.len >= 1) {
       py_high_water_mark = python_c.py_newref(args[0].?);
   }
   if (args.len == 2) {
       py_low_water_mark = python_c.py_newref(args[1].?);
   }
   try python_c.parse_vector_call_kwargs(knames, args.ptr + args.len, &.{ "high\x00", "low\x00" }, &.{ &py_high_water_mark, &py_low_water_mark });
   ```
   - **Rejects `None`**: Standard `asyncio` signature is `set_write_buffer_limits(high=None, low=None)`. Passing `None` calls `PyLong_AsUnsignedLongLong(Py_None)` at line 104 / 114, raising `TypeError: an integer is required`!
   - **Reference leak**: If a positional argument is passed and `parse_vector_call_kwargs` either fails or overwrites `py_high_water_mark` / `py_low_water_mark` with a keyword argument, the `py_newref` from lines 88/92 is leaked.
   - **Wrong default `low` and validation**: In `asyncio`, if `high` is given and `low` is `None`, `low` must default to `high // 4` (not `min(high, 32768)`), and passing `low > high` or negative values must raise `ValueError` (instead of silently clamping `low` or raising `OverflowError` from `PyLong_AsUnsignedLongLong`).
   - **Does not check `>` vs `>=` on `high == 0` or re-evaluate watermarks**: In `transport_write` (line 142) and `transport_write_lines` (line 177), `if (new_buffer_size >= instance.writing_high_water_mark)` pauses writing on an empty buffer (`new_buffer_size == 0`) when `high == 0` (standard `asyncio` uses `buffer_size > high`), and `set_write_buffer_limits` does not call `pause_writing()`/`resume_writing()` when the new limits cross the current `buffer_size`.

## Trigger Scenario

1. Call `transport.write(b"hello"); transport.write_eof()` -> `write_eof()` is silently ignored because `buffer_size == 5 > 0`.
2. Call `transport.set_write_buffer_limits(high=None, low=None)` -> raises `TypeError: an integer is required`.

## Proposed Remediation

1. Add an `eof_pending: bool = false` field to `WriteTransport`: if `queue_eof` is called while `self.buffer_size > 0` or `self.write_in_flight`, set `self.eof_pending = true` and submit `.SocketShutdown` in `write_operation_completed` once `self.buffer_size == 0` (before calling `self.close()`).
2. Invoke `self.write_completed_callback(self, written, self.buffer_size, .SUCCESS)` in `write_operation_completed` before `submit_next_chunk()` whenever `!instance.is_writing and self.buffer_size <= instance.writing_low_water_mark`.
3. In `z_transport_set_write_buffer_limits`, treat `Py_None` as omitted, raise `ValueError` on negative values or `low > high`, default `low = high / 4`, use `>` instead of `>=` for `writing_high_water_mark`, and re-check `buffer_size` against the updated watermarks.
