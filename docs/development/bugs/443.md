# BUG-443 — `MultiConnectState.init` OOM leak

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — one-struct leak on OOM
- **Category**: Error path / allocation
- **Files**: `src/loop/python/io/client/create_connection/types.zig:183-194`
- **Related**: [BUG-88](088.md), [BUG-77](077.md)

## Description

```zig
const self = try allocator.create(MultiConnectState);
self.* = .{ ... };
if (all_errors) {
    self.exceptions = python_c.PyList_New(0) orelse return error.PythonError;   // self leaked
}
return self;
```

On `PyList_New` failure the freshly allocated `self` is not destroyed.

## Fix

`errdefer allocator.destroy(self);` immediately after `create`.

## Resolution (2026-11-12)

`MultiConnectState.init` now arms `errdefer allocator.destroy(self);` immediately after the
`allocator.create`. On `PyList_New` failure the struct is destroyed on the error return; on the
success path the errdefer is discarded and ownership transfers to the caller as before. The payload
stores only borrowed pointers and `exceptions` is still null in this window, so destroying the
struct is the complete cleanup.

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (498 pytest passed on
py3.15, 497 + 1 skipped on py3.15t; stdlib asyncio green on both).
