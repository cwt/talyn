# BUG-437 — `getsockopt` int-vs-bytes keyed off the wrong condition

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — API shape mismatch
- **Category**: API compatibility
- **Files**: `src/utils/pseudosocket.zig:193-212`
- **Related**: [BUG-264](264.md), [BUG-262](262.md)

## Description

```zig
var buflen: std.c.socklen_t = 256;
if (argc >= 3) { ... buflen = @intCast(bl); }
const rc = getsockopt(...);
if (buflen == 4) {
    return python_c.PyLong_FromLong(@intCast(int_val));   // int form
}
return python_c.PyBytes_FromStringAndSize(...);
```

CPython's contract: `getsockopt(level, optname)` → int; `getsockopt(level, optname, buflen)` → `bytes`
of that length. The code keys off the post-call `buflen`, ignoring whether the length argument was
supplied, so `sock.getsockopt(SOL_SOCKET, SO_RCVBUF, 4)` returns an int instead of a 4-byte `bytes`.

## Fix

Remember whether the length argument was provided (`argc >= 3`) and only return the int form when it was
omitted.

## Resolution (2026-11-12)

`pseudosocket_getsockopt` now records whether the caller supplied the length argument
(`has_buflen = argc >= 3`) and returns the int form only when it was omitted; the bytes form is
returned whenever a length was passed, regardless of the post-call option size. CPython's contract
is restored: `getsockopt(level, optname)` → int, `getsockopt(level, optname, buflen)` → bytes.

Regression test added: `test_pseudosocket_getsockopt_buflen_returns_bytes` in
`tests/test_pseudosocket.py` (SO_TYPE as int without buflen; explicit `buflen=4` returns a 4-byte
bytes object).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (499 pytest passed on
py3.15, 498 + 1 skipped on py3.15t; stdlib asyncio green on both).
