# BUG-417 — reader-wake quantization (~100 µs) on sporadic single-byte fd reads

- **Status**: 🟡 Open
- **Severity**: ⚪ Low — fixed ~0.1 ms added to wake latency; invisible in throughput benchmarks, but a real *responsiveness floor* for the workload class talyn is positioned for (keypress → echo in editors/REPLs, single idle fd)
- **Category**: Latency / io_uring completion path (`add_reader` readers)
- **Files**: read scheduling (`src/loop/scheduling/io/read.zig`), Python watcher bridge (`src/loop/python/io/watchers.zig` — `loop_add_reader`)
- **Related**: [BUG-410](410.md) (fixed 10 ms idle `nanosleep` — the 100× bigger cousin, same symptom family), [BUG-418](418.md) (chained executor hand-off shows the same ≈ tick-shaped jitter — likely one root cause)

## Symptom

Writer thread writes **one byte** to a pipe every ≈1 ms; the reader fd is registered via `loop.add_reader` (Non-blocking read of 4096 B in the callback; latency = `perf_counter()` delta from right-before-`os.write` to callback handling the byte). Median-of-rounds across interleaved loop runs:

| Loop | best (min) µs | median µs |
|---|---:|---:|
| stdloop (Py 3.15.2) | 2.8 | 3.7 |
| uvloop 0.23.0 | 2.0 | 2.8 |
| **talyn 0.11.4** | **3.2** | **~100** ⚠️ |

talyn *can* wake as fast as the others (min ≈ 3.2 µs ⇒ the machinery supports it) — but most sporadic wakes land on what looks like a **fixed ≈100 µs quantum** in the completion path rather than waking promptly per CQE. The round-2 variation (this table) and a first-pass run (research at 153 µs median on stdloop between scheduler jitter noise; talyn ~10 µs on sparse 1 ms spacing, ~100 µs with 10-byte bursts at 0.4 ms spacing) both stabilize on the same signature: a bursty/idle-dependent tick, not a constant.

## Repro

```python
# loop_wake_probe.py — compare reader-wake per byte (pipe + add_reader)
import asyncio, os, statistics, threading, time

async def probe(n=300, gap=0.001):
    loop = asyncio.get_running_loop()
    rfd, wfd = os.pipe()
    os.set_blocking(rfd, False)
    lat, sent, state = [], [], {"i": 0}; done = asyncio.Event()

    def on_readable():
        data = os.read(rfd, 4096)
        for _ in data:
            state["i"] += 1
            lat.append((time.perf_counter() - sent[state["i"] - 1]) * 1e6)
        if state["i"] >= n:
            done.set()

    loop.add_reader(rfd, on_readable)
    def writer():
        for _ in range(n):
            sent.append(time.perf_counter()); os.write(wfd, b"x"); time.sleep(gap)
    t = threading.Thread(target=writer); t.start(); await done.wait()
    loop.remove_reader(rfd); t.join(); os.close(rfd), os.close(wfd)
    return min(lat), statistics.median(lat)

import talyn; talyn.install()
print(asyncio.run(probe()))   # talyn: (≈3.2 µs, ≈100 µs); stdloop/uvloop: (≈2-3 µs, ≈3 µs)
```

Same host/interpreter with talyn vs uvloop vs stdloop (medians of interleaved rounds): see table above.

## Hypotheses (falsified/implied by shape of the distribution)

The wide *median* with narrow *min* rules out constant syscall overhead — instead, sporadic completions frequently wait for a periodic boundary:

1. **Conservative wait timeout** on the reader path — e.g. `io_uring_wait_cqe_timeout` with a small fixed timeout instead of blocking-until-first-CQE; on timeout → drain periodically (≈ tick wake).
2. **Completion batching** — if completions from the write's SQE (or a related multishot operation) are coalesced/flushed by a snore flusher with a period around 100 µs, first-byte wakes ride the batch.
3. **Spin-then-sleep scheduler** — spinning window processes wakes at ~0–3 µs (the mins); after the spin window expires, waits until the next quantum (~100 µs).

BUG-410's fixed 10 ms idle `nanosleep` is now fixed, but this bug shows a ~100 µs sibling in the *reader* specifically. BUG-418's chained executor number (≈77 µs round-trip over 2 runs) is consistent with the same quantum being applied on the executor-charged wake → likely one root cause; fixing the completion-wake to honor first-CQE latency should collapse both.

## Fix direction

Make sporadic completion waits **block-until-CQE** (pu mean regain "wake minimum latency"): `io_uring_wait_cqetimeout` with the *next timer deadline as timeout* (or unbounded block when no timers pending) instead of a fixed small timeout; confirm there is no `getrandom`-periodic extra `io_uring_submit`/timeout re-arm on the read path for sporadic events. A micro test asserting `median wake < 10 µs` on a 1 Hz pipe byte adds a great regression canary (run inside talyn's pytest too).

## Environment
Python 3.15.2 / talyn 0.11.4 (PyPI wheel) / uvloop 0.23.0 reference / Linux x86_64 (kernel 7.2.15, io_uring enabled).
