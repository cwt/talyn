# BUG-186 — Double-close of socket file descriptors on connection_made exception in StreamServer, create_connection, and create_endpoint

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — File descriptor recycling hazards and race conditions
- **Files**: `src/transports/streamserver/main.zig:231-252`, `src/loop/python/io/client/create_connection.zig:848-862, 874-881`, `src/loop/python/io/datagram/create_endpoint.zig:263-264, 311-317`
- **Lessons**: [Lifecycle & Shutdown §Lesson 29](../lessons/03-event-loop-lifecycle.md), [Defensive Programming §Lesson 53](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `StreamServer.accept_callback`, `create_connection`, and `create_datagram_endpoint`, an `errdefer _ = std.os.linux.close(fd)` was defined. When the transport struct was instantiated with `owns_fd = true`, it assumed ownership of `fd`. If a subsequent operation (such as `protocol.connection_made` or `server_ref._attach`) raised a Python exception, `defer py_decref(transport)` destroyed the transport and closed `fd`. Then the function-level `errdefer` executed and closed `fd` a second time.
- **Trigger**: Any user protocol raising an unhandled exception in `connection_made()` or an error attaching to server ref.
- **Consequences**: Double close of file descriptors; in high-concurrency environments, this inadvertently closes a completely unrelated socket created concurrently on another thread.
- **Fix**: Replaced raw `errdefer close` with guarded `owns_fd` flags that are cleared immediately once the transport is constructed.
