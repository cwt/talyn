# BUG-341 — GC `future_traverse` visits freed `PyObject` pointers after `run_python_future_set_callbacks` error (UAF) and `Future.release` leaks `exceptions_queue` items

- **Status**: ✅ Fixed (2026-10-18) — `run_python_future_set_callbacks` now nulls out and clears `exceptions_queue` in its `errdefer`, and `Future.release` decrefs and nulls any remaining `exceptions_queue` items before `deinit`
- **Severity**: 🔴 Critical — GC traversal of freed `PyObject` pointers (segfault) on callback failure and reference leak on `Future.release`
- **Category**: Use-After-Free (UAF) & Reference Leak
- **Files**:
  - `src/future/callback.zig:84-89, 126-132`
  - `src/future/python/constructors.zig:95-101`
  - `src/future/main.zig:33-41`
- **Related**: [Lesson 44](../lessons/05-python-c-api-correctness.md), [Architectural Mandate #4](../architectural-mandates.md)

## Overview & Root Cause

There are two complementary lifetime bugs in `Future.exceptions_queue`:

1. **Dangling `PyObject` pointers in `exceptions_queue` after `errdefer` (UAF in `future_traverse`)**:
   In `src/future/callback.zig:84-89`, `run_python_future_set_callbacks` sets up an `errdefer` that decrefs every item in `exceptions_queue` without nulling out the entries or clearing the list:

   ```zig
   const exceptions = py_future.data.exceptions_queue.items;
   errdefer {
       for (exceptions) |exc| {
           python_c.py_xdecref(exc);
       }
   }
   ```

   Notice also that during the loop at lines 101–123, `exceptions[i]` is set to `null` as items are consumed, and `py_future.data.exceptions_queue.clearRetainingCapacity()` only runs at line 125 if the loop completes without error. If `call_exception_handler` fails (returning an error at line 118 or 121), the `errdefer` decrefs all remaining non-null `exc` pointers in `exceptions`, **leaving those freed pointers in `py_future.data.exceptions_queue.items`**.
   When CPython's cycle GC subsequently runs `future_traverse` (`src/future/python/constructors.zig:95-101`):

   ```zig
   for (future_data.exceptions_queue.items) |exc| {
       if (exc) |e| {
           const ret = visit.?(e, arg);
           if (ret != 0) return ret;
       }
   }
   ```

   `visit` is called on the already-freed `PyObject` pointers, crashing the interpreter.

2. **Reference leak in `Future.release` (`src/future/main.zig:33-41`)**:
   In `Future.release`, `self.exceptions_queue.deinit(self.loop.allocator)` is called directly without iterating over `self.exceptions_queue.items` to `py_xdecref` any remaining exception objects:

   ```zig
   Future.Callback.release_callbacks_queue(self);
   self.exceptions_queue.deinit(self.loop.allocator);
   ```

   If a `Future` is deallocated or cleared before `run_python_future_set_callbacks` drains `exceptions_queue` (e.g., when the callback is cancelled during loop teardown so `cleanup_python_future_callbacks_set_data` runs at `src/future/callback.zig:126-132`), every queued exception `PyObject` in `exceptions_queue` is leaked.

## Trigger Scenario

1. **UAF**: A `Future` done callback raises an exception (queued into `exceptions_queue`), and a subsequent exception handler call fails (`error.PythonError`). `run_python_future_set_callbacks` unwinds via `errdefer`, freeing `exc` while leaving the pointer in `exceptions_queue.items`. The next GC collection visits the freed pointer in `future_traverse`.
2. **Leak**: A `Future` done callback raises an exception, and the loop closes before `run_python_future_set_callbacks` executes (`cleanup_python_future_callbacks_set_data` runs). `Future.release` frees the `exceptions_queue` backing array without decrefing its `PyObject` elements.

## Proposed Remediation

1. In `src/future/callback.zig:84-89`, null out each entry and clear `exceptions_queue` inside the `errdefer`:

```zig
errdefer {
    for (py_future.data.exceptions_queue.items) |*exc| {
        python_c.py_xdecref(exc.*);
        exc.* = null;
    }
    py_future.data.exceptions_queue.clearRetainingCapacity();
}
```

2. In `Future.release` (`src/future/main.zig:33-41`) and `cleanup_python_future_callbacks_set_data` (`src/future/callback.zig:126-132`), `py_xdecref` and null out all items in `exceptions_queue` before calling `clearRetainingCapacity()` / `deinit()`.
