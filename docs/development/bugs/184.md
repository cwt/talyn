# BUG-184 — Premature decref / refcount underflow on positional arguments in set_write_buffer_limits

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — Python object reference count corruption
- **Files**: `src/transports/stream/write.zig:78-99`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/004-memory-management-and-refcounting.md), [Python C API §Lesson 21](../lessons/021-python-c-api.md)
- **Description**: In `src/transports/stream/write.zig`, `z_stream_set_write_buffer_limits` reads positional arguments directly into `py_high_water_mark` and `py_low_water_mark` (which are borrowed pointers from the caller). A `defer` block unconditionally executes `python_c.py_xdecref(py_high_water_mark)` and `python_c.py_xdecref(py_low_water_mark)`. When positional arguments are passed, their refcounts are decremented below zero or prematurely freed.
- **Trigger**: Calling `transport.set_write_buffer_limits(high, low)` with positional arguments.
- **Consequences**: Python integer constants or integer objects corrupted, premature deallocation, crashes.
- **Fix**: Only decref `py_high_water_mark` / `py_low_water_mark` if they were populated from keyword arguments (via `parse_vector_call_kwargs`), or increment borrowed positional references before deferring decref.
