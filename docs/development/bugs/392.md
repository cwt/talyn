# BUG-392 — `LRUCache.put` dangling key slice on key overwrite, `Address.parseIp6` accepting `":::1"`, `execute_task_send` running coroutine on cancelled loop shutdown, `enter_or_leave_task` partial failure corrupting `_current_tasks`, and `talyn.install()` globally disabling Python GC on 3.13t/3.14t

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — causes a dangling key slice in `LRUCache` when an existing key is updated, steps unstarted coroutines during `loop.close()` when they should be dropped, accepts malformed `":::1"` IPv6 addresses, and globally disables cyclic GC across the entire Python process in `talyn.install()` on free-threaded builds
- **Category**: Use-After-Free (Latent in `LRUCache`), Logic Bug, & Process-Wide Side Effect
- **Files**:
  - `src/utils/lru.zig:68-75`
  - `src/utils/address.zig:169-200`
  - `src/task/callbacks.zig:16-43, 567-580, 646-658`
  - `talyn/__init__.py:47-51`
- **Related**: [Lesson 28](../lessons/02-zig-and-memory.md), [Lesson 44](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

1. **`LRUCache.put` overwrites `node.data.key` with the caller's key slice while `StringHashMapUnmanaged` retains the old key slice (`src/utils/lru.zig:68-75`)**:
   ```zig
   const entry = try self.map.getOrPut(self.allocator, key);
   if (entry.found_existing) {
       const node = entry.value_ptr.*;
       node.data = .{
           .value = value,
           .key = key,
           .timestamp = timestamp,
       };
   ```
   In Zig's `StringHashMapUnmanaged`, `getOrPut` does **not** update `entry.key_ptr.*` when `entry.found_existing` is true (it keeps the original key slice), whereas `node.data.key` is overwritten with the new `key` parameter!
   If a caller passes a temporary `key` slice when updating an existing key (or frees the old key thinking `node.data.key` was updated, or frees the new `key` thinking the map kept its own copy), either `entry.key_ptr.*` or `node.data.key` becomes a dangling pointer when `remove()` or `put()` later runs `self.map.remove(lru.data.key)`! `node.data.key` should preserve `entry.key_ptr.*` when `entry.found_existing` is true.

2. **`execute_task_send` and `execute_task_throw` ignore `data.cancelled()` and execute the coroutine during `loop.close()` (`src/task/callbacks.zig:567-580, 646-658`)**:
   ```zig
   pub fn execute_task_send(data: *const CallbackManager.CallbackData) !void {
       const task: *TaskObject = @ptrCast(@alignCast(data.user_data.?));
       defer python_c.py_decref(@ptrCast(task));

       const future_data = utils.get_data_ptr(Future, &task.fut);
       if (future_data.status != .pending) {
           return;
       }
   ```
   When `loop.create_task(coro)` is called and `loop.close()` runs before the task's initial `execute_task_send` callback executes, `Loop.release()` drains `ready_tasks_queues` via `release_dynamic_ring_buffer`, which sets `item.data.set_cancelled(true)` and calls `execute_task_send(&item.data)`.
   Because `execute_task_send` (and `execute_task_throw`) never checks `if (data.cancelled()) return;`, `loop.close()` **actually starts and executes the coroutine inside `loop.close()`**!

3. **`enter_or_leave_task` does not roll back `PyContext_Enter` if `asyncio._enter_task` fails (`src/task/callbacks.zig:16-43`)**:
   In `enter_or_leave_task(task, true)`, `python_c.PyContext_Enter(task.context.?)` runs at line 20, followed by `PyObject_CallFunctionObjArgs(enter_task_fn, task.fut.py_loop.?, task, null)` at lines 24–26. If `_enter_task` fails (e.g. `RuntimeError`), `PyContext_Exit(task.context.?)` is **not** called, leaving `task.context` permanently entered on the current thread!

4. **`Address.parseIp6` accepts invalid triple-colon `":::1"` (`src/utils/address.zig:169-200`)**:
   In `parseIp6`, when `str` starts with `":::1"`, lines 173–178 consume the leading `"::"` (`i = 2`, `double_colon_pos = 0`), and then at the top of the `while` loop (`i == 2`, where `str[2] == ':'`), lines 183–190 see `i + 1 < str.len and str[i + 1] != ':'`, increment `i += 1` past the third colon without checking `if (i == 2 and double_colon_pos != null)`, and parse `"1"` as a valid IPv6 address!

5. **`talyn.install()` globally disables Python's cyclic garbage collector on free-threaded builds (`talyn/__init__.py:47-51`)**:
   ```python
   if getattr(_sys, "_is_gil_enabled", lambda: True)() is False:
       import gc as _gc
       _gc.disable()
   ```
   Calling `talyn.install()` (or `EventLoopPolicy`) silently disables CPython's cyclic garbage collector for the entire process on Python 3.13t/3.14t without warning or re-enabling it on loop close.

## Trigger Scenario

1. Call `loop.create_task(coro)` and immediately call `loop.close()` without running the loop -> `coro` is executed inside `loop.close()` because `execute_task_send` ignores `data.cancelled()`.
2. Call `Address.parseIp6(":::1", 80)` -> succeeds instead of returning `error.InvalidIp6Format`.

## Proposed Remediation

1. In `LRUCache.put` (`src/utils/lru.zig:71`), set `.key = entry.key_ptr.*` when `entry.found_existing` is true.
2. In `execute_task_send` and `execute_task_throw` (`src/task/callbacks.zig:567, 646`), check `if (data.cancelled()) return;` right after `defer python_c.py_decref(@ptrCast(task));`.
3. In `enter_or_leave_task` (`src/task/callbacks.zig:20-26`), add `errdefer _ = python_c.PyContext_Exit(task.context.?);` before calling `_enter_task`.
4. In `Address.parseIp6` (`src/utils/address.zig:176`), after consuming a leading `"::"` (`i = 2`), verify `if (i < str.len and str[i] == ':') return error.InvalidIp6Format;`.
