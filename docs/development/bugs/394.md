# BUG-394 — Build & AST linter bugs: missing `build_options` import on `utils_unit_tests` in `build.zig`, untested `sqe_pointer_lifetime` rule in `test_rules.zig`, and whole-file substring false negatives in linter rules

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — `utils_unit_tests` is missing the `build_options` module required by `src/utils/lock.zig`, `TALYN-015` (`sqe_pointer_lifetime`) is not wired into `test_rules.zig`, and several linter rules have whole-file substring false negatives
- **Category**: Build Configuration & Static Analysis Bug
- **Files**:
  - `build.zig:241-253`
  - `src/utils/lock.zig:2`
  - `tools/linter/test_rules.zig:1-20`
  - `tools/linter/rules/missing_tp_alloc_pyobject_init.zig:15`
  - `tools/linter/rules/gc_type_clear.zig:11-13`
  - `tools/linter/rules/python_rules.py:56-60, 99`
- **Related**: [BUG-335](335.md)

## Overview & Root Cause

1. **`utils_unit_tests` in `build.zig:241-253` is missing the `build_options` import**:
   In `src/utils/lock.zig:2`, `Lock` imports `@import("build_options")`.
   In `build.zig`, `utils_module` (line 138) and `lib_unit_tests` (line 225) add `build_options`:
   ```zig
   .imports = &.{
       .{ .name = "python_c", .module = python_c_module },
       .{ .name = "build_options", .module = options.createModule() },
   },
   ```
   However, `utils_unit_tests` (`build.zig:241-253`) only imports `python_c` and omits `build_options`! It currently compiles only because `utils.Lock` happens not to be referenced by any `test` block in `src/utils/main.zig`. Adding any unit test for `utils.Lock` fails with `error: no module named 'build_options'`.

2. **`tools/linter/test_rules.zig` omits `sqe_pointer_lifetime.zig` (`TALYN-015`)**:
   `tools/linter/main.zig` registers 11 Zig linter rules (including `sqe_pointer_lifetime.zig`), but `tools/linter/test_rules.zig` only imports and tests 10 rules, omitting `sqe_pointer_lifetime.zig`.

3. **Whole-file substring false negatives in linter rules**:
   - `tools/linter/rules/missing_tp_alloc_pyobject_init.zig:15`:
     `if (std.mem.indexOf(u8, source, "tp_alloc") != null and std.mem.indexOf(u8, source, "PyObject_Init") == null)` checks the **entire file** rather than each function body, so if one function in a file calls `PyObject_Init` (or mentions `"PyObject_Init"` in a comment) and a second function in the same file calls `tp_alloc` without `PyObject_Init`, the violation is suppressed.
   - `tools/linter/rules/gc_type_clear.zig:11-13`:
     Checks whole-file substring presence of `Py_TPFLAGS_HAVE_GC`, `Py_tp_traverse`, and `Py_tp_clear` rather than per-`PyType_Slot` array, so a file defining two GC types where only one has `Py_tp_clear` passes silently.
   - `tools/linter/rules/python_rules.py:56-60, 99`:
     - `TALYN-100` (`check_talyn_100`) only checks `isinstance(node.func, ast.Name) and node.func.id == "hasattr"`, missing `builtins.hasattr(...)`.
     - `TALYN-102` (`check_talyn_102`) uses the regex `r"await\s+self\._\w+\("`, which only matches `await self._<name>(` and misses `await waiter` (which is the exact pattern that leaked `raw_transport` in `_create_ssl_connection` in [BUG-375](375.md)!).

## Trigger Scenario

1. Add a `test` referencing `Lock` in `src/utils/main.zig` and run `zig build test` -> fails to compile `utils_unit_tests` due to missing `build_options` module.
2. Have `await waiter` after `raw_transport, _ = await self._create_connection_zig(...)` in `talyn/loop.py:967` -> `TALYN-102` misses the unguarded `await waiter` because it only regex-matches `await self._\w+\(`.

## Proposed Remediation

1. Add `.{ .name = "build_options", .module = options.createModule() }` to `utils_unit_tests` in `build.zig:247-249`.
2. Add positive and negative unit tests for `sqe_pointer_lifetime.zig` (`TALYN-015`) in `tools/linter/test_rules.zig`.
3. Scope `missing_tp_alloc_pyobject_init.zig` to individual `fn_decl` AST nodes, scope `gc_type_clear.zig` to individual slot arrays, and generalize `TALYN-102` in `tools/linter/rules/python_rules.py` to use `ast.Await` nodes inside `ast.AsyncFunctionDef` rather than a `self._\w+` regex.
