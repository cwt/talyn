# BUG-423 — `interleave_address_list` integer underflow

- **Status**: 🟡 Open
- **Severity**: 🟠 High — panic (Debug/ReleaseSafe) / wrong ordering (ReleaseFast)
- **Category**: Algorithm / integer overflow
- **Files**: `src/loop/python/io/client/create_connection/interleave.zig:33-51`
- **Related**: [BUG-212](212.md) (the guard that introduced this), [BUG-229](229.md), [BUG-72](072.md), [Lesson 115](../lessons/24-split-commit-hygiene-2026-11.md)

## Description

```zig
var interleave_count: usize = interleave;
...
for (address_list) |*v| {
    if ((interleave_count == 0 or ipv6_index >= ipv6_addresses) and ipv4_index < ipv4_addresses) {
        v.* = tmp_list[ipv4_index]; ipv4_index += 1; interleave_count = interleave;
    } else if (ipv6_index < ipv6_addresses) {
        v.* = tmp_list[address_list.len + ipv6_index]; ipv6_index += 1; interleave_count -= 1; // <-- underflows at 0
    } ...
}
```

When IPv4 is exhausted while IPv6 remain and `interleave_count == 0`, the `else if` branch subtracts
from 0. Reproduced with the exact BUG-212 input (4×IPv6 + 1×IPv4, `interleave = 1`): **integer
overflow panic**. Reachable from `create_connection(..., interleave=N)` or
`happy_eyeballs_delay` (the `interleave == 0 → interleave(..., 1)` path in `connect.zig`).

## Trigger

Dual-stack host whose A/AAAA counts differ, with `interleave` or `happy_eyeballs_delay` set.

## Consequences

Debug/ReleaseSafe builds panic inside connection setup (Mandate #1 violation); ReleaseFast wraps to a
huge count and mis-orders candidates.

## Fix

Guard the decrement:

```zig
} else if (ipv6_index < ipv6_addresses) {
    v.* = tmp_list[address_list.len + ipv6_index]; ipv6_index += 1;
    if (interleave_count > 0) interleave_count -= 1;
}
```

Also add the interleave tests to the `zig build test` roster — they currently live under a split root
that no test root reaches (Lesson 115 blind spot).
