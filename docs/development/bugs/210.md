# BUG-210 — Datagram SendToData Buffer and Transport Reference Leak on Protocol Exception

- **Status**: 🟡 Open
- **Severity**: 🟡 Medium — Resource Leak
- **Files**: `src/transports/datagram/write.zig:28-65`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Lifecycle & Error Handling §Lesson 4](../lessons/004-lifecycle-error-handling.md)
- **Description**: In `src/transports/datagram/write.zig`, `sendto_completed` uses `var success = false; defer if (success) cleanup_sendto(sd);`. If protocol `resume_writing` lookup or invocation fails with an exception, `success` is never set to `true`, skipping `cleanup_sendto`. This leaves `sd`, `sd.buf`, and `transport` refcount leaked.
- **Trigger**: Error or exception raised by `protocol.resume_writing()`.
- **Consequences**: Leaked heap buffer, struct, and transport PyObject reference.
- **Fix**: Use unconditional `defer cleanup_sendto(@ptrCast(@alignCast(sd)));`.
