# BUG-358 — `Resolv.build_queries` clobbers `server_data.dns_timeout` back to `null` via struct-literal assignment

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — user-configured `dns_timeout` is silently overwritten with `null` inside `build_queries`, causing all DNS response reads (`queue_read_package`) and subsequent query sends (`queue_send_query`) to fall back to the 5-second default timeout
- **Category**: Logic Bug
- **Files**:
  - `src/loop/dns/resolv.zig:695, 749-757, 880-881`
- **Related**: [BUG-334](334.md)

## Overview & Root Cause

In `src/loop/dns/resolv.zig`, `prepare_data` sets `server_data.dns_timeout = dns_timeout;` right before calling `build_queries` at two sites (lines 695–696 and lines 880–881):

```zig
server_data.dns_timeout = dns_timeout;
try build_queries(allocator, control_data, server_data, hostnames_array);
```

However, inside `build_queries` (`src/loop/dns/resolv.zig:749-757`), `server_data.*` is overwritten by a struct literal that does **not** include `.dns_timeout`:

```zig
server_data.* = .{
    .queries = queries_buffer[0..offset],
    .query_lengths = query_lengths,
    .queries_count = queries_count,
    .control_data = control_data,
    .transaction_ids = transaction_ids,
    .socket_fd = socket_fd,
    .nameserver = undefined,
};
```

Because `ServerData.dns_timeout` has a default field value of `null` (`dns_timeout: ?DnsTimeout = null` at line 117), this struct-literal assignment resets `server_data.dns_timeout` back to `null`!

Consequently:
- Only the very first UDP `PerformWrite` in `Resolv.queue` (`src/loop/dns/resolv.zig:905`) sees `control_data.dns_timeout`.
- Every UDP response read in `queue_read_package` (`line 331: server_data.dns_timeout orelse DefaultReadTimeout`) and every subsequent UDP query write in `queue_send_query` (`line 301: server_data.dns_timeout orelse DefaultWriteTimeout`) sees `server_data.dns_timeout == null` and uses the 5-second default timeout instead of the user-specified `dns_timeout`!

## Trigger Scenario

Call `await loop.getaddrinfo("example.com", 80, dns_timeout=0.1)` against a blackholed nameserver (where UDP `send` succeeds locally and the response `read` times out). Instead of timing out in `0.1s`, `queue_read_package` uses `DefaultReadTimeout` (`5.0s`) because `server_data.dns_timeout` was reset to `null` by `build_queries`.

## Proposed Remediation

Include `.dns_timeout = control_data.dns_timeout,` in the `server_data.* = .{ ... }` struct literal inside `build_queries` (`src/loop/dns/resolv.zig:749-757`):

```zig
server_data.* = .{
    .queries = queries_buffer[0..offset],
    .query_lengths = query_lengths,
    .queries_count = queries_count,
    .control_data = control_data,
    .transaction_ids = transaction_ids,
    .socket_fd = socket_fd,
    .nameserver = undefined,
    .dns_timeout = control_data.dns_timeout,
};
```
