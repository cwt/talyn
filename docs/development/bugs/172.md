# BUG-172 — Memory and reference leaks on failure paths in `z_loop_add_hook` and `z_loop_add_path_watcher`

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — resource & memory leak
- **Files**: `src/loop/python/control.zig:201-214,278-286`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/04-resource-cleanup-and-cancellation.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: In `src/loop/python/control.zig`, `z_loop_add_hook` allocates a `HookHandle` object and increments `callback` with `py_newref`. If the subsequent `loop_data.add_hook` fails (e.g. OOM), the handle and callback are not cleaned up. Similarly, in `z_loop_add_path_watcher`, if `tp_alloc` fails after `loop_data.fs_watcher.add_watch`, the newly created inotify watch in the kernel is not removed.
- **Trigger**: Memory allocation failure when registering loop lifecycle hooks or filesystem path watchers.
- **Consequences**: Leaked heap memory, leaked Python callback references, and dangling kernel inotify watches.
- **Fix**: Add appropriate `errdefer` statements to free memory, decref callback objects, and remove inotify watches on error.
