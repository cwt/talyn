# BUG-249 — Struct literal dns_timeout evaluation in getaddrinfo.zig leaks references and memory on error

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Resource / reference count leak on error path
- **Files**: `src/loop/python/io/socket/getaddrinfo.zig`
- **Lessons**: [Defensive §Lesson 46 — Allocation & Initialization Order](../lessons/10-defensive-programming-and-code-quality.md), [Python §Lesson 76 — Reference Cleanup on Early Exit](../lessons/11-python-c-api-and-abi-stability.md)
- **Description**: In `src/loop/python/io/socket/getaddrinfo.zig`, `dns_timeout` parsing was placed inside the struct literal initializer `gaid.* = .{ .future = py_newref(fut), .loop = py_newref(self), ..., .dns_timeout = blk: { ... if (PyErr_Occurred() != null) return error.PythonError; } }`. Because `fut` and `self` reference counts are incremented and `host_str` allocated before the `dns_timeout` block in the struct expression, returning `error.PythonError` aborts execution before the cleanup `errdefer` on line 190 is registered.
- **Trigger**: Invoking `await loop.getaddrinfo("example.com", 80, dns_timeout="invalid")`.
- **Consequences**: Memory leak of `host_str` and permanent reference count leaks of the newly-created `FutureObject` and `LoopObject`.
- **Resolution**: Move `dns_timeout` parsing and validation to the start of `z_loop_getaddrinfo` before `fast_new_future`, string duplication, and struct allocations.
- **Verification**: Verify that invalid `dns_timeout` raises `TypeError` without leaking any memory or object references under debug GPA checks.
