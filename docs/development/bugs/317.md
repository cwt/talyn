# BUG-317 — Multi-nameserver redundancy broken by premature abort in process_dns_response

- **Status**: 🔴 Open (2026-09-07)
- **Severity**: 🟡 Medium — DNS failover redundancy broken: single server failure immediately cancels all backup nameserver queries
- **Files**:
  - `src/loop/dns/resolv.zig` (`process_dns_response`: lines 390–395)
- **Lessons**: [Network Protocols & IO](../lessons/06-network-protocols-and-io.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**:
In `process_dns_response`:
```zig
if (io_uring_err != .SUCCESS) {
    log.err("resolv send/recv query failed for nameserver {s}: {s}", .{ server_data.nameserver, @tagName(io_uring_err) });
    self.mark_resolved_and_execute_user_callbacks(server_data);
    return;
}
```
When multiple nameservers are configured in `/etc/resolv.conf`, if the first nameserver times out or rejects the UDP query, line 392 immediately invokes `mark_resolved_and_execute_user_callbacks`. This marks the query resolved (failed) and cancels in-flight queries to secondary nameservers, defeating the purpose of multi-nameserver redundancy.
- **Root Cause**: Treating a single nameserver query failure as an immediate fatal error for the entire multi-server resolution batch.
- **Trigger Scenario**: Systems with multiple nameservers where the primary nameserver is unresponsive or experiencing packet loss.
- **Proposed Remediation**: Track outstanding server queries; only mark resolution failed when all nameserver queries have exhausted or failed.

- **Validation (2026-09-07)**: Confirmed still present.
  - `process_dns_response` (`src/loop/dns/resolv.zig:390-395`): a timeout or io_uring error on ONE nameserver immediately calls `mark_resolved_and_execute_user_callbacks`, whose first action is cancelling every pending server query (`resolv.zig:241-243` → `ServerQueryData.cancel` → `CancelByFd` per nameserver, `resolv.zig:132-139`) and marking the whole lookup resolved.
  - Structure confirmed: `control_data.queries_data` holds one `ServerQueryData` per nameserver (`resolv.zig:764`, `configuration.servers.len`), so a single primary-server failure aborts all secondary nameservers — failover defeated exactly as described.
