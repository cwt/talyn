# BUG-217 — Refcount leak of `mod` and `cb` on callback error in debug mode in `CallbackManager`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Python Reference Count Leak
- **Files**: `src/callback_manager.zig:448-503`, `src/callback_manager.zig:539-594`
- **Lessons**: [Memory & Reference Counting §Lesson 1](../lessons/01-memory-and-reference-counting.md), [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/callback_manager.zig`, both `execute_ring_buffer` and `execute_dynamic_ring_buffer` contain debug tracking code that acquires references to `mod` and `cb` via `python_c.py_incref` when `debug == true`. However, when `callback.func` fails and enters the `catch |err|` block, the functions return or continue without decreffing `mod` and `cb`.
- **Trigger**: Any callback executed in debug mode (`loop.set_debug(True)`) that raises an exception or returns an error.
- **Consequences**: Leaks Python references to module and callback objects on every callback failure during debug mode, preventing garbage collection of user callbacks and modules.
- **Fix**: Use a scope defer or ensure decref on the error path for `mod` and `cb` when `debug` is true.
