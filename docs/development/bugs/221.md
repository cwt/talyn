# BUG-221 — Leaked `future` and `loop` Python references on `reverse_lookup` error in `z_loop_getnameinfo`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Python Reference Count Leak
- **Files**: `src/loop/python/io/socket/getnameinfo.zig:96-121`
- **Lessons**: [Memory & Reference Counting §Lesson 1](../lessons/01-memory-and-reference-counting.md), [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/loop/python/io/socket/getnameinfo.zig`, `z_loop_getnameinfo` creates a `gnid: *GetNameInfoData` and increfs `future` and `loop`. It then calls `try loop_data.dns.reverse_lookup(addr, &callback, dns_timeout);`. If `reverse_lookup` fails (e.g. system socket or queue error), the function unwinds using `errdefer alloc.destroy(gnid)`. The references held on `gnid.future` and `gnid.loop` are never decreffed.
- **Trigger**: System resource failure or allocation error during `reverse_lookup` queueing.
- **Consequences**: Permanent Python reference leak on `FutureObject` and `LoopObject`.
- **Fix**: Add `errdefer { python_c.py_decref(@ptrCast(gnid.future)); python_c.py_decref(@ptrCast(gnid.loop)); }`.
