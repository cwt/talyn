# BUG-183 — Use-after-free and dangling pointer in loop.add_hook due to missing refcount hold

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — Use-after-free in hot event loop iteration
- **Files**: `src/loop/python/control.zig:126-171, 202-218`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/004-memory-management-and-refcounting.md), [Python C API §Lesson 21](../lessons/021-python-c-api.md)
- **Description**: In `src/loop/python/control.zig`, `z_loop_add_hook` allocates a `HookHandle` via `tp_alloc` (refcount = 1) and returns it to Python. The raw pointer is stored in the loop's hook list without calling `python_c.py_incref(@ptrCast(handle))`. If Python user code drops the handle object without calling `.cancel()`, Python GC deallocates `handle`. The loop's hook list retains the dangling pointer. On subsequent loop ticks, `hook_callback` dereferences `handle.callback` (UAF). Additionally, `data.cancelled()` calls `py_decref(handle)` without an internal reference having been held.
- **Trigger**: Adding a hook via `loop._add_hook(...)` without retaining the returned handle in a Python variable.
- **Consequences**: Memory corruption, invalid function calls, or segmentation fault on subsequent loop iterations.
- **Fix**: Hold an internal reference via `python_c.py_incref(@ptrCast(handle))` when adding to the hook list, and release it on cancellation or hook removal.
