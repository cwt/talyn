# BUG-264 — `pseudosocket.getsockopt` leaves pending exception on invalid `buflen` type

- **Status**: 🟢 Fixed (2026-08-21)
- **Validation**: 2026-08-21 — CONFIRMED REAL. In `pseudosocket_getsockopt`, `const bl = PyLong_AsLong(PyTuple_GetItem(arg_tuple, 2)); if (bl >= 0 and bl <= buf.len) buflen = @intCast(bl);` — for a non-numeric `buflen`, `PyLong_AsLong` sets `TypeError` and returns `-1`; `bl >= 0` is false so `buflen` is left unchanged and the pending exception is never `PyErr_Clear()`-ed. Execution proceeds to `getsockopt` and returns bytes with `PyErr_Occurred() != null` — the stale exception leaks to the caller.
- **Fix**: 2026-08-21 — Added the missing `PyErr_Occurred()` check after `PyLong_AsLong`; on error the function returns null, propagating the `TypeError` to the caller instead of continuing with a stale pending exception. Regression test `test_pseudosocket_getsockopt_invalid_buflen` (tests/test_pseudosocket.py): `getsockopt(..., "not-an-int")` raises `TypeError` and a subsequent `setsockopt`/`getsockopt` round-trip still works (no poisoned exception state). Full suite (`test_all.sh --python=3.14 --starburst --verbose`) passes.
- **Severity**: Medium-Low — Exception State Leak
- **File**: `src/utils/pseudosocket.zig:153-155` (`getsockopt` buflen parse)
- **Lessons**: [Python C API Correctness](../lessons/05-python-c-api-correctness.md)

## Description

```zig
if (argc >=3) {
    const bl = PyLong_AsLong(PyTuple_GetItem(arg_tuple,2));
    if (bl >=0 && bl <= buf.len) buflen = @intCast(bl);
}
```

If `buflen` argument is non-numeric (e.g., `"256"`), `PyLong_AsLong` sets `TypeError` and returns `-1`. The check `bl >=0` fails, so code silently keeps `buflen=256` without `PyErr_Clear()` or `return null`. The pending `TypeError` remains set while function proceeds to `getsockopt` syscall and returns `PyBytes` successfully — caller sees success but `PyErr_Occurred()!=null` later triggers spurious error in caller.

## Trigger

`pseudo_socket.getsockopt(SOL_SOCKET, SO_TYPE, "not-an-int")`.

## Consequences

- Stale exception leaks to next Python C API call → `SystemError` or mis-attributed error.

## Fix (Not Applied)

```zig
const bl = PyLong_AsLong(...);
if (PyErr_Occurred()!=null) { return null; } // propagate TypeError
if (bl >=0 && bl <= buf.len) buflen=@intCast(bl);
```
