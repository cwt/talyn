# BUG-342 — Unconditional double-decref of `protocol` and conditional leak or double-decref of `transport` in `unix_connect_callback`

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — 100% deterministic double-decref of `protocol` on every successful `loop.create_unix_connection()` call, causing use-after-free and heap/refcount corruption
- **Category**: Double-Decref / Use-After-Free & Reference Leak
- **Files**:
  - `src/loop/python/io/pipe/unix.zig:79-101`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md), [BUG-327](327.md)

## Overview & Root Cause

In `src/loop/python/io/pipe/unix.zig:79-101`, `unix_connect_callback` manages the reference counts of `protocol` and `transport` as follows:

```zig
const protocol = python_c.PyObject_CallNoArgs(ucd.protocol_factory) orelse return set_future_exception(error.PythonError, ucd.future);
defer python_c.py_decref(protocol);

const transport = try StreamTransport.Constructors.fast_new_connection(protocol, ucd.loop, ucd.fd);
ucd.fd = -1; // Transport now owns the fd
errdefer python_c.py_decref(@ptrCast(transport));

const connection_made = python_c.PyObject_GetAttrString(protocol, "connection_made\x00") orelse return set_future_exception(error.PythonError, ucd.future);
defer python_c.py_decref(connection_made);

const ret = python_c.PyObject_CallOneArg(connection_made, @ptrCast(transport)) orelse return set_future_exception(error.PythonError, ucd.future);
python_c.py_decref(ret);

const result_tuple = python_c.PyTuple_Pack(2, @as(PyObject, @ptrCast(transport)), protocol) orelse return set_future_exception(error.PythonError, ucd.future);
defer python_c.py_decref(result_tuple);

// PyTuple_Pack increments references, so drop our local references
python_c.py_decref(@ptrCast(transport));
python_c.py_decref(protocol);

const future_data = utils.get_data_ptr(Future, ucd.future);
try Future.Python.Result.future_fast_set_result(future_data, result_tuple);
```

There are three distinct reference-counting bugs in this 22-line block:

1. **Unconditional double-decref of `protocol` on the success path**:
   - `PyObject_CallNoArgs(ucd.protocol_factory)` returns a new reference (`+1`).
   - `defer python_c.py_decref(protocol)` is registered at line 80 (`-1` on scope exit).
   - `PyTuple_Pack(2, transport, protocol)` increments `protocol`'s refcount (`+1`, owned by `result_tuple`).
   - Line 97 manually calls `python_c.py_decref(protocol)` (`-1`), and then scope exit runs `defer python_c.py_decref(protocol)` (`-1` again).
   - Net change to caller/local refcount: `+1 - 1 - 1 = -1`, stealing a reference owned by `result_tuple` or `StreamTransport` and causing use-after-free when the tuple or transport is destroyed.

2. **Leak of `transport` if `connection_made` or `PyTuple_Pack` fails (lines 86, 89, 92)**:
   - Line 84 registers `errdefer python_c.py_decref(@ptrCast(transport))`.
   - However, lines 86, 89, and 92 use `orelse return set_future_exception(error.PythonError, ucd.future)`. Because `set_future_exception` returns `void` (not an error!), returning `set_future_exception(...)` is a **normal** return from `unix_connect_callback`, so the `errdefer` at line 84 does **not** run, leaking `transport` (and its underlying `fd`).

3. **Double-decref of `transport` if `future_fast_set_result` fails at line 100**:
   - Line 96 manually calls `python_c.py_decref(@ptrCast(transport))`.
   - If `try Future.Python.Result.future_fast_set_result(...)` at line 100 returns an error (e.g., `InvalidStateError` because `ucd.future` was cancelled inside `connection_made`), the `errdefer` at line 84 runs and decrefs `transport` a second time.

## Trigger Scenario

1. Any successful call to `await loop.create_unix_connection(factory, path)` executes both line 97 (`py_decref(protocol)`) and line 80 (`defer py_decref(protocol)`), corrupting `protocol`'s reference count.
2. Any exception raised inside `protocol.connection_made(transport)` during `create_unix_connection` returns via `set_future_exception` (`void`), bypassing `errdefer` and leaking `transport`.

## Proposed Remediation

Use `defer python_c.py_decref(@ptrCast(transport))` unconditionally (just like `defer python_c.py_decref(protocol)` at line 80) and remove both manual `py_decref` calls at lines 96–97:

```zig
const protocol = python_c.PyObject_CallNoArgs(ucd.protocol_factory) orelse return set_future_exception(error.PythonError, ucd.future);
defer python_c.py_decref(protocol);

const transport = try StreamTransport.Constructors.fast_new_connection(protocol, ucd.loop, ucd.fd);
ucd.fd = -1; // Transport now owns the fd
defer python_c.py_decref(@ptrCast(transport));
```
