# BUG-202 — Python OSError reference leak on failed unix socket connection in unix_connect_callback

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Python Reference Count Leak
- **Files**: `src/loop/python/io/pipe/unix.zig:68-73`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [BUG-146](146.md)
- **Description**: In `src/loop/python/io/pipe/unix.zig`, `unix_connect_callback` creates a new Python `OSError` instance via `PyObject_CallFunction` (which returns a new reference with refcount 1). It then passes this exception to `future_fast_set_exception`, which internally calls `python_c.py_newref(exc)` (increasing refcount to 2). The callback function exits without `defer python_c.py_decref(exc);`, leaking 1 `OSError` Python object per failed unix socket connection.
- **Trigger**: Any failed `create_unix_connection` attempt (e.g. non-existent socket path, connection refused, or timeout).
- **Consequences**: Gradual memory leak of Python exception objects on connection failure paths.
- **Fix**: Add `defer python_c.py_decref(exc);` immediately after successfully creating the `OSError` object in `unix_connect_callback`.
