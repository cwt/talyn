# BUG-149 — `PyObject` reference leak via `get_py_none()` default in task stack keyword argument parsing

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — reference leak of None singleton on argument parsing
- **Files**: `src/task/utils.zig:82, 112-113`
- **Lessons**: [Memory §Lesson 30](../lessons/01-memory-and-reference-counting.md), [Memory §Lesson 37](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `task_get_stack` and `task_print_stack`, default keyword arguments are initialized with `var limit: ?PyObject = python_c.get_py_none();`. Because `get_py_none()` calls `py_newref(_Py_NoneStruct)`, it holds a new strong reference. When `PyArg_ParseTupleAndKeywords` parses user arguments, it overwrites `limit` (and `file`) without decreffing the initial `None` reference.
- **Trigger**: Calling `task.get_stack(limit=...)` or `task.print_stack(limit=..., file=...)`.
- **Consequences**: Leaks 1 reference to `None` on every call.
- **Proposed Fix**: Initialize variables to `null` or `python_c.get_py_none_without_incref()`, passing `None` to the callee only if the parsed value remains `null`.
