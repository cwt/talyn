# BUG-200 — Managed HashMap in LRUCache violates Zig 0.16.0 unmanaged containers mandate

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Architectural Invariant & Zig 0.16.0 Standard
- **Files**: `src/utils/lru.zig:10-14`
- **Rules**: `TALYN-004/UNMANAGED_CONTAINERS`, [BUG-126](126.md), Zig 0.16.0 Rule 4
- **Description**: In `src/utils/lru.zig`, `LRUCache` declares `MapType` as either `std.StringHashMap(Node)` or `std.AutoHashMap(K, Node)`. These managed hash map structures embed the allocator pointer directly in the struct, which violates the repository's Zig 0.16 unmanaged container mandate.
- **Trigger**: Static AST linting rule `TALYN-004` or instantiation of `LRUCache`.
- **Consequences**: Violates project architectural standards, causes AST linter failure on `zig build lint`, and stores redundant allocator references.
- **Fix**: Change `MapType` to `std.StringHashMapUnmanaged(Node)` and `std.AutoHashMapUnmanaged(K, Node)`, initialize with `.empty`, and pass `allocator` explicitly to all hash map operations.
