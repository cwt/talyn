# BUG-286 — `dispatch_guaranteed_nonthreadsafe` drops the callback on allocation failure

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low (OOM-only) — Wrong logic / silent drop
- **Files**:
  - `src/loop/scheduling/soon.zig:22-32` (`reserved_slots -= 1` before `try ready_queue.push_or_grow(callback.*)`)
  - Callers include `future/callback.zig` (future resolution) and signal unregistration paths
- **Lessons**: [Event Loop Lifecycle §Lesson 57](../lessons/03-event-loop-lifecycle.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: The "guaranteed" variant promises delivery but propagates `push_or_grow` errors after consuming the slot; accounting stays balanced so nothing detects the loss. A dropped done-callback means a completed future whose awaiters are never resumed — a silent permanent hang.
- **Trigger**: OOM while growing the ready ring.
- **Consequences**: Awaited coroutines hang forever with no diagnostic.
- **Fix (Proposed)**: On push failure, retry via a fallback path or surface loudly (log + propagate) rather than losing the payload silently.
