# BUG-353 — 100% reference leak of return values in `sock_sendto_callback`, `sock_recv_into_callback_with_buf`, `sock_connect_callback`, and `sock_sendall_callback`

- **Status**: ✅ Fixed (2026-10-18)
- **Severity**: 🔴 High — 100% deterministic reference leak on every successful `loop.sock_sendto`, `loop.sock_recv_into`, `loop.sock_connect`, and `loop.sock_sendall` call
- **Category**: Reference Leak
- **Files**:
  - `src/loop/python/io/socket/ops.zig:218-221, 474-478, 743-746, 953-956`
  - `src/future/python/result.zig:84`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md), [BUG-12](012.md)

## Overview & Root Cause

In `src/future/python/result.zig:84`, `Future.Python.Result.future_fast_set_result` takes a borrowed reference to `result` and calls `python_c.py_newref(result)` internally.

In `src/loop/python/io/socket/ops.zig`, `sock_accept_callback` (line 103), `sock_recv_callback_with_buf` (line 336), and `sock_recvfrom_callback` (line 605) correctly register `defer python_c.py_decref(...)` on the result object they construct before calling `future_fast_set_result`. However, the remaining four socket callbacks in `ops.zig` fail to drop their local reference:

1. **`sock_connect_callback` (`src/loop/python/io/socket/ops.zig:218-221`)**:
   ```zig
   const future_data = utils.get_data_ptr(Future, d.future);
   try Future.Python.Result.future_fast_set_result(future_data, python_c.get_py_none());
   ```
   `python_c.get_py_none()` increments `Py_None`, and `future_fast_set_result` increments `Py_None` a second time, leaking 1 `Py_None` reference per `sock_connect`.

2. **`sock_recv_into_callback_with_buf` (`src/loop/python/io/socket/ops.zig:474-478`)**:
   ```zig
   const py_nread = python_c.PyLong_FromLong(@intCast(res)) orelse return set_future_exception(error.PythonError, d.future);
   const future_data = utils.get_data_ptr(Future, d.future);
   try Future.Python.Result.future_fast_set_result(future_data, py_nread);
   ```
   `py_nread` is a new reference from `PyLong_FromLong` and is never decref'd after `future_fast_set_result`, leaking the `int` object on every `sock_recv_into` call.

3. **`sock_sendto_callback` (`src/loop/python/io/socket/ops.zig:743-746`)**:
   ```zig
   const py_res = python_c.PyLong_FromLong(@intCast(res)) orelse return set_future_exception(error.PythonError, d.future);
   const future_data = utils.get_data_ptr(Future, d.future);
   try Future.Python.Result.future_fast_set_result(future_data, py_res);
   ```
   `py_res` is never decref'd, leaking the `int` object on every `sock_sendto` call.

4. **`sock_sendall_callback` (`src/loop/python/io/socket/ops.zig:953-956`)**:
   ```zig
   const future_data = utils.get_data_ptr(Future, d.future);
   try Future.Python.Result.future_fast_set_result(future_data, python_c.get_py_none());
   ```
   Calls `get_py_none()` instead of `get_py_none_without_incref()`, leaking 1 `Py_None` reference per `sock_sendall`.

## Trigger Scenario

Every successful call to `await loop.sock_sendto(...)`, `await loop.sock_recv_into(...)`, `await loop.sock_connect(...)`, or `await loop.sock_sendall(...)` leaks 1 Python object reference.

## Proposed Remediation

1. In `sock_recv_into_callback_with_buf` (line 474) and `sock_sendto_callback` (line 743), add `defer python_c.py_decref(py_nread);` and `defer python_c.py_decref(py_res);`.
2. In `sock_connect_callback` (line 220) and `sock_sendall_callback` (line 955), pass `python_c.get_py_none_without_incref()`.

## Resolution (2026-10-18)

Applied the proposed remediation in `src/loop/python/io/socket/ops.zig`:

1. `sock_sendto_callback` / `sock_recv_into_callback_with_buf`: `defer python_c.py_decref(...)` right after `PyLong_FromLong` (`future_fast_set_result` takes its own reference internally).
2. `sock_connect_callback` / `sock_sendall_callback`: pass `get_py_none_without_incref()` instead of `get_py_none()`.

Note: `Py_None` is immortal on 3.12+, so the None-leak side is not refcount-observable there; the PyLong side is. Test (`tests/test_socket_ops.py::test_bug353_no_result_reference_leaks`): 100 iterations of connect/sendall/recv/sendto/recv_into must leave `sys.getallocatedblocks()` flat (calibrated: +196 blocks pre-fix vs ~0 post-fix; threshold 150 for free-threaded deferred-dealloc noise). Passes on 3.13/3.13t/3.14/3.14t; verified to fail on the unfixed build (+226 on 3.13).
