# BUG-273 — `execute_task_send` / `_execute_task_throw` over-release the dispatch-owned task reference

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🔴 Critical — Double-free / UAF of `PythonTaskObject`
- **Files**:
  - `src/task/callbacks.zig:547-550` (`GetRaisedException() orelse { py_decref(task); return error.PythonError; }`)
  - `src/task/callbacks.zig:553-555` (errdefer + success-path decref around `future_fast_set_exception`)
  - `src/task/callbacks.zig:623-626, 629-631` (mirror in `execute_task_send`)
  - `src/callback_manager.zig:559-570` (manager invokes `cleanup(user_data)` = `cleanup_task` = plain `py_decref(task)` on error)
  - `src/task/constructors.zig:50-52` (registration with `.cleanup = &callbacks.cleanup_task`)
- **Lessons**: [Memory & Reference Counting](../lessons/01-memory-and-reference-counting.md), [Python C API Correctness §Lesson 97](../lessons/05-python-c-api-correctness.md)
- **Description**: The executor contract (verified across conforming callbacks like `callback_for_python_generic_callbacks`) is: func self-releases on SUCCESS only; on error the manager runs cleanup. These wrappers violate it on all three error shapes (null pending exception, `future_fast_set_exception` failure via errdefer, and the local decref before returning). Each path decrefs the dispatch-owned ref locally AND again via `cleanup_task`. The BUG-198 leak fix overshot into over-release.
- **Trigger**: `_leave_task` failure with a cleared error indicator (see BUG-292 trampoline clobber), OOM inside `dispatch_guaranteed`, or any `future_fast_set_exception` failure.
- **Consequences**: Task object freed while the future/registry may still hold it → UAF, corrupted `asyncio.current_task()` state.
- **Fix (Proposed)**: Remove the local decrefs from the catch blocks; rely solely on manager cleanup (matching the contract used everywhere else).
