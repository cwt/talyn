# BUG-368 — `BTree` child pointer shifting leaves duplicate/dangling pointer at `childs[nkeys + 1]` causing use-after-free in `change_parent`, and `split_nodes` leaks `new_node1` on OOM

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — use-after-free write (`c.parent = new_parent`) into a freed `BTree` node during timer/BTree churn (insertions after deletions), plus memory leak on OOM in `split_nodes`
- **Category**: Use-After-Free (UAF) & Memory Leak
- **Files**:
  - `src/utils/btree.zig:211-217, 253-283, 359-365, 394-408`
- **Related**: [BUG-1](001.md), [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/utils/btree.zig`, each `Node` has `keys: [M]Item` and `childs: [M + 1]?*Node`. Look at how `delete_from_right` (lines 359–365) and `delete_key_from_node` (lines 394–408) shift child pointers when `nkeys` decreases:

```zig
const nkeys = node.nkeys - 1;
for (index..nkeys) |i| {
    node.keys[i] = node.keys[i + 1];
    node.childs[i] = node.childs[i + 1];
}
node.childs[nkeys] = node.childs[nkeys + 1];
node.nkeys = nkeys;
```

Notice that `node.childs[nkeys]` receives a copy of `node.childs[nkeys + 1]`, **and `node.childs[nkeys + 1]` is never set to `null`**! Thus `node.childs[nkeys]` and `node.childs[nkeys + 1]` both point to the exact same child node.

Now trace what happens when that child nodelater becomes empty (`node.nkeys == 0`) in `delete_key_from_node` (`src/utils/btree.zig:396-406`):

```zig
if (node.nkeys == 0) {
    if (node.parent) |parent| {
        for (&parent.childs) |*child| {
            if (child.* == node) {
                child.* = null;
                break;
            }
        }
    } else {
        tree.root = null;
    }

    tree.allocator.destroy(node);
}
```

Because the loop stops at the **first** matching slot (`break;`), it nulls out `parent.childs[nkeys]` while **leaving the duplicate pointer at `parent.childs[nkeys + 1]` pointing to the destroyed `node`**!

Later, when `parent` splits or rebalances and calls `change_parent` (`src/utils/btree.zig:211-217`):

```zig
fn change_parent(new_parent: *Node) void {
    for (new_parent.childs) |child| {
        if (child) |c| {
            c.parent = new_parent;
        }
    }
}
```

`change_parent` iterates over **all `M + 1` elements** of `new_parent.childs` (not `0..new_parent.nkeys + 1`) and executes `c.parent = new_parent;` on the freed `node` pointer left behind in `childs[nkeys + 1]` — a **use-after-free write**!

Additionally, in `split_nodes` (`src/utils/btree.zig:253-254`):

```zig
const new_node1 = try tree.allocator.create(Node);
const new_node2 = try tree.allocator.create(Node);
```

There is no `errdefer tree.allocator.destroy(new_node1);` between lines 253 and 254, leaking `new_node1` if allocating `new_node2` fails.

## Trigger Scenario

1. Insert enough timers/keys into `BTree` to create internal and leaf nodes.
2. Delete keys from a node so `delete_from_right` / `delete_key_from_node` shifts `childs[nkeys] = childs[nkeys + 1]` without nulling `childs[nkeys + 1]`.
3. Delete the remaining keys in that child so `tree.allocator.destroy(node)` frees it (nulling only the first duplicate pointer in `parent.childs`).
4. Insert or rebalance `parent` so `change_parent(parent)` runs -> writes `c.parent = new_parent` into freed `node`.

## Proposed Remediation

1. In both `delete_from_right` (`src/utils/btree.zig:363`) and `delete_key_from_node` (`src/utils/btree.zig:394`), set `node.childs[nkeys + 1] = null;` right after `node.childs[nkeys] = node.childs[nkeys + 1];`.
2. In `change_parent` (`src/utils/btree.zig:211-217`), iterate only over `new_parent.childs[0 .. new_parent.nkeys + 1]` (or clear unused child slots to `null` in `split_nodes`).
3. In `split_nodes` (`src/utils/btree.zig:253`), add `errdefer tree.allocator.destroy(new_node1);` before allocating `new_node2`.


## Resolution (2026-10-18)

All three defects confirmed live in `src/utils/btree.zig` and fixed:

1. **Duplicate/dangling child pointer after shifts (fixed)**:
   `delete_from_right` and `delete_key_from_node`'s else branch complete
   the left-shift with `childs[nkeys] = childs[nkeys + 1]` and now
   clear `childs[nkeys + 1] = null` — the slot is beyond the valid
   child range of a node with `nkeys` keys. Without the clear, the
   destroy of the later-emptied child nulled only the first matching
   slot, leaving the duplicate alias in the array for `change_parent`
   to write into (`c.parent = new_parent` into freed memory).

2. **`split_nodes` OOM leak (fixed)**: `errdefer`s destroy `new_node1`
   around `split_node` / the second `create_node` / `split_root_node`
   (and `new_node2` around `split_root_node`). The post-`try`
   statements are infallible, so the errdefers are scoped exactly to
   the failure windows.

3. **Adjacent overflow found by the new test (fixed)**:
   `delete_key_from_node` walked
   `p_node.childs[0..(p_node.nkeys + 1)]` with the addition in the
   `nkeys` field's own tiny integer type — for Degree 3 (which
   production uses: `unix_signals.CallbacksBTree =
   BTree(u6, Callback, 3)` in src/loop/unix_signals.zig) the field is
   `u2`, so a FULL node (`nkeys == Degree`) overflowed with `3 + 1`
   and panicked. The bound is now computed in `usize`
   (`@as(usize, p_node.nkeys) + 1`).

## Test

Two unit tests appended to `src/utils/btree.zig`:

- `BUG-368: child shifting never leaves a pointer beyond the valid
  range` — a Degree-3 `BTree(i32, i32, 3)` churned across twelve PRNG
  seeds (insert 128 shuffled keys, delete half checking after every
  delete, delete the rest, re-insert a third, drain); after each step
  a recursive walker asserts every node's `childs[nkeys + 1..]` are
  null (no dangling duplicate beyond the valid range) and every child's
  `parent` back-pointer matches.
- `BUG-368: OOM while splitting does not leak nodes` —
  `std.testing.FailingAllocator` failing allocation indexes 1..5 in
  turn on a Degree-3 tree pumped to 40 keys (index 2 = the root split's
  `new_node2` — the exact OOM window the errdefer covers), drained and
  deinit'ed each time; the testing allocator teardown reports any leak.

**Bite verification**: with the fixes removed and the tests kept, the
invariant test fails inside `S.check` (`DanglingChildSlot` — the
shift-duplicate is live) stranding 58 nodes as teardown leaks, and the
OOM test fails with `leaked 1 allocations` (the pre-fix `new_node1`
leak). Green post-fix: 131/131 zig tests (utils 24/24), 419 passed × 4
pythons in ReleaseFast.
