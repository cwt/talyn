# BUG-174 — Leaked task Python reference on error in `py_wake_up`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — reference count leak
- **Files**: `src/task/callbacks.zig:582-602`
- **Lessons**: [Python C API Integration §Lesson 10](../lessons/03-python-c-api-integration.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: In `src/task/callbacks.zig`, `py_wake_up` is the C callback invoked when a future completes. When registered, `task` was incremented with `py_newref(self)`. If `PyObject_GetAttrString(py_future, "result")` returns `null` or `PyErr_GetRaisedException()` fails, `py_wake_up` returns `null` immediately without calling `python_c.py_decref(task)`.
- **Trigger**: Future completion raising an exception during result extraction.
- **Consequences**: Permanent reference count leak of the awaiting `Task` object.
- **Fix**: Added `python_c.py_decref(@ptrCast(instance))` on all error exit paths in `py_wake_up`.
