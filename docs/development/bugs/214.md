# BUG-214 — Invalid Pointer Comparison and Redundant UTF-8 Decode in z_loop_add_path_watcher

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Logic Bug & Redundant Decoding
- **Files**: `src/loop/python/control.zig:301-303`
- **Lessons**: [Type Safety §Lesson 8](../lessons/008-type-safety.md), [Python C-API §Lesson 3](../lessons/003-python-c-api-best-practices.md)
- **Description**: In `src/loop/python/control.zig`, `z_loop_add_path_watcher` calls `const path_len = python_c.PyUnicode_AsUTF8AndSize(py_path, null);` and checks `if (path_len < 0) return error.PythonError;`. `PyUnicode_AsUTF8AndSize` returns a pointer (`?[*c]const u8`), not an integer length. Comparing a pointer to `< 0` is invalid logic in Zig/C, and is immediately followed by a redundant call to `PyUnicode_AsUTF8`.
- **Trigger**: Adding a path watcher with `loop.add_path_watcher(path, callback)`.
- **Consequences**: Flawed error checking and redundant string conversion on filesystem watcher registration.
- **Fix**: Use `var size: python_c.Py_ssize_t = 0; const path_ptr = python_c.PyUnicode_AsUTF8AndSize(py_path, &size) orelse return error.PythonError;`.
