# BUG-375 — `talyn/loop.py` SSL transport bugs: plaintext dropped on `SSLWantReadError`/`SSLWantWriteError`, ciphertext dropped via `os.write` on `BlockingIOError`, unflushed `_write_buffer` on `resume_writing`, and unclosed socket on handshake timeout error

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — causes silent plaintext and TLS ciphertext data loss, `ssl.SSLError: BAD_RECORD_MAC` stream corruption under socket backpressure, permanent write stalls after `pause_writing()`/`resume_writing()`, and leaked sockets on failed TLS handshakes
- **Category**: Logic Bug (SSL Data Loss, Stream Corruption, Write Stall, & FD Leak)
- **Files**:
  - `talyn/loop.py:60-123, 688-698, 900-918, 963-975, 1025-1031, 1180-1190, 1398-1408, 1522-1599`
- **Related**: [Lesson 55](../lessons/06-network-protocols-and-io.md)

## Overview & Root Cause

In `talyn/loop.py`, the TLS/SSL layer has four severe correctness bugs across `_SSLTransportWrapper` and the 5 duplicated SSL protocol state machines:

1. **`_SSLTransportWrapper.write` silently drops application plaintext on `SSLWantReadError` / `SSLWantWriteError` (`talyn/loop.py:60-68`)**:
   ```python
   def write(self, data):
       if self._closing or not self._ssl_protocol._handshake_done:
           return
       try:
           self._ssl_protocol._sslobj.write(data)
           self._ssl_protocol._flush()
       except (ssl.SSLWantReadError, ssl.SSLWantWriteError):
           pass
       except ssl.SSLError as exc:
           self._ssl_protocol._on_error(exc)
   ```
   Notice that if `self._ssl_protocol._sslobj.write(data)` raises `SSLWantReadError` or `SSLWantWriteError` (or if `write()` is called before `_handshake_done`), `data` is **never buffered** and is silently dropped on the floor! Even when `self._ssl_protocol._sslobj.write(data)` only consumes part of `data` (returning the byte count written), the return value of `_sslobj.write(data)` is ignored!

2. **Direct `os.write(fd, view)` in `_flush_write_buffer` and `SP._f` silently drops TLS ciphertext on `BlockingIOError` (`EAGAIN`) and races with `WriteTransport` (`talyn/loop.py:688-698, 908-918, 1180-1190, 1398-1408, 1522-1527`)**:
   ```python
   def _flush_write_buffer(self):
       data = self._outgoing.read()
       if data:
           if self._fd >= 0:
               view = memoryview(data)
               while view:
                   try:
                       n = os.write(self._fd, view)
                       view = view[n:]
                   except OSError:
                       break
           elif self._transport is not None:
               self._transport.write(data)
   ```
   - `self._outgoing.read()` **destructively consumes** the encrypted TLS records from OpenSSL's `MemoryBIO`.
   - It then calls `os.write(self._fd, view)` directly on a **non-blocking socket**!
   - Whenever the kernel socket send buffer fills up (a normal occurrence on any bulk TLS transfer), `os.write` raises `BlockingIOError` (`EAGAIN`, which is a subclass of `OSError`).
   - The `except OSError: break` clause catches `BlockingIOError`, exits the `while` loop, and **throws away the remaining `view` bytes of the encrypted TLS record**!
   - The peer receives a truncated TLS record followed by the next TLS record, immediately failing with `ssl.SSLError: [SSL: DECRYPTION_FAILED_OR_BAD_RECORD_MAC] decryption failed or bad record mac`!
   - Even worse, in `start_tls` (`talyn/loop.py:1522-1599`), `SP._f` uses `os.write(self._fd, v)` only when `len(d) <= 16384` and `self._t.write(d)` (which queues via `io_uring`) when `len(d) > 16384`, interleaving synchronous `os.write` syscalls ahead of queued `io_uring` writes and scrambling TLS record order!

3. **4 of the 5 SSL protocol classes fail to call `_flush_write_buffer()` in `resume_writing()` (`talyn/loop.py:727-730, 956-959, 1219-1222, 1437-1440` vs `1596-1599`)**:
   In `_create_ssl_connection` (both timeout and non-timeout versions), `_create_ssl_server`, and `create_unix_connection`, `resume_writing` is implemented as:
   ```python
   def resume_writing(self):
       self._write_paused = False
       if self._app_protocol_has_pause:
           self._app_protocol.resume_writing()
   ```
   When `_write_paused` was `True`, `_flush()` buffered encrypted data in `self._write_buffer` instead of calling `_flush_write_buffer()`. When `resume_writing()` is called, it sets `self._write_paused = False` **without calling `self._flush_write_buffer()`**, leaving `self._write_buffer` stranded until the application happens to write more data!

4. **`_create_ssl_connection` with `ssl_handshake_timeout` leaks the open socket/transport when handshake fails (`talyn/loop.py:963-975` vs `1025-1031`)**:
   Compare the non-timeout version at lines 1025–1031 (which has `try: await waiter except BaseException: raw_transport.close(); raise`) with the `ssl_handshake_timeout is not None` version at lines 963–975:
   ```python
   raw_transport, _ = await self._create_connection_zig(...)
   await waiter
   return ssl_protocol._ssl_transport, app_protocol
   ```
   If `await waiter` raises `TimeoutError` or `ssl.SSLError` (or is cancelled), `raw_transport.close()` is **never called**, leaking the open TCP connection!

## Trigger Scenario

1. Send a multi-megabyte payload over HTTPS/TLS using `loop.create_connection(..., ssl=ctx)` -> as soon as the kernel socket send buffer returns `EAGAIN`, `_flush_write_buffer` catches `BlockingIOError` and drops the rest of the TLS record, corrupting the TLS connection.
2. Connect with `ssl_handshake_timeout=0.01` to a slow server -> `await waiter` raises `TimeoutError` and leaks `raw_transport`.

## Proposed Remediation

1. Never call `os.write(self._fd, ...)` directly on a socket managed by `StreamTransport`; always pass `self._outgoing.read()` to `self._transport.write(data)` so `WriteTransport` handles non-blocking `io_uring` writes, partial writes, and flow-control watermarks cleanly.
2. In `_SSLTransportWrapper.write`, buffer any unconsumed plaintext slice when `_sslobj.write(view)` returns `< len(view)` or raises `SSLWantReadError` / `SSLWantWriteError`, and drain that plaintext buffer inside `_flush()` / `data_received()`.
3. Call `self._flush_write_buffer()` inside `resume_writing()` across all SSL protocol classes (and deduplicate all 5 SSL protocol classes into a single shared implementation).
4. Wrap `await waiter` in `try: ... except BaseException: raw_transport.close(); raise` in `_create_ssl_connection` (`talyn/loop.py:967`).


## Resolution (2026-10-19)

All four defect classes confirmed live in the current code (which has
evolved past the report's line snapshot — the current `_f` machines
write through `self._raw_t.write` and only bypass to `os.write()` when
the raw transport raises its paused `RuntimeError`, the Want flags
already exist, and `on_timeout` already closes the transport when the
timeout itself fires) and fixed:

1. **Plaintext dropped on Want / partial write (fixed)**:
   `_SSLTransportWrapper.write` now buffers the plaintext
   (`self._write_buffer`) whenever `_sslobj.write` raises
   `SSLWantReadError`/`SSLWantWriteError`, and honors the
   partial-write return by requeueing the unconsumed remainder.
   `_flush_write_buffer`'s drain loop got the same partial handling
   (breaking out of the drain loop if `written == 0` to avoid spinning when
   no bytes can be consumed).

2. **`os.write()` ciphertext bypass (fixed)**: both bypass sites (the
   wrapper's `_flush_write_buffer` and the `SP._f` inside
   `_create_ssl_connection`) now re-queue the un-writable ciphertext
   into the outgoing `MemoryBIO` (`outgoing.write(d)` / break),
   instead of raw `os.write()` that lost the tail on EAGAIN
   (truncated TLS records → peer `BAD_RECORD_MAC`) and interleaved
   syscalls with the queued io_uring writes. `os.write` no longer
   appears in talyn/loop.py.

3. **`resume_writing()` missing wrapper flush (fixed)**: SP#1,
   SP#3 and SP#4 now call `self._wrapper._flush_write_buffer()`
   before `self._f()` (SP#2 already did), so plaintext stranded in the
   wrapper's buffer while writing was paused is drained on resume.

4. **Failed handshake with `ssl_handshake_timeout` leaking the raw
   transport (fixed)**: the timeout branch's `except BaseException`
   now mirrors the non-timeout branch — `transport.close()` on any
   failure out of `await waiter` (pepeer `SSLError`, or cancellation
   of the awaiting task), not only when the timeout itself fired.

## Test

`tests/test_ssl_375.py` (7 tests): five deterministic unit fixtures
around `_SSLTransportWrapper` with scripted `SSLSocket.write`
outcomes — Want-read/Want-write buffering, partial-write remainder
requeue (in `write` and in `_flush_write_buffer`), and the paused-raw
ciphertext requeue (a fake raw transport raising the paused error and
failing loudly on `get_extra_info` so any surviving `os.write`
bypass cannot silently pass) — plus two real-socket tests:

- `...handshake_ssl_error_closes_raw_transport`: a plain server that
  mirrors the ClientHello back (the client's `do_handshake` fails
  with `ssl.SSLError` long before the 5 s handshake timeout) — the
  server side must observe `connection_lost`.
- `...handshake_cancel_closes_raw_transport`: the awaiting task is
  cancelled mid-handshake against a never-answering stall server —
  same server-side observable.

**Bite verification**: reverting talyn/loop.py to tip, ALL 7 tests
fail (Want/partial plaintext dropped, buffer empty; paused ciphertext
lost; leaked sockets keep the server's connection open). Post-fix:
131/131 zig tests, 439 passed + 1 skipped × 4 pythons in ReleaseFast
gate. Also updated the pre-existing `test_ssl_transport_wrapper_write`
fixture: its fake `SSLSocket.write` returned `None`, violating the
real byte-count contract, which the new partial-write handling reads.
