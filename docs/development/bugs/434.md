# BUG-434 — `InlineQueue` promotion does not clear `inline_len`

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium (latent major) — double-pop / double-decref after heap drain
- **Category**: Data structure / SBO invariant
- **Files**: `src/future/callback.zig:71-108`
- **Related**: [BUG-414](414.md) (SBO), [BUG-341](341.md), [BUG-297](297.md)

## Description

```zig
// promote the inline buffer to the heap, then append
var heap: Heap = .empty;
...
heap.appendSliceAssumeCapacity(self.inline_buf[0..self.inline_len]);
heap.appendAssumeCapacity(value);
self.heap = heap;                 // <-- missing: self.inline_len = 0;
```

`items()`/`itemsMut()` are heap-authoritative only while `heap.items.len > 0`. After promotion
`inline_len` still equals `N`; once the heap is drained, the **stale inline span reappears** and `pop()`
returns already-owned entries. The test at `callback.zig:382-435` asserts the "inline span empty from
promote onward" invariant, but it only passes because `pop()`'s phantom decrement (`heap empty →
inline_len -= 1`) silently cleans it up.

## Trigger

Draining an `InlineQueue` to empty (e.g. the ExceptionGroup tuple path) then popping/inspecting it.

## Consequences

Double decref / GC visiting freed objects.

## Fix

Add `self.inline_len = 0;` immediately after `self.heap = heap;`.

## 2026-11-12 Validation

- Defect confirmed: promotion does `self.heap = heap;` with no `self.inline_len = 0;`
  (`callback.zig:82-87`), and `items()`/`itemsMut()` (`:57-69`) fall back to
  `inline_buf[0..inline_len]` whenever `heap.items.len == 0` — the stale span re-emerges after the
  heap drains.
- The invariant test's final `expectEqual(0, q.items().len)` (`:433-434`) passes only because
  `pop()`'s else-branch (`:96`) performs a phantom `inline_len -= 1` after the heap empties.
- Latent today: the sole production pop caller (the `run_python_future_set_callbacks` errdefer drain,
  `:159-165`) over-pops until `itemsMut().len == 0`, so it self-heals the stale span before any other
  reader (`Future.release`/traverse) observes it — no live double-decref on current paths. The
  one-line fix remains required for safety.

## Resolution (2026-11-12)

`InlineQueue.append` promotion now sets `self.inline_len = 0;` immediately after
`self.heap = heap;` — the queue is heap-authoritative from promotion onward, so a drained heap can
no longer fall back to the already-owned inline span. The invariant test now asserts the fix
**structurally** (`inline_len == 0` right after promotion and after the drain) instead of passing
transitively via `pop()`'s phantom decrement.

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (499 pytest passed on
py3.15, 498 + 1 skipped on py3.15t; stdlib asyncio green on both).
