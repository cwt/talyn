# BUG-248 — SocketCreationData.dns_timeout is never populated in hostname connect path of create_connection

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Silent functional omission / argument ignore
- **Files**: `src/loop/python/io/client/create_connection.zig`
- **Lessons**: [Defensive §Lesson 79 — Silent Failure](../lessons/10-defensive-programming-and-code-quality.md), [Python §Lesson 81 — Argument Validation](../lessons/11-python-c-api-and-abi-stability.md)
- **Description**: In `src/loop/python/io/client/create_connection.zig`, `py_dns_timeout` is parsed from vectorcall keyword arguments into `creation_data.py_dns_timeout`. However, the code converting `creation_data.py_dns_timeout` into `Resolv.DnsTimeout` was only written inside the `if (py_sock) |v|` branch (which operates on already-connected sockets and never performs DNS resolution). In the main branch where `py_sock == null` (resolving hostname and establishing a TCP socket), `creation_data.dns_timeout` is never populated and remains `null`.
- **Trigger**: Invoking `await loop.create_connection(..., host="example.com", port=80, dns_timeout=2.0)`.
- **Consequences**:
  1. User-supplied `dns_timeout` values are silently ignored in all client socket connections, always falling back to the default DNS timeout.
  2. Passing invalid types (e.g. `dns_timeout="invalid"`) is never evaluated, failing to raise the expected `TypeError`.
- **Resolution**: Move `dns_timeout` parsing and validation to the start of `z_loop_create_connection` immediately after keyword argument parsing, populating `creation_data.dns_timeout` before any connection branching.
- **Verification**: Test with `loop.create_connection(..., dns_timeout=...)` and verify timeout enforcement and `TypeError` on invalid arguments.
