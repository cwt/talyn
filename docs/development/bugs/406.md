# BUG-406 — `flags` ignored by `getaddrinfo`/`getnameinfo`; `host=None` unsupported

- **Status**: 🟢 Fixed (2026-11-01)
- **Severity**: 🟡 Medium — silent behavioral divergence from `socket.getaddrinfo`/`socket.getnameinfo`
- **Category**: POSIX API Compliance / DNS
- **Files**:
  - `src/loop/python/io/socket/getaddrinfo.zig:147-208` — flags parsed, never applied
  - `src/loop/python/io/socket/getnameinfo.zig:114-169` — flags stored in `GetNameInfoData`, never read
- **Related**: [BUG-320](320.md) (get_extra_info signatures), [BUG-384](384.md)

## Overview

`z_loop_getaddrinfo` declares `py_flags` and passes it to `parse_vector_call_kwargs`, then never uses it; the `defer` only decrefs it. `z_loop_getnameinfo` stores `flags` in `GetNameInfoData` (`getnameinfo.zig:150`) but `getnameinfo_callback` never reads the field.

Consequences:

- `AI_NUMERICHOST` with a non-numeric host still performs DNS/resolution instead of raising `EAI_NONAME`.
- `NI_NUMERICHOST` still performs a PTR lookup and can fail/hang instead of returning the numeric address immediately.
- `host=None` with `AI_PASSIVE` (valid stdlib usage for wildcard binds) raises `TypeError` because `PyUnicode_AsUTF8AndSize(None, ...)` is called unconditionally.

## Trigger Scenario and Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, ReleaseFast, Python 3.13.16 and 3.13.16t.

Repro: `h11_flags.py`.

```text
--- AI_NUMERICHOST on 'localhost' (not numeric) ---
RESULT: FAIL (flags ignored) returned ((2, 1, 0, None, ('127.0.0.1', 80)),)

--- NI_NUMERICHOST on 192.0.2.1 (TEST-NET, no PTR) ---
RESULT: FAIL raised RuntimeError: Failed to resolve name after 0.011s

--- host=None with AI_PASSIVE ---
RESULT: FAIL raised TypeError bad argument type for built-in operation
```

Reference behavior:

- `socket.getaddrinfo("localhost", 80, flags=AI_NUMERICHOST)` raises `socket.gaierror`.
- `socket.getnameinfo(("192.0.2.1", 80), NI_NUMERICHOST)` returns `("192.0.2.1", "80")` immediately.
- `socket.getaddrinfo(None, 0, type=SOCK_STREAM, flags=AI_PASSIVE)` returns wildcard entries.

## Proposed Remediation

Either implement the flags or reject non-zero flags explicitly with `NotImplementedError`/`ValueError` until implemented:

- `AI_NUMERICHOST`: skip DNS, parse the literal only.
- `AI_PASSIVE` + `host is None`: use wildcard addresses for the requested family.
- `NI_NUMERICHOST`: skip `reverse_lookup` and format `addr` directly.
- `NI_NAMEREQD`: return an error instead of falling back to the numeric address.
- Validate unsupported flag bits and raise rather than ignoring them.

Add tests comparing against `socket.getaddrinfo`/`socket.getnameinfo` for each supported flag.

## Resolution (2026-11-01)

- `getaddrinfo`: `flags` is narrowed with `checkedNarrow` and validated against `AI_PASSIVE|AI_NUMERICHOST|AI_ADDRCONFIG|AI_NUMERICSERV`; unknown bits raise `ValueError`. `AI_NUMERICHOST` resolves literals only, `host=None` yields loopback, and `host=None` with `AI_PASSIVE` yields the wildcard address.
- `getnameinfo`: flags are validated against `NI_NUMERICHOST|NI_NUMERICSERV|NI_NOFQDN|NI_NAMEREQD|NI_DGRAM`; `NI_NUMERICHOST` returns the numeric tuple without a PTR lookup, and `NI_NOFQDN` truncates the returned name at the first dot.

Verification: new `test_getaddrinfo_ai_numerichost_rejects_hostname` and `test_getnameinfo_ni_numerichost_skips_reverse_dns`, updated `test_getaddrinfo_missing_host`, and external repro `h11_flags.py` on 0.16.0/0.17.0 GIL and free-threaded.
