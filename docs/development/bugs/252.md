# BUG-252 — Uninitialized node access and GPA node leak in DNS ControlData.release()

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Undefined memory access on error & heap memory leak
- **Files**: `src/loop/dns/resolv.zig`
- **Lessons**: [Defensive §Lesson 46 — Allocation & Initialization Order](../lessons/10-defensive-programming-and-code-quality.md), [Memory §Lesson 55 — Double Free & Leak Prevention](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/loop/dns/resolv.zig:708`, `control_data.node` is assigned `undefined` during `prepare_data` initialization and only assigned a valid node pointer on line 726 (`create_new_node`). If any allocation between lines 712 and 726 fails, `errdefer control_data.release()` executes `self.loop.dns.pending_queries.unlink_node(self.node)` with an uninitialized node pointer, leading to undefined memory reads / SIGSEGV. Furthermore, `loop.dns.pending_queries` creates nodes with `loop.allocator` (GPA), but when `unlink_node` is called in `ControlData.release()`, `pending_queries.release_node(node)` is never called, leaking the node structure in the GPA on every completed DNS query.
- **Trigger**: DNS resolution query completion, cancellation, or allocation failure in `prepare_data`.
- **Consequences**: Undefined memory access on early allocation errors and continuous memory leakage of `LinkedList.Node` structs over the lifetime of the event loop.
- **Resolution**:
  1. Change `node: ?PendingList.Node = null` in `ControlData` and initialize it explicitly to `null`.
  2. In `ControlData.release()`, check `if (self.node) |node|`, call `unlink_node(node)`, invoke `self.loop.dns.pending_queries.release_node(node)`, and reset `self.node = null`.
- **Verification**: Run DNS lookups under debug GPA leak detection and verify zero memory leaks.
