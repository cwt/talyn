# BUG-253 — fixed_file_index uninitialized in stream_init_configuration for internal new_stream_transport callers

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — Defensive programming / field initialization consistency
- **Files**: `src/transports/stream/constructors.zig`
- **Lessons**: [Defensive §Lesson 49 — Struct Literal Default vs Struct Allocation](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: While `fixed_file_index = 0` was added to `z_stream_new` in commit `948` (BUG-238), `z_stream_new` is only invoked when Python code calls `talyn.StreamTransport(...)`. When transports are created internally by `create_connection` or `create_server`, they call `new_stream_transport` which allocates memory directly via `tp_alloc` and invokes `stream_init_configuration`. If `loop_data.io.register_fixed_file(fd)` returns `null` (e.g. fixed files disabled, fixed file table full, or fallback path), `self.fixed_file_index` was not explicitly assigned `0` in `stream_init_configuration`.
- **Trigger**: Creating stream transports via `create_connection` or `create_server` when fixed files registration is disabled or fails.
- **Consequences**: Inconsistent initialization in non-zeroed memory configurations.
- **Resolution**: Explicitly assign `self.fixed_file_index = 0;` inside `stream_init_configuration` alongside `self.dispatch_generation = 0;`.
- **Verification**: Verify fixed file fallback paths and field initialization during transport creation.
