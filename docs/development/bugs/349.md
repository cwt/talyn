# BUG-349 — `parse_vector_call_kwargs` casts `kwargs_len` to `usize` before checking `if (kwargs_len < 0)` (Mandate #1 panic)

- **Status**: ✅ Fixed (2026-10-18)
- **Severity**: 🔴 Critical — violates Architectural Mandate #1 (NO PANICS in the IO Path) and causes an integer cast panic or `usize` underflow in the central keyword-argument parser used by nearly every `METH_FASTCALL | METH_KEYWORDS` entrypoint
- **Category**: Logic Bug (Integer Cast Panic / Mandate #1 Violation)
- **Files**:
  - `src/python_c.zig:505-516`
- **Related**: [Architectural Mandate #1](../architectural-mandates.md), [BUG-324](324.md)

## Overview & Root Cause

In `src/python_c.zig:505-516`, `parse_vector_call_kwargs` calls `PyTuple_Size(knames_tuple)` (which returns `-1` on error) and casts `kwargs_len` (`isize`) to `usize` on line 511 **before** the `if (kwargs_len < 0)` check on line 512:

```zig
pub inline fn parse_vector_call_kwargs(
    knames: ?*PyObject, args_ptr: [*]?*PyObject,
    comptime target_names: []const [:0]const u8,
    values: []const *?*PyObject
) !void {
    if (knames) |knames_tuple| {
        const kwargs_len = PyTuple_Size(knames_tuple);
        const args = args_ptr[0..@as(usize, @intCast(kwargs_len))];
        if (kwargs_len < 0) {
            return error.PythonError;
        }
```

If `PyTuple_Size(knames_tuple)` returns `-1`, line 511 executes `@as(usize, @intCast(-1))` before line 512 is ever reached, panicking in `Debug`/`ReleaseSafe` builds and creating a `std.math.maxInt(usize)` slice in `ReleaseFast`.

## Trigger Scenario

Any error return (`-1`) from `PyTuple_Size(knames_tuple)` in `parse_vector_call_kwargs` hits `@intCast(kwargs_len)` on line 511 before the negative check on line 512.

## Proposed Remediation

Move `if (kwargs_len < 0) return error.PythonError;` **above** `const args = args_ptr[0..@as(usize, @intCast(kwargs_len))];`:

```zig
const kwargs_len = PyTuple_Size(knames_tuple);
if (kwargs_len < 0) {
    return error.PythonError;
}
const args = args_ptr[0..@as(usize, @intCast(kwargs_len))];
```

## Resolution (2026-10-18)

Moved `if (kwargs_len < 0) return error.PythonError;` above the `@as(usize, @intCast(kwargs_len))` slice in `parse_vector_call_kwargs` (`src/python_c.zig`), exactly as proposed. The subsequent `if (kwargs_len <= len) / else if (kwargs_len > len)` chain is preserved. `merge_vector_call_args` already had the correct order and is unchanged.

Tests:

- Added a dedicated `python_c` unit-test binary to `build.zig` (the module previously had no test target, so its tests were never collected): `zig build test` now runs it alongside `talyn`/`utils`/`callback_manager`/`linter-rules`.
- `BUG-349: parse_vector_call_kwargs checks PyTuple_Size error before usize cast` — passes a non-tuple `knames` so `PyTuple_Size` returns -1; asserts `error.PythonError` with no slots populated. Verified to panic with `integer does not fit in destination type` on the pre-fix code.
- `BUG-349: parse_vector_call_kwargs still parses valid keyword tuples` — happy-path guard for the reordered logic.
