# BUG-133 — Inverted `errdefer` in `Future.add_done_callback` pops empty exceptions queue

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — panic on memory allocation failure in future callback addition
- **Files**: `src/future/callback.zig:204-208`
- **Lessons**: [Zig §Lesson 77](../lessons/08-zig-specific-patterns.md), [Zig §Lesson 88](../lessons/08-zig-specific-patterns.md)
- **Description**: In `Future.add_done_callback`, after appending to `self.callbacks_queue`, the code declares:
  ```zig
  try self.callbacks_queue.append(self.allocator, callback);
  errdefer _ = self.exceptions_queue.pop();
  try self.exceptions_queue.ensureTotalCapacity(self.allocator, self.callbacks_queue.items.len);
  ```
  The `errdefer` intends to roll back the append to `callbacks_queue`, but instead pops from `exceptions_queue` (which was not appended to and may be empty).
- **Trigger**: An `error.OutOfMemory` occurring during `exceptions_queue.ensureTotalCapacity`.
- **Consequences**: `exceptions_queue.pop()` panics on an empty list while leaving the newly appended callback in `callbacks_queue`, corrupting the future's internal callback queue.
- **Fix**: Corrected the `errdefer` in `src/future/callback.zig` to call `_ = self.callbacks_queue.pop();`.
