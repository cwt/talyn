# BUG-147 — `FDWatcher` struct and `handle` PyObject leak on Loop release with active watchers

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium-High — heap memory and Python object leak on loop shutdown
- **Files**: `src/loop/main.zig:152-158`
- **Lessons**: [Event Loop §Lesson 56](../lessons/03-event-loop-lifecycle.md), [Event Loop §Lesson 84](../lessons/03-event-loop-lifecycle.md)
- **Description**: In `Loop.release()`, lines 152-156 drain remaining fd watchers before `io.deinit()`:
  ```zig
  var sig: std.posix.fd_t = undefined;
  while (self.reader_watchers.pop(&sig)) |_| {}
  while (self.writer_watchers.pop(&sig)) |_| {}
  ```
  The returned `*FDWatcher` is discarded in `|_| {}` without calling `allocator.destroy(watcher)` or `python_c.py_decref(watcher.handle)`.
- **Trigger**: Closing an event loop (`loop.close()`) while `add_reader` or `add_writer` watchers are still registered.
- **Consequences**: Heap memory allocated for `FDWatcher` and the Python `Handle` object reference are leaked permanently.
- **Proposed Fix**: Capture the popped `*FDWatcher` and invoke `loop_watchers_cleanup_callback` (or call `allocator.destroy(watcher)` and `python_c.py_decref(watcher.handle)` directly).
