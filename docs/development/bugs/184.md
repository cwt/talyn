# BUG-184 — Premature decref / refcount underflow on positional arguments in set_write_buffer_limits

- **Status**: ✅ Fixed
- **Severity**: 🔴 Critical — Python object reference count corruption
- **Files**: `src/transports/stream/write.zig:78-99`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/01-memory-and-reference-counting.md), [Python C API §Lesson 21](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/transports/stream/write.zig`, `z_stream_set_write_buffer_limits` read positional arguments directly into `py_high_water_mark` and `py_low_water_mark` (which were borrowed pointers from the caller). A `defer` block unconditionally executed `python_c.py_xdecref(py_high_water_mark)` and `python_c.py_xdecref(py_low_water_mark)`. When positional arguments were passed, their refcounts were decremented below zero or prematurely freed.
- **Trigger**: Calling `transport.set_write_buffer_limits(high, low)` with positional arguments.
- **Consequences**: Python integer constants or integer objects corrupted, premature deallocation, crashes.
- **Fix**: Wrapped positional argument assignments with `python_c.py_newref(...)` so that all paths hold an owned reference balanced by the `defer` decref. Added unit test in `tests/transports/test_stream.py`.
