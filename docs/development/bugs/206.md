# BUG-206 — deinitialize_object_fields Refcount Leak on ob_base Structs

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — Refcount & Memory Leak
- **Files**: `src/python_c.zig:604-614`, `src/loop/python/io/server/create_server.zig:33-40`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/01-memory-and-reference-counting.md), [Defensive Programming §Lesson 49](../lessons/08-zig-specific-patterns.md)
- **Description**: In `src/python_c.zig`, `deinitialize_object_fields` traverses struct fields to release held Python references. The `.optional` branch explicitly checks `if (data2.child == Python.PyObject)` and ignores fields typed as optional pointers to Python wrapper structs (e.g., `?*FutureObject`, `?*LoopObject`, `?*TaskObject`). In `ServerCreationData.deinit()`, `self.future` (`?*FutureObject`) and `self.loop` (`?*LoopObject`) are skipped during deinitialization and permanently leaked.
- **Trigger**: Any destruction or cleanup of structs containing optional `ob_base` pointer fields via `deinitialize_object_fields` (such as `ServerCreationData.deinit()`).
- **Consequences**: Permanent Python object reference leak for futures and event loops on every `create_server` invocation.
- **Fix**: Update the condition in `deinitialize_object_fields` to check `if (data2.child == Python.PyObject or (@typeInfo(data2.child) == .@"struct" and @hasField(data2.child, "ob_base")))`.
