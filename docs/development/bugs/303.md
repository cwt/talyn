# BUG-303 — `create_task` on a closed loop segfaults

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟠 High — Use-after-deinit / missing API guard
- **Files**:
  - `src/task/constructors.zig` (`task_schedule_coro`)
  - Discovered running CPython's `test_base_events` directly (module is excluded from the project gate; the test closes a loop then calls `asyncio.ensure_future(coro, loop=closed_loop)` expecting `RuntimeError` with no warnings)
- **Lessons**: [Event Loop Lifecycle](../lessons/03-event-loop-lifecycle.md), [Defensive Programming §Lesson 57](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: Unlike `z_loop_add_watcher` and friends, the task creation path never checked `loop_data.initialized`. `Soon.dispatch` then wrote into the released ready ring.
- **Fix (Applied — 2026-08-23)**: Guard at the top of `task_schedule_coro`: if `!loop_data.initialized`, raise `RuntimeError("Event loop is closed")`.
- **Regression test**: `tests/test_task_edge.py::test_create_task_on_closed_loop_raises_runtimeerror`.
