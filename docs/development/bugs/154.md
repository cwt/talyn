# BUG-154 — Uninitialized atomic module pointer storage in `release_python_imports` triggers invalid pointer decref

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — invalid memory access / undefined behavior
- **Files**: `src/utils/python_imports.zig:8-40, 99-111`
- **Lessons**: [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md), [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/utils/python_imports.zig`, all 33 global cached module references are initialized with `Atomic(PyObject).init(undefined)`. In non-debug and release builds, `undefined` contains stack/data segment garbage. If `import_python_modules()` fails partway and triggers `release_python_imports()`, the cleanup loop checks `if (@intFromPtr(val) != 0) python_c.py_decref(val)`. Uninitialized slots contain non-zero garbage pointers, causing `py_decref` to access invalid memory and crash.
- **Trigger**: Any failure during `import_python_modules()` (e.g. missing optional module or failed import).
- **Consequences**: Immediate SIGSEGV or heap corruption during error cleanup.
- **Proposed Fix**: Initialize all atomic slots with `std.atomic.Value(?PyObject).init(null)` and check `if (val) |v| python_c.py_decref(v)`.
