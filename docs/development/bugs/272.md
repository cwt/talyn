# BUG-272 — `perform_with_iovecs` reversed errdefer ordering double-frees `iov_copy`

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🔴 Critical — Double free under submission-queue pressure
- **Files**:
  - `src/loop/scheduling/io/write.zig:122` (`errdefer data_ptr.discard()`)
  - `src/loop/scheduling/io/write.zig:134-135` (`alloc iov_copy` + `errdefer free(iov_copy)`)
  - `src/loop/scheduling/io/write.zig:142` (`data_ptr.write_iovs_copy = iov_copy`)
  - `src/loop/scheduling/io/write.zig:153,162-164` (fallible `ring.sendmsg` / `link_timeout` with SQ rollback)
  - `src/loop/scheduling/io/main.zig:80-89` (`discard()` frees `write_iovs_copy` again)
- **Lessons**: [Zig-Specific Patterns §errdefer Discipline](../lessons/08-zig-specific-patterns.md), [io_uring & Kernel Interaction §Lesson 60](../lessons/04-io-uring-and-kernel.md)
- **Description**: After :142 the allocation has TWO registered owners: the local errdefer and the BlockingTask. On failure after :142, reverse-order errdefers run `free(iov_copy)` (:135) first, then `discard()` (:122) → `reset()` clears `data`/`operation` but not `write_iovs_copy`, so `discard()` frees the same pointer again (`io/main.zig:83-86`). Same shape as fixed BUG-2/Lesson 24 but for the heap iovec copy instead of the task slot.
- **Trigger**: SQ-full on vectored writes (the exact condition BUG-2's regression test manufactures) or `link_timeout` failure.
- **Consequences**: Heap corruption in normal vectored-write operation under load.
- **Fix (Proposed)**: Null the local before storing into the task (e.g., assign via a temporary and clear the errdeferred variable), or drop the :135 errdefer once :142 commits.
