# BUG-131 — DNS cache stores empty/failed lookup results with infinite TTL (cache poisoning)

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — long-running process DNS failure
- **Files**: `src/loop/dns/resolv.zig:228-230`, `src/loop/dns/cache.zig:43-57`
- **Description**: In `mark_resolved_and_execute_user_callbacks`, when a DNS resolution returned 0 address results (due to a transient network glitch, packet drop, or DNS server timeout), the resolver called `set_resolved_data(&[], std.math.maxInt(u32))` on the cache record. Because `ttl` was `std.math.maxInt(u32)`, `set_resolved_data` computed `expire_at = std.math.maxInt(i64)` (infinity). This permanently poisoned the DNS cache for that hostname with an empty address list. Subsequent `getaddrinfo` calls for the hostname returned `[]` from cache and raised `socket.gaierror` / `Name or service not known` without ever querying DNS again.
- **Trigger**: A temporary DNS lookup timeout or packet drop in a long-running process (e.g. asyncio web proxy running for ~24 hours).
- **Consequences**: Permanent DNS resolution failure for affected hostnames until the process is restarted.
- **Fix**: Call `control_data.record.discard()` when `results` and `ptr_results` are both empty so failed lookups are evicted from the cache immediately. Additionally, cap default/missing TTL values in `cache.zig` to 60 seconds instead of setting `expire_at` to infinity (`maxInt(i64)`).
