# BUG-428 — `IO.deinit` frees kernel-referenced memory before closing the ring

- **Status**: 🟡 Open
- **Severity**: 🟠 High — kernel-side UAF / heap corruption at loop close
- **Category**: Shutdown ordering / io_uring lifetime
- **Files**: `src/loop/scheduling/io/main.zig:749-781` (`IO.deinit`), `196-206` (`cancel_all`)
- **Related**: [Lesson 48](../lessons/04-io-uring-and-kernel.md), [BUG-20](020.md), [BUG-105](105.md), [BUG-56](../lessons/03-event-loop-lifecycle.md)

## Description

`IO.deinit` frees the `BlockingTasksSet` nodes (`task_data_pool` is inline in each node) and the
registered-buffer region **before** `ring.deinit()`:

```zig
self.set.cancel_all(self.loop) catch ...;   // only flips Zig callbacks to cancelled; no CancelIO/drain
self.set.deinit();                          // frees task_data_pool (node inline)
... for busy_sets ... set.deinit();
self.buffer_pool.deinit(...);               // frees registered buffers
if (self.ring.fd >= 0) { self.ring.deinit(); self.ring.fd = -1; }
```

`cancel_all` does not submit `CancelIO`/`CancelByFd` or drain CQEs. A deferred zero-copy `sendmsg` /
`perform_with_iovecs` (msghdr/iov live in `task_data_pool`) or a `READ_FIXED` (buffer in `buffer_pool`)
can still be referenced by the kernel when that memory is freed.

## Trigger

`loop.close()` with an in-flight vectored write or registered-buffer read.

## Consequences

Kernel reads freed memory → UAF / heap corruption; hard to reproduce, load-dependent.

## Fix

Submit real cancels and drain (or move the `buffer_pool`/set `deinit()` calls to **after**
`self.ring.deinit()`), so the kernel is guaranteed done with the backing store before it is freed.

## 2026-11-12 Validation

- Ordering and accounting confirmed exactly (`io/main.zig:750-775`): `cancel_all` (`:196-206`) only
  flips Zig callbacks to cancelled + dispatches — no CancelIO SQE, no CQE drain; `set.deinit()`
  (`:751`) frees the node including the inline `task_data_pool` (`linked_list.zig:33-35`), then
  `busy_sets` (`:757-758`), then `buffer_pool.deinit` (`:770`), and `ring.deinit()` runs last
  (`:773-775`, just munmap + close). The sole caller, `Loop.release_claimed` (`loop/main.zig:180`),
  drains nothing beforehand.
- Mechanism correction: the kernel-side UAF as stated is overstated for both named vectors.
  (1) **READ_FIXED** — registered buffers are kernel-**pinned** pages ("locked/pinned memory
  (RLIMIT_MEMLOCK)", `main.zig:451-458`); the in-flight-safe `unregister_buffers()` EBUSY path
  (`:765-769`) keeps the registration and pins alive until ring close, so a completing READ_FIXED
  lands in pages the process no longer maps — data loss, not a UAF. (2) **Zero-copy sendmsg** — the
  msghdr/iov in `task_data_pool` are imported by the kernel at submit time and never re-dereferenced
  afterwards; unsubmitted SQEs are dropped at ring close without processing.
- Real residual hazard (which the proposed "real CancelIO + drain" fix does close): async-retried
  **plain** (non-registered) reads/writes still hold user VAs into transport buffers freed even
  earlier in `release_claimed` (the queue release at `loop/main.zig:152-155` precedes `io.deinit` at
  `:180`) — kernel EFAULT, or a read/write landing in a reused allocation.
- Also observed: `unregister_buffers()` failure (e.g. EBUSY with in-flight READ_FIXED) is only
  warn-logged at `main.zig:767`, so `buffer_pool.deinit()` (`:770`) can run while the kernel
  registration is still live — benign solely because the pages stay pinned.
