# BUG-165 — Unsafe `@as(i32, @intCast(syscall_ret)) < 0` errno check pattern in syscall return handling

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — integer truncation & release miscompile
- **Files**: `src/loop/fs_watcher.zig:49,141`, `src/loop/dns/main.zig:48,60,66,73`, `src/loop/scheduling/io/main.zig:520`, `src/loop/python/io/server/create_server.zig:200`
- **Lessons**: [Syscall Errno Decoding §Lesson 109](../lessons/109-syscall-errno-decoding.md), [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: Several modules check raw Linux syscall returns using `@as(i32, @intCast(ret)) < 0`. Because raw syscall returns are `usize` values in Zig, casting large negative errno encodings (`~errno + 1`) to `i32` via `@intCast` can cause safety trap panics in safe build modes or truncation optimizations in ReleaseFast.
- **Trigger**: Any syscall failure in `inotify_init1`, `inotify_add_watch`, `socket`, `bind`, `listen`, `dup`, or `eventfd`.
- **Consequences**: Unhandled syscall failures or runtime integer overflow panics.
- **Fix**: Standardize all syscall return checks to use `utils.getSyscallErrno(ret)` or `@as(isize, @bitCast(ret)) < 0`.
