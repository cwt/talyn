# BUG-211 — Datagram ReadData and Transport Reference Leak on Task Cancellation

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Resource Leak on Cancellation
- **Files**: `src/transports/datagram/read.zig:48-56`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Lifecycle & Error Handling §Lesson 4](../lessons/004-lifecycle-error-handling.md), [BUG-175](175.md)
- **Description**: In `src/transports/datagram/read.zig`, `queue_read` allocates `ReadData` and increments `transport` refcount, but registers `.callback` with `.cleanup = null`. When the event loop shuts down or when `datagram_close` cancels pending io_uring read requests before execution, `CallbackManager` executes `.cleanup`. Because `.cleanup` is `null`, `cleanup_read` is never called, leaking `rd` and the transport PyObject.
- **Trigger**: Cancelling pending datagram reads or closing loop/transport while read is in flight.
- **Consequences**: Heap leak of `ReadData` and leaked Python transport object reference.
- **Fix**: Set `.cleanup = &cleanup_read` in `queue_read`.
