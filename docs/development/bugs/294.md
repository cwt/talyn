# BUG-294 — Unchecked `PyObject_IsTrue` treated as "loop closed"

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟢 Low — Unchecked C-API error
- **Files**:
  - `src/transports/stream/lifecycle.zig:58` (`const closed = python_c.PyObject_IsTrue(is_closed_py) != 0;`)
- **Lessons**: [Python C API Correctness §Lesson 95](../lessons/05-python-c-api-correctness.md), [Python C API Correctness §Lesson 27](../lessons/05-python-c-api-correctness.md)
- **Description**: `PyObject_IsTrue` returns `-1` on error. The truthiness check treats it identically to `1`, so on failure the transport tears down (`connection_lost`) with a pending exception active rather than clearing and propagating cleanly.
- **Trigger**: A user-supplied `is_closed()` implementation raising during lifecycle checks.
- **Consequences**: Misleading teardown path plus exception-state corruption at the callback boundary.
- **Fix (Proposed)**: Check `< 0` explicitly, clear/propagate the error, and skip the closed branch.
