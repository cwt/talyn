# BUG-291 — `PseudoSocket.close()` not idempotent

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟡 Medium-Low — Double-close / fd safety
- **Files**:
  - `src/utils/pseudosocket.zig:69-73` (`_ = std.os.linux.close(instance.fd)` unconditional, no guard/reset)
- **Lessons**: [Defensive Programming §Lesson 83](../lessons/10-defensive-programming-and-code-quality.md), [io_uring & Kernel Interaction §Lesson 110](../lessons/04-io-uring-and-kernel.md)
- **Description**: PseudoSocket mimics the stdlib socket API and is handed to user code as `sock=`. stdlib `socket.close()` is idempotent; here a second close closes an arbitrary descriptor that the kernel may have reassigned — spurious disconnects or EBADF in unrelated subsystems.
- **Trigger**: Any user pattern closing the pseudo socket twice.
- **Consequences**: Closing another connection's/socket's fd → hard-to-diagnose cross-component failures.
- **Fix (Proposed)**: Track a `closed` flag and set `fd = -1` after the first close.
