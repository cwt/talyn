# BUG-255 — `failed_execution` leaks the exception reference

- **Status**: 🔍 Open
- **Severity**: 🟠 High — Memory leak (reference counting)
- **Files**: `src/task/callbacks.zig`
- **Lessons**: [Memory §Reference Count Discipline](../lessons/01-memory-and-reference-counting.md)
- **Description**: `failed_execution` obtains an owned reference with `const exception: PyObject = python_c.PyErr_GetRaisedException() orelse return error.PythonError;` (line 328). It then calls `Future.Python.Result.future_fast_set_exception(fut, future_data, exception)` (line 369), whose body is `self.exception = python_c.py_newref(exception);` (`future/python/result.zig:74`) — i.e. it **copies** the reference; the caller's local is still an independent owner. The `StopIteration` branch (line 341: `python_c.py_decref(exception); return;`) and the `CancelledError` branch (line 357: `python_c.py_decref(exception); ...; return;`) both release the local, but the **generic exception branch falls through past line 369 without ever releasing `exception`**. The local is dropped at function exit with its refcount un-decremented, so the exception object leaks one reference on every failing task. Same root-cause class as BUG-12 (Double incref in `set_exception` — reference leak).
- **Trigger**: Any coroutine that raises a non-`StopIteration`, non-`CancelledError` exception — the common case for task failures.
- **Consequences**: Permanent reference leak of the exception object on every failing task → unbounded memory growth under load; the object (and anything it references) is never freed.
- **Resolution**: Add `python_c.py_decref(exception);` at the **end** of the function (after the `SystemExit`/`KeyboardInterrupt` check at lines 379-384), where the generic path is the only branch that reaches. Do **not** add a top-level `defer py_decref(exception)` — the other two branches already decref and would double-free.
- **Verification**: Run many failing tasks; observe monotonic growth of live exception objects via `gc.get_objects()` counts or a heap tracker. Add a unit test asserting the exception object's refcount returns to its pre-call value after `failed_execution`.
