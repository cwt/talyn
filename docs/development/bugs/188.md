# BUG-188 — Unbounded hostname slice length panic in DNS IO path violating Mandate 1

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — Architectural Mandate #1 violation (NO PANICS in IO path)
- **Files**: `src/loop/dns/main.zig:29, 92`, `src/loop/dns/parsers.zig:154, 200`
- **Lessons**: [Defensive Programming §Lesson 53](../lessons/10-defensive-programming-and-code-quality.md), [Architectural Mandates §Mandate 1](../architectural-mandates.md)
- **Description**: In `src/loop/dns/main.zig`, `self.parsed_hostname_buf` is a fixed-size `[255]u8` buffer. `lookup` called `std.ascii.lowerString(&self.parsed_hostname_buf, hostname)`. `lowerString` asserts `dest.len == src.len`. When a hostname exceeded 255 characters, Zig panicked and terminated the process. The same panic existed in `parse_resolv_configuration` when a search domain in `/etc/resolv.conf` exceeded 255 bytes.
- **Trigger**: DNS resolution requests with hostname longer than 255 bytes or long search domains in `/etc/resolv.conf`.
- **Consequences**: Fatal process termination, violating the zero-panic mandate.
- **Fix**: Added bounds checks (`if (hostname.len > 255) return error.InvalidHostname;` and `if (word.len > 255) return error.InvalidConfiguration;`) and properly sliced the target destination buffer `buf[0..len]`. Added unit test in `src/loop/dns/parsers.zig`.
