# BUG-167 — Socket file descriptor leak on Python object allocation failure in `sock_accept_callback`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — file descriptor leak on error
- **Files**: `src/loop/python/io/socket/ops.zig:65-108`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/04-resource-cleanup-and-cancellation.md)
- **Description**: In `src/loop/python/io/socket/ops.zig`, `sock_accept_callback` retrieves `client_fd` from `io_uring_res` (returned by kernel `accept4`). It then invokes `AddressUtils.toPyAddr`, `PyDict_New`, `PyTuple_Pack`, and `PyObject_Call(socket_class, ...)`. If any of these steps fail with OOM or exception, `set_future_exception` sets the exception on the future, but `client_fd` is never closed.
- **Trigger**: Memory pressure or Python exception while wrapping an accepted socket.
- **Consequences**: Permanent socket file descriptor leak leading to eventual FD exhaustion (`EMFILE`).
- **Fix**: Added an `owns_fd` guard closing `client_fd` on any failure before `socket.socket(...)` successfully takes ownership.
