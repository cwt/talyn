# BUG-170 — Memory and Python handle leak on unhandled exception in `loop_watcher_python_wrapper_callback`

- **Status**: 🔴 Open
- **Severity**: 🟠 High — memory & Python handle leak
- **Files**: `src/loop/python/io/watchers.zig:62-71`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/04-resource-cleanup-and-cancellation.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: In `src/loop/python/io/watchers.zig`, `loop_watcher_python_wrapper_callback` invokes `try Handle.callback_for_python_generic_callbacks(&temp_data);`. If the user-defined reader/writer callback raises an exception or fails, `try` immediately returns an error. This skips the mutex lock and subsequent watcher cleanup block. Since `CallbackManager`'s `.cleanup` only runs on discarded/cancelled callbacks, the heap-allocated `Loop.FDWatcher` and `watcher.handle` Python reference are never freed.
- **Trigger**: Any reader or writer Python callback raising an exception when invoked.
- **Consequences**: Permanent leak of `FDWatcher` heap structures and strong references to Python `Handle` objects.
- **Fix**: Handle exceptions via `catch` or add `errdefer loop_watchers_cleanup_callback(watcher)` before callback execution.
