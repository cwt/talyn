# BUG-298 — `writelines` swallows iterator errors

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Swallowed error / wrong logic
- **Files**:
  - `src/transports/stream/write.zig:169` (`PyIter_Next(iter) orelse break` — no `PyErr_Occurred()` afterwards)
- **Lessons**: [Python C API Correctness §Lesson 95](../lessons/05-python-c-api-correctness.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: `PyIter_Next` returns NULL both on exhaustion and on error. Treating both identically drops the remaining items, queues only part of the caller's data, and can return None with a dirty exception indicator (SystemError at the boundary).
- **Trigger**: Any iterator/generator raising during `transport.writelines(...)`.
- **Consequences**: Silent partial writes plus misattributed exceptions.
- **Fix (Proposed)**: After the loop, check `PyErr_Occurred()` and propagate via `handle_zig_function_error`.
