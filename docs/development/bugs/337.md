# BUG-337 — `Cancel.perform_by_fd` passes `fd = -1` to `IORING_ASYNC_CANCEL_FD`, causing every `CancelByFd` SQE to fail with `-EBADF`

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — every `CancelByFd` SQE fails silently in the kernel with `-EBADF`; in-flight DNS and transport operations targeted by file descriptor are never cancelled
- **Category**: Logic Bug (`io_uring` SQE preparation)
- **Files**:
  - `src/loop/scheduling/io/cancel.zig:13-16`
  - `src/loop/scheduling/io/main.zig:921`
  - `src/loop/dns/resolv.zig:139`
  - `src/transports/stream/lifecycle.zig:200`
- **Related**: [Lesson 60](../lessons/04-io-uring-and-kernel.md), [BUG-332](332.md)

## Overview & Root Cause

In `src/loop/scheduling/io/cancel.zig:13-16`, `perform_by_fd` prepares an `IORING_OP_ASYNC_CANCEL` SQE with `IORING_ASYNC_CANCEL_FD` by calling `ring.cancel`:

```zig
pub fn perform_by_fd(ring: *std.os.linux.IoUring, fd: usize) !usize {
    _ = try ring.cancel(0, @intCast(fd), std.os.linux.IORING_ASYNC_CANCEL_FD);
    return 0;
}
```

In Zig's `std.os.linux.IoUring`, `ring.cancel(user_data, cancel_user_data, flags)` calls `sqe.prep_cancel(cancel_user_data, flags)`, which sets:

```zig
sqe.fd = -1;
sqe.addr = cancel_user_data;
sqe.cancel_flags = flags;
```

However, inside the Linux kernel (`io_async_cancel_prep` / `io_try_cancel`), when `IORING_ASYNC_CANCEL_FD` is set in `cancel_flags` (without `IORING_ASYNC_CANCEL_FD_FIXED`), the kernel reads the target file descriptor from `sqe->fd` — **not** `sqe->addr` (in Zig's stdlib, `sqe.prep_cancel_fd(fd, flags)` sets `sqe.fd = fd`). Because `sqe.fd` is `-1`, the kernel immediately rejects every `CancelByFd` SQE with `-EBADF`. Because `user_data` is `0`, `wait_for_io` ignores the CQE (`if (cqe.user_data == 0) continue;`), hiding the failure completely.

Furthermore, `fd` is passed as `usize` and cast via `@intCast`, whereas `std.posix.fd_t` (`i32`) is required for `sqe.fd`. Note also that when `fixed_files_enabled` is active for a transport, operations submitted with `IOSQE_FIXED_FILE` require `IORING_ASYNC_CANCEL_FD | IORING_ASYNC_CANCEL_FD_FIXED` with the fixed file slot in `sqe.fd`.

## Trigger Scenario

1. A DNS lookup in `src/loop/dns/resolv.zig:139` or stream transport close in `src/transports/stream/lifecycle.zig:200` queues `.{ .CancelByFd = @intCast(fd) }`.
2. `Cancel.perform_by_fd` submits an `ASYNC_CANCEL` SQE with `sqe.fd = -1` and `sqe.addr = fd`.
3. The kernel fails the cancel with `-EBADF` and leaves the in-flight `io_uring` operations on `fd` armed.

## Proposed Remediation

Obtain an SQE via `try ring.get_sqe()` and call `sqe.prep_cancel_fd(@intCast(fd), std.os.linux.IORING_ASYNC_CANCEL_FD)` with `sqe.user_data = 0`:

```zig
pub fn perform_by_fd(ring: *std.os.linux.IoUring, fd: usize) !usize {
    const sqe = try ring.get_sqe();
    sqe.prep_cancel_fd(@intCast(fd), std.os.linux.IORING_ASYNC_CANCEL_FD);
    sqe.user_data = 0;
    return 0;
}
```
