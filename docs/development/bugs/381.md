# BUG-381 — `CallbackManager` bugs: `release_dynamic_ring_buffer` calls `consume()` after `func()` and skips `cleanup` on error; `execute_*` passes un-incref'd `mod`/`cb` when `debug == false`; `DynamicRingBuffer.executed` is non-atomic

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — causes double-decref/UAF of `module_ptr`/`callback_ptr` when `exception_context` is used with `loop.debug == false`, leaks remaining callbacks if a cancelled callback errors during `release_dynamic_ring_buffer`, and has a data race on `DynamicRingBuffer.executed`
- **Category**: Double-Decref / Use-After-Free, Resource Leak, & Race Condition
- **Files**:
  - `src/callback_manager.zig:273-419, 444-530, 540-628`
- **Related**: [BUG-5](005.md), [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

1. **Un-incref'd `mod` and `cb` decref'd in `exception_handler` when `debug == false` (`src/callback_manager.zig:446-529` & `542-627`)**:
   Look at `execute_dynamic_ring_buffer` (lines 460–467):
   ```zig
   var mod: ?PyObject = null;
   var cb: ?PyObject = null;
   if (item.data.exception_context) |exc_context| {
       mod = exc_context.module_ptr;
       cb = exc_context.callback_ptr;
       if (debug) {
           python_c.py_xincref(mod);
           python_c.py_xincref(cb);
       }
   }
   ```
   Wait: `mod` and `cb` are assigned `exc_context.module_ptr` and `exc_context.callback_ptr` **unconditionally**, while `py_xincref(mod)` and `py_xincref(cb)` are called **only `if (debug)`**!
   Then, if `item.func(&item.data)` returns an error (`else |err|` at line 476), lines 481–521 run:
   ```zig
   if (item.cleanup) |cleanup| {
       cleanup(item.data.user_data);
   }

   if (item.data.exception_context) |exc_context| {
       defer {
           python_c.py_xdecref(mod);
           python_c.py_xdecref(cb);
       }
       ...
       try exception_handler(.{
           .ExceptionHandlerData = .{
               .module_ptr = mod,
               .callback_ptr = cb,
               .exc_message = exc_context.exc_message,
           }
       });
   ```
   When `debug == false` (the default!), `mod` and `cb` were **never incref'd**, `item.cleanup` at line 482 frees `user_data` (which owns `mod` and `cb`), `exception_handler` then accesses the freed `mod` and `cb` pointers (UAF!), and the `defer` at lines 485–488 calls `python_c.py_xdecref(mod)` and `python_c.py_xdecref(cb)` on those un-incref'd pointers (double-decref)!

2. **`release_dynamic_ring_buffer` and `release_ring_buffer` call `queue.consume()` after `item.func(&item.data)` and skip `item.cleanup` on error (`src/callback_manager.zig:515-529, 613-627`)**:
   ```zig
   pub fn release_dynamic_ring_buffer(queue: *CallbacksQueue) !void {
       while (queue.pop()) |item| {
           item.data.set_cancelled(true);
           switch (item.type) {
               .ZigGeneric => {
                   try item.func(&item.data);
               },
               ...
           }
           queue.consume();
       }
   }
   ```
   - Because `queue.consume()` is called **after** `try item.func(&item.data)`, if `item.func` returns an error, `queue.consume()` is never called (leaving the item at the head of the ring buffer) and `release_dynamic_ring_buffer` aborts early without calling `item.cleanup` on the failed item or releasing any of the remaining items in `queue`!
   - Furthermore, if `item.func` re-entrantly appends to `queue` during `release_dynamic_ring_buffer` and triggers `queue.grow()`, calling `queue.consume()` after `item.func` advances `head` on the reallocated buffer. `queue.consume()` should always be called **before** invoking `item.func` (after copying `item.*` to a local variable, just as `execute_dynamic_ring_buffer` does at lines 455–457).

3. **Non-atomic `self.executed` in `DynamicRingBuffer` (`src/callback_manager.zig:273-419`)**:
   `DynamicRingBuffer` uses `@atomicLoad` / `@atomicStore` on `self.head` and `self.tail`, but mutates `self.executed += 1` (line 368), `self.executed += items.len` (line 395), and `self.executed -= 1` (line 418) with plain non-atomic arithmetic.

## Trigger Scenario

1. With `loop.set_debug(False)` (default), trigger an error in a callback that populates `data.exception_context` (such as `loop_watchers_soon_callback` in `src/loop/python/io/watchers.zig:124-128`) -> `execute_dynamic_ring_buffer` runs `item.cleanup`, passes freed `mod`/`cb` to `exception_handler`, and calls `py_xdecref` on `mod` and `cb` without having incref'd them.

## Proposed Remediation

1. In `execute_dynamic_ring_buffer` and `execute_ring_buffer`, either always `py_xincref(mod)` and `py_xincref(cb)` whenever `item.data.exception_context != null`, or only populate `mod` and `cb` (and only `py_xdecref` them) when `debug == true`.
2. In `release_dynamic_ring_buffer` and `release_ring_buffer`, copy `const item = item_ptr.*; queue.consume();` **before** calling `item.func(&item.data)`, and catch errors from `item.func(&item.data)` to invoke `if (item.cleanup) |cleanup| cleanup(item.data.user_data);` without aborting the loop.
