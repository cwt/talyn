# BUG-243 — `loop.reserved_slots` counter permanent leak on DNS query registration and callback attachment

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — Event loop idle sleep blocked / continuous io_uring syscall overhead
- **Files**: `src/loop/dns/resolv.zig:718`, `src/loop/dns/cache.zig:37`, `src/loop/dns/main.zig:126,149,159`
- **Lessons**: [Event Loop §Lesson 1 — Atomic Sleep](../lessons/02-concurrency-and-thread-safety.md), [io_uring §Lesson 19 — Syscall Elimination](../lessons/03-event-loop-lifecycle.md), [BUG-240](240.md) (reserved_slots underflow in DNS callback dispatch)
- **Description**: Commit `951` addressed BUG-240 where `Loop.Scheduling.Soon.dispatch_guaranteed` decremented `loop.reserved_slots` once per callback, causing underflow when multiple callbacks resolved for a single DNS query. The fix replaced `dispatch_guaranteed` with `Soon.dispatch` (which does not modify `reserved_slots`).

  However, the corresponding slot reservation calls were left intact:
  1. `src/loop/dns/resolv.zig:718`: `try loop.reserve_slots(1);`
  2. `src/loop/dns/cache.zig:37`: `try control_data.loop.reserve_slots(1);`
  3. `src/loop/dns/main.zig:126`: `try self.loop.reserve_slots(1);`
  4. `src/loop/dns/main.zig:149`: `try self.loop.reserve_slots(1);`
  5. `src/loop/dns/main.zig:159`: `try self.loop.reserve_slots(1);`

  Because `Soon.dispatch` never decrements `reserved_slots`, every DNS lookup and callback attachment permanently increments `loop.reserved_slots` without any corresponding decrement upon completion or cancellation. Furthermore, lines in `main.zig` (126, 159) called `reserve_slots(1)` immediately prior to calling `record.append_callback`, which itself called `reserve_slots(1)` a second time.

- **Trigger**: Any DNS resolution performed by the event loop.
- **Consequences**:
  - `loop.reserved_slots` monotonically grows with each DNS lookup.
  - In `src/loop/runner.zig:260`, the idle check `if (should_wait and self.reserved_slots == 0) should_wait = false;` can never evaluate to `true`.
  - The event loop is prevented from entering deep sleep and executes blocking `io_uring_enter(1)` syscalls on every loop iteration even when no operations are in-flight.
- **Resolution (2026-08-17)**: Removed all 5 redundant `reserve_slots(1)` calls across `resolv.zig`, `cache.zig`, and `dns/main.zig`. Underlying socket operations in `io.queue` already properly maintain their own slot lifecycle.
- **Verification**: `test_all.sh` passes cleanly.
