# BUG-396 — Duplicate code and unoptimized algorithms across the codebase: 5 copy-pasted SSL protocol classes & $O(N^2)$ buffer pops in `talyn/loop.py`, pre-cache heap allocations on DNS hits, per-hostname `getrandom` syscalls in `build_queries`, and duplicated linked-timeout SQE prep

## Overview & Inventory of Duplicate Code and Unoptimized Algorithms

### Part 1: Unoptimized Algorithms

1. **Heap-allocating async callback state structs and increfing `Future`/`Loop` *before* checking the synchronous DNS cache (`src/loop/python/io/socket/getaddrinfo.zig:172-212`, `src/loop/python/io/client/create_connection.zig:336-356`, `src/loop/python/io/server/create_server.zig:257-296`)**:
   In `z_loop_getaddrinfo` (`src/loop/python/io/socket/getaddrinfo.zig:172-212`):
   ```zig
   const host_copy = try allocator.dupe(u8, host_str);
   const gaid = try allocator.create(GetAddrInfoData);
   gaid.* = .{
       .future = python_c.py_newref(fut),
       .loop = python_c.py_newref(self),
       .host = host_copy,
       ...
   };
   if (try loop_data.dns.lookup(host_copy, &callback, dns_timeout)) |addrs| {
       // Synchronous resolution (IP literal, /etc/hosts, or cached)
       cleanup_getaddrinfo(gaid);
       ...
   ```
   On **every** cache hit, `/etc/hosts` hit (`"localhost"`), or IP literal (`"127.0.0.1"`, `"::1"`), `z_loop_getaddrinfo` heap-allocates `host_copy`, heap-allocates `GetAddrInfoData`, increments `fut` and `self` refcounts, calls `dns.lookup` (which returns `addrs` synchronously without using `callback`), and **immediately frees `gaid`, frees `host_copy`, and decrefs `fut` and `self`** via `cleanup_getaddrinfo(gaid)`!
   The exact same pre-allocation + immediate `deinit()` on synchronous cache hit occurs in `try_resolv_host` (`create_connection.zig:336-356`) and `try_resolve_server_host` (`create_server.zig:257-296`).
   Checking `loop_data.dns.cache.get(host_str)` / IP literal parsing first (or passing a lazy callback builder into `dns.lookup`) eliminates 2 heap allocations/frees and 2 refcount round-trips on every synchronous DNS hit.

2. **2 `getrandom` syscalls per candidate hostname inside `Resolv.build_queries` (`src/loop/dns/resolv.zig:720-747`)**:
   ```zig
   for (hostnames) |hostname| {
       var tx_id_a: u16 = 0;
       _ = std.os.linux.getrandom(@ptrCast(&tx_id_a), @sizeOf(u16), 0);
       ...
       var tx_id_aaaa: u16 = 0;
       _ = std.os.linux.getrandom(@ptrCast(&tx_id_aaaa), @sizeOf(u16), 0);
   ```
   Instead of filling the entire `transaction_ids` slice (`[]u16`) with a **single** `std.os.linux.getrandom(@ptrCast(transaction_ids.ptr), transaction_ids.len * @sizeOf(u16), 0)` syscall before the loop, `build_queries` invokes `getrandom` twice per search-domain hostname (`2 * hostnames.len` syscalls per nameserver).

3. **$O(N^2)$ `self._write_buffer.pop(0)` and `self._write_buffer.insert(0, data)` in `talyn/loop.py` (`lines 699, 709, 919, 929, 1191, 1201, 1409, 1419`)**:
   All SSL protocol state machines in `talyn/loop.py` use a Python `list` for `self._write_buffer` and drain from the front with `self._write_buffer.pop(0)` / push back with `self._write_buffer.insert(0, data)`, which is $O(N)$ per chunk ($O(N^2)$ total under backpressure) instead of $O(1)$ `collections.deque.popleft()` / `appendleft()`.

4. **Redundant `PyObject_GetAttrString(talyn_loop, "call_exception_handler")` during every `StreamTransport` initialization (`src/transports/stream/constructors.zig:210`)**:
   Every single accepted or connected `StreamTransport` performs a CPython attribute lookup `PyObject_GetAttrString(@ptrCast(talyn_loop), "call_exception_handler\x00")` (allocating a bound method object) and passes it to `ReadTransport.init` and `WriteTransport.init`, which store it in `.exception_handler` and **never use it** (and never `py_decref` the bound method object either — leaking 1 bound method object on **every single `StreamTransport` creation**!).

### Part 2: Duplicate Code

1. **5 copy-pasted SSL protocol state machines in `talyn/loop.py` (~550 lines)**:
   `_SSLProtocol` is copy-pasted 5 times in `talyn/loop.py`:
   - `_create_ssl_connection` (with timeout): lines 617–768
   - `_create_ssl_connection` (without timeout): lines 845–961
   - `_create_ssl_server`: lines 1117–1224
   - `create_unix_connection` (SSL path): lines 1335–1442
   - `start_tls` (`class SP`): lines 1515–1600
   Fixing a bug in one copy (such as calling `_flush_write_buffer()` in `resume_writing()` in `SP` at line 1598) repeatedly left the other 4 copies unfixed ([BUG-375](375.md)).

2. **4 copy-pasted linked-timeout SQE preparation blocks (`src/loop/scheduling/io/read.zig:60-71`, `src/loop/scheduling/io/write.zig:51-62, 117-128`, `src/loop/scheduling/io/socket.zig:33-44`)**:
   All 4 sites duplicate the exact same `sqe.flags |= std.os.linux.IOSQE_IO_LINK; data_ptr.ts = timeout; _ = ring.link_timeout(0, &data_ptr.ts, 0) catch |err| { ring.sq.sqe_tail -%= 1; return err; };` sequence.

3. **6 copy-pasted `set_future_exception` helpers across `src/loop/python/io/`**:
   `create_connection.zig:135`, `create_endpoint.zig:53`, `unix.zig:26`, `create_server.zig:75`, `ops.zig:12`, `getaddrinfo.zig:18`, and `getnameinfo.zig:19` all define identical local `set_future_exception` functions instead of sharing a single implementation in `src/loop/python/utils/future.zig`.

4. **Duplicated `talyn_task_step_trampoline` and `talyn_task_throw_trampoline` in `src/task/callbacks.zig:50-162`**:
   Lines 50–100 and 107–162 in `src/task/callbacks.zig` share 90% identical context-enter/exit, `_enter_task`/`_leave_task`, and post-step result/exception handling logic.

## Trigger Scenario

1. Every `StreamTransport` creation in `src/transports/stream/constructors.zig:210` leaks 1 `talyn_loop.call_exception_handler` bound method object because `PyObject_GetAttrString` returns a new reference that is never decref'd!
2. Every cached `loop.getaddrinfo` / `loop.create_connection` call allocates and immediately frees a heap callback struct before checking the DNS cache.

## Proposed Remediation

1. Remove the unused `PyObject_GetAttrString(@ptrCast(talyn_loop), "call_exception_handler\x00")` call in `src/transports/stream/constructors.zig:210` (fixing the per-transport bound method reference leak and saving an attribute lookup on every connection).
2. Check synchronous DNS resolution (cache / `/etc/hosts` / IP literal) before heap-allocating `GetAddrInfoData`, `SocketConnectionData`, and `ServerSocketData`.
3. Fill `transaction_ids` with a single `getrandom` call in `Resolv.build_queries`.
4. Consolidate the 5 SSL protocol classes in `talyn/loop.py` into a single shared class using `collections.deque` for `_write_buffer`, and extract shared helpers for `link_timeout` SQE prep and `set_future_exception`.
