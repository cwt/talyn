# BUG-147 — `FDWatcher` struct and `handle` PyObject leak on Loop release with active watchers

- **Status**: ⚪ False Positive (By Design)
- **Severity**: 🟡 Medium-High — heap memory and Python object leak on loop shutdown
- **Files**: `src/loop/main.zig:152-158`
- **Lessons**: [Event Loop §Lesson 56](../lessons/03-event-loop-lifecycle.md), [Event Loop §Lesson 84](../lessons/03-event-loop-lifecycle.md)
- **Description**: Investigation confirmed that `*FDWatcher` is owned by the in-flight `io_uring` polling task. When `Loop.release()` runs `self.io.deinit()`, the IO driver cancels all in-flight ring submissions, invoking `loop_watchers_callback` with `data.cancelled() == true`, which routes to `loop_watchers_cleanup_callback` to destroy the watcher and decref `watcher.handle`. Draining the B-Tree with `pop` merely clears index nodes prior to B-Tree deinitialization; destroying the watcher inside `Loop.release()` would cause a double-free when `io.deinit()` drains the ring.
- **Resolution**: Identified as intentional design behavior per [Event Loop §Lesson 84](../lessons/03-event-loop-lifecycle.md). Marked as False Positive.
