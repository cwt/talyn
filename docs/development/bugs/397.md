# BUG-397 — Duplicate `PySet_Discard` of task from `asyncio_tasks_set` in `set_result()` — `discard_from_asyncio_tasks_set` already does it

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — redundant duplicate work on every task completion-by-result path (~7 lines of dead code executed per completion)
- **Category**: Duplicate Code
- **Files**:
  - `src/task/callbacks.zig:224-231`
- **Related**: [BUG-373](373.md)

## Overview

`set_result()` at `src/task/callbacks.zig:218` calls `discard_from_asyncio_tasks_set(task)` at line 224. That inline function (defined at line 200) already performs:

```zig
if (task.fut.py_loop) |py_loop| {
    const loop_obj: *Loop.Python.LoopObject = @ptrCast(@alignCast(py_loop));
    if (loop_obj.asyncio_tasks_set) |tasks_set| {
        _ = python_c.PySet_Discard(tasks_set, @ptrCast(task));
    }
}
```

Then lines 226-231 duplicated that exact same block inline:

```zig
if (task.fut.py_loop) |py_loop| {
    const loop_obj: *Loop.Python.LoopObject = @ptrCast(@alignCast(py_loop));
    if (loop_obj.asyncio_tasks_set) |tasks_set| {
        _ = python_c.PySet_Discard(tasks_set, @ptrCast(task));
    }
}
```

`PySet_Discard` is idempotent, so calling it twice caused no crash. However, it was 100% redundant dead code performed on every task completion-by-result path, wasting a Python set lookup per completion.

## Trigger Scenario

Every task completion via `set_result()` (i.e., every coroutine that returns a value rather than raising) executed the duplicate `PySet_Discard` — approximately 7 lines of duplicated logic on every successful task completion.

## Proposed Remediation

Remove the duplicated lines 226-231 in `set_result()` — keep only the single call to `discard_from_asyncio_tasks_set(task)` at line 224.

## Resolution

Removed the duplicate `PySet_Discard` block from `set_result()` in `src/task/callbacks.zig`. The single call to `discard_from_asyncio_tasks_set(task)` at line 224 is now the sole discard site, matching the discard in `failed_execution()` at lines 465 and 479.
