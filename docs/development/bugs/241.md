# BUG-241 — `PyFloat_AsDouble` NaN/Inf silently accepted in happy eyeballs delay parsing

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — Invalid timer values / undefined connection scheduling
- **File**: `src/loop/python/io/client/create_connection.zig:651`
- **Lessons**: [Security §Lesson 34 — Parser Strictness](../lessons/09-security-and-input-validation.md), [BUG-185](0185.md) (kernel -EINVAL from unnormalized nanoseconds)
- **Description**: At line 651, `py_delay` is converted via `PyFloat_AsDouble`:

  ```zig
  delay = python_c.PyFloat_AsDouble(py_delay);
  const eps = comptime std.math.floatEps(f64);
  if (@abs(delay + 1.0) < eps) {
      if (python_c.PyErr_Occurred() != null) {
          return error.PythonError;
      }
      delay = 0;
  }
  ```

  The epsilon check `@abs(delay + 1.0) < eps` only fires when `delay ≈ -1.0`. This serves two purposes:
  1. Catch the error return value of `PyFloat_AsDouble` (which returns `-1.0` on conversion failure).
  2. Handle the user sentinel value `-1.0` (meaning "use default delay").

  However, `PyFloat_AsDouble` also returns `-1.0` and sets a Python error for **NaN** and **Infinity** inputs (e.g., `float("nan")`, `float("inf")`, or a non-numeric string that doesn't parse to a number). The problem is that `@abs(NaN + 1.0)` is `NaN`, and `NaN < eps` is **always false** in IEEE 754. So the `if` block is never entered for NaN/Inf inputs, the `PyErr_Occurred()` check is never reached, and the NaN/Inf delay value propagates silently into the happy eyeballs timer logic.

  A NaN delay passed to `std.time.Instant.add` or `loop.call_later` produces undefined scheduling behavior — the timer may never fire, fire immediately, or crash depending on the kernel and Python version.

  **Note**: All other `PyFloat_AsDouble` call sites in the codebase (create_endpoint, create_server, getaddrinfo, getnameinfo) share the same `if (timeout_val == -1.0 and PyErr_Occurred() != null)` pattern. They correctly catch the error+sentinel case, but like this site they silently accept NaN/Inf. This is a systematic issue across all 5 call sites, but BUG-241 specifically covers the happy eyeballs path where the effect is most visible (immediate vs. staggered connection attempts).

- **Trigger**: User passes `float("nan")`, `float("inf")`, or any non-numeric string as `happy_eyeballs_delay` to `create_connection`.
- **Consequences**: NaN/Inf delay propagates to happy eyeballs timer; undefined scheduling behavior; connections may fire immediately or never, breaking the staggered connection attempt semantics.
- **Fix**: Add an explicit error check immediately after `PyFloat_AsDouble`:
  ```zig
  delay = python_c.PyFloat_AsDouble(py_delay);
  if (python_c.PyErr_Occurred() != null) return error.PythonError;
  ```
  Then handle the `-1.0` sentinel separately if needed. This matches the pattern used for `PyLong_As*` checks throughout the codebase (e.g., `getaddrinfo.zig:138`).
- **Related**: BUG-242 (systemic `PyFloat_AsDouble` NaN/Inf issue across all DNS timeout parsing sites).
