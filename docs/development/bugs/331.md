# BUG-331 — `METH_FASTCALL`-only registrations reject keyword arguments

- **Status**: ✅ Fixed (2026-09-22)
- **Severity**: 🟠 Medium-High — Drop-in asyncio compatibility break: third-party libraries that call `loop.sock_*` (or the other listed methods) with keyword arguments raised `TypeError` on talyn while working on CPython asyncio and uvloop.
- **Detector**: `TALYN-014/FASTCALL_MISSING_KEYWORDS` (`tools/linter/rules/method_flags_missing_keywords.zig`)
- **Files**:
  - `src/loop/python/main.zig` (method tables, `METH_FASTCALL` without `METH_KEYWORDS`)
  - `src/loop/python/io/socket/ops.zig` (`loop_sock_*` entry points)
  - `src/loop/python/io/socket/getnameinfo.zig`, `control.zig`, `unix_signals.zig`, `io/watchers.zig`
  - `src/transports/datagram/main.zig`, `src/transports/datagram/write.zig`
  - `src/python_c.zig` (`merge_vector_call_args` helper)

- **Description**:
  The methods below were registered with `METH_FASTCALL` only, and their
  entry points were declared with the 3-argument `(self, args, nargs)` form.
  CPython's asyncio counterparts declare these parameters as ordinary
  (non-positional-only) parameters, so keyword calls are legal there, and
  uvloop mirrors that behaviour. On talyn any keyword call failed:

  ```text
  TypeError: Loop.sock_connect() takes no keyword arguments
  ```

  The original report covered the seven socket-op methods plus `getnameinfo`.
  The `TALYN-014` scan then showed the same registration gap on 9 more
  methods, for a total of 17 sites.

- **Evidence** (cross-loop probe, CPython 3.14.7, talyn 0.9.7):

  ```python
  import asyncio, socket

  async def check() -> None:
      loop = asyncio.get_running_loop()
      server = await asyncio.start_server(lambda r, w: None, "127.0.0.1", 0)
      port = server.sockets[0].getsockname()[1]
      sock = socket.socket()
      sock.setblocking(False)
      try:
          await loop.sock_connect(sock=sock, address=("127.0.0.1", port))
      finally:
          sock.close()
          server.close()
          await server.wait_closed()
  ```

  ```text
  stdlib: kwargs accepted
  uvloop: kwargs accepted
  talyn:  kwargs rejected -> Loop.sock_connect() takes no keyword arguments
  ```

- **Real-world impact**:
  `python-socks` (the engine behind `aiohttp-socks`) calls
  `loop.sock_connect(sock=..., address=...)`. Under talyn every outbound SOCKS
  connection failed. Observed in Wormhole's `--tor` mode as:

  ```text
  CONNECT 502 play.google.com:443 (Tor stream to play.google.com:443 failed:
  Loop.sock_connect() takes no keyword arguments)
  ```

- **Real Root Cause**:
  `METH_FASTCALL` without `METH_KEYWORDS` selects the positional-only
  entry-point signature and discards any keyword tuple at the C-API boundary.
  The `z_*` implementations consequently only ever saw positional args, so
  there was no place for keywords to be merged.

## Fix (implemented)

1. Added `| python_c.METH_KEYWORDS` to the 15 parity methods in the method
   tables and converted their entry points to the 4-argument
   `(self, args, nargs, knames)` form.
2. Added `python_c.merge_vector_call_args` (`src/python_c.zig`): merges
   positional and keyword values into fixed slots following CPython's
   `METH_FASTCALL | METH_KEYWORDS` vectorcall layout. Unknown keywords and
   arguments passed both positionally and by keyword raise `TypeError`
   (`unexpected keyword argument 'x'` / `got multiple values for argument
   'x'`); variadic callback args (`add_reader`/`add_writer`/
   `add_signal_handler`) remain positional-only.
3. The two internal methods are marked `// TALYN-014-EXEMPT: internal API
   with no CPython counterpart`, which the linter accepts.
4. Added `TALYN-014/FASTCALL_MISSING_KEYWORDS` to the offline linter so the
   registration gap cannot reappear silently (`zig build lint` is clean).

## Regression tests

- `tests/test_socket_ops.py::test_sock_methods_accept_keyword_arguments` —
  end-to-end keyword calls for all seven `sock_*` methods (TCP and UDP).
- `tests/test_socket_ops.py::test_getnameinfo_accepts_keyword_arguments` —
  `sockaddr=`, `flags=`, `dns_timeout=` dispatch (negative timeout path, no
  resolver dependency).
- `tests/test_kwargs_dispatch.py` — `add_reader`, `add_writer`,
  `add_signal_handler`, `add_child_handler`/`remove_child_handler`, and
  `DatagramTransport.sendto`/`set_write_buffer_limits` keyword calls.
