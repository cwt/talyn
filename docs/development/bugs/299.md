# BUG-299 — Missing `errdefer` for `fixed_file_free` in `IO.init`

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Error-path leak
- **Files**:
  - `src/loop/scheduling/io/main.zig:537-541` (`self.fixed_file_free = .empty; try ensureTotalCapacity(...); append(...)` — no errdefer, unlike peers at :514/:534/:558)
- **Lessons**: [Zig-Specific Patterns §Lesson 77](../lessons/08-zig-specific-patterns.md), [Event Loop Lifecycle §Lesson 56](../lessons/03-event-loop-lifecycle.md)
- **Description**: The initializer follows an acquire-then-errdefer pattern for ring, buffer pool, and eventfd; the fixed-file free-list is the lone exception. An OOM in `ensureTotalCapacity` or any `append` leaks its buffer while the rest of init unwinds correctly.
- **Trigger**: OOM during loop creation after earlier resources were acquired.
- **Consequences**: One leaked allocation per failed loop init.
- **Fix (Proposed)**: Add `errdefer self.fixed_file_free.deinit(allocator);` immediately after seeding.
