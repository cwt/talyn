# BUG-140 — Inverted condition in `Server._detach` causes `Server.wait_closed()` to hang indefinitely

- **Status**: 🔴 Open
- **Severity**: 🟠 High — event loop shutdown hang on `await server.wait_closed()`
- **Files**: `talyn/server.py:17-20, 28-36`
- **Lessons**: [Network Protocols §Lesson 40](../lessons/06-network-protocols-and-io.md), [Event Loop §Lesson 57](../lessons/03-event-loop-lifecycle.md)
- **Description**: In `talyn/server.py`:
  ```python
  def _detach(self) -> None:
      self._active_count -= 1
      if self._active_count == 0 and self._servers is not None:
          self._wakeup()
  ```
  When `server.close()` is called, `self._servers` is set to `None`. When existing active connections finish and call `_detach()`, `self._servers is not None` evaluates to `False`. Thus `_wakeup()` is never called, and any coroutine awaiting `server.wait_closed()` hangs forever. Furthermore, `close()` abruptly resets `self._active_count = 0` and calls `_wakeup()` immediately before active connections finish.
- **Trigger**: Calling `server.close()` while active client connections exist, followed by `await server.wait_closed()`.
- **Consequences**: Process hangs indefinitely waiting for server closure.
- **Proposed Fix**: Correct `_detach` to wake up waiters when `self._active_count == 0 and (self._servers is None or not self.is_serving())`. In `close()`, do not zero `self._active_count` if active connections remain; only wake up if `self._active_count == 0`.
