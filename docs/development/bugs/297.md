# BUG-297 — `add_done_callback` errdefer discards owned refs on OOM

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Refcount leak (OOM-only)
- **Files**:
  - `src/future/callback.zig:194-196` (`append(.{ .data = callback_data })` — entry owns newref'd callback + context)
  - `src/future/callback.zig:197` (`errdefer _ = self.callbacks_queue.pop();`)
  - `src/future/callback.zig:199` (`try exceptions_queue.ensureTotalCapacity(...)` — failure site)
- **Lessons**: [Memory & Reference Counting §Lesson 18](../lessons/01-memory-and-reference-counting.md), [Zig-Specific Patterns](../lessons/08-zig-specific-patterns.md)
- **Description**: Ownership of the PythonGeneric payload transfers into the queue entry at append time. The errdefer removes the container slot but never decrefs its contents, leaking both references per failure.
- **Trigger**: Allocation failure in `ensureTotalCapacity` after a successful append.
- **Consequences**: Leaked callback/context objects on OOM paths.
- **Fix (Proposed)**: Use an errdefer that releases the popped entry's data (mirroring `release_callbacks_queue` semantics).
