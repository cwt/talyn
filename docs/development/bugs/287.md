# BUG-287 — AF_UNIX address conversion spans non-NUL-terminated path

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟡 Medium — Wrong logic + potential out-of-bounds stack read
- **Files**:
  - `src/utils/pseudosocket.zig:27-28` (`std.mem.span(@as([*:0]const u8, @ptrCast(&un.path)))`)
  - `src/utils/address.zig:250-254` (same pattern in `Address.toPyAddr` AF_UNIX branch)
  - Callers: `pseudosocket_getsockname`/`getpeername` (`pseudosocket.zig:37-62`) which hold `addrlen` but don't use it here
- **Lessons**: [Security & Input Validation §Lesson 33](../lessons/09-security-and-input-validation.md), [Zig-Specific Patterns §Lesson 87](../lessons/08-zig-specific-patterns.md)
- **Description**: Two defects. (a) Linux abstract namespace sockets have `path[0] == 0`, so the span yields an empty string — identity of abstract sockets (supported by asyncio) is reported as `""`. (b) POSIX guarantees no NUL terminator when a pathname socket fills all 108 bytes of `sun_path`; the span then scans past `path` into uninitialized storage memory → garbage name or OOB read. The correct length (`addrlen - @offsetOf(...,"path")`) is available at both call sites.
- **Trigger**: UNIX sockets using abstract names or maximum-length paths.
- **Consequences**: Factually wrong peer/sock name via public API; potential uninitialized-memory disclosure.
- **Fix (Applied — 2026-08-23)**: Three coordinated changes. (1) `pseudosocket.zig sockaddr_to_py_object`: bounded by `addrlen`; abstract names keep their exact bytes, pathname names stop at the first NUL within bounds. (2) `Address.toPyAddr` AF_UNIX branch: same bounded conversion. (3) `Address.getOsSockLen()` now returns CPython-compatible lengths (abstract = exact byte length; pathname = +1 terminator) and the unix **connect** path uses it instead of hardcoded `sizeof(sockaddr_un)` — trailing-NUL padding made every abstract connect fail with ECONNREFUSED/EINVAL.
- **Regression test**: `tests/test_unix.py::test_abstract_unix_socket_peername` — connects to an abstract-named socket and asserts peername preserves the leading NUL and full name.
