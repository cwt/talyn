# BUG-235 — `dispatch_completion_batch` silently drops remaining records on Python error

- **Status**: ✅ False Positive
- **Severity**: 🟠 Medium-High — Silent data loss / Protocol state desync
- **File**: `src/loop/runner.zig:140-185` (dispatch_completion_batch)
- **Lessons**: [Event Loop §Lesson 18 — Reference leak in Future done callbacks](../lessons/01-memory-and-reference-counting.md), [Defensive §Lesson 79 — Silent Failure](../lessons/10-defensive-programming-and-code-quality.md), [BUG-18](018.md) (dispatch drops remaining records on Python error)
- **Description**: `dispatch_completion_batch` iterates over `batch.records[0..batch.ready_count]`, dispatching each `CompletionRecord`. If any record's dispatch raises a Python exception, `had_error` is set to `true` and the loop `continue`s to the next record. After the loop, `batch.reset()` is called (clearing ALL records), then the function returns `error.PythonError`.

  The problem: when `had_error` is true and the function returns `error.PythonError`, the caller (`start` in `runner.zig`) receives the error but the batch has already been reset. Any records that were **not yet processed** when the error occurred are silently dropped — their protocol methods (`data_received`, `buffer_updated`) are never called, and the transport's internal state (e.g., `batch_dispatched` flags on `ReadTransport`) may be left inconsistent.

  Additionally, records that **were** successfully dispatched before the error may have side effects (e.g., `queue_read_operation` was called to re-arm the read) that assume the full batch completes.

- **Trigger**: Any batch dispatch where a Python protocol callback raises an exception (e.g., `data_received` throws).
- **Consequences**: Silent data loss (unread data), protocol state desync, potential resource leaks on transport objects.
- **Fix**: Either (a) flush each record individually with error handling per-record rather than batching, or (b) preserve unprocessed records in a secondary buffer and retry on the next loop iteration. At minimum, log a warning when records are dropped due to batch error.
