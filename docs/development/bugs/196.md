# BUG-196 — SubprocessTransport protocol callback failure leaks pidfd descriptor and PyObject reference

- **Status**: 🔴 Open
- **Severity**: 🟠 High — File Descriptor & PyObject Reference Leak
- **Files**: `src/transports/subprocess/transport.zig:358-377`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Defensive Programming §Lesson 53](../lessons/053-defensive-programming.md)
- **Description**: In `src/transports/subprocess/transport.zig`, `pidfd_exit_callback` invokes the protocol's `process_exited` and `connection_lost` callbacks upon process termination. If `PyObject_GetAttrString` returns null or `PyObject_Call` returns an error on lines 361, 366, or 368, the function returns early via `return error.PythonError;` before reaching `success = true;` and the subsequent cleanup.
- **Trigger**: A subprocess protocol without `process_exited`/`connection_lost` or an unhandled Python exception raised in either callback.
- **Consequences**: `transport.pidfd` is never closed (kernel file descriptor leak), `popen` is not decreffed, and the `SubprocessTransportObject` itself leaks 1 reference count.
- **Proposed Fix**: Catch Python exceptions locally, forward to `loop.call_exception_handler` (mirroring lines 270-320), and guarantee `pidfd` closure and `transport` decref via `defer` or unified cleanup blocks.
