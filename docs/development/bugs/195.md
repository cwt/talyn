# BUG-195 — remove_done_callback recounts already-cancelled or executed callbacks on repeat calls

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Asyncio API Specification Violation
- **Files**: `src/future/callback.zig:206-224`
- **Lessons**: [Data Structures §Lesson 31](../lessons/031-data-structures.md)
- **Description**: In `src/future/callback.zig`, `remove_done_callback` searches `future.callbacks.items` and marks matching callbacks with `py_cb.cancelled = true` while incrementing `removed_count`. However, the loop does not check whether `py_cb.cancelled` or `py_cb.executed` is already `true`.
- **Trigger**: Calling `future.remove_done_callback(cb)` multiple times for the same callback on a pending or finished future.
- **Consequences**: Repeat calls erroneously return `1` instead of `0`, violating Python's `asyncio.Future.remove_done_callback` specification and breaking callers relying on the return value to determine whether removal actually occurred.
- **Proposed Fix**: Guard the match condition with `if (!py_cb.cancelled and !py_cb.executed and py_cb.callback == callback and py_cb.context == context)` before setting `cancelled = true` and incrementing `removed_count`.
