# BUG-439 — Cancelled read does not release `protocol_buffer`

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — temporary exported-buffer retention
- **Category**: Buffer lifetime
- **Files**: `src/transports/read_transport.zig:135-139`, `src/transports/stream/read.zig:65-88`
- **Related**: [BUG-351](351.md), [BUG-284](284.md)

## Description

`ReadTransport.read_operation_completed` on `data.cancelled()` calls `cleanup_resources_callback` and
returns **before** invoking `read_completed_callback`. The `Py_buffer` release lives in the stream read
callback (`stream/read.zig:69-75`), so `transport.protocol_buffer` is not released on the cancelled
path; a later re-arm (`queue_read_operation` → `protocol_get_buffer`) overwrites it, leaking the
`Py_buffer`/exported reference until dealloc.

## Fix

Release/clear `transport.protocol_buffer` on the cancelled path (or in `ReadTransport.cancel`).

## 2026-11-12 Validation

- Confirmed: `read_transport.zig:136-138` returns via `cleanup_resources_callback` on the cancelled
  path before `read_completed_callback` (`:160`); neither `cleanup_resources_callback` (`:118-133`)
  nor `ReadTransport.cancel` (`:222-231`) touches `transport.protocol_buffer`; the release lives
  solely in `stream/read.zig:69-75` plus dealloc (`stream/constructors.zig:326-327`).
- Worse than filed: the re-arm path (`stream/read.zig:57`) overwrites
  `transport.protocol_buffer = py_buffer` **without releasing the previous one**, so after a
  cancelled read followed by a re-arm the old export leaks permanently (dealloc later releases only
  the new buffer).

## Resolution (2026-11-12)

Two fixes, one per leak direction:

1. `ReadTransport.read_operation_completed`'s cancelled branch now takes-and-zeros
   `parent.protocol_buffer` and `PyBuffer_Release`s it before running the generic cleanup — the
   release no longer depends on the stream-level callback that never runs on this path. (The
   release deliberately does **not** live in `cleanup_resources_callback`, which other teardown
   paths also invoke — that would double-release.)
2. The re-arm path (`stream/read.zig`) now releases any still-exported previous buffer before
   overwriting the field — the validation finding that a re-arm leaked the old export permanently
   (dealloc released only the new one).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (505 pytest passed on
py3.15, 504 + 1 skipped on py3.15t; stdlib asyncio green on both).
