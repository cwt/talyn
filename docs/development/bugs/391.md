# BUG-391 — `LoopObject.weakref_list` decref'd instead of `PyObject_ClearWeakRefs`, free-threaded `LoopType` reference leak in `loop_dealloc`, and module init error leaks in `src/lib.zig`

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — leaks `LoopType` references on every `Loop` deallocation in free-threaded builds, mismanages `weakref_list` on `LoopObject`, and leaks module objects on initialization failure in `src/lib.zig`
- **Category**: Reference Leak & CPython C-API Bug
- **Files**:
  - `src/loop/python/constructors.zig:62, 86, 183-195`
  - `src/loop/python/main.zig:108-159`
  - `src/lib.zig:60-130`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md), [Lesson 44](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

1. **Free-threaded `LoopType` reference leak in `loop_dealloc` (`src/loop/python/constructors.zig:183-195`)**:
   ```zig
   pub fn loop_dealloc(self: ?*LoopObject) callconv(.c) void {
       const instance = self.?;

       python_c.PyObject_GC_UnTrack(instance);
       _ = loop_clear(instance);

       const @"type": *python_c.PyTypeObject = @ptrCast(python_c.Py_TYPE(@ptrCast(instance)));
       @"type".tp_free.?(@ptrCast(instance));

       if (!python_c.free_threaded) {
           python_c.py_decref(@ptrCast(@"type"));
       }
   }
   ```
   In CPython (both GIL and free-threaded 3.13t/3.14t), **every** instance of a heap type (created via `PyType_FromSpec` / `PyType_FromSpecWithBases`) holds a strong reference to its `PyTypeObject` (`tp_alloc` increments `Py_TYPE(self)`), which **must** be decref'd in `tp_dealloc` after `tp_free`! Skipping `python_c.py_decref(@ptrCast(@"type"))` when `python_c.free_threaded` is `true` leaks 1 reference to `LoopType` (and the extension module) on every `Loop` deallocation in free-threaded Python!
   (Note that `Future`, `Task`, `Handle`, `TimerHandle`, `StreamTransport`, `DatagramTransport`, `StreamServer`, and `SubprocessTransport` all unconditionally call `python_c.py_decref(@ptrCast(@"type"))` in their `tp_dealloc`; only `loop_dealloc` has this erroneous `if (!python_c.free_threaded)` guard.)

2. **`LoopObject.weakref_list` passed to `deinitialize_object_fields` (`py_xdecref`) instead of `PyObject_ClearWeakRefs` (`src/loop/python/constructors.zig:62, 86` & `src/loop/python/main.zig:111`)**:
   `LoopObject` defines `weakref_list: ?PyObject` at `src/loop/python/main.zig:111`, does not exclude `"weakref_list"` from `python_c.deinitialize_object_fields(instance, &.{})` in `loop_clear` (`src/loop/python/constructors.zig:62`), and does not call `python_c.PyObject_ClearWeakRefs(@ptrCast(instance))` in `loop_dealloc` (unlike `future_dealloc` and `task_dealloc`).

3. **Module initialization error handling in `src/lib.zig:60-130`**:
   In `PyInit_talyn_zig`, if type creation or `PyModule_AddObjectRef` fails mid-way through `init_module`, `utils.PythonImports.release()` and already-created heap types are not cleaned up, and lines 63, 73, 102 return `null` on Zig errors (`OutOfMemory`) without calling `utils.handle_zig_function_error` to set a Python exception.

## Trigger Scenario

Create and destroy `talyn.Loop()` instances in a loop on Python 3.13t / 3.14t -> `LoopType`'s reference count grows by +1 on every `Loop` deallocation.

## Resolution

1. In `src/loop/python/constructors.zig`:
   - Cleared weak references via `PyObject_ClearWeakRefs`.
   - Excluded `"weakref_list"` from `deinitialize_object_fields`.
   - Removed the `if (!python_c.free_threaded)` check in `loop_dealloc` so `Py_TYPE(self)` is unconditionally decref'd on all builds.
2. In `src/loop/python/main.zig`:
   - Left weakref management to CPython's `Py_TPFLAGS_MANAGED_WEAKREF` inherited from `BaseEventLoop`.
3. In `src/lib.zig`:
   - Added `errdefer utils.PythonImports.release_python_imports()` and `errdefer deinitialize_talyn_types()`.
