# BUG-159 — `pseudosocket_dup` checks `new_fd == -1` instead of `< 0`, missing Linux negative errno syscall failures

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — incomplete syscall error detection
- **Files**: `src/utils/pseudosocket.zig:183-187`
- **Lessons**: [Defensive §Lesson 12](../lessons/10-defensive-programming-and-code-quality.md), [Network Protocols §Lesson 08](../lessons/06-network-protocols-and-io.md)
- **Description**: In `src/utils/pseudosocket.zig`, `pseudosocket_dup` invokes `std.os.linux.dup(instance.fd)` and checks `if (new_fd == @as(usize, @bitCast(@as(isize, -1))))`. On Linux, raw system calls return negative values representing errno (`-EMFILE`, `-EBADF`, `-ENFILE`, etc.). Comparing only against `-1` misses all standard kernel error codes and causes `pseudosocket_dup` to treat negative return values as valid file descriptors.
- **Trigger**: Calling `.dup()` on a `PseudoSocket` when process or system file descriptors are exhausted (`EMFILE`/`ENFILE`) or the source fd is invalid (`EBADF`).
- **Consequences**: Silent creation of invalid `PseudoSocket` objects wrapping negative integer descriptors instead of raising an `OSError`/`ValueError`.
- **Proposed Fix**: Change check to `if (@as(isize, @bitCast(new_fd)) < 0)`.
