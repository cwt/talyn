# BUG-338 — Synchronous error in `Resolv.prepare_data` or `Resolv.queue` schedules `user_callback` on `Soon` queue while also returning error to caller (UAF & double-free)

- **Status**: ✅ Fixed (2026-10-18) — `prepare_data` and `queue` now clear `control_data.user_callbacks` in their `errdefer` paths so synchronous errors remain exclusively caller-owned without scheduling `user_callback` onto `ready_tasks_queues`
- **Severity**: 🔴 Critical — deterministic use-after-free, double-free, and Python `ob_refcnt` corruption whenever `prepare_data` or `Resolv.queue` fails synchronously (e.g. `loop.getaddrinfo(".", 80)`)
- **Category**: Use-After-Free (UAF) & Double-Free / Double-Decref
- **Files**:
  - `src/loop/dns/resolv.zig:201-214, 849-890, 920-932`
  - `src/loop/python/io/socket/getaddrinfo.zig:175-199`
  - `src/loop/python/io/socket/getnameinfo.zig:104-125`
  - `src/loop/python/io/client/create_connection.zig:336-380`
  - `src/loop/python/io/server/create_server.zig:257-285`
- **Related**: [BUG-332](332.md), [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/loop/dns/resolv.zig:845-889`, `prepare_data` registers `errdefer control_data.release()` at line 849 and immediately appends `user_callback.*` to `control_data.user_callbacks` at line 853 — **before** validating `hostnames_array.len == 0` (line 863) or calling `build_queries` (line 881):

```zig
const control_data = try gpa.create(ControlData);
control_data.* = .{ ... };
errdefer control_data.release();

try control_data.user_callbacks.append(allocator, user_callback.*);
...
if (hostnames_array.len == 0) {
    return error.InvalidHostname;
}
```

Similarly, in `resolv_host` (`src/loop/dns/resolv.zig:922-923`) and `resolv_ip` (`src/loop/dns/resolv.zig:930-931`):

```zig
const data = try prepare_data(loop, hostname, callback, .forward, dns_timeout);
errdefer data.release();
try queue(data);
```

When `prepare_data` returns an error after line 853 (such as `error.InvalidHostname` when `hostname` is `"."` or `"..."` so `std.mem.tokenizeScalar(u8, hostname, '.')` yields 0 tokens, or OOM in `build_queries`) or when `queue(data)` fails synchronously, `errdefer control_data.release()` runs:

```zig
if (!self.resolved and self.user_callbacks.items.len > 0) {
    for (self.user_callbacks.items) |*v| {
        v.data.set_cancelled(true);
    }
    self.loop.ready_tasks_queues.append_many(self.user_callbacks.items) catch ...
```

This schedules `user_callback` onto `loop.ready_tasks_queues` (`Soon` queue) **and** returns the error to the caller (`z_loop_getaddrinfo`, `z_loop_getnameinfo`, `try_resolv_host`, `try_resolve_server_host`).

In the caller (e.g. `src/loop/python/io/socket/getaddrinfo.zig:175-199`), the caller's `errdefer` immediately frees `gaid`, frees `host_copy`, and decrefs `fut` and `self`:

```zig
const gaid = try allocator.create(GetAddrInfoData);
errdefer allocator.destroy(gaid);
errdefer allocator.free(host_copy);
...
try loop_data.dns.lookup(host_copy, &callback, dns_timeout);
```

On the next event loop tick (or during `Loop.release()`), `ready_tasks_queues` executes the queued `getaddrinfo_callback` / `cleanup_getaddrinfo` with a dangling `gaid` pointer, reading freed memory and freeing/decrefing `gaid`, `host_copy`, `fut`, and `loop` a second time.

## Trigger Scenario

1. Call `await loop.getaddrinfo(".", 80)` in Python.
2. `get_hostname_array` tokenizes `"."` on `'.'` and returns an empty slice (`hostnames_array.len == 0`).
3. `prepare_data` appends `user_callback` at line 853, then returns `error.InvalidHostname` at line 863.
4. `errdefer control_data.release()` pushes `user_callback` to `loop.ready_tasks_queues`.
5. `z_loop_getaddrinfo` receives `error.InvalidHostname` and its `errdefer`s destroy `gaid`, free `host_copy`, and decref `fut` and `self`.
6. On the next loop tick or `loop.close()`, `ready_tasks_queues` invokes `getaddrinfo_callback` on freed `gaid` -> immediate UAF and double-free.

## Proposed Remediation

1. In `prepare_data`, do **not** append `user_callback.*` to `control_data.user_callbacks` until all fallible initialization inside `prepare_data` has succeeded, or clear `control_data.user_callbacks.clearRetainingCapacity()` in the synchronous `errdefer` before calling `control_data.release()` so synchronous errors remain caller-owned.
2. Likewise, in `resolv_host` and `resolv_ip`, if `queue(data)` fails synchronously before any `io_uring` task is armed, clear `data.user_callbacks` before `data.release()` so the caller's `errdefer` owns cleanup exclusively.
