# BUG-144 — Reference leak of coroutine, context, and name in `create_task` with custom `task_factory`

- **Status**: 🔴 Open
- **Severity**: 🟠 High — 3 Python object reference leaks on every task creation with a custom task factory
- **Files**: `src/loop/python/utils/task.zig:56-80`
- **Lessons**: [Memory §Lesson 37](../lessons/01-memory-and-reference-counting.md), [Memory §Lesson 107](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `z_loop_create_task`, `coro`, `context`, and `name` are created as new references. In the standard path (`self.task_factory == null`), ownership of these 3 references is transferred into `PythonTaskObject` fields via `fast_new_task`. However, when `self.task_factory != null`, the local variables are packed into `py_args` (which creates its own references) and `task` is returned directly without decreffing or transferring `coro`, `context`, and `name`.
- **Trigger**: Calling `loop.create_task()` when a custom `task_factory` is set on the loop.
- **Consequences**: Leaks 1 reference each to `coro`, `context`, and `name` per task created.
- **Proposed Fix**: Decref `coro`, `context`, and `name` on the `self.task_factory != null` branch after calling the factory.
