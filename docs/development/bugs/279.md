# BUG-279 — Exception/cancel-completed tasks never removed from `asyncio_tasks_set`

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟠 High — Unbounded strong-ref leak on long-running loops
- **Files**:
  - `src/task/callbacks.zig:177-181` (`PySet_Discard` — ONLY removal site, inside `set_result`)
  - `src/task/callbacks.zig:388-409` (CancelledError arm — no discard)
  - `src/task/callbacks.zig:413` (generic exception arm — no discard)
  - `src/task/constructors.zig:36-40` (`PySet_Add` inserts a STRONG reference at scheduling time)
- **Lessons**: [Memory & Reference Counting §Lesson 18](../lessons/01-memory-and-reference-counting.md), [Event Loop Lifecycle](../lessons/03-event-loop-lifecycle.md)
- **Description**: `task_schedule_coro` adds each task to `asyncio_tasks_set`, which holds a strong reference. Removal happens only on completion-by-result. Every failed or cancelled task — plus its coroutine, frames, tracebacks, and context — remains strongly referenced until the loop is destroyed.
- **Trigger**: Any long-running server workload where tasks raise or get cancelled (i.e., essentially all of them).
- **Consequences**: Unbounded memory growth; stale entries visible to registry consumers (`all_tasks()`-style introspection).
- **Fix (Applied — 2026-08-23)**: Extracted `discard_from_asyncio_tasks_set()` and invoked it from all three completion transitions — `set_result` (result), the cancelled arm after `future_fast_cancel` succeeds, and the generic exception arm immediately after `future_fast_set_exception` succeeds (covering the fatal KI/SystemExit early-return).
- **Regression test**: `tests/test_task_edge.py::test_failed_tasks_leave_asyncio_tasks_set` — exception-completed and cancelled tasks are absent from `_asyncio_tasks` right after completion.
