# BUG-433 — DNS response modulo heuristic resolves early

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — dropped addresses / wrong result set
- **Category**: Protocol logic / DNS
- **Files**: `src/loop/dns/resolv/response.zig:337-365`
- **Related**: [BUG-384](384.md), [BUG-317](317.md), [BUG-8](008.md)

## Description

```zig
const types_per_host: usize = if (... queries.len >= hostnames_array.len * 2) 2 else 1;
const current_candidate_done = (server_data.responses_received % types_per_host) == 0;
```

Queries for all candidates × {A, AAAA} are written back-to-back (each `on_query_sent` fires on **write**
completion, not on response), so UDP responses can interleave across candidates. The code assumes
responses arrive in exact send order; with interleaved replies (`a.A, b.A, a.AAAA, b.AAAA`) it declares
a candidate done after two responses and calls `mark_resolved_and_execute_user_callbacks` with a
partial/mixed result set — dropping AAAA addresses.

## Trigger

Dual-stack host, multiple candidate names, responses arriving out of send order.

## Consequences

IPv6 addresses omitted / premature resolution.

## Fix

Match each response to its `QuerySlot` (available as `matched_slot`) and track completion per
hostname/type instead of a global modulo counter.

## Resolution (2026-11-12)

Per-candidate completion tracking replaces the global modulo counter:

- `ServerQueryData` gained `responses_per_hostname: []u16` (allocated alongside the query slots in
  `build_queries`, arena-backed) and a
  `credit_response_and_check_candidate_done(slot)` helper: slots are built hostname-major, so
  `slot_index / types_per_host` identifies the candidate; a candidate is done when all of its own
  query types have been answered.
- `process_dns_response` now uses the (hoisted) `matched_slot` to credit exactly the response's
  candidate. Unmatched/malformed responses are never credited — the global `responses_received`
  backstop still resolves once every query is accounted for, so a malformed response merely
  forgoes an early resolve instead of stalling.
- In-order behavior is unchanged; interleaved behavior now completes the right candidate
  (`a.A, b.A, a.AAAA` → candidate a done → resolve with a's full set) instead of keying on packet
  position.

Unit test added: `BUG-433: interleaved responses complete the right candidate` in
`src/loop/dns/resolv/types.zig` (the old modulo would have declared candidate-done on the b.A
response).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (505 pytest passed on
py3.15, 504 + 1 skipped on py3.15t; stdlib asyncio green on both).

### Follow-up Hardening (2026-11-13)

- Added `answered: bool = false` to `QuerySlot` (`src/loop/dns/resolv/types.zig`) so retransmitted
  or duplicate UDP replies for an already-answered query ID cannot credit the candidate twice,
  append duplicate records, or advance `responses_received` ahead of pending query types.
- Extracted `reject_slot_response_and_continue()` and `finish_or_continue_response_read()` in
  `src/loop/dns/resolv/response.zig` so TC, `qdcount != 1`, short question, question mismatch, and
  short header paths consume the matched slot at most once and gate resolution failure via
  `should_fail_resolution_on_server_finish()` when other nameservers remain outstanding (preserving
  the BUG-317/BUG-384 contract).
- Added unit tests for duplicate-slot credit suppression and multi-server response finish gating in
  `src/loop/dns/resolv/response.zig` and `src/loop/dns/resolv/types.zig`.
