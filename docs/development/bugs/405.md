# BUG-405 — dotless hostnames fail when `search` is empty

- **Status**: 🟢 Fixed (2026-11-01)
- **Severity**: 🟠 High — single-label hostnames (containers, service discovery, `.local`-less names) cannot be resolved at all
- **Category**: DNS Resolver / Search-Domain Logic
- **Files**:
  - `src/loop/dns/resolv.zig:822-845` — `get_hostname_array`
  - `src/loop/dns/resolv.zig:904-913` — `prepare_data` rejects an empty candidate list
- **Related**: [BUG-384](384.md) (bare-hostname fix only covered `suffixes.len > 0`)

## Overview

```zig
if (std.mem.indexOfScalar(u8, hostname, '.')) |_| {
    // FQDN: only the hostname itself
} else if (suffixes.len > 0) {
    // search suffixes, then the bare hostname
}
// suffixes.len == 0: nothing is appended
```

For `"singlelabel"` with an empty `search` list, `hostnames_array.len` remains 0. `prepare_data` returns `error.InvalidHostname` (`resolv.zig:906-913`), so no DNS query is ever sent. The dotted control case (`"single.label"`) takes the FQDN branch and resolves normally.

## Trigger Scenario

1. Use a `/etc/resolv.conf` with only `nameserver ...` (no `search` line), as common in containers.
2. Call `await loop.getaddrinfo("singlelabel", 80)`.
3. The future fails with `RuntimeError: InvalidHostname`; no packet reaches the nameserver.

## Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, ReleaseFast, Python 3.13.16 and 3.13.16t.

A local DNS server on 127.0.0.1:53 answered both names (`single.label -> 1.2.3.4`, `singlelabel -> 5.6.7.8`); `/etc/resolv.conf` contained only `nameserver 127.0.0.1`.

```text
DNS query b'single.label' 1
DNS query b'single.label' 28
control dotted result: ((2, 1, 0, None, ('1.2.3.4', 80)),)
RESULT: FAIL dotless failed: RuntimeError: InvalidHostname
```

No query for `singlelabel` was observed.

## Proposed Remediation

Always append the bare hostname as the final candidate, independent of `suffixes.len`:

```zig
if (std.mem.indexOfScalar(u8, hostname, '.')) |_| {
    appendBare();
} else {
    for (suffixes) |suffix| appendCandidate(hostname, suffix);
    appendBare();
}
```

Add a unit test for `get_hostname_array("singlelabel", &.{})` and an integration test with a nameserver-only resolv.conf.

## Resolution (2026-11-01)

`get_hostname_array` now always appends the bare hostname for a dotless name, including when the search list is empty, so `singlelabel` produces a candidate instead of `prepare_data` rejecting an empty list.

Verification: external repro `h10_dotless_dns.py` resolves a dotless name through a stub DNS server; the DNS and `getaddrinfo` suites pass under both toolchains.
