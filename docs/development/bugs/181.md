# BUG-181 — Uninitialized stack memory read in DNS answer parsing yielding corrupt resolved addresses

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — Stack memory disclosure and corrupt DNS address resolution
- **Files**: `src/loop/dns/resolv.zig:304, 488, 505`
- **Lessons**: [Zig Patterns §Lesson 77](../lessons/08-zig-specific-patterns.md), [Network Protocols §Lesson 47](../lessons/06-network-protocols-and-io.md)
- **Description**: In `src/loop/dns/resolv.zig`, `process_dns_response` defined `var result: utils.Address = undefined;`. When parsing DNS responses that contain records other than A/AAAA/PTR (such as CNAME, SOA, NS, TXT), `parse_individual_dns_result` left `result` unchanged. The subsequent condition `else if (result.any.family != 0)` read uninitialized stack memory. If non-zero, it appended the uninitialized garbage `result` to `server_data.results`.
- **Trigger**: DNS responses containing CNAME, SOA, TXT, or other non-host record types.
- **Consequences**: Random garbage IP addresses returned to applications, failed connections, and potential security leaks of stack bytes.
- **Fix**: Initialized `result.*` and `var result` with zero family (`.{ .any = .{ .family = 0, .data = .{0} ** 14 } }`) in both `parse_individual_dns_result` and `process_dns_response`.
