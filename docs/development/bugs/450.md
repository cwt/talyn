# BUG-450 — enter_or_leave_task double-syncs the shared 3.13 current-task registry

- **Status**: 🟢 Fixed
- **Severity**: 🟠 High — every talyn task step raises RuntimeError on 3.13/3.13t; the stdlib asyncio suites (locks/queues/timeouts/waitfor/threads/staggered/server) fail wholesale
- **Category**: Compatibility / task registry
- **Files**: `src/task/callbacks.zig:18-85`, `src/utils/python_imports.zig`
- **Related**: [BUG-268](268.md) (dual-registry contract), [BUG-449](449.md) (the import failure that masked this), P23 stage 3b (the fast-path rewrite)

## Description

`enter_or_leave_task` calls the C `asyncio._enter_task`/`_leave_task` and then syncs the pure
registry — either via the native fast path (dict op against the captured
`asyncio.tasks._current_tasks`) or, on mismatch, by falling through to the real pure function.
The pure-dict identity with the C registry was never checked:

- **Python 3.13**: `asyncio.tasks._current_tasks` **is** `_asyncio._current_tasks` (machine-verified:
  `t._current_tasks is c._current_tasks == True`). After the C enter, the dict already holds the
  task → the enter fast-path guard (`existing == null`) is false → the fallback
  `_py_enter_task(task)` raises `RuntimeError: Cannot enter into task X while another task X is
  being executed` on **every task step**. The leave is equally broken (the C leave already
  deleted the entry → the pure leave raises on the missing key). The raise aborts the step
  mid-trampoline (leave skipped), and the next `_leave_task` runs with a live exception set →
  `SystemError: <built-in function _leave_task> returned a result with an exception set` —
  the cascade seen across the 3.13 stdlib suites.
- **Python 3.14/3.15**: the dicts are separate by design (`is` → False, machine-verified), so the
  sync is required and the code worked — which is why the 3.15-only intermediate gates passed.

Masked until [BUG-449](449.md) (the 3.13 import failure) was fixed: the suites never got far
enough to reach the task machinery.

## Consequences

On 3.13/3.13t: every talyn task step fails; stdlib asyncio suites fail wholesale; interpreter
state corruption (skipped leaves, SystemError on the next C call).

## Fix

Bind the accelerator registry at init (`_asyncio._current_tasks`, tolerant when the accelerator is
absent) as `c_current_tasks_dict`, and skip the whole pure-sync block when
`pure_dict == c_current_tasks_dict` — the C call already did the work (the 3.13 shared-registry
shape). Separate-dict versions (3.14/3.15) keep the sync unchanged.

## Resolution (2026-11-12)

Fixed together with [BUG-449](449.md) (same discovery run). A shape-independent behavioral guard
replaced the planned registry-identity check (an init-time snapshot of `_asyncio._current_tasks`
proved unreliable — the accessor is order/dynamic-dependent): in `enter_or_leave_task`'s pure-sync
block, the state that means "the C call above already did the work in this dict" is treated as
in-sync and skipped —

- enter: the dict already holds **this task** → skip (pre-fix this fell through to the pure
  `_py_enter_task`, which raised on the shared dict);
- leave: the dict no longer holds the entry → skip (pre-fix fell through to the pure
  `_py_leave_task`, which raised on the missing key).

Healthy 3.14/3.15 flows are handled by the fast path before this check, so their behavior is
unchanged; only the previously-fatal states are skipped.

Validation: the 3.13 stdlib asyncio suites that failed wholesale now pass in isolation
(test_locks 75, test_queues 59, test_timeouts 34, test_waitfor 19, test_threads 6,
test_staggered 7, test_server 13, test_subprocess, test_context 45, test_eager_task_factory —
0 failures/errors each); `zig build test` (3.13 headers) 148/148; the full 6-interpreter matrix
run (3.13, 3.13t, 3.14, 3.14t, 3.15, 3.15t, ReleaseFast, both toolchains) is green.
