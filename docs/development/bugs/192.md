# BUG-192 — Nested GC traversal bug in DNS resolver ControlData.traverse skipping callback_ptr

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Python cyclic garbage collector ghost cycle leak (BUG-173 class)
- **Files**: `src/loop/dns/resolv.zig:194-206`
- **Lessons**: [Python C API §Lesson 21](../lessons/021-python-c-api.md)
- **Description**: In `src/loop/dns/resolv.zig`, `ControlData.traverse` iterates over pending user callbacks:
  ```zig
  if (v.data.module_ptr()) |mod| {
      const vret1 = visit.?(@ptrCast(mod), arg);
      if (vret1 != 0) return vret1;
      if (v.data.callback_ptr()) |cp| {
          const vret2 = visit.?(@ptrCast(cp), arg);
          if (vret2 != 0) return vret2;
      }
  }
  ```
  `callback_ptr` was only visited if `module_ptr` was non-null. When `module_ptr == null` (standard for task/future callbacks), `callback_ptr` was never visited by Python's GC.
- **Trigger**: DNS resolution callbacks that participate in Python reference cycles with null `module_ptr`.
- **Consequences**: Memory leaks; Python GC cannot collect unreferenced cycles involving DNS callbacks.
- **Fix**: Un-nested the `callback_ptr` check so both pointers are visited independently.
