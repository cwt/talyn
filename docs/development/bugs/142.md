# BUG-142 — Double-add of `Loop` type object in `src/lib.zig` causes reference count underflow

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — reference count underflow / premature deallocation of Loop type
- **Files**: `src/lib.zig:125-141`
- **Lessons**: [Memory §Lesson 52](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/lib.zig`, `LoopType` is registered to the module once explicitly:
  ```zig
  if (python_c.PyModule_AddObject(module, "Loop\x00", LoopType) < 0) return null;
  ```
  Immediately following, the code iterates over `inline for (dynamic_talyn_modules_names, dynamic_talyn_types_ptrs)`. Since `dynamic_talyn_modules_names[0]` is `"Loop\x00"` and `dynamic_talyn_types_ptrs[0]` is `&LoopType`, `PyModule_AddObject` is called a second time on `LoopType`.
- **Trigger**: Extension module initialization during `import talyn`.
- **Consequences**: On Python 3.10+, `PyModule_AddObject` steals a reference. Stealing twice without an intermediate incref results in an undercounted reference count on the `Loop` type object, leading to premature deallocation during garbage collection.
- **Proposed Fix**: Remove the duplicate explicit `PyModule_AddObject(module, "Loop\x00", LoopType)` before the loop, relying solely on the `dynamic_talyn_modules_names` loop.
