# BUG-427 — Pseudo-socket aliases the transport fd without `dup`

- **Status**: 🟢 Fixed
- **Severity**: 🟠 High — double-close / fd-reuse
- **Category**: fd ownership / socket lifetime
- **Files**: `src/transports/stream/extra_info.zig:13-23`, `src/transports/stream/lifecycle.zig:278-301`
- **Related**: [BUG-291](291.md) (PseudoSocket.close idempotency), [BUG-110](110.md), [BUG-48](048.md), [BUG-447](447.md) (mirrored hazard: app `sock.close()` leaves `transport.fd` stale)

## Description

```zig
const py_sock = try utils.PseudoSocket.fast_new_pseudosocket(self.fd, self.family, std.posix.SOCK.STREAM, 0);
```

The pseudo-socket wraps the transport's raw fd **without** `dup`. When the transport tears down,
`cancel_and_close_fd` closes `self.fd` but never marks the pseudo-socket closed (the transport does not
hold a back-pointer to invalidate it). A subsequent `sock.close()` from the application closes a
descriptor number that may already have been reused by an unrelated socket.

## Trigger

`transport.get_extra_info('socket')`, then close the transport, then close the returned socket.

## Consequences

Closing an unrelated, reused fd → protocol corruption / hangs.

## Fix

`dup` the fd for the pseudo-socket (so it owns its own descriptor), or invalidate/mark the pseudo-socket
closed during transport teardown.

## Resolution (2026-11-12)

Fixed together with [BUG-447](447.md) by giving each side its own descriptor **plus** an explicit
teardown contract:

1. `create_socket_instance` now `dup()`s the fd — the pseudo-socket owns its own descriptor (same
   open file description, so option/name operations keep working) and the transport's fd is never
   aliased.
2. Transport teardown (`cancel_and_close_fd` and the `stream_clear` GC path) invalidates the cached
   pseudo-socket via the new `PseudoSocket.invalidate_and_close` (closes the dup, `fd = -1`,
   `closed = true`), so a later app `close()` is a no-op and can never target a reused number. This
   also preserves last-close FIN/RST semantics (a SO_LINGER abort still resets the peer — caught by
   `test_connection_lost_receives_error_on_reset` during validation) and keeps BUG-326's
   getsockname-after-close raising.

`tests/transports/test_stream.py`'s `fileno()` identity assertions were updated to the dup contract
(`> 0`, same open file description). New regression tests in `tests/test_pseudosocket.py`:
`test_bug427_socket_keeps_own_fd_across_transport_close` and
`test_bug447_transport_survives_app_socket_close`.

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (504 pytest passed on
py3.15, 503 + 1 skipped on py3.15t; stdlib asyncio green on both).
