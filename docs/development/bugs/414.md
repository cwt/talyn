# BUG-414 — ~32 B/task native retention on task spawn (long-run leak, all eras)

- **Status**: 🟡 Open — fix targeted for **v0.11.1**
- **Severity**: 🟡 Medium-Low — 32 B/task is small, but growth is **linear and unbounded**: long-lived services that spawn thousands of tasks accumulate steadily (1M tasks ≈ 32 MB)
- **Category**: Memory / Task Lifecycle / Native Allocation
- **Files**: culprit still unidentified (native side); workload path is `asyncio.create_task` → `talyn` fast task creation
- **Related**: [BUG-268](268.md) (task registry visibility), [BUG-279](279.md) (asyncio_tasks_set removal), [BUG-373](373.md) (per-step `Py_None` leak), [BUG-397](397.md) (registry double-discard)

## Overview

A 40-second RSS soak on a `create_task(noop())` + `asyncio.gather` workload (the `benchmarks/task_spawn.py` shape, 1024 tasks per round) shows **linear RSS growth at exactly ~32 kB per round in Talyn**, i.e. **~32 bytes per created task**:

| Build (Python 3.14, same host) | RSS after 40 s / ~770 rounds | Slope |
|---|---|---|
| talyn **v0.7.0** (tag `750` wheel) | 27.1 → 52.2 MB | **+32 B/task, linear** |
| talyn **v0.10.0** (tag `1173` wheel) | 26.5 → 51.4 MB | **+32 B/task, linear** |
| talyn **v0.11.0** (published wheel) | 25.2 → 51.7 MB | **+32 B/task, linear** |
| plain **asyncio** control | 22.1 MB constant | **0.0 kB/s (plateau)** |

Also confirmed on Python 3.15 GIL and 3.15t (free-threaded): same ~32–34 B/task slope. Free-threading is not special; the affected allocation is shared by both task paths.

## Evidence

- **Python side is clean**: a `tracemalloc` growth diff over 450,000 tasks shows +12 kB total (noise) — all `Task` objects, futures, and callbacks are released. The retention is therefore on the **native (Zig) side**, consistent with a fixed-size (~32 B) per-task allocation that is never freed: a suspect pool would be one of the task registries/rings that survived every audit — e.g. a BTree slot, registry node, or ring-buffer high-water that never shrinks.
- **The leak is ancient**: era wheels built from tags `v0.7.0` (750), `v0.10.0` (1173) and the published v0.11.0 all show the same slope — it predates the v0.8–v0.11 hardening band and was **not introduced by the 2026-11-01 audit fixes**.
- **Not an interpreter artifact**: the asyncio control on the same interpreter and workload plateaus (pymalloc arena high-water settles); only the Talyn-bound run grows.

## Repro

`soak.py` (1024 `create_task(noop())` + `gather` per round, RSS sampled per round, 40 s):

```python
import asyncio, time, talyn

def rss_kb():
    with open("/proc/self/status") as f:
        for line in f:
            if line.startswith("VmRSS:"):
                return int(line.split()[1])

async def noop(): pass

async def burst(n):
    tasks = [asyncio.create_task(noop()) for _ in range(n)]
    await asyncio.gather(*tasks)

async def main():
    start = time.monotonic()
    while time.monotonic() - start < 40.0:
        await burst(1024)
        await asyncio.sleep(0.05)
        print("rss=%d kB" % rss_kb())

talyn.run(main())
```

Observation: RSS rises ~32 kB per round, forever. Control (replace `talyn.run(main())` with `asyncio.run(main())`) plateaus.

## Diagnosis Findings (2026-11-03): allocation-site attribution

Instrumented dhat (valgrind 3.27) on a 40×512-task run plus workload-delta soaks narrow
the trigger to the **task create/complete lifecycle alone**:

| Workload variant (same interpreter, host) | RSS slope |
|---|---|
| `create_task` ×256 + `gather` per round | **+32 B/task, linear** |
| `create_task` ×256, no gather | **+32 B/task, linear** |
| `asyncio.sleep(0)` churn ×1024 (scheduler path) | 0 kB/round |
| `asyncio.sleep(0.002)` timing ×48 (timer path) | 0 kB/round |

dhat block-groups (all entries show `eb=0/ebk=0` — **everything is freed by process
exit**; the RSS growth is native *arena retention*, not classic unreachable blocks):

1. `array_list.Aligned(callback_manager.Callback).append` invoked from `Future.add_done_callback`
   (`src/future/callback.zig:206`) — one ×~160 B entry per task.
2. `array_list.Aligned(?*c_python.struct__object).ensureTotalCapacity` from
   `add_done_callback` (`src/future/callback.zig:211`) — the paired
   `exceptions_queue.ensureTotalCapacity(...)` capacity growth, one ×~136 B chunk per task.
3. `_asyncio._register_task_impl` → `get_or_create_weakref` — one weakref object per
   registered task (BUG-268/BUG-398 registration path; tracemalloc-clean).

Working hypothesis: the **two-list pattern in `add_done_callback`** keeps each live
Future carrying a `callbacks_queue` (with the callback struct) **plus** an
`exceptions_queue` capacity sized from the callbacks count; states are freed on task/future
teardown, but the interleaved small-block churn with pymalloc/glibc arena behavior dirties
new arena pages at a steady ~32 B/task — consistent with dhat "fully freed" + monotonic
RSS. A direct fix direction: **remove the two-list pattern** (fold `exceptions_queue`
capacity growth into the callbacks queue, lazy-allocate it on first exception instead), and
verify with the RSS soak gate that the slope goes to ≈ 0.

## Proposed Remediation

1. **Fix `add_done_callback` (first candidate).** The `exceptions_queue.ensureTotalCapacity`
   executed synchronously with every callback registration is the unexplained half of the
   pattern; make the callbacks/exceptions capacity changes rare or allocate-on-demand, and
   re-run the soak variants — expect slope ≈ 0.
2. If the slope remains > 0, build with `-Ddebug-alloc`/`-Dasan` and re-run the variants to
   get a symbolized allocation site (release-fast inlining ruined path-free stacks in the
   public wheel).
3. **Guard (this cycle):** `tests/test_longrun_leak_gate.py` — the RSS soak gate added with
   this fix; marked `xfail(strict=True)` while BUG-414 is open so the suite stays green,
   and becomes the mandatory regression gate for this class the moment the fix lands
   (unexpectedly passing removes the marker). Fix scheduled for **v0.11.1**.
