# BUG-352 — 100% reference leak of all keyword arguments in `z_loop_create_datagram_endpoint` due to double `py_newref`

- **Status**: ✅ Fixed (2026-10-18)
- **Severity**: 🔴 High — 100% deterministic reference leak of every keyword argument (`local_addr`, `remote_addr`, `family`, `reuse_port`, `allow_broadcast`, `sock`, `dns_timeout`) passed to `loop.create_datagram_endpoint()`
- **Category**: Reference Leak
- **Files**:
  - `src/loop/python/io/datagram/create_endpoint.zig:65-104`
  - `src/python_c.zig:530`
- **Related**: [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

In `src/python_c.zig:530`, `parse_vector_call_kwargs` returns **new (owned) references** (`values[k].* = py_newref(val)`) for every keyword argument it populates.

In `src/loop/python/io/datagram/create_endpoint.zig:65-104`, `z_loop_create_datagram_endpoint` parses 7 keyword arguments via `parse_vector_call_kwargs` without registering `defer python_c.py_xdecref(...)` for those local variables, and then calls `python_c.py_newref` a **second time** when storing them into `DatagramCreationData`:

```zig
try python_c.parse_vector_call_kwargs(
    knames,
    args.ptr + args.len,
    &.{ "local_addr\x00", "remote_addr\x00", "family\x00", "reuse_port\x00", "allow_broadcast\x00", "sock\x00", "dns_timeout\x00" },
    &.{ &py_local_addr, &py_remote_addr, &py_family, &py_reuse_port, &py_allow_broadcast, &py_sock, &py_dns_timeout },
);
...
dcd.* = .{
    .future = python_c.py_newref(future),
    .loop = python_c.py_newref(self),
    .protocol_factory = python_c.py_newref(protocol_factory),
    .py_local_addr = if (py_local_addr) |v| python_c.py_newref(v) else null,
    .py_remote_addr = if (py_remote_addr) |v| python_c.py_newref(v) else null,
    .py_family = if (py_family) |v| python_c.py_newref(v) else null,
    .py_reuse_port = if (py_reuse_port) |v| python_c.py_newref(v) else null,
    .py_allow_broadcast = if (py_allow_broadcast) |v| python_c.py_newref(v) else null,
    .py_sock = if (py_sock) |v| python_c.py_newref(v) else null,
    .dns_timeout = try Loop.Python.Utils.Time.parse_dns_timeout(py_dns_timeout),
};
```

As a result:
- `py_local_addr`, `py_remote_addr`, `py_family`, `py_reuse_port`, `py_allow_broadcast`, and `py_sock` each have their refcount incremented **twice** (`+2`), while `DatagramCreationData.deinit()` only decrefs each field **once** (`-1`), permanently leaking 1 reference per argument on every call!
- `py_dns_timeout` is incremented once by `parse_vector_call_kwargs` (`+1`), converted to `Resolv.DnsTimeout` at line 102, and **never** decref'd anywhere, leaking 1 reference on every call!
- If any check between lines 78 and 102 fails (e.g. `PyCallable_Check` at line 79, `allocator.create` at line 88, or `parse_dns_timeout` at line 102), all 7 parsed keyword argument references are leaked immediately.

## Trigger Scenario

Every call to `await loop.create_datagram_endpoint(factory, local_addr=('127.0.0.1', 0))` leaks the `('127.0.0.1', 0)` tuple (and any other passed keyword arguments).

## Proposed Remediation

Transfer ownership of the references returned by `parse_vector_call_kwargs` directly into `dcd.*` without calling `py_newref` a second time, add `defer python_c.py_xdecref(py_dns_timeout);`, and add an `errdefer` before `dcd.*` initialization to `py_xdecref` the parsed keyword arguments if an early error occurs.

## Resolution (2026-10-18)

Reworked the ownership flow in `z_loop_create_datagram_endpoint` (`src/loop/python/io/datagram/create_endpoint.zig`):

1. An `errdefer` right after `parse_vector_call_kwargs` releases all 7 owned slot references on any early error (`parse_dns_timeout`, `fast_new_future`, `allocator.create`).
2. `dcd.*` now **transfers** the owned references (`py_local_addr = py_local_addr`, …) instead of taking a second `py_newref`; the locals are nulled out afterwards so the errdefer becomes a no-op (no double-decref).
3. `py_dns_timeout` is released immediately after `Resolv.parse_dns_timeout` converts it to the plain `DnsTimeout` struct.

Test (`tests/test_datagram.py::test_bug352_no_kwargs_reference_leak`): 50 `create_datagram_endpoint` calls with `local_addr` and `dns_timeout` kwargs must leave `sys.getrefcount` of both argument objects unchanged (warmup call + `gc.collect()` first). Verified: +50/+50 on the stale build, exact balance on the fixed build.
