# BUG-432 — `CancelByFd` then immediate `close(fd)` race

- **Status**: ⚪ False Positive
- **Severity**: 🟡 Medium (as filed)
- **Category**: io_uring cancellation / fd lifetime
- **Files**: `src/transports/stream/lifecycle.zig:278-301`
- **Related**: [Lesson 48](../lessons/04-io-uring-and-kernel.md), [BUG-20](020.md), [BUG-105](105.md), [BUG-110](110.md)

## Description (as filed)

```zig
if (has_pending) {
    _ = loop_data.io.queue(.{ .CancelByFd = @intCast(fd) }) catch ...;   // deferred
}
...
if (self.owns_fd) { _ = std.os.linux.close(fd); }                        // immediate
```

`IORING_ASYNC_CANCEL_FD` matches by fd **number at execution time**. Because the cancel is deferred and
the fd is closed (and may be reused) before the SQE is submitted/consumed, the cancel can hit an
unrelated operation or miss the original.

## 2026-11-12 Validation — False Positive

Disproven against current source:

1. **The cancel is not deferred.** `io.queue` force-submits cancel SQEs before returning:
   `src/loop/scheduling/io/main.zig:850-853` (`if (is_cancel ...) _ = try self.flush_pending_sqes();`
   → `:819-826` → `submit_guaranteed` → `io_uring_enter`). The cancel SQE is in the kernel before
   `queue()` returns, strictly before the `close(fd)` at `lifecycle.zig:297-299` can run.
2. **The kernel binds the cancel target at consumption.** The ring is a plain
   `COOP_TASKRUN | SINGLE_ISSUER` ring (no SQPOLL/DEFER_TASKRUN, `io/main.zig:477-493`), and
   `cancel.zig:15` uses non-fixed `IORING_ASYNC_CANCEL_FD` — the kernel resolves the fd number to the
   target file (fget) when the SQE is consumed, so later fd reuse cannot retarget the cancel.
3. **The residual is benign.** If the cancel submit fails (`lifecycle.zig:289` catch → warn), the fd is
   still closed with no cancel queued: in-flight completions are user_data-keyed and hold their own
   file references, so there is no wrong-fd hazard — the op merely is not cancelled.

## Resolution

Marked False Positive (2026-11-12): the proposed fix — "submit/flush the cancel before closing" — is
effectively already implemented inside `queue()` itself.
