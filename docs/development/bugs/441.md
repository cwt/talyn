# BUG-441 — `future.cancel` positional+keyword message reference leak

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — reference leak / non-CPython duplicate-arg behavior
- **Category**: Reference counting / kwargs parsing
- **Files**: `src/future/python/cancel.zig:42-55`
- **Related**: [BUG-296](296.md), [BUG-339](339.md)

## Description

```zig
if (nargs == 1) cancel_msg_py_object = python_c.py_newref(args.?[0]);   // owned
...
parse_vector_call_kwargs(knames, ..., &.{"msg\x00"}, &.{&cancel_msg_py_object});
```

`parse_vector_call_kwargs` assigns `py_obj.* = py_newref(value)` (assumes the slot is null).
`future.cancel(x, msg=y)` overwrites the positional newref without decref'ing it → one reference leaks
(and CPython would raise `TypeError: got multiple values for argument 'msg'`).

## Fix

Pass a separate variable to the kwarg parser (or decref the pre-existing value first) and reject the
positional+keyword collision as CPython does.

## Resolution (2026-11-12)

`future_cancel` now parses the `msg` keyword into a **separate slot** and merges explicitly: a
positional + keyword collision is rejected with
`TypeError("cancel() got multiple values for argument 'msg'")` exactly like CPython, and the kwarg
reference is adopted (or both released on the collision) instead of overwriting the owned positional
reference. The kwarg-parsed reference is owned either way, so all downstream
`py_xdecref(cancel_msg_py_object)` paths stay balanced.

Regression test added: `test_future_cancel_positional_and_keyword_msg_collision` in
`tests/test_future.py` (TypeError on the collision; `sys.getrefcount` proves the positional
reference doesn't leak; the future stays cancelable afterwards).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (502 pytest passed on both
interpreters; stdlib asyncio green on both).
