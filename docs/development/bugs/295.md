# BUG-295 — `z_task_init(name=None)` spurious decref of borrowed reference

- **Status**: 🟢 Fixed (2026-08-23)
- **Severity**: 🟢 Low — Refcount imbalance (version-dependent impact)
- **Files**:
  - `src/task/constructors.zig:174` (`PyArg_ParseTupleAndKeywords("OO|$OO", ...)` — borrowed outputs)
  - `src/task/constructors.zig:198-200` (`py_decref_and_set_null(&name)` on the None branch)
  - `src/task/constructors.zig:184-186` (adjacent `context` None branch handles it correctly by overwrite — asymmetry proves unintended)
- **Lessons**: [Memory & Reference Counting](../lessons/01-memory-and-reference-counting.md), [Python C API Correctness §Lesson 95](../lessons/05-python-c-api-correctness.md)
- **Description**: Decrementing a reference the function does not own skews `Py_None`'s count once per `Task(name=None)` call. On CPython ≥3.12 immortality hides it; on 3.8–3.11 (supported per BUG-141) repeated calls can underflow the singleton.
- **Trigger**: Creating tasks with explicit `name=None`.
- **Consequences**: Singleton refcount corruption on older runtimes.
- **Fix (Proposed)**: Replace the decref with `name = null;`.
