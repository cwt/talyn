# BUG-344 — Double-decref of `LoopObject` (`self`) on `Soon.dispatch` failure in `z_loop_create_connection` (`sock=` path)

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — double-decref of the active `LoopObject` on `Soon.dispatch` failure corrupts the event loop's reference count and causes use-after-free
- **Category**: Double-Decref / Use-After-Free
- **Files**:
  - `src/loop/python/io/client/create_connection.zig:195-237`
- **Related**: [BUG-312](312.md), [BUG-327](327.md), [Lesson 41](../lessons/05-python-c-api-correctness.md)

## Overview & Root Cause

In `src/loop/python/io/client/create_connection.zig:195-237`, the `if (py_sock) |sock_obj|` branch of `z_loop_create_connection` initializes `transport_creation_data` with a single `py_newref(self)` at line 196, and then registers two overlapping `errdefer`s that both decref `self`:

```zig
const transport_creation_data = try allocator.create(TransportCreationData);
transport_creation_data.* = .{
    .loop = python_c.py_newref(self),
    .future = python_c.py_newref(future),
    .protocol_factory = python_c.py_newref(protocol_factory),
    .fd = fd,
    .owns_fd = true,
};
errdefer {
    // Release the extra future ref, protocol_factory ref, loop ref, and the struct on dispatch failure
    python_c.py_decref(@ptrCast(transport_creation_data.future));
    python_c.py_decref(transport_creation_data.protocol_factory);
    python_c.py_decref(@ptrCast(transport_creation_data.loop));
    allocator.destroy(transport_creation_data);
}

errdefer {
    python_c.py_decref(@ptrCast(future));
    python_c.py_decref(@ptrCast(self));
}

const loop_data = utils.get_data_ptr(Loop, self);
try Loop.Scheduling.Soon.dispatch(loop_data, &.{.{ .func = &create_transport_from_socket, .cleanup = &cleanup_create_transport_from_socket, .data = .{ .user_data = transport_creation_data } }});
```

Here:
- `future` has 2 owned references (`Future.Python.Constructors.fast_new_future` at line 188 + `py_newref(future)` at line 197), so decrefing `future` in both `errdefer` blocks is balanced.
- `self`, however, is a borrowed parameter that was only incref'd **once** (at line 196: `.loop = python_c.py_newref(self)`).
- If `Loop.Scheduling.Soon.dispatch` fails at line 236, the second `errdefer` decrefs `self` (line 231) **and** the first `errdefer` decrefs `transport_creation_data.loop` (which is `self`, line 225), dropping `self`'s reference count below its caller-owned value!

## Trigger Scenario

Call `loop.create_connection(factory, sock=s)` when `Soon.dispatch` returns an error (e.g. allocation failure). Both `errdefer` blocks run and decref `self` twice for a single `py_newref(self)`.

## Proposed Remediation

Remove `python_c.py_decref(@ptrCast(self));` from the second `errdefer` block at lines 229–232:

```zig
errdefer {
    python_c.py_decref(@ptrCast(future));
}
```
