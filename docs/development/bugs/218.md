# BUG-218 — Nested GC traversal bug skipping `callback_ptr` when `module_ptr` is null in `traverse_hooks`

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Incomplete GC Traversal & Cyclic Memory Leak
- **Files**: `src/loop/python/constructors.zig:175-182`
- **Lessons**: [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md), [Defensive Programming §Lesson 10](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/loop/python/constructors.zig`, `traverse_hooks` iterates through registered event loop hooks (`prepare`, `check`, `idle`) to report PyObject references to CPython's cyclic GC. The check `if (cb.data.callback_ptr()) |cp|` was placed inside `if (cb.data.module_ptr()) |mod|`. For hook callbacks registered without a module pointer (`module_ptr == null`), the GC traversal skips `callback_ptr` completely.
- **Trigger**: Hook callbacks with `module_ptr == null` forming reference cycles with Python objects or the loop.
- **Consequences**: CPython cyclic GC cannot detect and break reference cycles involving loop hooks, leading to uncollectable garbage and memory leaks.
- **Fix**: Unnest `callback_ptr()` visit into its own independent `if` statement, and invoke `cb.data.traverse()` if present.
