# BUG-168 — File descriptor leak on `tp_alloc` failure in `pseudosocket_dup`

- **Status**: 🔴 Open
- **Severity**: 🟠 High — file descriptor leak on error
- **Files**: `src/utils/pseudosocket.zig:191-199`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/04-resource-cleanup-and-cancellation.md)
- **Description**: In `src/utils/pseudosocket.zig`, `pseudosocket_dup` duplicates the internal file descriptor using `std.os.linux.dup(@intCast(self.fd))`. If `fast_new_pseudosocket` fails (for instance, when `tp_alloc` returns `null` under memory pressure), the catch block returns `error.PythonError` without closing `new_fd`.
- **Trigger**: Duplicating a pseudo-socket under low-memory conditions.
- **Consequences**: Permanent leak of duplicated file descriptors in the kernel table.
- **Fix**: Close `new_fd` in the catch block: `catch { _ = std.os.linux.close(new_fd); return error.PythonError; }`.
