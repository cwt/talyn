# BUG-362 — `ChildWatcher` reads uninitialized `siginfo_t` when `waitid(WNOHANG)` returns `0` with no exited child and leaks `pidfd`, callback reference, and `ChildHandler` on `on_child_exit` error/shutdown paths

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — reads uninitialized stack memory into child exit codes on spurious `pidfd` poll wakeups and leaks `pidfd` file descriptors, Python callback/args references, and `ChildHandler` allocations on loop shutdown or error
- **Category**: Uninitialized Memory Read & FD/Ref/Memory Leak
- **Files**:
  - `src/loop/child_watcher.zig:164-275`
- **Related**: [BUG-313](313.md), [BUG-314](314.md), [Lesson 28](../lessons/02-zig-and-memory.md)

## Overview & Root Cause

In `src/loop/child_watcher.zig:164-275`, `on_child_exit` has two major defects:

1. **Uninitialized `siginfo_t` read when `waitid(..., WNOHANG)` returns `0` with no state change (lines 173–231)**:
   ```zig
   var siginfo: std.os.linux.siginfo_t = undefined;
   const rc = std.os.linux.waitid(.PID, handler.pid, &siginfo, std.os.linux.W.EXITED | std.os.linux.W.NOHANG, null);
   ```
   Per Linux `waitid(2)`, when `WNOHANG` is specified and the target child has not yet changed state, `waitid` succeeds (returns `0`) with `siginfo.signo == 0` (`si_pid == 0`), leaving the union fields (`si_status`, `si_code`) untouched.
   Because `siginfo` is initialized to `undefined` (instead of `std.mem.zeroes(std.os.linux.siginfo_t)`) and `on_child_exit` never checks `if (siginfo.signo == 0)` (re-arming the `PollFd` if the child is still running), it proceeds directly to lines 221–227 and reads uninitialized stack bytes from `siginfo.fields.common.second.sigchld.status` and `siginfo.code`, invoking the user's child exit callback with a garbage exit status!

2. **Leaked `pidfd`, Python references (`callback`, `args`), and `ChildHandler` struct on shutdown and error paths (lines 167–275)**:
   At the very top of `on_child_exit` (line 167), it sets:
   ```zig
   handler.completed = true;
   ```
   And in `ChildWatcher.deinit` (line 42):
   ```zig
   if (!handler.completed) {
       self.cleanup_handler(handler);
   }
   ```
   Setting `handler.completed = true` means `ChildWatcher.deinit()` assumes `on_child_exit` has taken full responsibility for cleaning up `handler`. Yet inside `on_child_exit`:
   - **Line 188 (`if (!self.loop.initialized) return;`)**: When `waitid` returns `EINTR` during loop shutdown (`!self.loop.initialized`), `on_child_exit` returns immediately without calling `self.cleanup_handler(handler)` or removing `handler.pid` from `self.handlers`! Since `handler.completed == true`, `ChildWatcher.deinit()` also skips `handler`, leaking `handler.pidfd`, `handler.callback`, `handler.args`, and `handler`!
   - **Line 201 (`try self.arm_poll(handler)` on `EINTR`)**: `arm_poll` fails to reset `handler.completed = false` before re-arming, and if `arm_poll` returns an error, `handler` is never cleaned up.
   - **Line 246 (`orelse return error.PythonError`) and lines 269–275 (`errdefer` on `Soon.dispatch`)**:
     After `cleanup_handler(handler)` closes `handler.pidfd` at line 233, if `PyLong_FromLong` fails at line 246, `callback_ref` and `args_ref` are leaked! And if `PyTuple_New` (line 251) or `Soon.dispatch` (line 266) fails, the `errdefer` at lines 269–273 decrefs `callback_ref` (which is already owned by `handle` after line 264, causing a **double-decref** if `Soon.dispatch` fails!) and never destroys `ctx`.

## Trigger Scenario

1. Register `loop.add_child_handler(pid, cb)` and close the loop while `on_child_exit` hits `EINTR` or `Soon.dispatch` fails -> `pidfd`, `callback`, `args`, and `ChildHandler` are leaked.
2. A spurious readiness notification on `pidfd` causes `waitid(..., WNOHANG)` to return `0` with `si_signo == 0` -> `on_child_exit` reads uninitialized stack memory as the child's exit code.

## Proposed Remediation

1. Initialize `var siginfo = std.mem.zeroes(std.os.linux.siginfo_t);`. After `waitid` returns `.SUCCESS`, check `if (siginfo.signo == 0)`: if `0`, reset `handler.completed = false` and re-arm `try self.arm_poll(handler)`.
2. In `on_child_exit`, if `!self.loop.initialized` or `arm_poll` fails on the `EINTR` path, remove `handler.pid` from `self.handlers` and call `self.cleanup_handler(handler)`.
3. After `self.cleanup_handler(handler)` at line 233, guard `callback_ref` and `args_ref` with `errdefer` before line 246, and once `Handle.fast_new_handle` takes ownership at line 264, replace those `errdefer`s with `errdefer python_c.py_decref(@ptrCast(handle))` and `errdefer self.allocator.destroy(ctx)`.


## Resolution (2026-10-18)

The code at `on_child_exit` had already been reworked by BUG-313/314/336/280/307
(identity-guarded teardown, transient-error re-arm classification, the `completed`
marker, shutdown dispatch design), but the report's first defect still stood:

1. **Uninitialized `siginfo_t` read (real, fixed)**: `waitid` was still called
   against `var siginfo: siginfo_t = undefined` with no `signo == 0` check. A
   `WNOHANG` success with no state change would have dispatched a fabricated
   exit status from uninitialized stack bytes AND consumed the handler, leaving
   the real exit undeliverable. Fixed three ways:
   - `siginfo` is now zero-filled (`std.mem.zeroes`), so any field read is of
     defined bytes regardless of which kernel behaviour applies (signo cleared,
     or the struct left untouched — waitid(2) leaves the content unspecified);
   - the interpretation of the siginfo moved into
     `classify_child_siginfo(siginfo) ?i32`, which returns `null` when
     `si_signo == 0` (no state change). `on_child_exit` re-arms the WaitReadable
     op (new `rearm_child_handler` helper, which also re-clears the BUG-336
     `completed` marker) and returns instead of dispatching;
   - the EINTR/EAGAIN re-arm and the non-transient BUG-314 teardown were
     deduplicated onto the new `rearm_child_handler` /
     `finalize_child_handler` helpers.

2. **Error-path leaks (real remainder, fixed)**: across the long lifetime of
   this code the `PyObject_Call`-via-`Soon.dispatch` shape the report described
   became a direct in-callback `PyObject_Call`, but the post-waitid dispatch
   still leaked on allocation failure: `PyLong_FromLong` / `PyLong_FromLong`
   / `PyTuple_Pack` returning NULL early-returned `error.PythonError` with the
   `completed` marker already set, so `ChildWatcher.deinit` skipped the handler
   and leaked pidfd, callback ref, and struct. Each failure site now finalizes
   the handler (unmap with the BUG-313 identity guard + `teardown_child_handler`)
   before propagating.

3. **`!loop.initialized` early-return (audit verdict: unreachable)**: the branch
   cannot fire with a live map in the current design — `release_claimed` clears
   `initialized` *before* `ChildWatcher.deinit`, and every drain dispatch during
   release is forced `cancelled = true`, so the cancelled branch (which owns the
   teardown) runs first. Touching `self.handlers` there would risk use-after-free
   against the deinit'd map, so the early-return stays and is documented with
   this analysis.

## Test

- Zig unit tests (`zig build test`) in `src/loop/child_watcher.zig`:
  - a real forked child probed with `waitid(P_PIDFD, WEXITED|WNOHANG)` while
    still running pins the kernel sentinel the guard re-arms on: SUCCESS with
    `signo == 0`, unwritten siginfo, and `classify_child_siginfo == null`;
    the child's real exit is then verified deliverable afterwards (POLLIN →
    SIGCHLD/CLD_KILLED siginfo → status −9; the safety-net `defer` reaps via
    `waitid(.PID, ...)` for Zig 0.16.0 and 0.17.0 dual-toolchain compatibility);
  - `classify_child_siginfo` maps CLD_EXITED → status and CLD_KILLED →
    −status, and rejects the zeroed siginfo.
  **Bite verification**: removing the `signo == 0` guard from the classifier
  (pre-fix semantics: always dispatch the switch value) makes the waitid
  unit test fail with `expected null, found 0`.
- Python regression test `test_bug362_zombie_registration_reports_exit`
  (tests/test_child.py): registering a handler for a child that already became
  a zombie (parent never waited) arms the pidfd with POLLIN immediately;
  on_child_exit must read the *real* filled siginfo and report the true exit
  status (guards the reworked waitid flow end-to-end). The spurious
  `signo == 0` branch itself is not deterministically reachable from Python —
  pidfd POLLIN only signals terminal states — hence the Zig-level premise test.

Passes on 3.13/3.13t/3.14/3.14t in ReleaseFast.
