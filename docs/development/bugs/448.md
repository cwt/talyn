# BUG-448 — BTree `replace()` swallows the failed-split window identically

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — same consequence as BUG-422 (High) via a single narrow call site; fix subsumed by the BUG-422 fix
- **Category**: Data structure / OOM rollback
- **Files**: `src/utils/btree.zig:310-325`, `src/loop/unix_signals.zig:185,193`
- **Related**: [BUG-422](422.md) (same root defect), [BUG-368](368.md), [BUG-1](001.md)

## Description

```zig
pub fn replace(self: *@This(), key: Key, value: Value) ?Value {
    ...
    insert_in_node(allocator, node, key, value) catch return null;   // :323
    return null;
}
```

Identical swallow to `insert()`'s `catch return false` (`:306`): when `do_insertion` commits
(`defer node.nkeys += 1`) and `split_nodes`' fallible `create_node` OOMs, the tree keeps an overfull
node (`nkeys == Degree`), and the next insert/replace descending into it writes `keys[Degree]` /
`childs[Degree+1]` out of bounds. The only production call site is the UnixSignals callback table
(`self.callbacks.replace(...)`, `unix_signals.zig:185, 193`).

## Trigger

Allocation failure while splitting a full node during a `replace()`, followed by a later insert into
that node.

## Consequences

Same as BUG-422: panic (Debug/ReleaseSafe) / heap corruption (ReleaseFast) — Mandate #1 violation in
the tree backing the signal-callback table.

## Fix

Lands with the BUG-422 fix (allocate the split node before `do_insertion`, roll back the insertion, or
reject `nkeys == Degree`) — no separate change is needed; exercise the fix through `replace()` as well.

## Resolution (2026-11-12)

Fixed together with [BUG-422](422.md): the `insert_in_node` pre-allocation + rollback fix covers the
`replace()` entry point automatically (both share the same `insert_in_node` call), and the regression
test `BUG-448: replace() survives split OOM the same way (BUG-422 fix covers it)` drives the OOM
through `replace()` specifically (every `FailingAllocator` fail index; invariant + full-load
readback asserted).

Validation: identical to BUG-422 — `zig build test` green on both toolchains;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green.
