# BUG-244 — `PyErr_Occurred` check stripped in `create_endpoint` and `create_server` DNS timeout parsing causing Python `SystemError`

- **Status**: 🔴 Open
- **Severity**: 🔴 High — Unhandled exception state / Python process crash
- **Files**: `src/loop/python/io/datagram/create_endpoint.zig:136,164,189,223`, `src/loop/python/io/server/create_server.zig:281`
- **Lessons**: [Python C API §Lesson 27 — NULL return checks](../lessons/05-python-c-api-correctness.md), [Security §Lesson 34 — Parser Strictness](../lessons/09-security-and-input-validation.md), [BUG-242](242.md) (PyFloat_AsDouble NaN/Inf error checking)
- **Description**: Commit `952` attempted to address BUG-242 by separating Python C API error checking from `-1.0` sentinel handling in `PyFloat_AsDouble` calls. However, in 5 call sites across `create_endpoint.zig` and `create_server.zig`, the author changed:

  ```diff
  - if (timeout_val == -1.0 and python_c.PyErr_Occurred() != null) return error.PythonError;
  + if (timeout_val == -1.0) break :blk null;
  ```

  This change completely eliminated the `PyErr_Occurred()` check instead of checking it before the sentinel comparison.

  When a caller passes an invalid argument (such as `dns_timeout="invalid"` or `dns_timeout=[]`), `PyFloat_AsDouble` sets a `TypeError` on the Python thread state and returns `-1.0`. The Zig code matches `timeout_val == -1.0`, treats it as `null` (default timeout), and returns a successful Python object while the Python exception remains active.

- **Trigger**: Passing any non-float/non-integer object as `dns_timeout` to `create_datagram_endpoint` or `create_server`.
- **Consequences**:
  - Python runtime detects that a native C extension function returned successfully with an active exception set.
  - Python immediately raises `SystemError: <built-in function ...> returned a result with an exception set` and aborts the operation.
- **Fix**: Reintroduce explicit `if (python_c.PyErr_Occurred() != null) return error.PythonError;` immediately following `PyFloat_AsDouble` at all 5 call sites.
