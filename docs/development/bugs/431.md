# BUG-431 — `datagram_close` does not release the receive buffer

- **Status**: 🟡 Open
- **Severity**: 🟡 Medium — buffer / registered-slot retention until dealloc
- **Category**: Resource lifecycle
- **Files**: `src/transports/datagram/main.zig:154-194`
- **Related**: [BUG-367](367.md), [BUG-52](052.md), [BUG-256](256.md)

## Description

`datagram_close` sets `closed`, cancels `read_task_id`, issues `CancelByFd`, unregisters the fixed
file, closes the fd, and schedules `connection_lost` — but never calls `cleanup_resources`, which is
what releases `fixed_buffer_index` (registered-buffer slot) and frees `buffer_ptr`. The 64 KiB buffer /
pool slot is therefore held until `datagram_dealloc` / `datagram_clear`.

## Trigger

Closing a datagram endpoint while keeping the Python object alive (or before GC).

## Consequences

Registered-buffer pool slots (16) and 64 KiB heap buffers accumulate for every closed-but-not-collected
endpoint.

## Fix

Release the buffer after the cancelled read completion has drained (call `cleanup_resources`, or release
the lease/free the buffer in `datagram_close`).
