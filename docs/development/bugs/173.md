# BUG-173 — Nested GC traversal bug skipping `callback_ptr` when `module_ptr` is null in `UnixSignals`

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — GC cycle leak / incomplete traversal
- **Files**: `src/loop/unix_signals.zig:227-234`
- **Lessons**: [Python GC & Traversal §Lesson 02](../lessons/02-python-gc-and-traversal.md)
- **Description**: In `src/loop/unix_signals.zig`, `traverse_btree_node` visits signal callbacks stored in the BTree. The check `if (cb.data.callback_ptr()) |c|` is mistakenly placed inside the `if (cb.data.module_ptr()) |m|` block. If a signal callback is registered with a `null` module pointer but a non-null `callback_ptr`, Python's Garbage Collector will never visit the callback object.
- **Trigger**: Signal handlers registered without a module pointer participating in a cyclic reference.
- **Consequences**: Premature collection or cyclic memory leaks by the Python GC.
- **Fix**: Move the `callback_ptr()` visit check outside the `module_ptr()` check so both are visited unconditionally.
