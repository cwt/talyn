# BUG-157 — `ChildWatcher.on_child_exit` leaks `pidfd`, heap handler, and Python callback on callback exception

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — descriptor & memory leak
- **Files**: `src/loop/child_watcher.zig:160-194`
- **Lessons**: [Unix Signals §Lesson 77](../lessons/07-signals-and-processes.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: In `src/loop/child_watcher.zig`, `on_child_exit` invokes the Python child exit callback via `PyObject_Call(handler.callback, py_args, null)`. When the callback raises an exception, the error branch calls `call_exception_handler` and immediately executes `return;`. This returns before reaching `self.handlers.fetchRemove(handler.pid)`, leaving the dead process's `handler.pidfd` open, the `ChildHandler` struct leaked in heap memory, and the Python callback reference never decreffed.
- **Trigger**: A registered child watcher callback raising any unhandled Python exception when a child process terminates.
- **Consequences**: Permanent file descriptor leak of `pidfd`, heap memory leak of `ChildHandler`, and Python reference leak.
- **Fix**: Removed early `return` from the exception handling path in `on_child_exit`, ensuring `self.handlers.fetchRemove(handler.pid)` and resource deallocation always execute.
