# BUG-213 — Panic Risk from Unchecked .? Unwrapping on Nullable Callbacks in dispatch_completion_batch

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Architectural Mandate 1 Panic Risk
- **Files**: `src/loop/runner.zig:142-156`
- **Lessons**: [Architectural Mandates §Mandate 1](../architectural-mandates.md), [Panic Prevention §Lesson 1](../lessons/001-panic-prevention.md)
- **Description**: In `src/loop/runner.zig`, `dispatch_completion_batch` unwraps `transport.protocol_data_received.?` and `transport.protocol_buffer_updated.?` using force unwrap `.?`. If a transport changes protocols via `set_protocol` or has its protocol callbacks cleared, force-unwrapping a `null` callback will trigger a panic in the event loop's main iteration path.
- **Trigger**: Protocol modification or clear while batch read completions are pending in the event loop.
- **Consequences**: Fatal process abort/panic in production IO path.
- **Fix**: Replace force-unwraps with safe pattern `if (transport.protocol_data_received) |cb| ...`.
