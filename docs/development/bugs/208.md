# BUG-208 — Leaked Heap Structs, Buffers, and PyObjects on Error Path in src/loop/python/io/socket/ops.zig

- **Status**: ⚪ False Positive (Invalid)
- **Severity**: 🔴 High — Memory & Reference Leak
- **Files**: `src/loop/python/io/socket/ops.zig:45-66, 193-219, 298-328, 537-573, 663-694, 897-929`
- **Lessons**: [BUG-177](177.md), [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [Lifecycle & Error Handling §Lesson 4](../lessons/004-lifecycle-error-handling.md)
- **Description**: Initial audit flagged `var success = false; defer if (success) cleanup_*(ad);` as a potential leak on error paths. However, architectural design per BUG-177 mandates that when a callback returns a Zig error, `CallbackManager.execute_dynamic_ring_buffer` catches the error, passes context to `exception_handler`, and then executes `callback.cleanup(callback.data.user_data)`. Unconditional local cleanup inside the callback causes double-free and double-decref bugs. The success guard is correct and required.
- **Trigger**: Error during terminal socket operation completion or exception setting.
- **Consequences**: Permanent heap and PyObject memory leaks during socket errors.
- **Fix**: Perform `cleanup_*` unconditionally on terminal completions.
