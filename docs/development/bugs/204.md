# BUG-204 — Uninitialized popen struct field in SubprocessTransport.new_with_pid

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Defensive Initialization & Free-Threading Safety
- **Files**: `src/transports/subprocess/transport.zig:408-418`
- **Lessons**: [Defensive Programming §Lesson 49](../lessons/049-uninitialized-struct-fields.md), [BUG-032](032.md), [BUG-033](033.md)
- **Description**: In `src/transports/subprocess/transport.zig`, `new_with_pid` allocates a new `SubprocessTransportObject` via `tp_alloc` and sets fields (`loop`, `protocol`, `pid`, `returncode`, `pidfd_task_id`, `pidfd`, `closed`), but omits `self.popen`. Because field-by-field assignment does not apply struct-literal default values, `self.popen` is left uninitialized. In `subprocess_dealloc` (`py_xdecref(instance.popen)`) and `subprocess_traverse` (`if (instance.popen) |p|`), this field is accessed as a Python pointer.
- **Trigger**: Garbage heap data returned by allocator or non-zero allocator debug modes.
- **Consequences**: Garbage pointer passed to `py_xdecref` or `Py_Visit` during garbage collection or destruction.
- **Fix**: Explicitly set `self.popen = null;` in `new_with_pid`.
