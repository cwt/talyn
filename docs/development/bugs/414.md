# BUG-414 — bounded task-churn warm-up: steady-state RSS ≈ 3× the asyncio baseline

- **Status**: 🟡 Open — fix targeted for **v0.11.1** (now as a *footprint-efficiency* fix, not a leak fix; see the 2026-11-03 revision below)
- **Severity**: 🟡 Medium-Low — sustained native memory footprint 3× a plain asyncio run under the same churn (bounded; no unbounded growth)
- **Category**: Memory / Task Lifecycle / Native Allocation
- **Files**: per-task allocation pattern in the create/complete path (catalog below)
- **Related**: [BUG-268](268.md), [BUG-279](279.md), [BUG-373](373.md), [BUG-397](397.md)

## 2026-11-03 REVISED characterization (plateau, not linear growth)

A 3-minute soak corrected the original reading:

| Soak point (talyn, 1024-task rounds, 0.05 s idle) | RSS |
|---|---|
| t≈30 s | 46.7 MB (still ramping) |
| t≈60 s | 60.9 MB |
| t≈90 s | 61.0 MB (**plateau**) |
| t≈175 s | 61.2 MB |

- talyn **plateaus near ~61 MB**; the earlier "linear +32 B/task forever" was an artifact of the 40 s sampling windows sitting inside the warm-up ramp. The identical plateau is reached on era wheels v0.7.0, v0.10.0 and v0.11.0 (all ~51–52 MB at their 40 s cutoffs, same ramp shape) — era-uniform, not a regression from recent fixes.
- The plain **asyncio control plateaus at ~22.1 MB** on the same workload (slope ≈ 0 from the very start).
- dhat (valgrind 3.27) on the full workload: **no blocks live at exit** (`eb=0/ebk=0` everywhere; total still-live ≈ 34 kB, all linker/loader leftovers) — the memory *is* freed; the footprint is **arena high-water** that never shrinks. tracemalloc shows the Python side is clean (+12 kB over 450k tasks).

So BUG-414's standing issue is: **bounded warm-up → a steady-state native footprint ~3× the asyncio baseline**, concentrated in the task lifecycle's small-block churn. Per-task allocation catalog (dhat, wheel build):

| Per-task alloc (avg size) | Site |
|---|---|
| ~248 B | `fast_new_task` → `PyType_GenericAlloc` — the `PythonTaskObject` itself (freed) |
| ~160 B | `add_done_callback` → `array_list.Aligned(callback_manager.Callback).append` — `callbacks_queue` entry per Future (`src/future/callback.zig:206`) |
| ~136 B *(now removed)* | `add_done_callback` → `exceptions_queue.ensureTotalCapacity` — pre-grown exceptions buffer, freed unused for most Futures (`src/future/callback.zig:211` — removed in the 2026-11-03-frozen build, slope unchanged) |
| ~80 B | `_asyncio._register_task_impl` → weakref per registered task (BUG-268/398 path) |
| ~64–160 B | `z_future_add_done_callback` → `context_new_from_vars` — context/uv entry per callback |

## Workload funnel (clean attribution)

| Variant (same interpreter/host) | Slope |
|---|---|
| `create_task` ×N + `gather` (per round) | +32 B/task (warm-up ramp only) |
| `create_task` ×N, no gather | +32 B/task (warm-up ramp only) |
| `asyncio.sleep(0)` churn ×N | 0 |
| `asyncio.sleep(0.002)` timers ×N | 0 |

The task create/complete lifecycle is the sole footprint driver; scheduler and timer paths are flat.

## Repro

`soak.py` (1024 `create_task(noop())` + `gather` per round, 0.05 s idle, RSS per round): talyn ramps for ~60–90 s and holds ~61 MB; `asyncio.run(main())` control holds ~22 MB throughout.

## Falsified hypotheses (2026-11-03)

1. ~~Eager `exceptions_queue.ensureTotalCapacity` per callback~~ — made lazy (freed capacity no longer allocated); **slope unchanged (8 kB/round)**. The change is kept (strict improvement, no downside), but the sticky footprint lives elsewhere.
2. ~~Unreachable leaked blocks (classic leak)~~ — dhat proves every block is freed by exit.

## Next probes toward the footprint reduction

1. `-Ddebug-alloc` (DebugAllocator) and `-Dasan` builds with the same variant soaks — DebugAllocator's allocation map/sizes will separate *which* subsystem's native allocations dominate the high-water (Soon/queue tables, callback ring buffers, BTree nodes) since C-tracked pymalloc is already accounted clean.
2. Candidate structural reductions once the subsystem is known: small-buffer optimization (inline capacity) for the common single-callback Future (removes BOTH per-task ArrayList allocations), `trim`/shrink of per-round queue capacity after callback dispatch, or pooling the `callback_manager.Callback` structures across rounds.
3. Gate: `tests/test_longrun_leak_gate.py` asserts the **plateau slope is flat and the final footprint delta vs an asyncio control run is small** — `xfail(strict=True)` while this bug remains open; it becomes the standing memory-footprint regression gate for all task-hot-path work after the fix lands.

Fix scheduled for **v0.11.1**.
