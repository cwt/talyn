# BUG-226 — Unchecked `u64` to `usize` integer cast on `ready_tasks_queue_capacity` risking overflow on 32-bit platforms

- **Status**: ✅ Fixed
- **Severity**: 🟢 Low — Defensive integer casting / Platform compatibility
- **Files**: `src/loop/python/constructors.zig:200-226`
- **Lessons**: [Defensive Programming §Lesson 10](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: In `src/loop/python/constructors.zig`, `ready_tasks_queue_capacity` is parsed from Python kwargs using format code `"KO\x00"` (`u64`) and later cast using `@intCast(ready_tasks_queue_capacity)` to `usize`. On 32-bit platforms or if an excessively large integer is passed from Python, `@intCast` will trigger an integer overflow trap.
- **Trigger**: Passing a capacity exceeding `std.math.maxInt(usize)` on 32-bit targets.
- **Consequences**: Runtime integer overflow trap in loop initialization.
- **Fix**: Added overflow check `if (ready_tasks_queue_capacity > std.math.maxInt(usize))` raising `ValueError` before `@intCast`.
