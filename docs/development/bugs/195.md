# BUG-195 — remove_done_callback recounts already-cancelled or executed callbacks on repeat calls

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — Asyncio API Specification Violation
- **Files**: `src/future/callback.zig:206-224`
- **Lessons**: [Data Structures §Lesson 31](../lessons/07-data-structures-and-algorithms.md)
- **Description**: In `src/future/callback.zig`, `remove_done_callback` searches `future.callbacks.items` and marks matching callbacks with `py_cb.cancelled = true` while incrementing `removed_count`. However, the loop did not check whether `callback.cancelled` or `callback.executed` was already `true`.
- **Trigger**: Calling `future.remove_done_callback(cb)` multiple times for the same callback on a pending or finished future.
- **Consequences**: Repeat calls erroneously returned `1` instead of `0`, violating Python's `asyncio.Future.remove_done_callback` specification and breaking callers relying on the return value to determine whether removal actually occurred.
- **Fix**: Added `if (callback.cancelled or callback.executed) continue;` in `remove_done_callback` so already-cancelled or executed callbacks are skipped.
