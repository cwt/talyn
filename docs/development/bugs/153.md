# BUG-153 — `Py_IncRef` called on native `*Loop` pointer in `signal_handler` on default SIGINT disposition

- **Status**: ✅ Fixed
- **Severity**: 🔴 Critical — native heap corruption / memory corruption
- **Files**: `src/loop/unix_signals.zig:78`
- **Lessons**: [Unix Signals §Lesson 37](../lessons/06-network-protocols-and-io.md), [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md)
- **Description**: In `src/loop/unix_signals.zig`, `signal_handler` handles signals delivered via `signalfd` on io_uring. It retrieves the registered callback and unconditionally runs `python_c.py_incref(@ptrCast(@alignCast(callback_ptr.data.user_data.?)))`. However, when `UnixSignals.init` installs the default handler for `SIGINT`, it sets `.data = .{ .user_data = loop }`, passing the native `*Loop` pointer. Calling `Py_IncRef` on `*Loop` interprets `loop.allocator.ptr` (the first 8 bytes of `Loop`) as a reference count and increments it, causing heap pointer corruption and segfaults on subsequent allocations.
- **Trigger**: Delivery of `SIGINT` to a process running the default event loop signal disposition.
- **Consequences**: Silent corruption of `loop.allocator.ptr`, leading to panics, misaligned pointer errors, or segfaults during subsequent allocator operations.
- **Fix**: Guarded `python_c.py_incref` with `if (callback_ptr.cleanup != null)` so that `Py_IncRef` is only invoked on Python-managed callback handles, bypassing native Zig pointers.
