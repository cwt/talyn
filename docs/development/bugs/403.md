# BUG-403 — FS watcher never re-arms after the watcher list becomes empty

- **Status**: 🔴 Open (confirmed, unfixed)
- **Severity**: 🟠 High — path watchers silently stop delivering events for the rest of the loop lifetime
- **Category**: Filesystem Watcher / Event Loop Lifecycle
- **Files**:
  - `src/loop/fs_watcher.zig:45-63` — `ensure_inotify`
  - `src/loop/fs_watcher.zig:65-93` — `on_inotify_event` re-arm condition
  - `src/loop/fs_watcher.zig:224-250` — `remove_watch`
- **Related**: [BUG-387](387.md) (re-arm on callback error)

## Overview

`on_inotify_event` has a deferred re-arm:

```zig
if (self.inotify_fd >= 0 and self.inotify_task_id == 0 and self.watchers.items.len > 0) {
    self.inotify_task_id = self.loop.io.queue(.{ .WaitReadable = ... });
}
```

`remove_watch` only calls `inotify_rm_watch`; it keeps the inotify fd open. `ensure_inotify` starts with `if (self.inotify_fd >= 0) return;`, so adding a new watch after the last one was removed never queues a read again. Even the `IN_IGNORED`/removal event that drains the old read while the list is empty leaves `inotify_task_id == 0` with no new arm.

## Trigger Scenario

1. `h = loop._add_path_watcher(dir, mask, cb)`; create a file to prove events flow.
2. `h.cancel()`; generate one more event (or let `IN_IGNORED` arrive) while the watcher list is empty.
3. `h2 = loop._add_path_watcher(dir, mask, cb2)`; create a file.
4. `cb2` never fires.

## Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, ReleaseFast, Python 3.13.16 and 3.13.16t.

Repro: `h2_fs_rearm.py`.

```text
first events: ['one.txt', 'one.txt']
second events: []
RESULT: FAIL
```

## Proposed Remediation

Treat "fd open but read not armed" as a valid state:

- In `ensure_inotify`/`add_watch`, queue a read when `self.watchers.items.len > 0 and self.inotify_task_id == 0` (not only when `inotify_fd < 0`).
- If the deferred re-arm fails, schedule a retry (mirror `StreamServer.schedule_accept_retry`) instead of leaving the watcher permanently dead.
- Keep `inotify_fd` open or close it when the last watch is removed; either way the state machine must be explicit.

Add a regression test: remove all watches, drain the inotify read, add a new watch, and assert events arrive.
