# BUG-270 — Datagram `sendto` errdefers stay armed after `io.queue()` ownership transfer

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🔴 Critical — Use-after-free + double-free
- **Files**:
  - `src/transports/datagram/write.zig:110-115` (`alloc data_buf` + `create sd`, both with errdefer)
  - `src/transports/datagram/write.zig:156-169` (`io.queue(.PerformSendMsg)` transfers raw pointers to pending op)
  - `src/transports/datagram/write.zig:172` (`try buffer_watermark_check(...)` — fallible AFTER queueing)
  - `src/transports/datagram/write.zig:67-78` (`buffer_watermark_check` returns error.PythonError when `pause_writing` lookup/call fails)
- **Lessons**: [Memory & Reference Counting §Lesson 26](../lessons/01-memory-and-reference-counting.md), [Zig-Specific Patterns §errdefer Discipline](../lessons/08-zig-specific-patterns.md)
- **Description**: Ownership of `sd` and `data_buf` passes to the queued operation at :156 (freed later by `cleanup_sendto`). Zig errdefers cannot be disarmed by ownership transfer, so a failure at :172 fires them while the SQE is still outstanding. When the CQE arrives, `sendto_completed` dereferences freed memory via `sd.transport` (UAF) and `cleanup_sendto` frees `sd.buf` and destroys `sd` again (double-free). Distinct from fixed BUG-4/Lesson 26, which covered only `queue()` itself failing.
- **Trigger**: Any datagram send crossing the high-water mark whose protocol raises from `pause_writing`, or where the attribute lookup fails.
- **Consequences**: Heap corruption / crash on user-triggerable flow-control path.
- **Fix (Proposed)**: Move `buffer_watermark_check` before the queue call, or disarm the local errdefers immediately after successful `queue()` (set locals to sentinel / use a `success` flag pattern like `cleanup_sendto`).
