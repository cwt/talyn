# BUG-197 — Coroutine throw error paths bypass _leave_task leaving corrupted asyncio.current_task state

- **Status**: 🔴 Open
- **Severity**: 🟠 High — State Invariant Violation & Task Tracking Corruption
- **Files**: `src/task/callbacks.zig:396-446`
- **Lessons**: [Concurrency & Free-Threading §Lesson 11](../lessons/011-concurrency.md), [Architectural Mandates §Mandate 4](../architectural-mandates.md)
- **Description**: In `src/task/callbacks.zig`, `_execute_task_throw` calls `enter_task_func` on line 396 to register the task as the current running task on the loop. If `PyContext_Enter` fails (line 401) or `PyObject_GetAttrString(task.coro.?, "throw")` fails (line 408), the function returns `error.PythonError` immediately before calling `leave_task_func`.
- **Trigger**: Failure to enter the task context or failure to resolve the `throw` method on a task's coroutine object.
- **Consequences**: `asyncio.current_task(loop)` permanently reports this task as running on the loop, corrupting asyncio context and task tracking invariants.
- **Proposed Fix**: Ensure `leave_task_func` is always called if `enter_task_func` succeeded, structured through a dedicated trampoline function or guaranteed scope cleanup.
