# BUG-132 — `py_warn` parameter type mismatch passes `PyObject*` instead of `const char*`

- **Status**: 🔴 Open
- **Severity**: 🔴 Critical — memory corruption / segmentation fault on ResourceWarning
- **Files**: `src/python_c.zig:97-99`, `src/transports/stream/constructors.zig:372`, `src/transports/streamserver/main.zig:59`, `src/transports/subprocess/transport.zig:33`, `src/transports/datagram/main.zig:93`
- **Lessons**: [Python C API §Lesson 95](../lessons/05-python-c-api-correctness.md), [Zig §Lesson 87](../lessons/08-zig-specific-patterns.md)
- **Description**: `pub inline fn py_warn(category: *Python.PyObject, message: *Python.PyObject, stack_level: isize) void` in `src/python_c.zig` invokes `_c.PyErr_WarnEx(category, @ptrCast(message), stack_level)`. In the CPython C API, `PyErr_WarnEx(PyObject *category, const char *message, Py_ssize_t stack_level)` expects `message` to be a null-terminated UTF-8 C string (`const char *`), NOT a `PyObject *`. All transport deallocation paths pass a `PyObject *` (created via `PyUnicode_FromFormat`).
- **Trigger**: When an unclosed transport (Stream, StreamServer, Subprocess, Datagram) is deallocated with debug mode enabled.
- **Consequences**: CPython reads the memory address of the `PyObject` struct header as a C string pointer, resulting in garbled warning text or fatal segmentation faults / memory corruption.
- **Proposed Fix**: Change `py_warn` to accept `message: [*:0]const u8` (or convert `PyUnicode` to UTF-8 C string before calling `PyErr_WarnEx`).
