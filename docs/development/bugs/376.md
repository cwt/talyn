# BUG-376 — `create_server` and `_create_ssl_server` never wire `srv.server_ref = server`, breaking `Server.wait_closed()` active connection tracking

- **Status**: ✅ Fixed
- **Severity**: 🔴 High — breaks Python 3.12+/3.13+ `Server.wait_closed()` active connection tracking for all TCP (`loop.create_server`) and SSL (`_create_ssl_server`) servers
- **Category**: Logic Bug
- **Files**:
  - `talyn/loop.py:1091-1100, 1257-1265, 1503-1506`
  - `talyn/server.py:8-12, 51-67`
  - `src/transports/streamserver/main.zig:84-90, 200-209`
- **Related**: [Lesson 55](../lessons/06-network-protocols-and-io.md)

## Overview & Root Cause

In `src/transports/streamserver/main.zig:84-90, 200-209`, `StreamServer` calls `server_ref._attach()` when a client connection is accepted and wraps `protocol.connection_lost` with `_ClientProtocolWrapper` to call `server_ref._detach()` when the client connection closes — **if and only if `srv.server_ref` is set on the `StreamServer` instance**.

Look at `create_unix_server` in `talyn/loop.py:1503-1506`:

```python
server = Server(self, srvs)
for srv in srvs:
    srv.server_ref = server
return server
```

Now look at `create_server` (`talyn/loop.py:1091-1100`) and `_create_ssl_server` (`talyn/loop.py:1257-1265`):

```python
srvs = await self._create_server_zig(
    protocol_factory, host, port, **zig_kwargs
)
return Server(self, srvs)
```

Neither `create_server` nor `_create_ssl_server` sets `srv.server_ref = server` (and `Server.__init__` in `talyn/server.py:8-12` does not set it either)!
As a result:
- `srv.server_ref` is always `null` for every TCP and SSL `Server`.
- `server._attach()` and `server._detach()` are never called when clients connect or disconnect.
- `server._active_count` is permanently `0`.
- Calling `server.close()` followed by `await server.wait_closed()` resolves immediately even while active client connections are still open and transferring data (violating Python 3.12+/3.13+ `Server.wait_closed()` semantics).

## Trigger Scenario

1. Create a TCP server via `server = await loop.create_server(factory, '127.0.0.1', 0)`.
2. Connect a client so a connection is active.
3. Call `server.close()` -> `server._Wakeup()` sees `self._active_count == 0` and immediately resolves `await server.wait_closed()` while the client connection is still open!

## Proposed Remediation

Set `srv.server_ref = self` directly inside `Server.__init__` in `talyn/server.py:8-12` so that all `Server` instances (`create_server`, `_create_ssl_server`, and `create_unix_server`) automatically wire `server_ref`:

```python
class Server(asyncio.AbstractServer):
    def __init__(self, loop, servers):
        self._loop = loop
        self._servers = servers
        self._waiters = []
        self._active_count = 0
        self._serving = True
        for srv in servers:
            srv.server_ref = self
```


## Resolution (2026-10-19)

The ROOT cause is deeper than the report's remediation could reach:
`talyn.StreamServer` (the Zig type) has no `__dict__` and no setter,
so even the pre-existing unix-server wiring was a silent NO-OP —
`if hasattr(srv, "server_ref"): srv.server_ref = server` never fired
(`hasattr` False). `_attach()`/`_detach()` were never callable from
this side. Additionally the current Zig accept path had `_attach`
support but NO `_detach` machinery at all (the report's
`_ClientProtocolWrapper` never materialized). Fixes:

1. **Zig `talyn.StreamServer.set_server_ref(wref)`** (new O-method):
   installs the Python wrapper reference. It is handed a WEAKREF, not
   the wrapper itself: a strong `srv.server_ref` would have formed a
   permanent `Server -> _servers -> server_ref -> Server` cycle.

2. **Zig transport tracking**: `StreamTransportObject` gained a
   `server_ref` field (traversed/cleared via the automatic
   `py_visit`/`deinitialize_object_fields` walkers; explicit null in
   the tp_new). The accept path now dereferences the weakref (a dead
   wrapper makes tracking a no-op), holds the only extra strong
   reference on the ACCEPTED TRANSPORT (transport -> wrapper —
   acyclic), calls `wrapper._attach()` BEFORE
   `protocol.connection_made` so an instantly-closing protocol never
   decrements below the count of its own connection (storing
   `transport.server_ref` only after `_attach()` succeeds and registering
   `errdefer transport_force_close` if `connection_made` fails). A shared
   `Lifecyle.detach_server(transport)` helper — called from
   `close_transports`, `schedule_connection_lost_once` (covering
   `transport_close`'s both-closed branch and `transport_force_close` /
   `abort()`), and `stream_clear` — resolves `_detach` FIRST (BUG-369 lesson:
   never use the captured pointer after releasing the field — an earlier
   draft of this fix segfaulted in Server._detach exactly like that),
   releases the field as the once-guard, then invokes `_detach()` outside
   the teardown path with errors swallowed (BUG-375-style `PyErr_Clear`, no
   empty catch).

3. **`Server.__init__` wiring**: every `Server` instance (TCP, SSL,
   unix, ssl-unix — `Server(loop, None)` tolerated) now installs
   `weakref.ref(self)` on all of its StreamServers; the two
   hasattr-guarded unix blocks (never-functional) were removed.
