# BUG-388 — `StreamTransport.get_extra_info` ignores positional `default` argument (`transport.get_extra_info('unknown', 'fallback')` returns `None`)

- **Status**: 🟢 Fixed
- **Severity**: 🟡 Medium — violates the standard `asyncio.BaseTransport.get_extra_info(name, default=None)` signature on `StreamTransport` whenever `default` is passed positionally (which is how nearly all Python code calls `transport.get_extra_info('sslcontext', None)` or `transport.get_extra_info('custom', 'fallback')`)
- **Category**: Logic Bug (`asyncio` API Compatibility)
- **Files**:
  - `src/transports/stream/extra_info.zig:25-36`
  - `src/transports/datagram/extra_info.zig:16-39`
- **Related**: [BUG-320](320.md)

## Overview & Root Cause

In [BUG-320](320.md), `DatagramTransport.get_extra_info` (`src/transports/datagram/extra_info.zig:16-39`) was fixed to accept `default` both positionally (`if (args.len == 2)`) and by keyword (`default=`).

However, `StreamTransport.get_extra_info` in `src/transports/stream/extra_info.zig:25-36` only parses `default` from keyword arguments (`knames`) and completely ignores `args[1]`:

```zig
inline fn z_transport_get_extra_info(self: *StreamTransportObject, args: []?PyObject, knames: ?PyObject) !PyObject {
    if (args.len < 1) {
        python_c.raise_python_value_error("Invalid number of arguments\x00");
        return error.PythonError;
    }

    const info_name = args[0].?;
    var default_value: ?PyObject = null;

    try python_c.parse_vector_call_kwargs(knames, args.ptr + args.len, &.{"default\x00"}, &.{&default_value});
    defer python_c.py_xdecref(default_value);
```

Consequently:
- Calling `stream_transport.get_extra_info("unknown_key", "my_default")` with 2 positional arguments ignores `"my_default"` and returns `None`!
- Calling `stream_transport.get_extra_info("a", "b", "c")` with >2 positional arguments does not raise `TypeError` either.

## Trigger Scenario

```python
assert stream_transport.get_extra_info("nonexistent", "fallback") == "fallback"
# FAILS under Talyn: returns None!
```

## Resolution

1. In `src/transports/stream/extra_info.zig:z_transport_get_extra_info`:
   - Added validation for argument count: returns `TypeError` if `args.len > 2`.
   - Supported positional `default` parameter (`args[1]`).
   - Parsed keyword `default` via `python_c.parse_vector_call_kwargs`.
   - Raised `TypeError` if `default` was supplied as both positional argument and keyword argument.
   - When the requested extra info key is unrecognized, returns `python_c.py_newref(default_value)` (or `None` if no default was specified).
2. Added unit tests in `tests/transports/test_stream.py` and `tests/test_dns_resolver_resilience.py`.
