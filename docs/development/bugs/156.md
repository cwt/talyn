# BUG-156 — Use-after-free and double-free in `HookHandle.cancel()`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — use-after-free / double-free
- **Files**: `src/loop/python/control.zig:126-152`
- **Lessons**: [Memory Safety §Lesson 01](../lessons/01-memory-and-reference-counting.md), [Event Loop §Lesson 03](../lessons/03-event-loop-lifecycle.md)
- **Description**: In `src/loop/python/control.zig`, `HookHandle` represents an installed loop hook node. Calling `hook_handle_cancel` passes `instance.node` to `instance.loop_data.remove_hook(hook_type, instance.node)`, which unlinks and destroys the node via `HooksList.release_node`. Because `HookHandle` lacks a `cancelled` boolean field, invoking `.cancel()` multiple times on the same handle causes subsequent calls to access and release the already-freed node pointer.
- **Trigger**: Calling `hook.cancel()` more than once on a hook handle returned by `loop.add_hook()`.
- **Consequences**: Heap corruption, invalid linked-list traversals, and potential crashes during event loop hook execution.
- **Fix**: Added `cancelled: bool` field to `HookHandle`, initialized it to `false` in `z_loop_add_hook`, and guarded `hook_handle_cancel` to return immediately if already cancelled.
