# BUG-324 — Unchecked 64-bit integer narrowing panics across socket and transport APIs

- **Status**: 🔴 Open (2026-09-07)
- **Severity**: 🟢 Low — Unchecked @intCast on 64-bit Python values causing runtime integer cast panics
- **Files**:
  - `src/utils/pseudosocket.zig` (lines 120, 127); `src/loop/python/io/socket/ops.zig` (line 340); `src/loop/python/io/subprocess/exec.zig` (line 43); `src/utils/address.zig` (lines 353–356)
- **Lessons**: [Security & Input Validation](../lessons/09-security-and-input-validation.md), [Zig Specific Patterns](../lessons/08-zig-specific-patterns.md)
- **Description**:
Across several files:
- `pseudosocket.zig:120, 127`: `level` and `optname` cast from `c_long` to `u32` with `@intCast`.
- `ops.zig:340`: `nbytes` in `loop_sock_recv` cast from `isize` to `usize` with `@intCast(nbytes_long)`.
- `exec.zig:43`: `pid` cast from `c_long` to `i32` with `@intCast`.
- `address.zig:353–356`: `flowinfo` and `scope_id` cast to `u32` with `@intCast`.
If negative or out-of-range values are passed from Python, `@intCast` panics in Debug/ReleaseSafe builds instead of raising `ValueError` or `OverflowError`.
- **Root Cause**: Direct `@intCast` without prior range validation.
- **Trigger Scenario**: Passing negative `nbytes`, out-of-range socket options, or invalid scope IDs from Python.
- **Proposed Remediation**: Use `std.math.cast` or explicit `if (val < 0 or val > max) return PyErr(ValueError);`.
