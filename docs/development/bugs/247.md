# BUG-247 — Documentation link formatting and severity summary math desync in bug tracker

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — Documentation integrity / OKF metadata consistency
- **Files**: `docs/development/bugs/index.md`, `docs/development/bugs/227.md`–`242.md`
- **Lessons**: [Defensive §Lesson 79 — Silent Failure](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**: Commits `951` through `954` introduced three inconsistencies in the bug documentation bundle:

  1. **Broken 404 Links**: In `docs/development/bugs/index.md:264-279`, table links for bugs 227 to 242 were written with a four-digit zero-padded pattern `[240](0240.md)`, but the actual files on disk are three-digit filenames (`240.md`). All links in this range resolve to 404.
  2. **Frontmatter Status Desync**: In `docs/development/bugs/227.md` through `242.md`, the YAML frontmatter headers retained `status: "Open"` despite the bugs being marked as `"Fixed"` or `"False Positive"` in both the document body and the bug tracker index.
  3. **Severity Table Mathematical Mismatch**: The "Summary by Severity" table rows in `index.md` list counts that sum to 211 (due to missing the `Medium-Mid` category and outdated counts), whereas the summary total row was manually set to 241 in commit `954`.

- **Trigger**: Navigating bug tracker links in documentation or parsing YAML frontmatter.
- **Consequences**: Broken navigation links for recent bugs and inconsistent metadata for automated OKF parsers.
- **Fix**: Update index links to match disk filenames (`227.md`–`242.md`), correct frontmatter status across all bug entries, and reconcile severity counts in the summary table.
