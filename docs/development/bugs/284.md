# BUG-284 — `new_stream_transport` error path leaks fd + fixed-file slot

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟡 Medium — fd / resource leak
- **Files**:
  - `src/transports/stream/constructors.zig:205` (`errdefer ... tp_free(instance)` — no close/unregister)
  - `src/transports/stream/constructors.zig:170` (`self.fd = fd` stored before fallible tail)
  - `src/transports/stream/constructors.zig:185-190` (fixed-file slot registered)
  - `src/transports/stream/constructors.zig:192` (`try Read.queue_read_operation(...)` — protocol `get_buffer` may raise; ring overflow possible)
  - `src/loop/python/io/pipe/unix.zig:70-76` (`ucd.socket_fd = -1` ownership transfer, then `new_stream_transport`)
- **Lessons**: [Zig-Specific Patterns §Lesson 77](../lessons/08-zig-specific-patterns.md), [io_uring & Kernel Interaction](../lessons/04-io-uring-and-kernel.md)
- **Description**: The only errdefer is a bare `tp_free`. A failure after the fd is stored and the slot registered leaks both. Via the unix-pipe connect path the caller has already relinquished ownership (`socket_fd = -1`), so the descriptor is never closed by anyone; the accept path compensates the fd but still loses the fixed-file table entry.
- **Trigger**: Protocol factory objects whose `get_buffer` raises during transport construction, or submission-ring exhaustion.
- **Consequences**: Cumulative fd exhaustion and fixed-file pool depletion.
- **Fix (Proposed)**: Add `errdefer` cleanup that unregisters the fixed-file slot and closes the fd when `owns_fd` is set.
