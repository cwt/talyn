# BUG-194 — Unsafe @enumFromInt on unchecked signal integers causing enum cast panics

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Architectural Mandate #1 violation (NO PANICS in IO path)
- **Files**: `src/transports/subprocess/transport.zig:128`, `src/loop/python/unix_signals.zig:76, 109`
- **Lessons**: [Defensive Programming §Lesson 53](../lessons/10-defensive-programming-and-code-quality.md), [Architectural Mandates §Mandate 1](../architectural-mandates.md)
- **Description**: In `src/transports/subprocess/transport.zig` (`subprocess_send_signal`) and `src/loop/python/unix_signals.zig`, integers received from Python were cast to Zig enum types via `@as(std.os.linux.SIG, @enumFromInt(sig))` without range checks. In Zig safe builds, passing an integer that does not map to a declared enum tag triggered an unrecoverable `@panic("illegal enum value")`.
- **Trigger**: Passing an unsupported or out-of-range signal number (e.g. `send_signal(999)`).
- **Consequences**: Uncaught panic and process crash.
- **Fix**: Validated `sig <= 0 or sig > 64` raising `ValueError("Invalid signal")` before enum casting across all affected signal entrypoints.
