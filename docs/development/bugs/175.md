# BUG-175 — Missing `.cleanup` function pointer on IO queues leading to leaks during loop shutdown

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — resource & memory leak on teardown
- **Files**: `src/transports/datagram/write.zig:154`, `src/transports/subprocess/transport.zig:387`, `src/loop/python/io/socket/ops.zig:165,270,480,522,649,785,895`
- **Lessons**: [Resource Cleanup §Lesson 04](../lessons/04-resource-cleanup-and-cancellation.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: Several modules allocate contextual tracking structures on the heap (e.g. `SendToData`, `AcceptData`, `SockConnectData`, `SockRecvData`, `SockSendAllData`) and increment Python object references before submitting tasks to `io_uring`. While cleanup functions such as `cleanup_sendto` or `cleanup_pidfd` are implemented, the task submission passes `.cleanup = null`. When the event loop shuts down or discards cancelled tasks, `CallbackManager` relies on `.cleanup` to free resources. Passing `null` bypasses cleanup entirely.
- **Trigger**: Closing the event loop or cancelling tasks while asynchronous I/O operations are in flight.
- **Consequences**: Heap memory and Python reference leaks on loop termination.
- **Fix**: Connect the corresponding cleanup functions (`&cleanup_sendto`, `&cleanup_pidfd`, etc.) to the `.cleanup` field in `Callback` structs.
