# BUG-445 — Dead `Record.hostname` field

- **Status**: 🟡 Open
- **Severity**: ⚪ Low — dead code / confusing duplicate ownership
- **Category**: Dead code / code quality
- **Files**: `src/loop/dns/cache.zig:28-70`
- **Related**: [BUG-395](395.md), [Lesson 98](../lessons/10-defensive-programming-and-code-quality.md)

## Description

`Record.hostname` (`cache.zig:29`) is assigned in `create_new_record` /
`create_new_record_from_resolved` but never read in production — the only syntactic readers are unit
tests (`cache.zig:176, 247`). It duplicates ownership of the same allocation and confuses who frees it.

Validation (2026-11-12): there is no double-free and no leak — `LRUCache` stores the key un-duped
(`lru.zig:88-93`), so `record.hostname` aliases the map key, and `evict_record` frees it exactly once
via `self.allocator.free(key)` (`cache.zig:76`). The field is purely a dead duplicate.

## Fix

Drop `Record.hostname` (or document it as a `[]const u8` alias owned by the map).
