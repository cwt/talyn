# BUG-246 — Broken unit test in `streamserver/main.zig` crashes with optional null unwrap panic

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — Broken unit test / Test suite stability
- **File**: `src/transports/streamserver/main.zig:447-464`
- **Lessons**: [Defensive §Lesson 79 — Silent Failure](../lessons/10-defensive-programming-and-code-quality.md), [BUG-234](234.md) (trivially true unit test in streamserver)
- **Description**: Commit `952` attempted to replace the tautological unit test for BUG-234 with:

  ```zig
  test "BUG-33: start_serving clears accept_paused" {
      var server: StreamServerObject = .{
          .ob_base = undefined,
          .loop = null,
          .protocol_factory = null,
          .server_fd = -1,
          .family = 0,
          .backlog = 0,
          .blocking_task_id = 0,
          .closed = false,
          .accept_paused = true,
          .server_ref = null,
      };
      try start_serving(&server);
      try testing.expect(!server.accept_paused);
      try testing.expect(!server.closed);
  }
  ```

  However, `start_serving(&server)` immediately delegates to `enqueue_accept(server)`:
  ```zig
  fn enqueue_accept(server: *StreamServerObject) !void {
      const loop_data = utils.get_data_ptr(Loop, @as(*Loop.Python.LoopObject, @ptrCast(server.loop.?)));
      ...
  ```
  Unwrapping `server.loop.?` when `.loop = null` causes a fatal Zig runtime panic: `panic: attempt to unwrap null optional`.

  The panic was masked only because `src/main.zig` does not import `Transports` in its top-level test block. As soon as `Transports` tests are referenced, `zig build test` panics.

- **Trigger**: Executing unit tests in `src/transports/streamserver/main.zig`.
- **Consequences**: Test runner crashes with a null-dereference panic.
- **Fix**: Update the test to verify flag state independently or supply a properly initialized mock loop structure rather than passing `null` into `start_serving`.
