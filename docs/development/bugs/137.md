# BUG-137 — Stream write raises `RuntimeError` on paused transport instead of buffering

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium-High — asyncio transport flow-control contract violation
- **Files**: `src/transports/stream/write.zig:158-161, 188-191`, `talyn/loop.py:103`
- **Lessons**: [Network Protocols §Lesson 40](../lessons/06-network-protocols-and-io.md)
- **Description**: `src/transports/stream/write.zig` checks `if (!instance.is_writing) { python_c.raise_python_runtime_error("Writing operations are paused\x00"); return null; }`. In the asyncio specification, `pause_writing()` is an advisory notification of high-watermark backpressure to the protocol; callers are explicitly permitted to call `transport.write()` and the transport MUST buffer the data. Raising a runtime error broke standard protocols and forced a synchronous `os.write` bypass in `talyn/loop.py:103`.
- **Trigger**: Writing to a stream transport after high-watermark backpressure has triggered `pause_writing()`.
- **Consequences**: `RuntimeError: Writing operations are paused` is raised in user code, crashing standard asyncio stream writers.
- **Proposed Fix**: Remove the `!instance.is_writing` runtime error check; allow `WriteTransport.write` to buffer data normally. Remove the `os.write` workaround in `talyn/loop.py`.
