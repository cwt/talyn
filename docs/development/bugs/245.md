# BUG-245 — Float cast safety violation on `float("nan")` and `float("inf")` in `timeout_from_secs` and `create_connection`

- **Status**: ✅ Fixed
- **Severity**: 🟠 Medium-High — Zig runtime safety panic / undefined behavior
- **Files**: `src/loop/dns/resolv.zig:24-30` (timeout_from_secs), `src/loop/python/io/client/create_connection.zig:650-662, 690-700`
- **Lessons**: [Security §Lesson 34 — Parser Strictness](../lessons/09-security-and-input-validation.md), [io_uring §Lesson 185 — Kernel -EINVAL from unnormalized nanoseconds](../lessons/04-io-uring-and-kernel.md), [BUG-241](241.md) (happy eyeballs delay parsing), [BUG-242](242.md) (DNS timeout parsing)
- **Description**: Python's `PyFloat_AsDouble(float("inf"))` and `PyFloat_AsDouble(float("nan"))` return IEEE-754 `Inf` and `NaN` values without setting `PyErr_Occurred()`, as `float("inf")` and `float("nan")` are valid Python float instances.

  Consequently, checking `PyErr_Occurred() != null` does not catch `NaN` or `Inf`.
  1. In `src/loop/dns/resolv.zig:24-30` (`timeout_from_secs`):

     ```zig
     pub fn timeout_from_secs(timeout_secs: f64) ?DnsTimeout {
         if (timeout_secs < 0.0) return null;
         const sec: i64 = @floor(timeout_secs);
         const frac = timeout_secs - @as(f64, @floatFromInt(sec));
         const nsec: i64 = @floor(frac * 1e9);
         return .{ .sec = @as(u64, @intCast(sec)), .nsec = @as(u32, @intCast(nsec)) };
     }
     ```

     `NaN < 0.0` and `Inf < 0.0` evaluate to `false`. When passed `NaN` or `Inf`, `@floor` produces `NaN` or `Inf`, and `@intCast` triggers an illegal float-to-integer cast panic under Zig 0.16.0 runtime safety checks.
  2. In `src/loop/python/io/client/create_connection.zig:685-692`:

     ```zig
     if (address_list.len > 1 and delay > 0) {
         const seconds: u64 = @intFromFloat(@floor(delay));
         const nanoseconds: u64 = @intFromFloat((delay - @floor(delay)) * 1e9);
     ```

     For `delay = Inf`, `delay > 0` is `true`, and `@intFromFloat(@floor(inf))` triggers a Zig runtime safety panic.

- **Trigger**: Passing `float("nan")` or `float("inf")` as a timeout or happy eyeballs delay parameter.
- **Consequences**: Zig process abort / safety panic in Debug and ReleaseSafe modes; undefined integer conversions and invalid kernel timespecs in ReleaseFast.
- **Resolution (2026-08-17)**: Guarded `timeout_from_secs` with `if (!std.math.isFinite(timeout_secs) or timeout_secs < 0.0) return null;` using typed `@intFromFloat` conversions, and guarded `create_connection.zig` with `if (!std.math.isFinite(delay) or delay < 0.0) delay = 0;`. Added regression tests in `test_create_connection.py`.
- **Verification**: `test_all.sh` passes cleanly.
