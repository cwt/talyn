# BUG-181 — Uninitialized stack memory read in DNS answer parsing yielding corrupt resolved addresses

- **Status**: 🔴 Open
- **Severity**: 🟠 High — Stack memory disclosure and corrupt DNS address resolution
- **Files**: `src/loop/dns/resolv.zig:496, 500, 513-516`
- **Lessons**: [Zig Patterns §Lesson 77](../lessons/077-zig-patterns-and-idioms.md), [Network Protocols §Lesson 47](../lessons/047-network-protocols.md)
- **Description**: In `src/loop/dns/resolv.zig`, `process_dns_response` defines `var result: utils.Address = undefined;`. When parsing DNS responses that contain records other than A/AAAA/PTR (such as CNAME, SOA, NS, TXT), `parse_individual_dns_result` leaves `result` unchanged. The subsequent condition `else if (result.any.family != 0)` reads uninitialized stack memory. If non-zero, it appends the uninitialized garbage `result` to `server_data.results`.
- **Trigger**: DNS responses containing CNAME, SOA, TXT, or other non-host record types.
- **Consequences**: Random garbage IP addresses returned to applications, failed connections, and potential security leaks of stack bytes.
- **Fix**: Initialize `var result: utils.Address = .{ .any = .{ .family = 0, .data = .{0} ** 14 } };`.
