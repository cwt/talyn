# BUG-191 — Use-after-free / double-release hazard in LRUCache.pop_tail with eviction callback

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium — Dangling pointer return on cache pop
- **Files**: `src/utils/lru.zig:105-117`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/004-memory-management-and-refcounting.md), [Data Structures §Lesson 40](../lessons/040-data-structures-and-algorithms.md)
- **Description**: In `src/utils/lru.zig`, `pop_tail` removes the oldest entry. If `self.evict_callback` is configured (which typically frees or decrements the reference count of the value), `pop_tail` invokes `evict_callback` and then returns `value` to the caller. The caller receives a pointer to already-freed or decreffed data.
- **Trigger**: Calling `pop_tail` on an LRUCache configured with an eviction callback.
- **Consequences**: Use-after-free if the caller attempts to use or free the returned value.
- **Fix**: Skip `evict_callback` when the caller explicitly pops an item, transferring value ownership directly to the caller.
