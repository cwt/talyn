# BUG-407 — unchecked `fileno()` in datagram endpoint creation

- **Status**: 🔴 Open (confirmed, unfixed)
- **Severity**: 🟠 High — native panic in safety builds; silent fd truncation/confusion in ReleaseFast
- **Category**: Python C API / Input Validation / File Descriptors
- **Files**:
  - `src/loop/python/io/datagram/create_endpoint.zig:311-347` — sock path
  - `src/loop/python/io/socket/ops.zig` — correct `checkedNarrow`/`PyErr_Occurred` pattern used elsewhere
- **Related**: [BUG-361](361.md) (unchecked narrowing), [BUG-324](324.md)

## Overview

```zig
const raw_fd = python_c.PyObject_CallMethod(sock_obj, "fileno\x00", null) orelse return error.PythonError;
defer python_c.py_decref(raw_fd);
const lfd = python_c.PyLong_AsLong(raw_fd);        // no PyErr_Occurred check
const dup_ret = std.os.linux.dup(@intCast(lfd));   // @intCast may panic / truncate
```

`PyLong_AsLong` can return `-1` with a Python exception set; `@intCast` on an out-of-range `i64` is a panic in ReleaseSafe/Debug and truncates in ReleaseFast. There is also no `fd >= 0` check before `dup`.

## Trigger Scenario and Evidence (confirmed 2026-11-01)

Environment: Apple `container` 1.6.1, Fedora 44 aarch64, Zig 0.16.0, Python 3.13.16.

Repro: `h15_fileno.py` — `create_datagram_endpoint(Proto, sock=EvilSock())` where `EvilSock.fileno()` returns `2**40`.

ReleaseFast:

```text
warning: PerformRead/RecvMsg: unexpected io_uring result NOTSOCK
RESULT: FAIL accepted huge fileno -> <talyn.DatagramTransport object ...>
```

`2**40` truncates to 0, `dup(0)` duplicates stdin, and the transport is created over a non-socket descriptor. The process continues with a bogus endpoint.

ReleaseSafe (diagnostic build):

```text
panic: integer does not fit in destination type
src/loop/python/io/datagram/create_endpoint.zig:315
```

## Proposed Remediation

Follow the pattern used by the socket operations:

```zig
const lfd = python_c.PyLong_AsLong(raw_fd);
if (python_c.PyErr_Occurred() != null) return error.PythonError;
const fd: std.posix.fd_t = try utils.checkedNarrow(std.posix.fd_t, lfd, "invalid file descriptor\x00");
if (fd < 0) {
    python_c.raise_python_value_error("invalid file descriptor\x00");
    return error.PythonError;
}
```

Also validate that the descriptor is a socket (`getsockopt(SO_TYPE)` or `fstat`) before adopting it.
