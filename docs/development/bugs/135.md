# BUG-135 — Task cancellation request count skipped when task is awaiting a future

- **Status**: 🔴 Open
- **Severity**: 🟡 Medium-High — broken PEP 678 / Python 3.11+ task cancellation tracking
- **Files**: `src/task/cancel.zig:46-54`
- **Lessons**: [Network Protocols §Lesson 44](../lessons/06-network-protocols-and-io.md)
- **Description**: In `fast_task_cancel`, when `task.fut_waiter` is non-null, the function cancels the waiter and immediately returns (`return ret;`) before executing `task.cancel_requests +|= 1;` and `task.must_cancel = true;`.
- **Trigger**: Calling `task.cancel()` on any Task that is currently awaiting a Future or another Task.
- **Consequences**: `task.cancelling()` returns 0 and `task.uncancel()` has no effect, violating PEP 678 semantics where cancel count must be tracked on the Task regardless of whether a sub-future is being awaited.
- **Proposed Fix**: Increment `task.cancel_requests +|= 1;` and set `task.must_cancel = true;` before checking/cancelling `task.fut_waiter`.
