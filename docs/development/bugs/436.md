# BUG-436 — Parser strictness gaps (IPv4 trailing dot, DNS empty name)

- **Status**: 🟢 Fixed
- **Severity**: 🟢 Low — malformed input silently accepted
- **Category**: Parser strictness / input validation
- **Files**: `src/utils/address.zig:120-151`, `src/loop/dns/parsers.zig:73-104`
- **Related**: [Lesson 58](../lessons/09-security-and-input-validation.md), [BUG-9](009.md), [BUG-33](033.md)

## Description

1. **`Address.parseIp4`** — after the 4th octet, `if (i < host.len) i += 1;` consumes the trailing `.`
   and the outer loop exits with `octet_i == 4`, so `"1.2.3.4."` is silently accepted (whereas
   `inet_pton` / Python `ipaddress` reject it).

2. **`parse_name`** — a compression pointer whose 14-bit target is `>= full_data.len` makes the
   `while (offset < full_data.len)` loop exit immediately; the function then returns an **empty slice**
   instead of `error.MalformedDnsResponse`. For a PTR record this caches an empty hostname rather than
   rejecting the malformed response.

## Consequences

Ambiguous address accepted; malformed DNS response treated as an empty name.

## Fix

- `parseIp4`: after the loop require `i == host.len` (reject trailing/empty final octet).
- `parse_name`: validate `target < full_data.len` before following the pointer and return
  `error.MalformedDnsResponse` otherwise.

## 2026-11-12 Validation

- Both gaps traced: `address.zig:147-149` consumes the trailing dot after the 4th octet and the loop
  exits with `octet_i == 4` (the `octet_i >= 4` check at `:125` only fires when a 5th octet starts,
  e.g. `"1.2.3.4.5"`), and `parsers.zig:82-103` returns an empty slice for an out-of-range pointer
  target (the guards at `:89-90`/`:97` cover pointer count, second-byte presence and label length —
  not the target range).
- Sharpened consequence: errored names are skipped via `catch null` (`resolv/parse.zig:64`), but a
  non-null **empty** slice passes through and is appended as a PTR hostname
  (`response.zig:323-325`) — the empty name really does reach the cache.

## Resolution (2026-11-12)

1. **`parseIp4` trailing dot**: the octet loop now breaks on a clean end-of-host and rejects a dot
   after the 4th octet (`"1.2.3.4."` → `error.InvalidIPAddressFormat`, matching `inet_pton` /
   `ipaddress`). Dot-before-4th-octet and 5th-octet behavior unchanged.
2. **`parse_name` pointer target**: the 14-bit compression target is validated against
   `full_data.len` before following it — an out-of-range target now returns
   `error.MalformedDnsResponse` instead of the (possibly empty) accumulated slice. In-range
   pointers still resolve (regression-tested with a two-label jump).

Unit tests added: `parseIp4 rejects a trailing dot (BUG-436)` (`src/utils/address.zig`) and
`parse_name rejects an out-of-range compression pointer (BUG-436)` (`src/loop/dns/parsers.zig`).

Validation: `zig build test` green on Zig 0.16.0 and 0.17.1;
`./scripts/test_all.sh --python=3.15,3.15t --starburst --verbose` green (498 pytest passed on
py3.15, 497 + 1 skipped on py3.15t; stdlib asyncio green; both toolchains green).

### Follow-up Hardening (2026-11-13)

- `parse_name` (`src/loop/dns/parsers.zig`) now requires reaching an explicit `0x00` root label
  terminator (rejecting truncated names or EOF offsets with `error.MalformedDnsResponse`) while
  still accepting the valid root domain `"\x00"`.
- Both `parse_name` (`src/loop/dns/parsers.zig`) and `skip_name` (`src/loop/dns/resolv/parse.zig`)
  now reject reserved/extended label bit patterns (`01xx_xxxx` and `10xx_xxxx`, `(byte & 0xC0) != 0`).
- Added unit tests `"parse_name rejects missing terminator and reserved label bits (BUG-436)"` in
  `src/loop/dns/parsers.zig` and extended `"skip_name: malformed"` in `src/loop/dns/resolv/parse.zig`.
