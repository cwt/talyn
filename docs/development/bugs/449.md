# BUG-449 — `import talyn` fails outright on Python 3.13/3.13t

- **Status**: 🟢 Fixed
- **Severity**: 🟠 High — the accelerator fails to import at all on 3.13/3.13t
- **Category**: Compatibility / module init
- **Files**: `src/utils/python_imports.zig:141-150`
- **Related**: [BUG-268](268.md) (dual-registry contract), P23 v0.11.2 review (the rebind)

## Description

The P23 v0.11.2 review added the rebind of `asyncio.tasks._py_all_tasks` to the accelerator's
`all_tasks` (dual-registry contract, BUG-268 narrowed registration). The fetch of the ORIGINAL
binding was hard:

```zig
py_all_tasks_original.store(python_c.PyObject_GetAttrString(tasks_mod, "_py_all_tasks\x00")
    orelse return error.PythonError, .release);
```

`_py_all_tasks` was introduced in **Python 3.14** (the pure-Python `all_tasks` registry split).
On 3.13/3.13t `asyncio.tasks` has no such attribute (machine-checked:
`hasattr(asyncio.tasks, "_py_all_tasks") == False` on 3.13, `True` on 3.14), so
`initialize_python_imports` returned `error.PythonError` at module init and **every**
`import talyn` failed with `AttributeError: module 'asyncio.tasks' has no attribute
'_py_all_tasks'` — 61 collection errors across the pytest suite on 3.13/3.13t (full matrix run).

Found by the final 6-interpreter matrix run (`3.13,3.13t,3.14,3.14t,3.15,3.15t`); the
intermediate gates only exercised 3.15/3.15t, which is why the sweep's per-bug runs missed it.
The defect predates the sweep (P23 v0.11.2 review band).

## Consequences

`import talyn` fails on Python 3.13/3.13t; all tests error at collection; no accelerator use.

## Fix

Tolerant fetch: when `_py_all_tasks` is absent (≤ 3.13), clear the error and skip the rebind —
on those versions the accelerator's C registry is already the reader of `asyncio.all_tasks()`
(the pure-Python registry split that makes `_py_all_tasks` a *reader* exists only in 3.14+).
The restore-on-release path already handles a null `py_all_tasks_original`.

## Resolution (2026-11-12)

Fixed together with [BUG-450](450.md) (same discovery run). The `_py_all_tasks` fetch is now
tolerant: when the attribute is absent (≤ 3.13), the error is cleared and the rebind is skipped —
on those versions the accelerator's C registry is already the reader of `asyncio.all_tasks()`. The
restore-on-release path already handled a null `py_all_tasks_original`.

Validation: `zig build test` (3.13 headers) green; `import talyn` works on 3.13/3.13t; the full
6-interpreter matrix run (see BUG-450's validation) is green.
