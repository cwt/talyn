# BUG-220 — Resource and reference count leak on synchronous cache return error in `z_loop_getaddrinfo`

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium — Resource & Reference Count Leak
- **Files**: `src/loop/python/io/socket/getaddrinfo.zig:170-209`
- **Lessons**: [Memory & Reference Counting §Lesson 1](../lessons/01-memory-and-reference-counting.md), [Python C-API Correctness §Lesson 5](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/loop/python/io/socket/getaddrinfo.zig`, `z_loop_getaddrinfo` initializes `gaid: *GetAddrInfoData` by allocating memory, duping `host_str`, and acquiring references to `gaid.future` and `gaid.loop`. On synchronous cache hit, `loop_data.dns.lookup` returns an `address_list`. If `build_result_tuple` or `future_fast_set_result` errors, the error unwinds through `errdefer alloc.destroy(gaid)` and `errdefer alloc.free(host_str)`. However, `gaid.future` and `gaid.loop` were already increffed, so their references are leaked, and `host_str` cleanup ordering is violated.
- **Trigger**: An OOM or Python error occurs while converting a cached DNS lookup result into a Python tuple.
- **Consequences**: Python references on `Future` and `Loop` objects leak along with string allocations.
- **Fix**: Provide an `errdefer` block that decrefs `gaid.future` and `gaid.loop` and properly cleans up `host_str` and `gaid`.
