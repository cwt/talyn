# BUG-137 — Stream write raises `RuntimeError` on paused transport instead of buffering

- **Status**: ✅ Fixed
- **Severity**: 🟡 Medium-High — asyncio transport flow-control contract violation
- **Files**: `src/transports/stream/write.zig:158-176, 188-210`
- **Lessons**: [Network Protocols §Lesson 40](../lessons/06-network-protocols-and-io.md)
- **Description**: `src/transports/stream/write.zig` checked `if (!instance.is_writing)` and raised `RuntimeError("Writing operations are paused")`. In the asyncio specification, `pause_writing()` is an advisory notification of backpressure; callers are permitted to call `transport.write()` and the transport must buffer the data.
- **Trigger**: Writing to a stream transport after high-watermark backpressure has triggered `pause_writing()`.
- **Consequences**: `RuntimeError: Writing operations are paused` was raised in user code.
- **Fix**: Removed the `!instance.is_writing` runtime error check from `transport_write` and `transport_write_lines`, allowing writes to buffer normally while guarding `protocol_pause_writing` callback invocations to occur only on transition from `is_writing == true`.
