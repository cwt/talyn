# BUG-384 — Multi-server DNS premature failure on negative responses (`SERVFAIL`/`NXDOMAIN`/`NODATA`), dual-stack `A`+`AAAA` first-packet race, and missing bare hostname in `get_hostname_array` for dotless names

- **Status**: 🔴 Open
- **Severity**: 🟠 Medium-High — breaks multi-nameserver redundancy when the primary nameserver returns `SERVFAIL`/`REFUSED`/`NXDOMAIN`, drops `A` or `AAAA` records in dual-stack lookups, and fails to resolve dotless hostnames not in the search domain
- **Category**: Logic Bug (DNS Resolver Protocol)
- **Files**:
  - `src/loop/dns/resolv.zig:492-655, 780-800`
- **Related**: [BUG-8](008.md), [BUG-317](317.md), [Lesson 55](../lessons/06-network-protocols-and-io.md)

## Overview & Root Cause

In `src/loop/dns/resolv.zig`, there are three protocol logic bugs in `process_dns_response` and `get_hostname_array`:

1. **Multi-nameserver redundancy broken when a nameserver returns `SERVFAIL`/`REFUSED`/`NXDOMAIN` or `NODATA` (`src/loop/dns/resolv.zig:511-528, 639-653`)**:
   In `process_dns_response`:
   - At lines 511–528, if `rcode != 0`:
     ```zig
     if (rcode != 0) {
         if (server_data.queries_sent < server_data.queries_count) {
             try queue_send_query(server_data);
             return;
         }
         const control_data = server_data.control_data;
         try mark_resolved_and_execute_user_callbacks(control_data);
         server_data.release();
         return;
     }
     ```
   - And at lines 639–653, if `added_records == 0`:
     ```zig
     if (server_data.queries_sent < server_data.queries_count) {
         try queue_send_query(server_data);
     } else {
         const control_data = server_data.control_data;
         try mark_resolved_and_execute_user_callbacks(control_data);
         server_data.release();
     }
     ```
   Notice that neither path checks `if (control_data.active_servers == 1)` (unlike the I/O error path in `on_response_received` at line 408)!
   If `/etc/resolv.conf` has two nameservers (`nameserver 10.0.0.1` and `nameserver 8.8.8.8`) and `10.0.0.1` responds faster with `SERVFAIL`, `REFUSED`, or `NXDOMAIN`, `process_dns_response` **immediately** calls `mark_resolved_and_execute_user_callbacks(control_data)` (resolving the lookup as `.none` / failed and cancelling the pending query to `8.8.8.8`) instead of waiting for `8.8.8.8` when `control_data.active_servers > 1`!

2. **Dual-stack (`A` + `AAAA`) query state machine flaw (`src/loop/dns/resolv.zig:308, 639-653, 712-748`)**:
   In `build_queries` (lines 712–748), for each candidate hostname in `hostnames_array`, 2 queries are built: query 0 is `A` (IPv4) and query 1 is `AAAA` (IPv6).
   In `Resolv.queue` (line 908), query 0 (`A`) is sent first (`queries_sent = 1`).
   When the `A` response arrives in `process_dns_response`:
   - If the `A` response contains >= 1 IPv4 address (`added_records > 0`), lines 616–638 **immediately** mark the lookup `.resolved` and fire all user callbacks — **never sending query 1 (`AAAA`) at all**! Thus `loop.getaddrinfo(host, port)` (with `family=AF_UNSPEC`) **never returns IPv6 (`AAAA`) addresses** for any dual-stack host that has an `A` record!

3. **`get_hostname_array` never includes the bare hostname when `dots < ndots` (`src/loop/dns/resolv.zig:780-800`)**:
   ```zig
   var dots: usize = 0;
   var iter = std.mem.tokenizeScalar(u8, hostname, '.');
   while (iter.next()) |_| {
       dots += 1;
   }
   if (dots == 0) {
       return &.{};
   }
   dots -= 1;

   var hostnames_size = loop.dns.search_domains.items.len;
   if (dots >= loop.dns.ndots) {
       hostnames_size += 1;
   }
   ```
   Per `resolv.conf(5)`:
   - When `dots < ndots` (e.g., `dots == 0` for a single-label hostname like `"myhost"` or `"localhost"` when `/etc/hosts` doesn't match, with default `ndots == 1` and `search corp.local`), the resolver must try the search domains first (`myhost.corp.local`) **and then fall back to the bare hostname (`myhost`)**!
   - When `dots >= ndots` (e.g., `"example.com"` with `dots == 1 >= ndots == 1`), the resolver must try the **bare hostname (`example.com`) FIRST**, and only try `example.com.corp.local` if the bare hostname fails!
   Instead, `get_hostname_array`:
   - Completely **omits** the bare hostname whenever `dots < ndots` (so if `/etc/resolv.conf` has `search example.org`, a single-label hostname is **only** queried as `name.example.org` and never as `name`)!
   - Appends the bare hostname **last** (`hostnames_array[i] = hostname` at line 796) after all search domains when `dots >= ndots`, querying `google.com.corp.local` **before** `google.com` on every lookup!

## Trigger Scenario

1. Have `search localdomain` in `/etc/resolv.conf` and call `await loop.getaddrinfo("google.com", 443)` -> Talyn queries `google.com.localdomain` first before `google.com`!
2. Call `await loop.getaddrinfo("dualstack.example.com", 443)` -> Talyn only sends the `A` query, resolves as soon as the `A` response arrives, and never queries `AAAA`.
3. Have a broken first nameserver returning `SERVFAIL` and a working second nameserver -> Talyn fails the lookup immediately upon receiving `SERVFAIL` from the first nameserver.

## Proposed Remediation

1. In `get_hostname_array` (`src/loop/dns/resolv.zig:780-800`), always include the bare `hostname` (`hostnames_size = loop.dns.search_domains.items.len + 1`): place `hostname` **first** (`index 0`) when `dots >= loop.dns.ndots`, and **last** when `dots < loop.dns.ndots`.
2. In `process_dns_response`, when all queries for one `server_data` have yielded negative responses (`rcode != 0` or `added_records == 0`), only call `mark_resolved_and_execute_user_callbacks(control_data)` if `control_data.active_servers == 1`.
