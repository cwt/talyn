# BUG-293 — Trampolines clobber `_leave_task` exception state

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟢 Low — Wrong logic (exception-state mishandling)
- **Files**:
  - `src/task/callbacks.zig:72-85` (step trampoline save/leave/restore sequence)
  - `src/task/callbacks.zig:127-140` (throw trampoline mirror)
  - `src/task/callbacks.zig:547-550, 623-626` (wrapper null-exception branches reached as a result — see BUG-273)
- **Lessons**: [Python C API Correctness §Lesson 28](../lessons/05-python-c-api-correctness.md), [Event Loop Lifecycle §Lesson 8](../lessons/03-event-loop-lifecycle.md)
- **Description**: When `_leave_task` fails it sets a Python exception; the unconditional restore overwrites it with the coroutine-era saved exception — and when that saved value is null, `SetRaisedException(null)` clears the error indicator. The wrapper then takes its `orelse { py_decref(task); return error.PythonError; }` path with no pending exception, violating Lesson 27 and triggering the BUG-273 double-free path.
- **Trigger**: `_current_tasks`/`_scheduled_tasks` manipulation failure during task step/throw.
- **Consequences**: Lost diagnostics plus a route into the task over-release bug.
- **Fix (Proposed)**: Only restore the saved exception when leave succeeds; otherwise chain or preserve the leave error.
