# BUG-169 — Leaked `parent_transport` Python reference on error in `write_operation_completed`

- **Status**: ✅ Fixed
- **Severity**: 🟠 High — reference leak on I/O error
- **Files**: `src/transports/write_transport.zig:240-347`
- **Lessons**: [Python C API Integration §Lesson 10](../lessons/03-python-c-api-integration.md), [Memory Safety §Lesson 01](../lessons/01-memory-safety-and-pointers.md)
- **Description**: In `src/transports/write_transport.zig`, `write_operation_completed` initializes `var success = false;` and sets `defer if (success) python_c.py_decref(self.parent_transport);`. If `PyObject_CallFunction(python_c.PyExc_OSError, ...)` returns `null` on line 284, the function immediately executes `return error.PythonError;` while `success` was still `false`.
- **Trigger**: Write failure where OSError instantiation fails or Python raises an exception.
- **Consequences**: Leaked strong reference to `self.parent_transport`, preventing the Python transport object from ever being collected by GC.
- **Fix**: Replaced conditional decref with unconditional `defer python_c.py_decref(self.parent_transport);` on every entry to `write_operation_completed`.
