# BUG-183 — Use-after-free and dangling pointer in loop.add_hook due to missing refcount hold

- **Status**: ✅ Fixed
- **Severity**: 🔴 Critical — Use-after-free in hot event loop iteration
- **Files**: `src/loop/python/control.zig:126-171, 202-218`
- **Lessons**: [Memory Management & Refcounting §Lesson 04](../lessons/01-memory-and-reference-counting.md), [Python C API §Lesson 21](../lessons/05-python-c-api-correctness.md)
- **Description**: In `src/loop/python/control.zig`, `z_loop_add_hook` allocated a `HookHandle` via `tp_alloc` (refcount = 1) and returned it to Python. The raw pointer was stored in the loop's hook list without calling `python_c.py_incref(@ptrCast(handle))`. If Python user code dropped the handle object without calling `.cancel()`, Python GC deallocated `handle`. The loop's hook list retained the dangling pointer. On subsequent loop ticks, `hook_callback` dereferenced `handle.callback` (UAF).
- **Trigger**: Adding a hook via `loop._add_hook(...)` without retaining the returned handle in a Python variable.
- **Consequences**: Memory corruption, invalid function calls, or segmentation fault on subsequent loop iterations.
- **Fix**: Held internal reference with `python_c.py_incref(@ptrCast(handle))` when adding to the hook list with `.cleanup = &cleanup_hook_handle`, and balanced with `python_c.py_decref` on cancellation or hook cleanup. Added unit test in `tests/test_hooks.py`.
