# BUG-314 — Child watcher unhandled non-transient waitid error descriptor leak

- **Status**: 🟢 Fixed (2026-09-07)
- **Severity**: 🔴 High — Permanent ChildHandler and pidfd leak when waitid returns non-zero error
- **Files**:
  - `src/loop/child_watcher.zig` (`on_child_exit`: lines 170–173)
- **Lessons**: [io_uring & Kernel](../lessons/04-io-uring-and-kernel.md), [Defensive Programming](../lessons/10-defensive-programming-and-code-quality.md)
- **Description**:
In `on_child_exit`:
```zig
const wait_res = std.os.linux.waitid(.PID, handler.pid, &info, std.os.linux.W.EXITED | std.os.linux.W.NOHANG);
if (wait_res != 0) {
    log.err("waitid failed for pid {d}: {d}", .{ handler.pid, wait_res });
    return;
}
```
If `waitid` returns a non-zero error (e.g. `-ECHILD` because another thread, library, or signal handler reaped the zombie):
The function logs and returns immediately. The handler remains permanently registered in `self.handlers`, `handler.pidfd` is never closed, and the allocated `ChildHandler` memory is leaked.
- **Root Cause**: Early return on `waitid` failure without cleaning up registered handler state.
- **Trigger Scenario**: Subprocess monitored by child watcher that is reaped by a parent process hook or external signal disposition.
- **Proposed Remediation**: On non-zero `waitid` return, log the error, remove `handler` from `self.handlers`, and invoke `self.teardown_child_handler(handler)`.

- **Fix (Applied — 2026-09-07)**:
  - `on_child_exit` (`src/loop/child_watcher.zig`): the non-EINTR/EAGAIN branch now unmaps the handler (only if the entry is still ours — BUG-313 identity guard) and calls `teardown_child_handler` before returning. This op is finished — no re-arm and no further completion can arrive for it — so the invocation owns the final teardown (pidfd close, callback decref, struct destroy). The user callback is not invoked: no exit status is available for an externally reaped child (matches the asyncio external-reap gap; the previously stranded handler also meant the pid could never be re-registered cleanly).
  - Note: this fix also restores the deferred-teardown contract for `remove_child_handler` — previously a handler whose op had already died with a non-transient `waitid` error would never receive the owning callback invocation, so removal leaked it permanently.
- **Regression test**: `tests/test_child.py::test_child_handler_external_reap_teardown` — child exits, an external `os.waitpid` reaps it first, the loop then processes the POLLIN CQE → `waitid` → ECHILD; asserts the callback did not fire, `remove_child_handler(pid)` reports `False` (previously `True`: stranded mapped handler), and the loop stays healthy.
- **Validation (2026-09-07)**: Confirmed still present.
  - `on_child_exit` (`src/loop/child_watcher.zig:160-173`): a non-EINTR/EAGAIN `waitid` failure logs `"not re-arming"` and returns; the handler stays mapped in `self.handlers`, the `pidfd` is never closed, and the `ChildHandler` struct is never destroyed — permanent leak exactly as described.
