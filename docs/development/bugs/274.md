# BUG-274 — `Loop.release()` runs cancelled watcher completions against deinitialized B-trees

- **Status**: 🔵 Open (2026-08-23)
- **Severity**: 🟠 High — Use-after-free on ordinary loop close
- **Files**:
  - `src/loop/main.zig:152-156` (pop-drain discards watchers without setting `fd = -1` or cancelling tasks)
  - `src/loop/main.zig:157-158` (`reader_watchers.deinit()` / `writer_watchers.deinit()` — frees root node)
  - `src/utils/btree.zig:28-33` (`deinit` destroys root without nulling `parent`)
  - `src/loop/main.zig:160-165` (`io.deinit()` cancel_all → second release pass executes callbacks AFTER tree teardown)
  - `src/loop/python/io/watchers.zig:16-33` (`loop_watchers_cleanup_callback`: `if (fd >= 0)` → `delete(fd)`)
- **Lessons**: [Event Loop Lifecycle §Lesson 56](../lessons/03-event-loop-lifecycle.md), [Data Structures & Algorithms](../lessons/07-data-structures-and-algorithms.md)
- **Description**: Cancelled completions of armed WaitReadable/Writable ops are dispatched by `io.deinit()`'s `cancel_all` and executed by the post-deinit release pass. Their cleanup sees `watcher.fd >= 0` (never invalidated by the pop-drain) and calls `reader_watchers.delete(fd)` / `writer_watchers.delete(fd)`, whose traversal starts at the destroyed root node → reads `nkeys` from freed memory, traverses wild child pointers. Distinct from fixed BUG-29/Lesson 56 (drain-vs-ring ordering).
- **Trigger**: `loop.close()` on a loop with live `add_reader`/`add_writer` watchers whose io ops are in flight.
- **Consequences**: UAF / wild writes during teardown; Debug-build crashes, ReleaseFast corruption.
- **Fix (Proposed)**: In the pop-drain, set each watcher's `fd = -1` (or run the drain after the final release pass), and/or have `BTree.deinit` null the root.
