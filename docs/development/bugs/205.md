# BUG-205 — Unhandled dns_timeout keyword argument and PyObject reference leak in DatagramCreationData

- **Status**: 🔴 Open
- **Severity**: 🟢 Low — Incomplete API Argument Support & Refcount Leak
- **Files**: `src/loop/python/io/datagram/create_endpoint.zig:23, 81-86, 28-46`
- **Lessons**: [Memory & Refcounting §Lesson 2](../lessons/002-memory-refcounting.md), [BUG-189](189.md)
- **Description**: In `src/loop/python/io/datagram/create_endpoint.zig`, `DatagramCreationData` defines `py_dns_timeout: ?PyObject = null` and `resolve_local_addr` checks this field. However, `parse_vector_call_kwargs` at line 84 omits `"dns_timeout"` from its parsed keyword argument list. Furthermore, `DatagramCreationData.deinit()` does not call `python_c.py_xdecref(self.py_dns_timeout)`.
- **Trigger**: Passing `dns_timeout` to `loop.create_datagram_endpoint(...)` or cleanup of `DatagramCreationData`.
- **Consequences**: Custom DNS timeouts ignored for UDP endpoint creation, and Python object reference leaked if set.
- **Fix**: Add `"dns_timeout"` to `parse_vector_call_kwargs` and add `python_c.py_xdecref(self.py_dns_timeout);` to `DatagramCreationData.deinit()`.
